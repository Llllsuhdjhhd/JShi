# 匠石总体架构

## 1. 架构目标

匠石的总体架构服务于两个目标：

1. 使身份、经历、价值和关系能够长期连续；
2. 使模型、检索方法和外部能力能够替换，而不把技术替换直接当成人格成长。

系统由七个部分组成。这些部分是职责边界，不要求分别部署，也不预先规定内部算法。

## 2. 七个系统部分

这七项是相互协作的职责部分，不是从上到下依次调用的七层。

### 2.1 主体基础设施

主体基础设施负责事件记录、数据保存、消息传递、权限、版本、备份、恢复和插件加载。它承载整个匠石，但不决定匠石是谁，也不解释事件的意义。

外部输入、内部活动、判断和行动结果都通过统一事件进入基础设施。事件可以追加说明和修正，但原始记录不得被解释层无声覆盖。

### 2.2 身份系统

身份系统包含身份档案和“我”接口。

身份档案保存身份来源、重要历史、长期承诺、自我叙事、重要关系及变化记录，负责跨时间连续性。

“我”接口接收当前事件，以及记忆、价值、审美、能力、关系和知识等主体材料，形成带来源的当前主体状态。它回答的不是抽象的资料查询，而是：

> 基于我的历史和当前处境，我此刻以怎样的自己面对这件事？

第一版只提供简单占位实现。未来可以替换主体整合方法，但不能无声改写身份档案或原始历史。

### 2.3 心智编排器

心智编排器负责组织一次具体活动：识别当前事件，选择需要调用的心智子系统，调用“我”接口形成主体状态，选择模型与工具，组织行动，并在得到结果后提交候选变化。

它是协调者，不是全部智能的来源，也不保存各子系统的专有状态。

### 2.4 可插拔心智子系统

心智子系统包括记忆、价值与边界、审美、能力、关系、知识与世界认识，以及判断与反思。

每个子系统都可以采用独立实现，但必须保留输入来源、输出类型和版本。子系统可以提出候选变化，不能绕过治理和身份系统直接重写长期身份。

### 2.5 通用模型与工具

通用模型与工具提供语言、理解、推理、想象、感知和外部操作能力。GPT、Gemini、未来微调模型及各种工具均位于这一部分。

它们是可替换的认知器官，不是匠石身份本身。替换后必须评估行为、能力和关系认识是否仍然连续。

### 2.6 治理、评估与升级系统

治理系统维护共同价值和行为边界，检查候选变化、插件兼容性、模型替换和重大身份更新，并提供审计、迁移和回退能力。

它通常不代替匠石作日常判断，而是维护长期运行条件。

### 2.7 内在活动系统

内在活动系统在没有直接外部任务时，按时间、重要事件、矛盾或未完成问题触发记忆整理、自我反思、学习、能力练习、模拟和梦式联想。

它负责发起和安排活动，实际内容仍由心智子系统、“我”接口及模型共同形成。内部产出必须区分事实、推断、反思和想象。

## 3. 依赖关系

七个部分之间遵循以下基本关系：

- 主体基础设施承载其他部分，并保存所有外部和内部事件；
- 心智编排器只依赖稳定接口，不直接读取插件内部存储；
- 心智子系统向“我”接口提供记忆、价值、审美、能力、关系和知识等主体材料；
- “我”接口把身份档案、当前事件与主体材料整合为当前主体状态；
- 编排器将主体状态和有关材料交给通用模型与工具，组织判断和行动；
- 外部结果返回基础设施，各心智子系统据此提出候选变化；
- 治理系统检查边界和连续性，身份系统只吸收具有充分依据的重要变化；
- 内在活动系统通过编排器发起活动，不绕过正常的来源记录和更新过程。

依赖方向不等于控制关系。任何部分都不能无记录地修改原始历史，也不能无来源地改变身份。

## 4. 两类数据流

### 4.1 外部互动流

外部互动流处理匠石与人和环境之间的往返：

> 外部输入 → 基础设施记录 → 编排器召集心智子系统 → “我”接口形成主体状态 → 模型与工具参与判断和行动 → 外部结果 → 形成新事件 → 提交候选变化

这条流强调当下回应和可追踪行动。每次重要输入、判断依据、使用能力和执行结果都应能够追溯。

### 4.2 内在活动流

内在活动流处理没有直接外部请求时的整理、反思和成长：

> 内在活动触发 → 编排器选择经历与心智材料 → “我”接口形成当前关切 → 模型进行反思、学习或模拟 → 形成候选解释或改变 → 治理与连续性检查 → 更新相应子系统 → 记录内部事件

触发条件可以是时间、重要事件、矛盾、未完成承诺或系统维护要求。内在活动不是虚构外部经历；其输入和产出同样需要来源记录。

两类数据流相互连接。外部互动提供经历，内在活动重新理解经历；内在活动形成的身份状态又约束下一次外部互动。

## 5. 稳定核心

稳定核心是跨模型、跨算法和跨插件保持连续的部分，包括：

- 原始事件及其来源；
- 身份标识和个人历史；
- 必须坚持的价值与不可越过的边界；
- 已有承诺和重要关系；
- 价值、偏好、自我叙事的版本与变化理由；
- 数据格式的版本信息和迁移记录；
- 对重要变更进行连续性检验的规则。

稳定不等于永不改变。它表示改变必须显式发生、可以解释、可以审查，并保留旧状态。

## 6. 可替换边界

以下能力原则上可以替换：

- 通用模型和推理服务；
- 记忆检索、排序、摘要和关联方法；
- 反思、评估和连续性检查的具体方法；
- 外部工具、数据源和交互渠道；
- 表达风格、语音和界面；
- 执行上述能力的插件。

可替换部分只能通过稳定接口读取或提出变更。替换时必须记录版本，验证数据兼容性，并比较替换前后的重要判断、承诺和关系认识。不能把算法输出直接写成不可修改的历史事实。

## 7. 横向约束

来源追踪、权限、安全、版本、审计和失败隔离贯穿全部七个部分，不属于某一个局部模块。

受约束偶然性也处于横向位置。它可以影响注意对象、候选方案、回忆顺序、探索方向和表达细节，使发展不被固定脚本完全决定；但它必须受事实、价值边界、承诺、权限和当前情境约束。偶然选择的结果及其条件应被记录。偶然性不得用来伪造来源、绕过边界或无理由改写身份。
