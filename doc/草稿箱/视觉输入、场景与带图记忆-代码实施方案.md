# 匠石视觉输入、场景与带图记忆 · 代码实施方案

2026-11-26 · 设计稿 · 对应 Windows 项目 JShi

## 要实现的行为

用户把摄像头从同伴转向一本书。匠石仍记得刚才在哪里、和谁一起看书。用户说“左下角那行”，它能在当前帧或仍可用的近期帧里找到对应局部，把书页全景和局部一起交给主认知。第二天，仅仅由一句话唤起这次经历，主认知就同时收到当时的经历和留存的低清图片。追问那行字时，再调出对应的高清局部。图上看不清的字、已经释放的像素和从未确认的人名，都保留为未知。

上面是验收场景。以下文件路径相对于 JShi 仓库根目录。拟增字段、模块和容量参数属于设计建议。

## 五步如何接进现有代码

| 功能 | 建议落位 | 输出与边界 |
|---|---|---|
| 1. 视觉输入 | 沿用 `vision/web.py`、`VisionService._observe`、`VisionModel` 和 `VisionStore` | 每份材料为本图及本图描述，保留来源、帧、采集会话、拍摄和接收时间。未完成描述的帧保留待处理状态。来自上一帧的描述继续带原依据帧。单图描述端只使用本图。 |
| 2. 当前场景感知与维持 | 拟增 `src/jshi/vision/scene.py`。由服务发布新观察、片场有相关新事件时更新，通过 `core/inputpack.py` 向下游提供固定版本 | 维护观察视角、当前地点、在场人物、活动、变化和遮挡。只读入与这些问题有关的片场材料，每条保留依据和最后确认时间。主认知可以提出候选解释。 |
| 3. 注意焦点与主认知输入 | 在现有视觉动作 `VisionService.request_action`、输入信封和 `SubjectProcess._cognize_once` 之间传递焦点 | 焦点由话语指向、上一轮目标、可见变化或主认知动作产生。记录“看哪一帧的哪个区域、在意什么”。给主认知的材料包括当前的话、有限的场景背景、相关图片和不确定之处。普通采样沿用现有入口调度。 |
| 4. 经历与视觉记忆的留存和回忆 | 扩展 `vision/store.py`、`vision/memory.py`、`vision/main_media.py` 和 `subject/process.py` | 选中经历后保留低清全图、重要焦点及关联。召回进入工作集时，历史图片随经历进入主认知；有针对性的追问才加载局部。 |
| 5. 人物、环境与经验更新 | 人物沿用 `vision/faces.py`、`recognition/photos.py` 和 `SubjectProcess._apply_visual_associations`；环境从 `vision/evidence.py` 的预留接口接入 | 人物肖像、共同经历、地点布局和找物经验可追到原始观察。单次看到“书在桌上”先成为经历；跨次观察或可靠纠正再推动长期认识更新。 |

五步之间允许反馈。主认知要求回看书页时，程序按目标重新读取已采集材料。读图结果带上“当时观察”或“本次回看”的时间和来源。每次只在出现新问题、新材料或更清晰局部时重新处理；相同请求重试复用结果。

## 先完成最短闭环：一句话唤起昨天，模型当轮收到昨天的图片

现有代码已经有半条以上的链路。`VisualMemory._ingest_batch` 把经历来源和快照关联交给记忆后端；召回先取文字片段。工作集选定之后，`SubjectProcess._recall_media` 用 `VisionStore.associated_many` 查关联图。当前能否送图还受 `main_image`、`cognition_images` 和 `MainImageGate` 的会话级去重影响。两处提供商消息构造还会给所有带标签图片追加“关联历史事件”的说明。

建议保留文字检索和工作集筛选，在**筛选之后、模型请求序列化之前**完成以下改动。

1. 按用途分别收集当前帧、近期比较帧、回忆全图、回忆焦点。当前图的 `main_image` 决策只管当前图。召回了一段有留存图片的经历，即使由纯文字触发，也产生历史图片候选。组包时按“是否已有当前帧”判断，避免已有历史图导致当前图漏装。
2. 引入请求内媒体清单，建议字段为 `role, frame_ref, asset_ref, captured_at, experience_ref, focus_ref`。程序保留完整关联，发送前映射为本轮短号。每张图前的文字交代来源、时间和与哪次经历关联；“当前图”“昨天的回忆图”和“昨天图的左下角”能明确对应到实际像素。
3. 调整 `MainImageGate.prepare`，使其按具体资产版本读取全图或局部。目前按 frame 再读原图，会把已选缩略图替换回大图。一次独立认知请求需要的回忆图须随请求发送；同一请求里相同内容只传一次，保留不同用途的文字关联。模型成功接收后再记录投递。回忆图的投递单独记作回看，避免 `record_main_images` 把它再次绑定成今天拍到的现场。
4. 在 `models/base.py` 和 `models/routing.py` 共用按角色生成图文块的逻辑，检查普通、流式、备用路由最终发出的消息。配置允许带图时，选择具备图像输入能力的主认知路由；纯文本配置只返回可用经历和明确的缺图状态。若使用视觉模型代看，应标明“视觉模型回看所得”。验收“主认知带图”时必须检查实际请求的图片字节，单有文字、图片 ID 或界面预览均不能通过。
5. 为最终请求设图数、字节和模型能力预算。在材料选择阶段让一段被作为视觉回忆采用的经历携带至少一张代表图，优先于同一经历的第二张图。多段经历同时命中而装不下时，记录哪些只作为文字背景，后续可逐段回看。预算、路由失败和图片缺失都可在诊断中区分。

建议组包顺序如下，名称仅示意接口职责：

```python
live = select_live_media(current_input, scene, focus)
recalled = select_memory_overviews(subject, selected_fragments)
details = resolve_requested_crops(subject, focus, selected_fragments)
manifest = fit_media_budget(live, recalled, details, model_capabilities)
parts = materialize_media(manifest)  # 在这里才读图、编号和编码
```

## 存什么，什么时候释放

继续使用视觉 SQLite 和已有的经历、事件关联。在 `VisionStore` 中增加两类持久记录，首版可按现有数据库风格实现：

| 建议记录 | 关键字段 | 作用 |
|---|---|---|
| 视觉记忆条目 | subject、来源 frame、描述依据 frame、关联 snapshot、capture、拍摄时间及其来源、概念摘要、可选布局关系 | 原始帧清理后，仍能通过经历和事件找到当时的材料。已知拍摄时间、上传时间和回看时间分别记录。 |
| 记忆图片版本 | 条目、版本类型 overview / crop / sketch、资产哈希、尺寸、父图、归一化区域、关注目标、首次观察或事后回看、生成版本 | 一张低清全图可对应多个原分辨率局部。线稿若有可靠生成依据则可作为资产；仅记得布局关系时，直接存关系即可。 |

**保存顺序。** 先在有界近期缓存中保留足够清晰的帧，支持用户晚几秒指出局部。决定存入记忆时，从经方向校正的同一张源图分别生成低清全图和裁片，记录坐标基准、尺寸及裁切边界。现有桌面采样宽度最多 1280，存储归一化后最长边最多 1600；局部保留的是实际取得的像素。位置不确定时保留全图或请求对准目标。已有文字抄录能保留内容，后续核对字形仍以图为据。

**提交与回收。** 在同一视觉库事务内写入资产、版本和关联，再释放原图保护。重复摄入按主体、源帧、区域、用途及生成版本幂等。跨记忆后端沿用现有摄入确认和 `record_delivery` 对账，可安全重试。垃圾回收同时检查滚动帧、在途读取、已有事件关联和新版本引用；相同内容只计一次实际占用。容量不足先保住已承诺的低清代表图，未能留存的局部记录不可用原因。没有保留像素的概念经历，召回时仍可正常使用。

**兼容旧数据。** 使用增量建表。旧条目有可读原图时可按需生成 overview；若只有描述，保留文字。现有 `associated_many(images_only=True)` 依赖旧帧和 `description_frame`，应扩展为从持久条目独立寻址，分别记录“描述依据帧”和“关注目标帧”。须覆盖“原图已回收、缩图和局部还在”的读路径。保留按需生成期间的旧读取路径，待新资产验证可读再释放旧资产。

## 如何维持场景、选择近期帧、避免越想越偏

- **场景中的每项判断都带依据。** 对人物在场、地点、物体位置，记录内容、状态、原始证据引用、最后观察时间。状态至少区分当前可见、此前确认、他人陈述、待核实和有依据的离场。主认知片场和推断继续指向原始帧或原话；同源转述不能增加独立证据数量。旧片场缺少可解析来源时只作为待核实线索。
- **选帧考虑时间和观察位置。** 用当前帧作锚点，按问题选择最近相关帧或变化前后的关键帧，保留采样间隔和明显缺口。只在同主体、兼容会话和视角中延续现场；镜头、设备或地点切换时显式划界。历史图片仍可用于对照，但标作历史材料。“书先在桌上、后来在手里”可以支持位置变化，两端图片不足以确认中间是谁拿的。
- **焦点先有对象和目的，再决定是否裁图。** 保存父帧、目标、区域、请求依据和有效范围。“下面那行”可以继承同一本书的焦点；镜头移开后不能把上一帧的像素坐标直接套到新画面。首版可接已有检测框、用户明确指向或模型在指定帧上给出的候选区域，裁切前校验边界；无法定位时保留全图并说明缺口。全景变化仍可触发新的关注。
- **处理迟到与纠正。** 场景更新核对 capture、观察时间与版本。旧结果可以补全对应历史帧，但不得覆盖更新的现场状态。明确纠正可以撤销人物或地点关联，并使依赖它的经验待复核。事后重看带来的发现记作新解释，保留当时所知。
- **经验从经历中生成。** 延用已有面孔候选、确认和撤销路径。人物画像以有依据的身份关联积累，环境经验先做“地点、稳定布局关系、支持或反驳该关系的经历”。同一次到访的连续帧只算同一事件来源。熟悉的地点帮助选择观察目标；现在人在不在、东西还在不在，仍需当前材料支持。

近期时效、代表图尺寸、每轮图数和长期预算都做成可调参数。优先复用 `VisionConfig` 的现有预算，分别统计存储字节、模型侧带图字节和响应延迟，再用桌面、手机与书页小字场景确定默认值。

## 实施顺序与验收

| 阶段 | 最小可交付改动 | 验收条件 |
|---|---|---|
| A · 带图回忆 | 先用现有已关联图片生成 overview；分开当前图与历史图的选择、去重和发送 | 用户只说“还记得昨天那本书吗”，主认知实际请求有历史图片。当前摄像头也开启时，两张图都有正确角色与时间。失败重试仍能带图。 |
| B · 保存精度与按需深看 | 版本表、持久清单、裁切、配额、旧数据读取与回收 | 同一经历先加载 overview；追问左下角后读取对应 crop。释放滚动原图、进程重启后仍可取回；未存的区域如实报告。 |
| C · 现场与焦点 | 串起场景状态、近期选帧、片场材料和细看动作 | 转向白板后，刚才的同伴成为“此前见到”。错名经多轮复述仍待核实；新证据能纠正。切换设备、延迟描述或看旧照片均不刷新旧人在场时间。 |
| D · 人物与经验 | 接人物确认链，持久化有证据的地点关系与纠正 | 同一人第二天回到同一房间，能回想共同经历；昨天的书在桌上，今天画面在书架时可更新位置，保留未知的搬动过程。 |

功能验收同时走桌面和手机来源、文本与多模态主模型、不同主体和已有记忆后端。先扩展 `tests/test_vision.py` 及已有主认知组包和路由测试，既检查图像内容、角色、顺序和拍摄时间，也检查取消、重试、容量不足、只存概念、身份纠正和不串主体。测试使用隔离数据，结束后释放服务、端口和文件句柄。真实摄像头材料和模拟书页分别记录验证结果。

**提示词维护。** 实施时按实际改动核对 P10 视觉描述/变化判断、相关 JEV、主认知和回看动作的完整请求。图片区块和标签也属于实际组包。依项目约定同步对应现有文档、索引和北京时间更新时间；旧例子保留版本边界，新例子用实际请求补齐。本文阶段不改变程序提示词或增加固定模型调用。
