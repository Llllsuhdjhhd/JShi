# Split 综合修订：总结与边界

最近更新时间：2026-11-01 16:00（北京时间）。

目标仍是复杂环境下认人与接话准确、主认知前反应及时。保留Split两阶段，不新增第三阶段或第四种模式，持续理解暂不实现。

## 两轮测试的结论

四场景对照减少输入但没有稳定提速；三段5–8分钟材料中67点完成新旧测试，11点原请求缺失。新版仍把未知对象当成不确定交往，延伸旧招呼和自身播放，误将旁聊未完或问完待答视为等待；输出格式及字段矛盾仍存在。人物无逐句真值，不报告准确率。长回放是固定历史前文模型测试，不是新版片场闭环或正式宿主效果。

## 本次修订

1. 用途缩为人物、交往和处理职责。
2. 交往部分集中为四类依据：有效面对设备说话、点名、语义问答承接、仍有效的持续交谈。时间支持关系，不单独授予许可。
3. uncertain必须具有关联依据和明确缺口；对象未知、熟人、同话题、能帮忙均不替代关联。短例覆盖游戏转向、延迟问答、辣度旁聊及点名广。
4. 完整度与交往独立：问完等答不是表达未完；旁聊未完也不wait。程序拒绝none+wait，失败走原有异常处理，不能宣称这解决全部语义误判或正式宿主所有后续行为。
5. 恢复关键约束提示：理由长度、引用最多6个、不得新增字段或代号、level必须为JSON整数。Schema不变，不增加模型调用。
6. 沿用前轮组包精简：准备阶段仅保留可处理/待续人物，原始entry和关联材料不改写。

## 主认知复核

已核对style/prompt_levels.py的DIALOGUE_DIRECTION_NOTE：入口人物不证明受话对象，旁聊可ignore，指向未明不允许开口。models/prompt.py也把JEV片场作为可滞后的参考。未新增相同规则，未更改人物复判分工。该能力能否实际拦截仍需隔离接入主认知验证；不把规则存在当成运行已可靠。短答、等待接话和提前控制仍受入口许可，不能靠事后主认知撤回。
