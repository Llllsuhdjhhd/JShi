# 匠石（JShi）

**一个尝试综合构建长期交往能力的 AI 个人项目。**

我想探索怎样把记忆、情境理解、人格、判断和工具行动结合起来，让 AI 能够持续与人相处，并逐步形成有连续性的认识。

目前，匠石已经有可运行的文字与语音交互、人物判断、情境整理、记忆接入和工具流程，并在实际对话中持续改进。下一步是提高这些机制的可靠性，并实现经历持续影响认识、人格与行动的完整闭环。

## 一、为什么做这个项目

有时在思考，或读文学和科幻作品，尤其是阿西莫夫的机器人系列时，我常常希望自己身边也有这样一个机器人：能够长期相处，成为一个伙伴、一个朋友。随着AI 对编程技能的解放，也让我这样的非计算机从业者有机会去尝试实现这个想法。

“怎样成为一个人”是这个项目的出发点。对我来说，这意味着它不仅能回答当前的问题，还能保留经历，理解所处的情境，形成自己的判断，并让经历参与后续的认识与行动。这是我希望在已有基础上继续实现的目标。

“匠石”这个名字来自《庄子》中匠石与郢人的故事。我也想希望人和 AI 能否形成这样的信任与默契。

做到现在，匠石已经实现了文字与语音交互、人物判断、情境整理、记忆接入和工具执行等部分功能，并能在实际对话中试用。开发和使用的过程让我看到，这个目标中的许多部分可以转化为具体的工程问题，借助现有技术，通过实现、测试和迭代逐步解决。已经做出来的这些功能，让我觉得有机会继续把最初的想法向前推进，在很多方面，可以看到最初想法的实现的可能性。

接下来需要提高已有机制的可靠性，并补上经历怎样持续修正认识、人格与行动的闭环。最终能做到什么程度，要在继续实现和实际使用中检验。

## 二、这是怎样的项目

匠石是一套围绕语言模型组织输入、上下文、记忆与行动的软件。程序负责维护状态、组织材料和调度工作，模型负责相应的判断与表达。

当前主要流程是：

**输入 → 人物判断 → 组装上下文 → 主认知 → 回应或工具行动 → 记录与后台整理。**

历史材料可以通过记忆接口被召回，整理后的情境可以供后续轮次使用。这个数据流程已经存在，但它是否能够稳定支撑长期交往，仍在验证。

当前入口是网页版文字和语音。以后可以探索接入应用、音箱、带视觉的设备或机器人，具体入口不限定项目的整体结构。

软件主要做流程和数据组织，模型通过接口接入。可以使用线上服务，也可以适配提供兼容接口的本地模型。不同模型仍需核对接口、输出能力和运行资源，不能假设更换后效果相同。

### 这些机制怎样配合

我认为这个项目值得介绍的一点，是把现场理解、上下文整理、记忆和工具放在同一个交往流程里，让它们分工配合。

大语言模型的上下文能力为理解现场材料提供了基础。写场把积累的输入输出整理成持续更新的情境，保留活动、参与关系和未完成事项；近期尚未整理的事件继续作为补充。这样，模型既能接触当前输入，也能读到前面发生的事情，而不必每轮载入完整历史。

在此基础上，第一次 JEV 判断人物，并选择主认知档位与历史记忆需求。同一人格可以按本轮需要使用不同功能和长度的提示词。主认知据此读取材料，决定是否回应以及是否实际使用工具；后台 JEV 和写场则继续整理情境，为后续轮次提供参考。工具执行通过独立流程推进，再把相关结果和进展交回主流程。

交流还需要处理“正在说话时，别人又开口了”的情况。语音入口已有停止和播放接续机制，可以响应明确的停止要求；JEV 中也保留了判断继续播放、停止或接话的处理。当前人物终审与主认知接话已经分工，这些播放控制还需要继续协调和完善。

这套配合希望同时解决两个问题：让交往保持必要的上下文，也让不必立即完成的工作在后台推进，减少交流中的等待。它已经有相应的程序机制，但能否稳定改善理解、响应时间和运行成本，还需要继续测试。

## 三、关键机制

### 记忆与回忆

记忆是项目的核心之一。记忆负责保存和整理经历，回忆负责在当前需要时取回相关材料。

这部分通过独立接口接入，可以替换和继续改进。目前提供内置后端及 REMS 后端接入，已有存储、整理和召回方面的处理，但效果还需要验证。遗忘、过时信息的处理，以及纠正之后如何更新记忆，也需要继续完善。

检验重点不只是有没有存下、能不能搜到，还包括取回的材料是否正确，是否被主认知合理使用。

### 输入落位与人物判断

输入需要保留人物、时间、来源和所属活动等信息。原话、声纹候选和模型的人物结论分别记录，便于检查错误发生在哪一层。

第一次 JEV 综合声音证据、当前输入和已有情境判断人物，并选择主认知提示词档位与历史记忆需求。它不生成回应，也不决定实际使用工具。

第二次 JEV 在后台结合积累材料整理情境、复核人物判断，供后续入口使用。当前真实使用中仍有错认、漏认和关系信息丢失，需要继续改进。

### 主认知、上下文与写场

主认知读取当前输入和组装后的材料，判断是否回应、向谁回应，以及是否使用工具。

“写场”是把分散的输入输出整理成一份可以直接阅读的情境文字，保留当前活动、交互关系和未完成事项。系统提示词说明工作方法，片场提供动态材料。这是一种让通用语言模型使用持续上下文的方法。

当前有主认知片场与 JEV 片场，两者承担不同用途。写场在后台运行，尚未整理的事件作为补充保留。需要持续检验摘要是否遗漏重要信息、是否把推测写成事实，以及场景变化后旧信息是否及时更新。

### 人物肖像与人格配置

人物肖像用于浓缩相处材料，作为理解人物的参考；人格配置和提示词用于组织匠石的表达方式、交往原则与任务要求。两者用途不同。

当前已有相关配置与材料接入，部分人物经验整理依赖 REMS 后端。这些材料的质量和使用效果仍需验证。

我希望人格提示词能够开放讨论和修改。同一人格可以按任务使用不同功能和长度的提示词，当前主认知已经有三档。**配置人格不等于实现人格成长；通过经历持续修正性格、认识和判断的机制，还需要进一步设计与实现。**

### 实时交流与模型匹配

当前通过入口判断、后台整理、按需回忆和提示词分档，调整主流程需要等待的工作量。工具执行也通过独立流程推进。

实时性还包括说话过程中能否被打断、什么时候该停下来听，以及哪些附和或背景发言不应中断播放。当前已实现明确停止要求的处理，并有 JEV 播放控制与接续逻辑，但自然插话、重叠声音和主认知接话之间的配合还不完善。判断有人开口、判断是否需要回应、判断是否停止当前播放，是需要协调的几件事。

后续可以继续研究不同阶段与模型的匹配，以及同一人格下不同提示词的使用方式。目标是同时改善交流体验、响应时间和运行成本；不能只缩短提示词，却丢掉必要能力。

### 工具与运行记录

工具流程包含策划、执行和结果包装。主认知需要理解实际进展，区分完成、部分完成与失败，并复用已有结果。这部分仍有材料筛选和结果交付上的问题需要完善。

我希望工具能够独立开发和复用，既可以在本地执行，也可以通过远端服务提供结果。共享工具目录或工具市场是后续设想，目前没有实现。

网页调试入口可以查看原始记录、整理材料、实际提示词、模型输出和耗时，帮助定位问题。记录存在不代表处理正确，需要把输入、过程与结果对照起来看。

## 四、下一步怎样改进

项目可以按模块推进。每个模块都应该有明确的问题、实现和验证方式。

| 方向 | 接下来要做的事 |
| --- | --- |
| 记忆与回忆 | 验证整理和召回效果，完善遗忘、过时信息与纠正处理 |
| 人物与情境 | 改善综合辨人、关系保留、并行活动理解和场景更新 |
| 主认知与写场 | 检查材料遗漏、事实与推测的区分，以及回应是否合适 |
| 提示词与模型 | 比较不同档位和模型组合的能力、速度与成本 |
| 工具 | 完善结果筛选、状态交付和复用，探索统一接入方式 |
| 长期发展 | 设计并实现经历如何影响认识、人格与行动的闭环 |
| 多模态 | 接入新的感知材料，并与现有事件和情境关联 |

前几项是在已有机制上继续改进；长期发展和新的感知入口还需要补充实现。它们可以拆成工程问题逐步尝试，但是否能达到最初的目标，需要持续验证。

## 五、参与这个项目

目前这是一个个人项目。我希望公开代码、设计和实际问题，让感兴趣的人可以从具体模块参与。

可以参与记忆与召回、语音与人物判断、上下文整理、模型与提示词、工具接口、网页展示，或测试和文档。一个可复现的问题、一组有预期结果的案例，也能成为有价值的贡献。

项目仍处在开发和验证阶段。当前已有文字与语音入口、两段 JEV、主认知、后台写场、记忆接口、人物参考、工具流程及数据查看。长期人格发展、完整的认识修正闭环、视觉和机器人接入，以及工具市场，尚未完成。
