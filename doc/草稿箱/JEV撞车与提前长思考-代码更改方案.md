# JEV撞车与提前长思考：代码更改方案

- 状态：核心实现已落地；本文件保留设计目标，实际文件、取舍及验证以[实施记录](JEV撞车与提前长思考-实施记录.md)为准。
- 最近更新时间：2026-10-28 08:40（北京时间）。
- 讨论依据：[JEV撞车与提前长思考：讨论纪要](JEV撞车与提前长思考-讨论纪要.md)。
- 本轮交付：代码改动设计、供应商协议核对、阶段划分与验收要求。未修改运行代码、现行提示词、密钥或模型路由，未发起真实推理请求。

## 1. 本轮确定的方向与修正

1. **阿里云百炼 `decision-model-preview` 为优先决策模型，TypeSafe 官方 Jev 为可切换选项。** 两者实现相同的业务接口；选择供应商不能要求修改语音调度代码。用户已说明在 `.env` 配置 key；实施时沿用现有环境加载机制，验证实际变量绑定和地域端点，不复制密钥到文档或网页响应。
2. **统一决策接口至少服务两个用途**：JEV1 调用撞车调度，以及后续长句对前段思考成果的影响判断。两用途共用供应商配置，但使用独立问题定义、超时策略、评估样本与置信度阈值。
3. **决策模型只选择处理路径，不能负责生成语境化接话或答案。** 不增加“决策 → 生成等待话 → 播完 → 重新思考”的串行链路。
4. **长思考提前，主认知状态仍线性提交。** 用户继续说话时先做记忆与材料准备，条件适合再分析候选答案；后文到齐后短思考收尾，实质转折时重新长思考。
5. **短思考不是强制省算。** 后续生成模型读取完整输入与证据，有权升级到长思考；一次错误的快判断不能把它锁在旧答案里。
6. **语音反馈分三类**：话中短暂停歇的附和、说完后的等待接话、转折后的重想接话。共享播放出口，分别设置许可，避免重复与抢话。

## 3. 供应商适配：共用业务接口，不冒充聊天接口

### 3.1 已核对的协议

| 项目 | 阿里百炼 | TypeSafe Jev |
| --- | --- | --- |
| 选用模型 | `decision-model-preview` | 默认可用 `jev-latest`；校准及正式验收固定具体版本 |
| 请求 | System One：model、state、questions | System One：model、state、questions |
| HTTP 地址 | 当前 API 文档示例为工作空间地域地址下 `/compatible-mode/v1/systemone` | `https://api.typesafe.ai/v1/systemone` |
| 认证 | Bearer，绑定百炼 key | Bearer，绑定 TypeSafe key |
| 首期公共能力 | choice、noul；score 仅保留类型支持，当前两个用途不必使用 | 同左；不启用图像或其他实验能力 |
| 关键差异 | 官方说明最多 16 问，问题数增加会影响延迟 | 官方说明可在同请求并行评估多问；仍以实际调用测试为准 |

两家均不是 Chat Completions，不能发送 messages、stream、temperature、max_tokens 或 reasoning_effort 代替它们的请求格式。阿里模型页“不支持结构化输出”指通用生成式功能栏，不能据此否定专用 System One 决策返回。

阿里官方不同文档中可见工作空间地址与旧 DashScope 地址示例。本方案不依据普通 Qwen 地址猜测接口必定可用；把**完整 System One endpoint**作为可配置字段，按用户账号和当前 API 文档验证。没有 workspace 信息时不虚构；先完成不依赖它的代码，连接检查明确提示所缺配置。

来源：[阿里决策 API](https://help.aliyun.com/zh/model-studio/decision-model-api)、[阿里模型说明](https://help.aliyun.com/en/model-studio/decision-model-preview)、[TypeSafe API](https://docs.typesafe.ai/api/system-one)、[TypeSafe 模型与限制](https://docs.typesafe.ai/models)。用户提供的控制台详情页本次无法直接读取，以上通过官方公开文档核对；未验证账号的模型权限。

### 3.2 新增模块及契约

建议新增 `src/jshi/decision/`，避免将供应商协议塞进 `voice/jev.py` 或 `models/base.py` 的聊天实现：

| 新文件 | 职责 |
| --- | --- |
| `base.py` | DecisionRequest、DecisionQuestion、DecisionAnswer、DecisionResult、DecisionPort、能力描述 |
| `system_one.py` | 共用异步 HTTP 传输、响应结构校验、deadline、脱敏错误、连接生命周期 |
| `providers.py` | BailianDecisionPort、TypeSafeDecisionPort、供应商能力和配置校验 |
| `routing.py` | 当前供应商快照、按用途预算、熔断、显式备用路由；不保存业务对话 |
| `config.py` | 环境与本地设置合并、密钥引用、功能开关、阈值版本 |
| `material.py` | 请求材料精简、人物和输入短代号、时间表达、长度预算 |
| `policies.py` | 撞车与后续影响的问题定义，以及回答组合规则 |

拟定接口：

```python
class DecisionPort(Protocol):
    async def decide(self, request: DecisionRequest, *, deadline: float) -> DecisionResult: ...
```

`deadline` 是单调时钟绝对截止时间，覆盖排队、连接、读取和解析，不只设置 socket 超时。请求包含 purpose、state、questions；input_revision、session、generation、配置版本在程序侧作为关联元数据，不必全部发送给模型。

结果至少保留：供应商、实际模型名、逐问题答案／概率／可选 confidence、usage、服务端耗时（如有）、客户端总耗时、request_id、状态。状态区分 success、timeout、unavailable、invalid、stale；没有 confidence 时保持缺失，不能用最高选项概率冒充 confidence。noul 与 choice 使用独立阈值。

公共传输优先复用语音已依赖的 aiohttp，一个服务生命周期内复用连接，不为每个片段新建客户端。不要求额外安装两套 SDK；如果后续改用 SDK，必须关闭超出实时 deadline 的自动长重试。禁止发送 key 到另一供应商地址。

校验：答案问题 ID、问题类型、枚举值与概率键匹配，数值有限且在合法范围，概率和允许合理浮点误差；缺项、额外未知动作或矛盾控制进入不确定回退，不按“接近正确”执行停止。保留未知响应字段以便诊断，但不让它们成为新动作。

### 3.3 配置与页面

新增独立 `decision` 配置区：

```text
provider: bailian | typesafe          默认 bailian
providers.bailian: model、endpoint、api_key_env
providers.typesafe: model、endpoint、api_key_env
purposes: collision、continuation
mode: off | shadow | active
budgets: 按用途设置截止时间及最大积压
threshold_profile: 供应商＋模型版本＋用途＋问题版本
fallback_provider: 可空；默认不自动跨供应商
```

建议新增环境变量 `JSHI_DECISION_PROVIDER`、`JSHI_DECISION_MODE`、`JSHI_DECISION_BAILIAN_ENDPOINT`、`JSHI_DECISION_BAILIAN_MODEL`、`JSHI_DECISION_TYPESAFE_ENDPOINT`、`JSHI_DECISION_TYPESAFE_MODEL`。密钥引用先支持现有 `DASHSCOPE_API_KEY`／`JSHI_API_QWEN_API_KEY` 与 `TYPESAFE_API_KEY`；若用户实际配置使用其他名称，通过 api_key_env 绑定，不要求重复填写。当前只检查过相关变量名，未输出值，也未据此证明 key 可用。

优先级：明确保存的用途配置 > 环境配置 > 非敏感默认值。新路由缺密钥时显示未配置并走回退，不能影响原聊天服务。首次迁移不直接打开 active；完成连接验证及 shadow 回放后启用阿里 active。

页面增加“快速决策模型”选择和两个用途开关，提供“只观察、不影响对话”状态与连接测试。选择 TypeSafe 时保持原阿里配置，反向亦然。全局主认知模型切换不覆盖 decision。每次请求绑定配置快照，热切换只影响新请求。

连接测试发固定合成材料，验证答案结构及实际耗时；不拿“请回复 OK”的聊天测试代替，不测试真实个人历史。页面只返回 has_key 和脱敏诊断；本地配置保存密钥引用，沿用 `.env` 密钥，不把环境 key 另存一份。

## 4. JEV1 撞车状态机与接入位置

### 4.1 新增入口协调器

新增 `src/jshi/voice/entry_scheduler.py`，由它管理：

- 当前 JEV1 作业及输入范围、原话版本、阶段、取消 token；
- 等待批次，按来源和音频范围去重、保留修订，不跨人拼句；
- 至多一个在途 collision 决策及一个“最新待判断快照”；
- 对旧作业的控制许可与交付许可；
- 已消费输入范围，避免合批后重复启动主认知。

新输入记录与展示继续独立运行。不能把快速决策放进被旧 `_judge` 阻塞的同一串行 await 后面，否则失去作用。也不为每个字启动独立模型任务；快速判断忙时持续更新待处理快照。

### 4.2 触发与动作

仅当已有 JEV1 作业且出现新的稳定转写片段、修订或独立提交时触发撞车判断。空队列正常输入不多加一层决策。待判断期间旧作业可继续计算，涉及新输入的正式交付暂缓至决定或预算到期。

首期两题：`relation`（接续／纠正／独立／背景／明确停止／不确定）与 `old_work`（继续／暂缓交付／停止）。程序用受限组合表转换动作；矛盾组合按不确定处理。识别停止对象靠材料与选项说明，不用停止词正则替代语义。

| 语义 | 入口处理 | 对主认知的影响 |
| --- | --- | --- |
| 接续补充 | 累积原话，保留可用旧判断，下一轮处理联合材料 | 未完整时不抢答；已运行主认知按独立任务控制处理 |
| 纠正替换 | 撤销旧交付许可，取消或逻辑作废旧入口，合并修订后再进入 JEV1 | 不让旧答案新开口；是否终止外部任务不能由此隐含决定 |
| 独立交往 | 独立排队并保留原任务 | 主认知仍串行；紧急程度由已有交往控制处理 |
| 无关背景 | 旧入口继续，背景原话仍留事件记录 | 不重新启动主认知，不污染人物归属 |
| 明确停止 | 优先撤销对应表达／入口的交付许可 | 外部操作请求仍交原业务流程，不能仅停止音频就算完成 |
| 不确定／失败 | 原话合并交普通 JEV1；不再串行问一个备用裁判 | 不使用未经新材料核对的旧候选直接回答 |

程序不能依据快速模型直接覆盖人物身份或丢弃新原话。快速模型返回的是调度依据，不替代 JEV1 的入口终审。

### 4.3 竞态与过时结果

在事件循环内维护 `session_generation`、`entry_job_id`、`input_revision`，以及每个原始片段的替换关系。旧结果只能作用于它实际覆盖的输入范围。A/B 的判断期间来了 C，则禁止它放行涵盖 C 的整体回应；可应用明确只影响 A 的保守动作，其余进入最新快照判断。

统一检查点必须覆盖：

1. `_judge` 内的 `apply_entry/on_entry`，在执行 stop/redirect 之前；
2. JEV1_2 回应准备启动前与返回后；
3. direct_reply 与 waiting_reply 入队前；
4. `_judge_work` 向 turn_queue 交付前；
5. `_start_plan` 与实际播放前。

已有 epoch 的含义保持为会话／任务控制版本，不能每来一段话都递增 epoch 并顺带停止所有播放。输入版本与任务取消分别建模。

停止任务需要唤醒 await 并拦截迟到回调；线程中的 HTTP 请求可能仍占资源。保持残留请求数量上限与 deadline，不能持续取消又无限启动线程。关闭会话时清理协调器、网络请求、预览与反馈；重启不恢复未提交候选。

### 4.4 避免连续输入导致无限等待

未启动作业合批，保留一个最新快照，完成表达优先于试探准备；新说话持续到来时不强行抢答。若第一人的表达完整而第二人持续说话，按人物与输入范围处理，不能用会话全局“还有新话”永远阻塞第一人。无法可靠分开时保留给普通入口判断，不制造确定身份。

超出缓冲预算时保留输入归档并分批送普通入口，明确记录降级；不能静默丢掉开头条件，也不能把限长截断伪装为已经说完。

## 5. 阶段性长句材料：先打通预览，再谈提前思考

新增 `src/jshi/voice/provisional.py`，定义 `ProvisionalInputSnapshot`：会话、表达连续性键、覆盖片段、原话修订、说话人证据、音频起止、收集时间、表达完成状态。模型可见时间使用明确的相对秒与间隔；原始精确时钟和长 ID 留程序侧。

修改 `turns.py` 生成不可变的待接续快照，通过 `local_input.py` 的专用准备回调传递。可以复用现有预览来源，但不要让 `turn_analysis` 的展示副作用触发正式入场。稳定 ASR 片段和整句 final 分别标记。

预览重复、最终释放和 ASR replaces 必须归一到同一来源记录。预览只供准备，不重复写 external_input、不提前宣称用户完成表达、不在 JEV2 中记录“匠石已经回答”。实际原话仍可按原事件机制保留。

启动准备的首期条件：已有可靠接续关系、明确朝向匠石的任务、足够稳定的任务材料，且当前主认知不忙。未知人物不自动拒绝，但身份相关召回范围必须受现有证据约束；无法确认归属的半句先不进行私人记忆召回。

首期每个表达最多一个在途重准备；新片段只累计，不逐字重跑。字数／时间仅作节流及最大积压限制，不作语义完成依据。明确停止、正常完整请求优先，准备占用不应拖慢它们。

## 6. 主认知拆分：准备、分析、收尾、提交

### 6.1 不直接复用 experience 的副作用

新增 `src/jshi/subject/preparation.py`，把可复用准备逻辑从 `process.py` 和回忆调用处提取；保留 `experience()` 为兼容的正式入口，逐步让它调用这些共用函数。不得同时复制两套人格组包与记忆筛选逻辑。

拟定服务：

```text
prepare_materials(snapshot, scope, cancel_token) -> PreparedMaterials
analyze_provisional(materials, snapshot, cancel_token) -> PreparedAnalysis
finalize_with_preparation(final_input, preparation, route) -> FinalCandidate | NeedDeep
commit_final(final_candidate, expected_revision) -> 正式结果
```

`PreparedMaterials` 保存有效记忆、来源、检索条件、人物范围、时间与版本；`PreparedAnalysis` 保存候选答案、采用的假设、未解决问题和证据引用，不要求暴露内部思维链。两者均为临时工作成果，不能成为用户事实或已交付内容。

### 6.2 状态和副作用隔离

准备阶段允许：读取记录、检索候选、模型分析、写独立诊断。需要审计记忆检索内部是否会更新 working set、命中次数、评价记录或人物状态；这些要延迟提交或明确标为试探，不能把函数名中的 load 当作无副作用保证。

准备阶段禁止：创建正式活动、推进记忆游标、消耗 gap、写人物确认、采纳工具结果为已使用、更新长期记忆、执行外部工具、提交片场、生成可播放音频。若工具查询未来要提前，须按工具实际副作用另行扩展；首期只预读内部材料。

`_cognize_once` 目前有片场协调；应拆成“从固定快照构造请求”和“调用模型”再复用，不能直接让试探分析进入写场锁与回填。`self.last_model_response`、`_deferred_write`、`_voice_party_ids` 等运行状态改为正式执行上下文或只在 commit 后更新，避免候选污染正式任务。

### 6.3 线性执行及取消

保留同一主体的一条主认知执行线。首期主任务忙时不另启长准备；空闲时准备先行，真正请求到齐后升级同一工作，或取消其过时分支并接续。可以并行的只有持续收音、快速判断和只读准备中的受控操作，不允许两个 experience 同时写共享状态。

前段分析迟迟未完成时，后段并不能读取尚不存在的成果：沿用方向可等待同一分析完成后收尾；已经确定目标被推翻就取消旧分析，按完整输入重算；不得无限等准备结果，也不得为了等它而延迟明确停止。

复用有效性由程序核对主体、人物范围、来源版本、记忆删除／更新、材料时效与权限；通过之后，内容是否仍适用才交决策或生成模型。更换说话人不能直接复用另一人的私人材料。

正式输入和输出只提交一次，绑定最终输入版本；回忆可见、实际使用、播放确认和后续评价仍按既有闭环区分。预览被废弃只留下诊断，不参与“成功回答／成功记住”的统计。

## 7. 后续长句判断：快模型参与，但不是唯一裁判

### 7.1 谁做什么

新增 `src/jshi/voice/continuation.py`，消费完整或新增表达与 PreparedAnalysis。

| 工作 | 负责方 |
| --- | --- |
| 材料、人物和输入版本是否可复用 | 程序校验 |
| 后文是否改变目标／关键条件，是否适合沿用前段成果 | 决策模型提供快速建议 |
| 怎样回应新内容、是否需要解释、更改措辞 | 生成式短思考／长思考 |
| 何时开口、是否可以附和、音频如何让出 | 播放仲裁与声音状态 |

首期不需要每次后文都调用快模型。前段只有少量准备、直接正常处理更便宜时跳过；材料版本已确定失效时直接正常长思考。保留快判断的条件是它有机会避免昂贵重算，而且耗时预算允许。

### 7.2 判断内容与路由

输入提供前段原话、后段原话、必要完整上下文、候选目标及假设、已准备材料清单；不能只提供“前面结论”要求模型维护它。对材料不足或截断明确标记，不把未知当作未改变。

问题分别判断：

- `impact`：可沿用／局部变更／目标或关键前提改变／不确定；
- `expression`：已足够处理／仍需后文／不确定。

程序组合为 `reuse_light / revise_light / restart_deep / wait`。出现“但是”不自动重算；没有转折词也可能完全换目标。仅靠高置信度不能取消后段生成模型的复核责任。

| 条件 | 下一步 |
| --- | --- |
| 表达未完且没有独立可处理部分 | 继续收集，可保留准备，不正式回答 |
| 材料有效、快判断建议沿用或局部修改 | 一次生成式短思考，读取完整输入与候选依据 |
| 目标／关键前提改变或校验失效 | 立即进入长思考，可复用仍有效的材料 |
| 快判断不确定、失败或超时 | 回到完整输入的正常主认知，不再排一层裁判 |
| 短思考返回 NeedDeep | 不交付其未完成实质答案，升级长思考；同输入版本最多升级一次 |

首期即使 impact=可沿用，也不直接播放旧候选答案，仍由短思考核对新内容。是否日后开放直接使用候选，需独立验证，不包含在首期。

### 7.3 回应用户对“先输出一段话”的提醒

这里有两种不同需求：

1. **仅表达仍在处理**，如“我再想一下”。可以从经过审核的短句集合选择，或保持静默；无需再问一次生成模型。重新长思考已经启动，短句不成为启动条件。
2. **解释转折、回应情绪、纠正已说出口的内容或回答其中一部分**。这是有内容的生成任务，决策模型与固定短句都不能胜任。交给正式生成模型处理：如果当前短思考已在运行，可一并产出恰当过渡；否则由长思考生成阶段给出有依据的开场，不为必须先说一句而串联额外调用。

禁止让决策模型返回自由文本 reply，禁止把“好的”统一解释成无意义占位，禁止从概率标签拼成似懂非懂的解释。没有合适话就静默，比错误表态更好。已经播出的错误内容需要明确纠正，不能靠“我再想一下”掩盖。

## 8. 三类短反馈及统一播放仲裁

新增 `src/jshi/voice/feedback.py`，管理 `listening_ack / waiting_ack / reconsider_ack` 三类意图。每个意图绑定来源版本、有效期、对象、类别、候选短句及是否仍有效。

- listening_ack：只在语义许可、短暂停顿、无重叠且尚未结束表达时考虑；对方恢复说话立即让出，迟到则丢弃。
- waiting_ack：正式完整输入进入主认知后，预计等待足够长且没有近期反馈时考虑，复用现有 WaitAckTiming。
- reconsider_ack：确定需要重新深入思考后考虑；属于可选反馈，不必每次转折播放。

统一优先级：有效停止／用户正在说话 > 正式回应 > 合适的短反馈。正式回应已准备好时取消尚未播放的短反馈；同一轮不能先“嗯”、再“我想一下”、又“我再想一下”连续占用话轮。

播放前检查最新声音活动、输入版本、重叠和现有队列，而不只检查文本生成时状态。独立句级回执记录实际已播；未播、部分播与完整播分开。反馈不计为任务完成，也不提前关闭工具事项。

短停顿识别需持续音频活动事件。如果当前链路只在 ASR batch 完成后才知道停顿，不能宣称已具备及时附和；实施时补实时 speech-start/end 信号及回声处理，在可用前关闭 listening_ack，保留说完后的等待反馈。

短反馈可预合成并按声音／语调／语速版本缓存；缓存命中也必须过实时播放许可。先复用当前语音出口与停止机制，不另起一个无法统一打断的播放器。

## 10. 预算、降级与观测

初期只给实验配置，不将任何数值写成产品性能承诺。建议快速决策客户端总预算先以 800 毫秒作可调整起点，shadow 实测后按两个用途分别确定；它不是厂家延迟保证，也不应无限放大以掩盖慢请求。预算耗尽返回明确降级路径。

- 首期每会话最多一个碰撞快判断和一个最新待处理快照；续句判断合并同版本重复触发。
- 关闭实时路径自动重试，认证／权限／格式错误直接提示；429/5xx 触发短期熔断，期间走正常入口，不阻塞收音。
- TypeSafe 作为可手动选择的完整实现；自动跨供应商重试默认关闭。若以后开启，必须在同一总预算内，不把一次 800 毫秒预算变成两个完整超时。
- 不同供应商和版本分别保存校准数据。不能把阿里 confidence=0.9 与 TypeSafe confidence=0.9 当作相同实测可靠度。
- 记录：purpose、实际模型、问题版本、输入版本、排队／网络／模型报告耗时、判定、采用／拒绝原因、旧结果作废数、准备复用率、NeedDeep 次数和最终首个有效音频时间。
- 不输出 Authorization、环境值或带凭据 URL；原始请求材料沿用项目本地诊断访问控制，不在通用错误日志复述个人资料。

收益指标以“用户说完到有效回应”计；短接话只能单独改善感知等待，不能用它的首音频掩盖实质答案更慢。增加快判断后若节约不了重算或明显增加尾延迟，应允许按用途关闭。

TypeSafe 与阿里用相同业务样本分别评估，不能跨供应商直接套置信度门槛。对话测试要包含真实原话的否定、反问、引用、玩笑、多人接续与 ASR 修订，而不只用几个清晰的“改成明天”样例。
