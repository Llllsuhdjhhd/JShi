# 信封与 JEV 场景回放测试：实施方案

- 日期：2026-10-29（北京时间）。
- 状态：首批实施中；已实现独立录音与场景库、收录页面、流式识别回放及冻结 JEV 入口。正式信封合批、完整撞车联测和对比报告尚未完成，实际能力以[使用说明](../场景录音与回放测试.md)为准。
- 范围：信封阶段、JEV1 的 combined／split／decision，以及入口结果执行与主认知交接边界。不评价主认知生成质量。
- 场景由用户人工添加、标注和调整；不预设必须使用某套剧情，不编造真实录音或测试结果。

## 1. 目标与阶段边界

建立可以长期追加的独立录音素材库，通过人工场景重复测试、比较程序改动前后效果。每次能追溯：原声是什么、各阶段如何处理、JEV 实际看到了什么、最终交给主认知什么。

信封阶段包含六个调试子阶段，属于职责划分，不要求实现按六步串行：

| 编号 | 子阶段 | 检查内容 |
|---|---|---|
| E1 | 输入接收与保存 | 音频、文字和媒体的完整性、来源、收到时间 |
| E2 | 分段与媒体对齐 | 语音起止、停顿、强制切分、音画时间关联 |
| E3 | 内容提取 | 转写、修订结果、视觉材料及其版本 |
| E4 | 人物与来源证据 | 声音分组、候选人物、绑定身份、不确定与冲突 |
| E5 | 统一封装 | 原文、媒体、人物、时间与输入编号的一致性 |
| E6 | 收集与合批 | 续句、排序、去重、当前批次及待处理范围 |

JEV 阶段分为五个观察点：J1 实际请求材料；J2 入口判断；J3 人物归属；J4 回应准备；J5 结果应用、时效和异常。J2/J3/J4 在不同模式中可能合并或跳过，不为测试额外添加模型调用。

JEV2 写场不纳入本轮质量评估；已有片场作为初始材料注入。独立人物复核可用固定的完成事件测试其对后续输入的影响，真实复核另作为可选扩展。主认知、播放器、工具执行用可记录调用的替身接收结果，验证交接及停止控制，但不实际执行外部动作。

## 3. 素材、场景、运行结果分开保存

建议默认目录如下，允许设置专用数据根目录：

```text
test_assets/entry/
  README.md
  media/<素材编号>/
    original.<原格式>
    playback.wav
    metadata.json
  scenarios/<场景编号>/
    scenario.json
    annotations.json
    context.json
    frozen_input.json
    baseline/                 # 可选：明确选定的对照结果
test_runs/entry/<运行编号>/
  manifest.json
  scenario_snapshot/
  events.jsonl
  requests.jsonl
  results.json
  report.html
  state/                     # 本次独立运行状态
```

素材永久保留，不参与近期录音清理；运行结果允许以后单独清理，不能连带删除素材。原件不覆盖；素材使用内容摘要校验，同一素材可关联多个场景。场景修改产生新版本或保留旧版本快照；每次运行冻结当时场景、标注和配置。

`metadata.json` 记录格式、采样率、声道、时长、文件摘要、导入来源、原 capture 与区间（有则保存）、转换参数。未知录制时间留空；文件导入时间不能代替录制时间。

`scenario.json` 使用带 `schema_version` 的 JSON，首期避免引入额外配置格式依赖。必需字段：场景编号、版本、名称、说明、标签、素材引用、测试能力要求、时间线和预期引用。支持纯文字场景；图片、视频保留媒体类型和时间关系，但只有接入对应适配器后才允许运行，未支持时显示“不支持”，不能静默忽略媒体。

时间线事件区分：输入音频、文字到达、播放开始／已播放片段／结束、思考开始／结束、复核结果完成。每个事件有相对毫秒时间和明确类型。人工场景从页面填写，不要求用户编辑 JSON。

人工标注与模型可见材料分开：正确文字、真实人物和预期决策只供评估器使用，禁止随模型请求发送。记录标注状态：待补充、已人工核对、有争议；缺失预期显示“未评分”，不算通过。

本地音频、人物状态和完整运行记录默认不提交 Git；实施时配置精确忽略规则，模板、说明和脱敏的人工构造自动化用例可以提交。只保存和本场景有关的人物参考及上下文，不把完整正式数据库复制为默认素材。

## 4. 人工添加场景的操作

入口一：近期录音页选择连续录音的开始与结束位置，试听后“保存为测试素材”；支持添加到已有场景或创建新场景。跨录音分块要拼接连续区间，缺块时明确失败或标记缺口，不能补静音伪装完整录音。

入口二：上传已有录音，或直接添加文字场景。导入时验证格式与时长；不支持转换时保留原件并显示待转换，不能宣称可回放。

场景编辑页填写名称、说明、说话人标注、上下文、预期处理；按需添加多个时间线事件。可以先只存录音，之后补标注。复制场景可复用素材并修改上下文，例如同一句话在播放中和闲置时分别测试。

导入必须复制文件而不是只记临时缓存路径，采用临时写入、校验、原子提交；失败不出现半成品场景。并发创建不能覆盖已有编号，所有媒体引用限制在指定素材根目录内。

## 5. 三种运行范围与两种模型方式

### 运行范围

1. **信封单测**：录音／文字进入真实入口，停在交给 JEV 的边界，输出 E1–E6 结果。
2. **JEV 单测**：读取人工确认并冻结的信封及上下文，分别调用三种模式。冻结的是运行参数与证据，不是上一版已经渲染的提示词；当前程序重新组装请求，并保存实际 system/user。
3. **信封＋JEV 联测**：按时间线重放真实入口，经真实合批与调度，记录所有决策和最终主认知交接。整个场景按顺序运行，不把连续场景误拆成互不关联的单句测试。

冻结信封不能简单把 dataclass 的字典当作 `decide_batch` 参数；适配器明确转换 batch、context、delivery、媒体参数和关联映射，保留版本及来源。历史快照字段不兼容时需迁移或提示不可运行，不能猜值。

### 模型方式

- **离线模拟**：转写、模型返回或故障按脚本注入，验证程序合批、路由、控制和竞态。用于自动化回归，不声称真实识别或模型质量。
- **真实模型**：实际调用配置的识别／JEV 服务，评估质量、稳定性和耗时。界面明确显示会调用哪些服务；配置次数、调用上限和总预算，取消后停止派发新请求并忽略迟到结果。

运行范围与模型方式分别选择；本地真实声纹／断句不应被含糊地标成“模拟”。报告逐阶段标明真实、模拟、冻结或未运行。

音频质量回归可快速处理；等待、合批、打断和时延测试使用原始速度回放。快速回放结果不计入真实时延比较。原始录音时间、录音内偏移、场景相对时间、运行墙钟、单调计时分别保存；需要适配当前时钟的材料统一平移，保留原值，不能把所有历史材料重置成刚发生。

### 时间驱动的断句与撞车测试（补充约定）

时间不是报告附件，而是输入契约。断句、续句、合批、JEV 在途撞车均依赖输入到达节奏。完整联测必须从连续音频小块送入真实入口开始，不能先离线转写整段，再按句子开始时间投递文字来代替。

保存连续原声，同时保存可获得的接收时间表：每块的样本起点、样本数量、通道／capture、相对接收时刻与顺序。音频样本时间和接收时间分别保留；网络延迟、抖动或积压不能被误写成原声停顿。旧录音只有波形而无接收记录时，只能按采样时间生成标准流式节奏，明确标为“重建输入节奏”，不能称为原现场精确复现。

回放按同一个单调时钟的绝对目标时刻调度，避免逐块 sleep 累积漂移。音频投递任务不等待识别或 JEV 完成，保持真实积压、背压及报错行为；记录计划投递、实际投递和偏差。结尾保留场景规定的观察期，让真实静音等待和在途任务完成；文件 EOF 的强制刷新与自然断句单独标记，不能靠立即 flush 掩盖未正确结束的片段。

必须关联记录以下时刻：音频区间起止、块收到、语音起止检测、分段发布、临时／最终转写及修订、信封就绪、合批提交、JEV 排队／许可／请求开始／返回／结果应用，以及停止／失效事件。音频片段的结束时刻不等于转写就绪或 JEV 收到的时刻。独立 JEV 回放使用边界实际就绪事件及其相对时间，不用音频起点冒充送达时间。

提供两种互补的时序场景：

1. **固定时间线回放**：按原接收记录或明确的人工节奏输入音频，重新经过断句和识别，再观察真实 JEV 延迟下是否发生撞车。相同输入不保证每次撞在同一个处理阶段，报告必须列出实际发生的重叠区间。
2. **受控撞车回归**：通过可控模型返回延迟、事件屏障及后续音频输入，稳定制造“首个 JEV 尚未返回时出现续句”“旧结果在新输入后返回”“返回与应用之间失效”等顺序。事件触发可表示为“请求开始后指定间隔送入下一段连续音频”；设等待上限，前置事件未发生则标为未触发／未覆盖，不能算通过。动态拼接必须标为人工时序变体，保留素材原件和实际投递时间线。

断句测试包括短停顿续说、较长静音、长句强制切分、尾段、多人交叠以及临时转写被最终结果替换。标注给出可接受边界与必要语义覆盖，不要求只有一种切法。原静音保留，不能删除或压缩后称为原场景；改变停顿长度须建立独立场景变体。

受控测试可使用真实断句／转写配模拟 JEV 来验证入口联动，也可使用冻结就绪事件单测 JEV 调度；两种覆盖范围分别标记。断言包括：续句引用正确、合批无遗漏重复、旧结果不越权提交、停止幂等、超时回退只按约定执行。固定时序真实模型回放用于评估实际质量与延迟，受控模拟用于保证竞态分支可重复覆盖。

实施补充：`store.py` 保存音频接收索引；`clock.py` 提供统一调度与偏差记录；`scenario_runner.py` 实现独立输入生产任务、事件触发、屏障和有界结束等待；通过入口与调度只读观测记录阶段时间，必要时注入时钟／模型延迟依赖，禁止测试逻辑改写正式分支。`test_entry_replay.py` 覆盖静音、尾段与接收时钟，`test_entry_jev_replay.py` 覆盖上述竞态。报告用同一时间轴展示“音频—断句—转写—信封—JEV”，明确素材时间和实际处理时间。

## 6. 三种 JEV 的公平比较

同一场景版本、冻结材料、初始状态、模型配置、预算和重复次数构成一组比较。每种模式每次重复使用全新状态。初始建议每种运行 3 次作为观察，不据此宣称统计显著；出现波动再增加次数。

记录选择模式、实际路径、decision 服务 off／shadow／active、回退原因、所有模型调用和成本信息。decision 回退 split 计入 decision 的实际使用结果，同时单列原生路径与回退比例；不能藏掉失败和回退。

模型不同时明确标注“整套配置比较”；相同模型时才能更直接比较流程差异。小样本列出每次耗时、中位数、最大值与样本数，样本足够时再用 P95。轮换模式顺序，避免长期固定顺序造成缓存或服务负载偏差。记录超时与失败，不只统计成功请求。

独立 JEV 测试固定上下文；联测时每种模式保有自己的隔离状态，后续上下文差异作为该模式行为的结果记录，不能强称每一轮材料完全相同。

## 7. 观测与评价

统一事件字段建议为：运行编号、场景编号、阶段、事件类型、相对时间、输入引用、父事件引用、状态、产物引用和耗时。异步阶段按实际事件关联，不能把重叠耗时简单相加。诊断文件保留真实程序引用，模型端继续沿用既有短代号映射。

| 范围 | 自动检查 | 人工评价 |
|---|---|---|
| 接收／封装 | 音频摘要、顺序、引用有效、无重复、无缺口 | 原声是否完整 |
| 断句 | 对标注边界的容差、覆盖与遗漏 | 字头字尾是否损伤、切分是否妨碍理解 |
| 转写 | 中文字符错误率、漏句；保留原文及评分归一化规则 | 同音字、语气和关键语义 |
| 人物 | 错认、未知、分组混淆分开统计 | 有争议归属与背景声音 |
| JEV | 允许的路由／控制集合、引用范围、是否重复停止、禁止旧结果提交 | 介入时机、短答合理性、准备材料是否合适 |
| 交接 | 主认知触发次数、实际交接内容、迟到丢弃、停止回执 | 是否漏回应或误插话 |

预期支持多个合理结果、禁止行为及必要条件，不要求所有回答逐字相同。不确定人物保持 unknown 不等于错认；模型失败、环境缺失、未标注、运行通过分别显示。历史运行只作对照，不自动成为正确答案。

报告按“录音与标注 → 信封各阶段 → JEV 实际请求／返回 → 应用结果”展示，支持三种模式并排、同模式两次运行对照。首期不自动调用另一个模型打分。

## 9. 分批实施与验收

### 第一批：独立留存与人工场景管理

完成素材库、场景结构、导入／试听／编辑页面和近期录音导出。允许先存录音再补预期。

### 第二批：信封回放

### 第三批：JEV 三模式独立比较

完成固定输入运行、真实／模拟服务适配、请求和结果报告。decision 包含运行方式及回退诊断；同场景可多次运行。

验收：三模式使用相同初始材料；人工答案没有进入请求；可识别原生 decision 与回退 split；记录模型失败与预算耗尽；缺少模型配置显示不可运行，不伪装通过。

### 第四批：联测与调度边界

复用真实入口调度，加入播放中插话、半句续接、多批输入、超时和旧结果迟到的事件脚本；主认知只记录交接。

验收：停止只执行一次；迟到结果不提交；背景和等待输入保留正确；交接输入不遗漏／重复；同场景可以定位“信封材料错误”还是“JEV 判断错误”或“应用结果错误”。

### 第五批：持续回归

支持按场景标签／范围选择、与指定基线比较和差异汇总。运行记录不覆盖基线；只有人工选择才能更新基线。新增真实问题先保存场景，修复后将其加入相关回归集合。

## 10. 文档与范围约束

### 火山与本地声学对齐：本轮处理思路

两边应共用同一采集会话、同一16kHz PCM样本流及会话内样本编号；火山当前发送内容与本地 `SessionAudio.append` 内容相同。但共用坐标不等于两边选出的发言起止相等，也不等于结果返回时刻相等。断连重建、跳过静音、重采样或源裁剪时必须有独立capture编号和显式偏移映射，不能继续假定零点相同。

当前火山路径是云端转写、分段返回后本地取对应原声做声纹，不经过旧 `LocalASR` 六秒转写窗口。不得以修改六秒上限代替接入火山侧本地声学。

本地声学旁路已在2026-10-29接入火山在线入口：同流VAD持续推进，最终转写对应原声由Smart Turn判断，按可靠声音续接，完成／未知／超时放行；不运行整套本地转写，不等待六秒窗口。JEV在途／思考／播放优先旁路，EOF释放，关闭隔离。单人原声已真实复验；实现和限制见[整句判断说明](../整句判断说明.md)。

对齐按样本时间区间建立多对多关联：一条火山转写可以覆盖多个本地声学片段，一个本地活动区间也可能覆盖多条火山结果。禁止按第几条、返回先后或强制边界相等去配对。声纹优先用火山对应原声，必要时在其范围内选较干净的单人子区间，记录实际使用区间；不能跨到邻人声音或用另一个人较长的片段替代。多人的重叠、候选冲突、时间差距过大时保留不确定，不硬认人。

已实施的末尾20毫秒内取音容差只规避小范围边界误差，不承担上述全套区间会合。原始云端时间不改写，实际使用范围另记。真正缺块或超出容差继续诊断失败，未知人物不阻断输入。

首期不修改业务提示词，只记录当前真实请求。若实施中改变 system/user 组装、变量、分支或 Schema，必须同步受影响的提示词全文、说明和索引，并更新北京时间分钟级时间；不得以“只是测试工具”为由漏同步。

已新增 `tests/README.md` 使用入口及正式使用说明。首批已写入代码，未自动收录实际录音、调用真实模型或重启正在运行的应用；后续实施仍按上文分批验收。
