# 400 自我调优 阶段 0——实现方案

> 对应：`doc/草稿箱/400-自我调优.md`
> 状态：阶段 0 已编码
> 本方案只做阶段 0 和草稿里已写明的过渡期。阶段 1 以后不在本文。

## 0. 独立判断

自我调优不新建包。登记、建议、预检都放在现有的 `src/jshi/effectiveness/`。魔法书的登记和覆盖层放在 `src/jshi/core/`，因为读取发生在各模块，不该反向依赖有效性分析。

现有分析器在 `InProcessEffectiveness._run` 里直接 `strategy.apply`，不写原因。按草稿的过渡期，这一步停掉：仍可出建议，不改 `recall_strategy.json`。宁可暂时不调档，也不留一条不写原因的写入。

覆盖层按参数名取代默认值。每一版保存当时的整份覆盖。不把覆盖值加到默认值上。覆盖层只收 `params.py` 里的项，一个数据目录一份，该目录下的主体共用。召回档位和条数不进覆盖层，仍由各主体的 `recall_strategy.json` 存放，03 继续从那里读。登记表只约束这两项的范围和可调级别。

计数口径是程序里的计数器编号。观察期用同一个函数、同一套窗口算法重数。建议文字里可以有说明，说明不能当口径。

耗时目前只在当轮内存里。阶段 0 开始落盘，落盘之前的耗时没有记录。费用仍在 REMS 的调用历史里，本阶段不新做费用计数器。

进程启动时读一次覆盖层，装进进程里唯一的当前快照，之后不再更换。读取函数一律读这份快照，不另接参数。漏传参数就不会悄悄退回默认值。

## 1. 目标与范围

### 做

1. 给 `params.py` 里已有的参数，以及召回档位 `default_level`、召回条数 `limit`，补登记：名称、默认值、允许范围、可调级别、影响的指标、关联约束。待迁移的参数不搬。覆盖层里出现表外的名字就拒绝。召回两项只登记，不写入覆盖层。
2. 覆盖层文件、版本和回滚。`locked` 项出现在覆盖层里时，启动报错，错误信息包含文件路径和参数名。提供 CLI 子命令查看当前版本并回滚到上一版。
3. 启动时把快照装进进程级的当前位置，只装一次。下面第 2 节列出的导入时取值点改为用到时再读。台账由 `cli` 构造时传入字数。
4. 分析器不再调用 `strategy.apply`。它把问题、计数器编号、样例活动编号、原因文字和建议的新值写成一条建议。建议不生效。停用时把各主体当时的档位和条数记一笔，作为以后的起点。
5. 预检函数：没有计数器、没有样例、没有原因、一次改多于一项、超出范围、改 `locked`，都拒绝。已登记的关联约束被破坏时，只允许把绑定项调整到刚好满足约束，并记在同一条建议里。档位和条数同时变化时，本条建议只留档位。
6. 登记阶段 0 能重数的计数器。材料只来自已经落盘或本阶段开始落盘的记录。
7. 活动耗时追加写入主体数据目录。`subject_activity` 和 `write_zone` 两次调用把渲染后的提示词按第 3.6 节存下来。`reflection` 本阶段不存。写入失败不挡说话。
8. 单元测试覆盖上面几条，包括覆盖 `SUXIPO_ZONE_CHARS` 之后 `zone_chars_for("suxipo")` 读到覆盖值。改掉「分析器会把档位改低」的现有测试。

### 不做

- 不调用模型写原因，不读源码，不自动改任何参数。这是阶段 1、阶段 2 的事。
- 不跑 LoCoMo-Plus，不建调参集。
- 不重放样例。本阶段只把以后能重放的输入存下来。
- 不做提示词版本（L2）和补丁分支（L3）。
- 不迁 `params.py`「待迁移」那一节。
- 不做热加载，不做夜间调度。建议仍由现有的活动收尾调用 `run_due` 产生。运行中不更换当前快照。
- 不从 REMS 汇总费用。
- 不统计用户纠正和不满。账本里没有单独字段，本阶段不新写识别规则。
- 不把召回档位或条数写进 `param_overlay.json`。

## 2. 读取参数

### 2.1 当前快照

`param_overlay.install` 在进程启动时调用一次，把快照放进模块级的当前位置。再次调用直接拒绝，除非走测试用的上下文管理器。

`params.py` 里的读取函数（`active_zone_chars`、`working_set_limit`、`suxipo_zone_chars`、`value_narration_chars`、`memory_flush_chars`、`value_load_char_budget`）不再接受快照参数。它们只读当前位置。未安装时读登记的默认值，这只发生在尚未启动的单元测试里。已安装之后，没有任何调用点可以绕开它去读另一套数。

测试用上下文管理器临时换上另一份快照，退出时恢复。测试结束时当前位置必须回到进入之前，避免用例互相污染。

不把快照对象从 `cli` 一层层传到账本、风格包和自省。那些地方改为调用上面的读取函数，或在构造时向读取函数要一次值。

## 4. 数据结构

### 4.1 参数登记

一条登记是不可变对象，写在代码里，不写进主体数据目录。

| 字段 | 内容 |
|------|------|
| `name` | `params.py` 的项与常量同名，如 `MEMORY_FLUSH_CHARS`。召回两项用 `recall.default_level`、`recall.limit`，标明 `store` 为 `recall_strategy`，不进入覆盖层 |
| `default` | 与现在的常量或策略默认值一致。召回档位默认 1 |
| `low`、`high` | 闭区间。召回档位为 1 至 9，与 `strategy.py` 里已有的限制相同 |
| `level` | `auto`、`review` 或 `locked` |
| `metrics` | 这项若被改动，观察期还要看哪些计数器。只作记录，本阶段不据此自动改值 |
| `constraint` | 可空。现只登记一条，见第 4.4 节 |

初始可调级别从紧：

- `auto`：只有 `recall.default_level`、`recall.limit`。存放处是 `recall_strategy.json`。本阶段预检通过也不写入。
- `locked`：`DEFAULT_MODEL_CONTEXT_WINDOW`、`INTROSPECTION_ENABLED`，以及 `VALUE_NARRATION_CHARS`。
- 其余现有常量先标 `review`。没有人审入口之前，预检把 `review` 和 `locked` 一样拒绝。

待迁移参数不进这张表。覆盖层里出现表外的名字，或出现 `recall.default_level`、`recall.limit`，启动报错。

### 4.2 覆盖层

路径：`{data_dir}/param_overlay.json`。一个数据目录一份，不按主体拆分。不管召回策略。

```text
{
  "version": 2,
  "values": {"MEMORY_FLUSH_CHARS": 4000},
  "history": [
    {"version": 1, "values": {}, "record_id": "", "at": "..."},
    {"version": 2, "values": {"MEMORY_FLUSH_CHARS": 4000}, "record_id": "...", "at": "..."}
  ]
}
```

当前值：`values` 里有这个名字就用它，没有就用登记的默认值。回滚把 `values` 换成上一个版本里的整份 `values`，`version` 加一，不删除历史。`locked`、未登记或越界的名字出现在 `values` 里，加载抛出。异常文本同时写出文件路径和参数名。调用方不要捕获后继续用默认值。

本阶段没有任何对话路径调用写入。写入函数给测试、CLI 回滚和以后的阶段 2 用。

CLI 子命令 `overlay`：不带参数时打印路径、版本号和当前 `values`。`--rollback` 回滚一版并打印回滚后的版本号。文件不存在时说明路径，退出码非零，不新建文件。

### 4.3 计数器

每个计数器是一个纯函数：输入为某个主体已经读入的记录和时间窗，输出为次数或比例，外加命中的 `activity_id` 列表。

本阶段登记这几个：

| 编号 | 数什么 | 来源 |
|------|--------|------|
| `ratings.unrelated_ratio` | 评分条目里 `relevance == unrelated` 的比例，并列出所在活动 | `memory_ratings.jsonl` |
| `ratings.missing_coverage` | `coverage == missing` 的轮数 | 同上 |
| `ratings.misleading` | `misleading` 为真的条目数 | 同上 |
| `traces.empty_recall` | 有查询文本但 `recalled_event_ids` 为空的次数 | `recall_traces.jsonl` |
| `timing.total_ms_p90` | 落盘耗时的 90 分位 | 本阶段新写的耗时文件。落盘前没有历史 |

窗口由调用方传入起止时间。计数器内部不读「目标值」。第 5.2 节规定建议所用的窗口怎么取。

### 4.4 建议记录

路径：`{data_dir}/tuning_suggestions.jsonl`。追加，不改旧行。

| 字段 | 内容 |
|------|------|
| `id`、`subject_id`、`created_at` | 起点记录没有 `subject_id`，见下 |
| `status` | `baseline`、`suggestion` 或 `rejected` |
| `counter_id` | 上表中的编号。起点记录为空 |
| `window` | `start`、`end`，取这批评分 `created_at` 的最小值和最大值 |
| `count` | 该计数器在这个窗口内的结果 |
| `sample_activity_ids` | 命中的活动编号，至少一条，否则不写这条建议 |
| `cause` | 现有启发式的 `reason` 文字，外加参数名 |
| `code_ref` | 固定写 `src/jshi/effectiveness/memory_analyzer.py`，本阶段不让模型填 |
| `proposed` | 一项：参数名、旧值、新值。约束要求随同调整时，`companion` 里再写一项，并写明约束名 |
| `applied` | 固定为 `false` |

起点记录在建议文件还不存在、或还没有 `status` 为 `baseline` 的行时，由 `cli` 启动写一次。内容是当时 `recall_strategy.json` 里每个主体的 `default_level` 和 `limit`。没有策略文件的主体记默认档位 1、条数空。以后自动改档位停用，观察从这些值算起。已有起点记录则不再写。

没有样例活动编号的，不写建议。`run_due` 的触发条件（8 条未分析评分，或间隔）保持不动。

### 4.5 新落盘

耗时：`{data_dir}/activity_timings.jsonl`。一行一轮，字段为 `subject_id`、`activity_id`、`started_at`、`total_ms`、`steps`。在现有 `clock.finish` 之后追加。失败只记日志。

重放输入：`{data_dir}/step_inputs.jsonl`。只存两种用途，并写上 `purpose`：

- `subject_activity`：认知、开口这一次；
- `write_zone`：写片场这一次。压缩片场时丢掉事实，发生在这一步。

`reflection` 本阶段不写。存渲染后的文本，不存 `SubjectState`，不复制 REMS。这样以后只能重放这一次模型调用，不能重放投递。失败只记日志。主路径不读这个文件。

文件里是完整对话，不外传，不进仓库。`.gitignore` 增加 `step_inputs.jsonl`。

体积：系统提示词相同则只存一次。正文行带哈希；每次调用只记 `purpose`、`activity_id`、`subject_id`、`model`、系统提示词哈希和当轮用户提示词。设一个字节上限，登记在 `params.py` 旁，本阶段为 `locked`。超出后按调用时间删最旧的调用行；某个系统提示词哈希已经没有调用引用时，再删那一行正文。做法与记挂账本超过上限后丢掉最旧记录相同，不把整份文件留在内存里重写以外的状态。

## 5. 行为

### 5.1 启动

`cli._runtime` 读取 `param_overlay.json`。文件不存在视为空覆盖、版本 0，然后 `install`。`locked`、未登记、召回项或越界则启动失败，错误信息包含该文件的路径和参数名，进程不要接着用默认值说话。

安装成功后构造台账，把当时的 `active_zone_chars()` 传进去。若建议文件还没有起点记录，写第 4.4 节的 `baseline`。

### 5.2 收尾时的建议

`run_due` 仍在活动收尾后调用，异常不向外抛。

内部顺序：

1. 取未分析评分。未到触发条件则返回。
2. 用现有启发式或已有基准评估器得出建议档位、建议条数和原因文字。不再把结果写入 `RecallStrategyStore`。现有启发式只改档位，条数为空；基准评估器也写明本期不调条数。若两者相对当前值都变了，本条只保留档位，条数留给以后另一批评分。
3. 选定计数器：档位建议下降时用 `ratings.unrelated_ratio`，上升时用 `ratings.missing_coverage`，不变则不写建议，只把这批评分标为已分析。
4. 窗口取这批评分 `created_at` 的最小值和最大值，写进 `window`。用该计数器在这个窗口上重数。命中活动编号为空则不写建议。
5. 预检这份建议。预检失败也追加一条建议，`status` 为 `rejected`，写上拒绝理由，仍然不改档位。
6. 预检通过则 `status` 为 `suggestion`，`applied` 为 `false`。

标为已分析的规则与现在相同，避免同一批评分每轮都出建议。

### 5.3 预检

纯函数。拒绝时返回理由字符串，不抛异常给说话路径。测试里可以单独调用。

拒绝条件：

- 没有 `counter_id`，或编号不在登记表里；
- `sample_activity_ids` 为空；
- `cause` 为空；
- `window.start` 或 `window.end` 为空，或 `start` 晚于 `end`；
- `proposed` 多于一项，且多出来的项不是该约束声明的绑定项；
- 同一次既改 `recall.default_level` 又改 `recall.limit`；
- 新值超出登记范围；
- 目标项的级别不是 `auto`；
- 提议写入覆盖层的名字是召回两项；
- 绑定项的调整幅度超过「刚好满足约束」所需。

通过不产生副作用。

### 5.4 关联约束

`SUXIPO_ZONE_CHARS` 必须不小于 `MEMORY_FLUSH_CHARS` 的 1.5 倍。

这个 1.5 不是临时取的。`params.py` 里片场预算的注释写的是投递阈值的 1.5 到 2 倍，为的是尚未投递的原话还能留在片场里。`subject/process.py` 里人格生效的条件之一，是素材达到片场预算的一半。约束取注释里的下限 1.5，不取 2。按现在的默认值，5000 只比 3000 的 1.5 倍（4500）多 500，改其中一项时容易顶到这条边界。

只改其中一项且结果破坏约束时，预检给出绑定项的最小调整值。两项都由提议者指定、且与这个最小值不一致的，拒绝。未登记的参数对之间，任何越界关系都拒绝，不自动补第二项。

本阶段没有业务写入，这条只由单测固定下来。

## 6. 测试

放在现有 `tests/test_effectiveness.py`、`tests/test_effectiveness_baseline.py` 和新建的 `tests/test_param_overlay.py`。不跑 live 测评。

- 覆盖层取代默认值：默认 3000、覆盖 4000 时，读取函数读到 4000，不是 7000。
- 回滚后读到上一版的整份 `values`。CLI `overlay --rollback` 同样。
- 覆盖层含 `locked`、未知名字或召回项时，加载抛出，异常文本里有路径和参数名。
- 越界值拒绝写入。
- 安装覆盖了 `SUXIPO_ZONE_CHARS` 的快照后，`zone_chars_for("suxipo")` 返回覆盖值。退出上下文管理器后回到原值。
- 台账在不传 `active_window_chars` 时，读到的是当前快照，而不是导入模块时的整数。
- 约束：只提高投递阈值并破坏片场下限时，预检附带片场的最小调整；乱写的第二项被拒绝。
- `run_due` 在无关评分足够时不改变 `default_level` 和 `limit`。建议文件里有 `ratings.unrelated_ratio`、样例活动编号、原因文字，以及由这批评分 `created_at` 最小和最大组成的 `window`。`applied` 为 false。
- 评估器同时给出新档位和新条数时，建议里只有档位。
- 同一路径上预检失败时档位仍不变，建议状态为 `rejected`。
- 建议文件为空时，启动写一条 `baseline`，里面有各主体当时的档位和条数。已有 `baseline` 时不再写。
- 计数器对同一批行、同一窗口重复调用，次数和活动编号相同。
- `step_inputs.jsonl` 在一次同时有认知和写场的活动后含有 `subject_activity` 和 `write_zone` 两行，系统提示词正文按哈希只出现一次。
- `experience` 在建议写入或耗时落盘抛错时仍返回回复。沿用现有「分析失败不挡说话」的测法。

## 7. 阶段 0 的验收

- 同一批无关评分能写出一条建议：计数器编号、次数、窗口、样例活动编号、原因、建议档位都在，`recall_strategy.json` 不变。
- 覆盖 `SUXIPO_ZONE_CHARS` 后，`zone_chars_for("suxipo")` 和因此替换进写场提示词的字数都是覆盖值。台账的 `active_window_chars` 也来自当前快照，不是导入时的常量。
- 停用自动改档时留下起点记录，写明各主体当时的档位和条数。
- 没有一条路径会按范围去试下一个值。同一次建议不会同时改档位和条数。

阶段 1 才让匠石根据建议写原因。阶段 2 才把 `applied` 变成真，并接上观察期重数。那两阶段另写方案，不在这次编码里顺手做。
