# JEV第三种决策模式：实施方案

- 状态：已完成首期程序实现；此文保留方案目标，实际范围与验证见[实施记录](JEV第三种决策模式-实施记录.md)。未自动切换运行模式。
- 最近更新时间：2026-10-28 21:28（北京时间）。
- 目标：保留合并、拆分两种模式，新增可切换的决策模式，验证控制响应与入口分流收益。
- 依据：当前 `jev.py`、`jev_serial.py`、`decision/service.py`、`entry_scheduler.py`，以及[第一次JEV](../提示词/P10-30.0-第一次JEV.md)、[回应准备](../提示词/P10-40.0-JEV回应准备.md)、[既有决策实施记录](JEV撞车与提前长思考-实施记录.md)。

## 1. 实施范围与模式关系

新增公开模式 `decision`，与 `combined`、`split` 并列。界面分别显示“合并判断”“拆分判断”“决策模型判断”。现有 legacy／serial 兼容行为保留，不作为新增公开选项。

| 模式 | 入口与准备 | 本次处理 |
| --- | --- | --- |
| combined | 生成模型一次完成入口和回应准备 | 保留原路径与默认选择 |
| split | JEV1_1入口，通过后串行JEV1_2准备 | 保留原路径 |
| decision | 决策入口、必要的人物核对、按需JEV1_2准备 | 新增路径 |

“并列”指可选择三种实现，不是让三种结果同时控制系统。每批只有一个正式入口结果和一个交付出口。模式在批次开始时固定；设置切换对下一批生效，不让正在运行的批次中途改变协议。

第一版迁移交往指向、表达完整度、控制和入口去向。人物综合判断仍由生成模型承担；档位、记忆、图片、短答和等待接话继续复用JEV1_2。JEV2继续负责异步片场整理，主认知和工具执行职责不变。

第一版不承诺全部请求变快：带人物核对的正式回应可能仍需两次生成调用，外加决策调用。主要验证停止响应、明确背景／等待分流，以及已绑定人物文字输入的入口收益。

## 2. 已有基础与实际缺口

已有 DecisionService、两家 System One 适配、deadline、结果校验和审计记录；已有撞车调度及后续表达影响决策。可以复用这些基础，不新建第三套供应商客户端。

当前缺口：

1. `DecisionService.decide`只接受collision／continuation，问题定义和开关也按这两种用途实现；必须增加entry用途，不能复用撞车问题冒充入口判断。
2. `jev_serial.decide_serial`将非combined路径作为split处理；必须显式分流，不能仅把decision加入配置枚举。
3. JEV1_2依赖完整entry，包括人物、处理范围、控制、理由及引用；决策输出必须经过适配与校验，不能直接作为entry传入。
4. 现有入口是同步生成调用，DecisionService为异步服务。新模式应在宿主事件循环编排，生成模型部分通过现有有界执行器运行；不能在工作线程反复创建事件循环，或跨循环使用同一个HTTP会话和信号量。
5. 语音页、已选人物文字输入、独立文字入口均需明确分流。不能只修改语音页而在其他入口静默退回split。

## 3. 运行流程

```text
输入进入现有有序队列
  → 固定模式、配置版本、作业许可和同版材料快照
  → decision适用性检查
      不适用：同批直接走split，记录原因
      适用：一次entry决策请求
        → 校验类型、阈值、范围和组合一致性
        → 不确定／失败：同批回退split一次
        → 有效快速控制：检查作业许可后执行，登记已执行动作
        → 需要人物核对：生成模型只核对人物及支持依据
        → 合成并校验完整entry
            background：结束入口，保存原话与人物结果，正常交JEV2
            wait：保留待接续范围，保存原话与人物结果
            prepare：复用JEV1_2 → 现有短答／主认知出口
```

为控制第一版复杂度，人物核对先采用有界串行阶段，不额外建立异步身份回填系统。快速stop可在人物核对之前生效，但该批完整结果仍在人物核对后完成。这样不会将“快停播”夸大成“全批瞬间完成”。

明确绑定人物的文字输入沿用绑定，省去人物调用。语音输入不能仅凭声纹首名、同轨或单个高分省去综合辨人；第一版默认仍核对。背景和等待材料同样保留人物核对，避免为了减少调用损害后续片场。

### 3.1 首期适用边界

- 接受文字或已转写语音，现场、实际已播内容和任务状态足够表达当前关系。
- 一次处理单条输入，或已有可靠连续性依据的同一表达组；不把同轨自动当同人。
- 重叠语音、多名说话者混合、完整与未完范围交错、必须看原图才能判断、关键材料超预算或缺失：直接走split，不先付出一次无必要的决策调用。
- 明确绑定人物只能证明输入归属；引用、转述和对旁人的指令仍按语义判断，不机械停播。
- 首期不拆成每句一个请求。扩大多人场景之前，先单独验证逐句范围选择与跨句组合，避免问题数和网络调用膨胀。

此边界意味着第一版无需让决策模型生成任意长度的process_refs／pending_refs数组；适用批次作为一个表达单元，由程序按决策结果映射现有短引用。无法全批一致处理时回退split。

## 4. 入口决策契约

以下为待实现的业务契约，不是已上线提示词全文。正式实施时按完整请求集中编写state与questions，并加入提示词索引。

| 问题 | choice选项 | 作用 |
| --- | --- | --- |
| address | direct／other／uncertain | 当前表达是否面向匠石；other必须有旁聊或背景依据 |
| expression | complete／incomplete／uncertain | 是否已有可独立处理内容，不用标点、ASR final或切窗证明说完 |
| task_effect | keep／stop／redirect／uncertain | 对当前思考或表达的影响；无旧任务的明确新交往可选redirect |
| work_after_stop | none／required／uncertain | 若要求停说，是否另有取消下载等仍需下游处理的独立操作 |

同次请求的问题独立读同一state，不假设前一题输出已成为后一题输入。路由由程序组合，不再增加一个可能自相矛盾的route题。

### 4.1 组合规则

按以下顺序处理，只执行满足全部前提的分支：

| 条件 | 结果 |
| --- | --- |
| 明确面向匠石、stop，work_after_stop=none | stop＋background；允许早期停播 |
| 明确面向匠石、stop，work_after_stop=required，表达complete | stop＋prepare；早期停播，下游静默main＋L1 |
| 明确stop但剩余操作范围或完整度不清 | 可先执行已独立确认的停播；保留原话回退split，继续理解其余内容 |
| address=other且task_effect=keep | keep＋background；不因背景话未完而阻塞对话 |
| address=direct、expression=incomplete且task_effect=keep | keep＋wait，整批放入pending |
| address=direct、expression=complete，task_effect为keep或redirect | prepare，整批放入process |
| 其他组合、低于用途阈值或任一必要判断uncertain | 回退split；不据此忽略原话 |

background的process为空；wait的pending为本批原话；prepare的process为本批原话。首期不同时给同一表达分配完整和未完范围；需要这种表达能力时回退原入口。

“明确”是业务标签和各用途经校准门槛共同满足，不等于取最大概率即可。stop、background、wait分别设置门槛，两家模型分别校准。0.85仅为现有实验配置，不能直接作为新用途正式验收值；confidence也不能解释成真实准确率。

### 4.2 完整entry适配

复用当前entry结构和一致性检查。人物结果补齐items；决策组合产生interaction、utterance_complete、control、route、process_refs、pending_refs。

决策模型不生成decision_reason／decision_refs。程序可生成明确标注来源的说明，例如“决策入口选择直接交往、表达完整，进入回应准备”；引用只指实际参与该次决策的输入，不能声称模型给出了因果解释或逐条证据。该说明用于诊断，不伪造模型推理。需要无法用现有材料表达的依据时回退原入口。

## 5. 人物核对与JEV1_2复用

新增仅供decision模式使用的人物核对请求：读取同版原话、片场、未编排事件、候选及声音／有效视觉证据；输出每句person、certainty、why，以及是否出现影响入口判断的关键来源冲突。

- 保留现有综合认人原则，不把任务改成声纹最高分选择。
- 每句候选范围、unknown、confirmed／tentative规则和用户文字绑定保持一致。
- 不重复输出控制、路由、档位或回复。
- 新发现媒体来源、说话人关系冲突等可能推翻交往指向时，先阻止交付，再回退完整split判断；不能将人物结果机械接到过期决策上。
- 身份unknown本身不构成失败，不应让明确交往永远不能回应；沿用当前下游对未知人物的处理边界。
- 人物调用错误不等同于unknown。记录失败并走有界降级，不编造身份或确认程度。

为了复用JEV1_2，需要从`decide_serial`中提取“已校验entry进入准备”“准备结果归一化与交付许可检查”的共用函数。新模式传入同一快照和已接受entry；split／combined保留原调用次数和结果语义。

人物核对可能改变短答许可和私人材料使用范围。实际准备前重新按已核对人物取得或核验所需材料，保持人物代号映射一致；不得用暂归人物加载私人记忆，也不得因为decision模式默认开放short_chat。

## 6. 材料、版本和时效

优先复用`build_snapshot`及现有短引用机制，一批建立一次映射。entry决策、人物核对、JEV1_2共用人物与输入映射，避免不同请求的P1被误认为同一个人物。

决策state保留：原话、必要接续、相关现场与新事件、实际思考／播放状态、实际已播内容、称呼及必要任务摘要。声音和人物证据只保留判断交往与连续性所需部分；原始声音证据供人物核对使用。

长ID、精确内部时间、代次、原始记录放在程序侧；模型侧使用短引用和必要时间关系。绝对时间、事件先后、音频偏移和间隔分别注明，不把未知时间写成当前时间，不让旧图描述变成当前画面。

关键材料放不进预算时直接回退，不截掉否定词、原话后半段或人物归属后继续执行。记录快照指纹、原话版本、片场generation和配置版本；每个控制、准备和最终交付点重新检查许可。

## 7. 与撞车、提前准备及取消的关系

三类用途分工：entry判断本批如何处理；collision判断新输入是否使旧作业失效；continuation判断提前准备能否复用。

- EntryScheduler继续持有作业有效性与交付许可，entry不能绕过它。
- 新输入到达时，无论旧批在决策、辨人还是JEV1_2阶段，都受相同的失效规则约束。
- A/B撞车判断期间出现C，不能根据旧结果释放A或B；原话按现有有序合批规则保留。
- stop／redirect经过统一、幂等的控制入口，以作业和目标代次登记；撞车和entry都要求停止时，只执行一次。
- entry的stop不等于外部工具已取消；独立工具操作仍交main＋L1静默处理。
- 提前准备继续由原开关控制；新模式不自动开启，不放宽原话、人物、记忆版本和候选有效期检查。
- 三用途共享连接与并发上限，但必须给正式入口／撞车留出优先处理能力。容量不足时跳过试探准备，不能让正式停播等待准备请求。

先不增加自动跨供应商重试。选定一家处理本批；失败走现有生成入口，避免多个网络预算叠加。

## 8. 失败、回退与模式配置

新模式固定以split为第一版回退路径，避免在故障中再次选择复杂策略。每批最多回退一次，不从split返回decision造成循环。

| 情况 | 处理 |
| --- | --- |
| 决策关闭、缺配置或冷却中 | 直接split，记录实际路径 |
| 决策超时、非法返回、组合矛盾或必要判断不足 | 保留完整原话，split一次 |
| 材料或作业已过期 | 废弃旧结果，交队列重组；不拿旧材料回退 |
| stop已执行后需要回退 | 保留动作登记，禁止重放或恢复已停的旧回答；仍处理新操作请求 |
| 人物核对失败 | 在剩余预算允许时完整split一次；否则按既有入口失败语义处理并记录，不将故障当背景 |
| JEV1_2失败 | 保留有效身份与控制，沿用各宿主现有失败策略；不再重跑入口 |
| 回退也失败 | 沿用原宿主的失败／主认知降级机制，明确诊断；不伪装为正常忽略 |

设置建议：

- `jev_mode`增加decision；当前用户选择和默认值不变。
- 决策服务新增entry用途开关、独立预算和按供应商／策略版本划分的门槛配置；旧设置文件缺字段时补默认值，不重置已有供应商和开关。
- 现有off／shadow／active继续作为决策权限总开关。选择decision且active时才采用新入口；off时走split；shadow时split正式执行，entry只读比较并明确显示“观察中，实际执行拆分模式”。
- shadow仅比较入口判断，不额外生成回复、执行工具或改变身份和片场；有容量限制，不阻塞正式请求。三模式完整回放在离线评估中做，不在线同时跑三套正式链路。
- 切模式不自动把shadow改成active，不暗中开启付费观察调用；界面说明两项设置的组合含义。
- 控制台同时显示“选择模式”“实际路径”“回退原因”和供应商，避免用户以为一直在使用决策模式。

entry初始超时预算可沿用现有800ms作为实验起点，不是速度指标。为决策、人物核对、准备和回退设整批总预算；回退只使用剩余时间，不能每阶段重新获得完整等待时长。具体总预算沿用并核对各宿主当前配置后确定，发布前记录实际值。

## 10. 实施顺序与完成条件

### 第一阶段：整理共用边界

提取入口校验、准备及交付转换；模式／配置做向后兼容。先让现有combined和split回归通过，确认调用次数、短答许可、失败语义不变，再接新模式。

### 第二阶段：新增入口决策与观察

实现四类问题、材料、组合、日志和shadow对照。用假模型验证决策契约与控制状态，真实供应商只验证协议和样本质量；两类结果分开记录。

### 第三阶段：人物阶段和正式链路

实现人物核对、entry适配、JEV1_2复用及一次回退，接入语音与文字宿主。全部早期控制和正式结果统一经过作业许可与幂等校验。

### 第四阶段：真实回放和按需开启

固定供应商模型版本与策略版本，使用相同真实材料分别运行三模式。先离线评估和shadow，再小范围active；合并／拆分随时可切回。正式开启依据验收结果，不以“接口能通”代替业务有效。

## 11. 测试与验收

### 11.1 必须通过的程序测试

- 三模式选择、旧配置加载、切换时在途批次保持模式快照。
- 决策off／shadow／active的执行权限；shadow绝不产生控制或业务写入。
- 四类决策的合法组合、缺项、非法概率、低置信与矛盾结果。
- 明确停止；停止加独立操作；引用中的停止词；旁人互聊；不确定指向。
- 未完表达完整保留；完整和未完混合直接回退；多人和重叠不错误合并。
- 绑定文字省去辨人，语音保留核对；unknown与调用失败分开；人物冲突触发回退。
- A/B/C撞车、迟到返回、关闭、原话修订、切换供应商、stop与redirect重复到达。
- 决策失败最多回退一次；回退不重开已停回答；总预算覆盖排队和回退。
- 正式主认知和工具操作只提交一次；未播回复不冒充用户已听见。
- 原话、人物证据与JEV2材料不因background／wait丢失，跨请求短引用不串人。
- 阿里／TypeSafe分别验证请求及返回契约；共用服务无跨事件循环使用错误。

优先扩展现有`test_jev_split_modes.py`、`test_decision_runtime.py`、`test_jev_failure_diagnostics.py`、完整度／短答／失败降级测试，再新增新模式端到端测试。无需为文档本身新增程序测试。

### 11.2 真实质量与性能验收

建立人工核对的真实输入集，覆盖明确交往、旁聊、电视声音、半句、纠正、停止、工具取消、身份不明和多人混合。旧模型结果可作对照，不能直接当正确答案。校准集与验收集分开，保留未参与调参的样本。

按供应商分别报告：

| 指标 | 评价方式 |
| --- | --- |
| 误停、漏停 | 对照人工标签及停止到播放器确认的P50/P95 |
| 漏掉有效交往、误插话 | 对照人工标签，分场景报告数量与比例 |
| 人物归属 | 比较原路径，核对新模式是否丢失依据或错误升级确定度 |
| 首次有效回应 | 从输入可用到实际首个有效回答，不把等待接话计作答案 |
| 全批耗时与费用 | 包含决策、人物、准备、回退及废弃请求 |
| 覆盖率与回退率 | 分绑定文字、单人语音、混合场景报告 |
| 数据正确性 | 不丢原话、不重复提交、不交付过期结果 |

固定回归集中新增误停、丢输入、重复执行、过期结果交付任一出现即阻止启用。真实验收要求质量至少达到现有基线，且目标场景的控制或回应延迟有可重复改善；样本量和波动区间一并报告。未达到时保留实验模式，不自动推广。具体业务容忍率应在评估前写入验收记录，不能看完结果后修改标准。

## 13. 两个说明性场景

以下仅解释预期流程，不是真实调用或验收结果。

- 匠石正在播放，用户明确说“别说了”：entry判断停止，作业许可有效即停播；人物核对继续完成该批记录。后续不能因回退又恢复旧答案。

## 14. 协议依据与收益边界

两家均提供原生System One结构化决策，不负责生成回复。TypeSafe说明同请求问题独立评估；阿里当前文档列出最多16问且问题数会影响延迟，因此本方案先使用四问，不按“增加问题没有代价”设计。

- [TypeSafe介绍与独立问题说明](https://docs.typesafe.ai/introduction)
- [阿里决策模型API](https://help.aliyun.com/en/model-studio/decision-model-api)

这些协议资料在本次讨论前序核对过；正式开发时仍需核验实际账号和模型版本。项目已有模拟回归不能证明两家在当前中文现场的准确率或提速幅度。

本方案的第一版交付是可切换、可诊断、可回退的第三种模式。人物异步回填、多人逐句决策、档位与材料选择迁移属于后续优化，不作为第一版隐藏依赖。
