## 1. 目标与讨论结论

改善连续语音输入时的调度与等待体验，分别处理以下问题：

1. **JEV1 与 JEV1 撞车**：前一批尚在判断，后一批发言已经到达。采用专用决策模型做快速语义调度，最新选型为阿里百炼优先、TypeSafe Jev 可切换；判断接续、替换、独立交往、无关背景及停止等关系，由程序执行合并、继续、暂缓交付或终止。接入前仍需验证中文准确率、可用性和本地网络耗时。
2. **提前长思考、后续短思考**：用户还在讲长句时，任务已足够明确便先启动记忆检索、材料收集和较重分析；后续信息到齐后，尽量通过一次较轻的调用完成校正与回答。
3. **转折后的重新思考**：后文实质改变任务时，允许先给一句适当的接话，如“哦，我再想一下”，随后重新进入长思考。接话不是已经解决问题的答案，也不应每次固定播放。
4. **听话过程中的反馈**：在尚未达到整句结束条件的短暂停歇中，可以适度用“嗯”等反馈表示仍在听；与用户说完后的等待接话分开控制。

以上是讨论认可的设计方向，不等于已验证的系统能力。此前提出的“只要有新输入就一律阻止旧结果交付”属于保守备选，不作为本次最终首选；不能把有无新增输入代替新旧语义关系判断。

## 2. 分清 JEV1、JEV2 与主认知

- 主认知承担匠石的主要思考与任务推进，保持单线的任务状态和交付顺序；可以停止或转向，但不默认同时推进多个相互竞争的主任务。
- JEV1 服务于主认知，持续处理入口材料。其调用间的撞车是输入调度问题，不能和主认知的任务抢占混为一谈。
- JEV2 负责后台情境整理，其更新和积累另有机制，本次不重新设计。
- 项目中的“JEV1/JEV2”是模块名称；“TypeSafe Jev”是外部供应商的决策模型。采用后者处理撞车，不等于用它整体替换项目全部 JEV 职责。

## 3. 当前实现依据

核对本次讨论涉及的代码后，可确认：

- `voice.py` 的 `_judge_work` 串行处理入口判断，`_take_judge_group` 合并上一轮判断期间积累的待审输入；当前不是每来一句就取消上一调用。
- 入口提示词区分可处理与待接续材料，以及保持、停止、转向等控制；这些语义判断与人物判断分别表达。
- 语音上游存在未完表达暂存及释放机制；部分长句材料不会立即进入 JEV1，但不能概括为“所有未完长句都不进入 JEV”。参见[语音轮替与JEV聚合](../语音轮替与JEV聚合.md)。
- 回应准备已有 `waiting_reply`，语音主流程已有短接话播放入口；这不等于已实现本文提出的短停顿附和或提前长思考。
- 本轮未运行新的模型测试，未测得这些设想的真实延迟收益。

## 4. JEV1 撞车：用专用决策模型做快速判断

### 4.1 判断材料与职责

当旧 JEV1 在处理 A、新发言 B 到达时，将 A 的必要原话、B 的原话、人物归属及不确定性、必要前文和当前处理阶段交给快速决策模型。不要为构造这份材料再等待一次长摘要调用。

建议在一次调用中分别判断两个维度；以下是设计语义，不是已确定的接口 Schema 或实际发送提示词：

| 维度 | 候选判断 |
| --- | --- |
| 新旧内容关系 | 接续补充、纠正替换、独立交往、无关背景、不确定 |
| 对旧处理的影响 | 继续、暂缓交付、停止 |

“合并”和“打断”可以同时成立，所以不宜粗糙地把所有动作塞进一个互斥列表。明确停止要求也应单独识别其对象：停止当前表达、停止当前分析、取消外部任务并非同一操作。

### 4.2 调度方向

| 判断情形 | 程序处理方向 |
| --- | --- |
| 无关背景 | 旧调用继续，新增内容保留为背景；不因有新输入而一律重算 |
| 同一表达接续补充 | 保留可用工作，合并后续材料；按判断决定是否暂缓旧结果交付 |
| 纠正或替换前意 | 旧结果不得按被推翻的意思交付；必要时取消旧调用，按更新材料处理 |
| 独立交往 | 独立保留，根据优先级排队或转向，不覆盖旧原话 |
| 明确停止 | 执行对应停止控制；涉及外部任务时另走任务取消流程 |
| 不确定、调用超时或失败 | 保留原话，回退到普通 JEV1 合并判断；不默认为无关并丢弃 |

每次判断须绑定它实际看到的输入版本。若判断期间又来了 C，程序不能把针对 A/B 的结论冒充针对 A/B/C 的结论；应限制其适用范围，并积累下一次判断。输入版本检查不需要模型，语义关系判断由模型完成。

取消本地等待和禁止结果交付，并不保证供应商已经停止服务端推理或停止计费。普通在途请求也不能直接插入新文字；复用结果、合并后续请求与真正的增量推理要区分。

### 4.3 官方能力与待验证边界

TypeSafe 官方文档说明 Jev 返回类型化决策和概率，并支持一次请求并行评估多个独立问题，适合为程序提供快速分支判断。[官方文档](https://docs.typesafe.ai/introduction)

官方发布时给出的端到端耗时为 70–500 毫秒，主要测试环境位于美国西海岸。这不是当前项目的延迟承诺，也不包括我们的语音采集、转写和播放全过程。[官方发布说明](https://typesafe.ai/blog/introducing-system-one-models-and-jev)

官方说明英语效果最好，中文等语言需自行测试；输出类型正确不保证语义正确。应测量实际中文撞车判断的准确率、P50/P95 延迟、超时率及额外调用开销，再决定投入使用。[模型说明](https://docs.typesafe.ai/models)

## 5. 提前长思考与后续短思考

### 5.1 用户提出的处理过程

```text
用户持续说话
  → 已有材料足以启动准备：进入长思考
      → 检索记忆、收集材料、分析问题、形成候选答案
  → 后续发言继续积累
  → 前段成果可用且后续材料到齐：短思考收尾
      → 原意基本不变：复用成果，形成正式回答
      → 局部新增条件：调整受影响部分，形成正式回答
      → 任务实质转折：适当短接话，再进入长思考
```

“说了四分之三”是描述思路的假设，不是可提前测出的比例，也不固定为启动阈值。实际应根据任务明确程度、已积累的语义片段、可用材料及当前负载决定是否启动。字数和时长可以限制调用频率，不能证明话已说完。

这里主要让“用户继续说话”和“前段长思考”并行。后段短思考依赖前段成果，成果尚未返回就不能假装已有；也不需要两个主认知同时修改共同状态。若旧分析被放弃，其迟到结果不得重新覆盖新任务。

### 5.2 复用什么

提前工作优先包括记忆召回、读取已有材料、问题分析与候选回答。输出需区分：

- 已有事实、原话和可复用的证据材料；
- 已取得的相关记忆及其来源；
- 暂定目标、条件和仍缺的信息；
- 候选答案依赖哪些条件，哪些内容尚未确认。

后段调用应接收必要的完整原话、前段材料及新增内容，不能只依据旧结论作修饰。模型不会自动继承另一次调用的内部计算过程；复用应通过明确保存的材料和工作结果实现。

提前预测后文只能用于准备，不写成用户已经表达的事实。未确认前不提前发送消息、下单、修改外部状态，也不把暂定意图保存为确定的长期记忆。

### 5.3 转折不是禁用提前思考的理由

后文没有改变任务时，较轻调用可能足以收尾；局部补充时可以复用大部分成果；实质转折时需要重新深入分析。最后一小段话也可能改变整个目标，不能保证“后文短，所以必定能短思考”。

用户明确提出：遇到转折，可先用“哦，我再想一下”一类简短表达接住，再重新进入长思考。该表达是等待反馈，不是凭旧材料给一个可能错误的实质答案。仅在对方已经让出说话机会、预计确有等待且反馈有帮助时使用；新长思考应尽快开始，不必等短接话播完。

转折后仍可保留有效记忆和材料，不要求全部从零检索。若前段已无价值，则舍弃，不为了复用强行维持旧方向。

### 5.4 预期收益

主要收益是把部分耗时工作提前放进用户仍在说话的时间里，缩短说完后的等待。可能代价是猜错方向造成额外调用与资源占用。真实收益取决于提前量、成果复用率、转折比例、模型耗时与并发资源，当前尚无实测结论。

## 6. 三种短反馈分别控制

| 时机 | 目的 | 表达与限制 |
| --- | --- | --- |
| 用户尚未说完，出现短暂停歇 | 表示仍在听、鼓励继续 | 可用轻声“嗯”；不视为整句结束，不抢正式回答 |
| 用户已说完，准备进入长思考 | 缓和等待 | 需要时说“我想一下”；与主认知尽量并行启动 |
| 后文改变原任务，需要重新长思考 | 表示已接住变化 | 可用用户提出的“哦，我再想一下”；不假装已完成分析 |

听话附和可由语义判断先给一次短时许可，声音链路在合适空隙播放；许可过期、后文变化或用户恢复说话时丢弃。不能每遇到停顿才发起一个慢调用，等结果迟到后再硬插话。

短暂停顿并不保证用户接下来还会保持沉默，因此反馈应简短、稀疏，并能在对方继续说时让出。文本 Jev 不能直接听出停顿和语调，须结合音频链路。避免把“好的”“对”当作无语义填充，它们可能传达同意或承诺。

## 7. 中国是否有类似产品或项目

检索日期：2026-10-27。已有相关中文决策模型和国内团队实现，但研究模型、专项工程和通用云模型不能当作同一种成熟产品。以下只列本次核对到一手材料的候选，不宣称穷尽市场。

| 候选 | 一手资料确认的定位 | 与本项目的关系及限制 |
| --- | --- | --- |
| 阿里百炼 decision-model-preview | 原生 System One 决策 API，返回选项、概率等结果，不生成自由文本 | 用户后续指定的优先供应商；与 TypeSafe 共用接口抽象，具体协议差异见代码方案 |
| Chinese-Jev | 复旦大学、新加坡国立大学、中国科学院大学研究人员参与的中文决策项目；提供训练、校准、评估代码和数据，当前明确公开的权重为医疗版 | 范式较接近；适合研究中文专用决策与训练路线，不能把医疗权重直接当通用对话调度产品 |
| APUS AI Lab / fast-browser-use | 国内团队的本地浏览器自动化决策工程，基于 Qwen 权重与单步候选打分 | 可借鉴本地选择式决策实现；面向浏览器动作，不是现成的语音撞车判断 API，也不是官方 Jev 原模型复现证明 |
| 阿里云百炼 qwen-flash | 支持思考/非思考模式和结构化输出的通用文本模型 | 可作为国内云端快速分类基线；仍是生成式模型，不等同于原生概率决策模型，实际速度需测 |

Chinese-Jev 项目报告其 General 模型在单张 H200、批量为一的条件下，中位延迟约 14 毫秒；这是作者测试口径，不能外推到当前电脑或云 API，也不能据此认定通用权重已可下载。[项目主页](https://gulucaptain.github.io/Chinese-Jev/)；公开权重与训练范围以[作者仓库](https://github.com/gulucaptain/Chinese-Jev/blob/main/README_zh.md)为准。

APUS 项目使用本地 Qwen 模型，将浏览器候选动作映射为离散选择，仓库描述为秒级决策；没有证据表明它在我们的中文语音调度场景达到官方 Jev 宣传的延迟和准确率。[作者仓库](https://github.com/APUS-AI-Lab/fast-browser-use/blob/main/README.md)

qwen-flash 的结构化输出与非思考能力可用于对照测试，不应将模型名称中的 Flash 当成固定毫秒数承诺。[阿里云模型文档](https://docs.bailian.console.aliyun.com/zh/model-studio/qwen-flash)

最新选型记录：优先验证用户指定的阿里百炼 `decision-model-preview`，TypeSafe 官方 Jev 保留为可切换选项。阿里原生接口见[官方 API 文档](https://help.aliyun.com/zh/model-studio/decision-model-api)。其他国内方案作为对照候选；尚未部署或切换任何服务。
