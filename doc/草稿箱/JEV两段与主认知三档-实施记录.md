# 两段JEV与主认知三档：实施记录

更新：2026-10-06。已修改程序并完成自动检查，未提交代码。用户已运行两段JEV方案；12:36真实运行发现人物输出格式与界面回填问题，已修订，见[JEV人物归属复查](JEV人物归属-12点36分复查.md)。本次补修尚未重启服务验证真实模型效果。此前保存的10月5日实际请求保持原样。

## 已落实的行为

- 主认知三档：1完整，2删除工具正文和输出字段，3在2基础上简写回应、交往和来源说明。三档都保留人物参考；历史事件召回由第一次JEV的recall_memory独立选择，缺省保留。片场读取依次为tier1/2/3、tier1/2、tier1。
- 第一次JEV实际材料改为输入信封和JEV片场。本批及尚未整理的输入输出接续保留，内部长ID不发给模型；人物候选只留短代号、姓名线索、相似度及来源。单独复核报告不再加入第一段请求。
- 第一次只选主认知提示词level及历史召回开关，不输出tool_needed、工具调用参数或执行决定。有效且覆盖当前输入的JEV选档直接执行，不因旧工具材料自动升档。若无工具档意外输出工具请求，记录异常并移除这些字段，不暗中重跑完整档。具体工具执行仍由完整档主认知决定。
- 声纹初判与第一次JEV最终归属分开记录。第一次可以支持、改判或将声纹初判降为待定；改变归属需依据及允许候选，人工关联保留保护。短句重复拼接仍只作辅助，不独立确认姓名，不自动修改声纹库。
- 第二次替代原默认PersonReviewer调用，用主认知片场近期完整块、旧JEV片场及积累输入输出，写一份JEV片场，目标800、上限1000字符。不要求场景分类；第一次内部根据片场假设情境。
- 进入主认知的自然批次触发后台需求。通知合并，原始事件持久化；后台单并发，忙时积累。近期输入输出与主认知参考序列化后合计上限3000字符，旧JEV片场、人物映射、提示词及Schema另计。最新事件优先，最近人工纠正及各人的确认事件在有限预算内优先，再按新到旧填充完整事件、参考块；不硬截断原话。单条超过预算时明确未载入并完整归档，不能声称已读。成功后同一快照的旧积压退出待办并归档，避免之后重放旧材料覆盖新场面；整理过程中新增事件仍保留待办。失败、版本冲突保留待办，不归档未接纳的结果。
- 片场正文和覆盖进度同一次文件替换提交，版本或人工纠正冲突不接纳旧结果。超过1000字符不硬截断。保留最近8次整理快照及其覆盖原话，用于第一段按输入时间取材料，防止把输入之后才播放/整理的内容当作此前已知。完整原始日志仍由原记录机制保存。
- 本地JEV工作文件按主体与会话隔离，保存片场、待办、短代号映射。页面sessionStorage保留会话ID，同一页面会话重连可恢复；新标签页是新会话，不把不同现场强合并。恢复不凭旧轨迹号确认新声音连续性。
- 轮次查看增加“JEV片场（会话后台）”实际提示词入口以及“JEV片场与待办”查看项。后台成功与失败均记录原始模型输出，便于后续分析。

第一段新增候选排序、领先差、近期确认与连续性来源说明；临时声音P不作为实名判断的安全替代。确认、可能、未知都须有证据，漏认与错认都算失败。声纹低于程序门槛不直接约束JEV最终归属；媒体、换人、冲突仍须辨别。三条历史真实输入的第六次回放为luguang“可能／确定／可能”；这些是经过迭代的有限案例，不是独立准确率评估。
