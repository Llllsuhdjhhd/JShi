## 1. 按本次说明固定的流程

第一次JEV的两个主要来源是：输入、JEV片场。输入由程序在声音识别后标注；JEV片场由第二次JEV整理。声纹先按门槛给人物初判，第一次JEV综合声音证据、当前及未整理输入输出、已有JEV片场，给出本轮最终人物归属与确定程度，也判断对话指向和主认知提示词档位，再交主流程。第一次可支持或有依据地反驳声纹初判；第二次是补充材料的整理者。

第二次JEV在后台读取本轮及积累输入、旧JEV片场，并读取当时已提交的整个主认知片场作为额外参考，整理下一版JEV片场。目标800字符以内，硬上限1000字符。来不及处理的新增材料积累，空闲后合并整理一次。

```text
声音或其他输入 → 程序标注 → 第一次JEV → 主认知快速反应
                              ↑
                          最新JEV片场
                              ↑
积累输入＋旧JEV片场＋主认知片场参考 → 第二次JEV后台整理
```

JEV片场是专门的概念：入口判断需要的当前对话情境。它可以写谁说了什么、交往如何接续、人物归属哪些确定哪些暂定、当前还在等什么；不要求机械描述环境。与主认知片场分开存储，第二次可参考后者，但第一次不直接接收后者全文。

这次撤回上一版的400/600字符片场预算、独立recent材料入口、强制块操作输出。第二次按本次思路直接写一份完整JEV片场；不要求增改删JSON来表达自然情境，也不同时交完整复核报告。

## 3. 第一次JEV：输入与输出

### 3.1 两个来源，不再分散展开背景

**输入**是一组带简短标注的现场发言。每条包含本批序号、会话短代号、时间、原话、程序人物归属及确定程度。只有存在影响辨人的竞争或冲突时，才附最少候选证据；不重复带完整候选资料、人物档案、相处经验或声纹统计。

人物编号是程序内部的对象标识：没确定就标未确定，后来确定了更新同一对象的姓名、状态和依据。长期内部ID与模型短代号分开，保存关联映射；P1、P2等短代号用于节省请求字数。恢复时保留可靠人物关联，不能只因曾经待定就丢掉编号。编号本身不证明声音连续性，不把不同未知声音合并。

声音初判与最终归属分开保存，两者均可记录confirmed/tentative/unknown。声纹达到约定相似度门槛可给confirmed声音初判，但不是禁止第一次JEV反驳的锁定值。第一次利用声音和语义材料作本轮最终判断；证据不足可暂定或未知。声音连续性、姓名归属、对话指向分开；具体门槛仍待落实，声纹相似度不写成身份概率。

**JEV片场**是第二次产出并经程序验收的最新完整版本。当前时间、播放状态、有效称呼等是程序的短控制标注，放在输入信封，不再作为第三份长背景。实际播出且尚未整理的关键接续事件也由程序并入输入来源，明确它是匠石已播出的事件，不伪装成用户发言。

构造示例（不是真实请求复原）：

```json
{
  "now": "2026-10-06T21:32:40+08:00",
  "input": {
    "play_state": "idle",
    "lines": [{"i": 1, "p": "P2", "at": "21:32:36", "text": "以后我想叫你酱酱。", "identity": "tentative", "name": "lux", "basis": "voice"}]
  },
  "scene": "21:32:30 P2解释‘僵尸’来自转写误差，正在与匠石讨论称呼。P2姓名暂定，不按已确认处理。"
}
```

未整理输入输出始终保留：第一次的输入包括本批，以及尚未被JEV片场覆盖的接续原话和实际播出事件。没有写进片场不等于没有记录，也不应因此漏传前一轮相关问题。这仍属于“输入”来源，不另开recent模块。程序保存与本次发送需要通过覆盖进度衔接；积压时按自然轮次组装和处理，不静默丢掉未整理事项。

### 3.2 快速输出给主流程

```json
{
  "items": [{"i": 1, "person": "P2", "certainty": "tentative", "to": "yes", "keep": "related"}],
  "level": 3,
  "control": "pass"
}
```

- person/ certainty：第一次作出的本轮最终人物归属与确定程度，可支持或反驳声纹初判；反驳留简短why。无足够依据确定另一人时可降为unknown或暂定，不强猜。人工关联的优先级另行说明，不与可复核的声纹初判混为一类。
- to=yes/maybe/no：是否对匠石说话；keep=related/uncertain/unrelated：是否作为交往背景保留。知道是谁不等于在对匠石说，保留旁人背景也不等于请求回应。
- 第一次只选择提示词档位，不输出tool_needed或具体工具决定；是否调用、复用结果和补查全部由主认知判断。
- level=1/2/3：1完整，2无工具，3无工具且简写。需要工具选1；无工具但需要展开理解选2；普通交流选3；不确定回退1。程序已知有工具反馈待处理时强制1，不把工具结果全文塞给JEV。
- control=pass/stop/continue：交程序处理、明确停止、播放中继续。pass不保证主认知开口，maybe也不等于必须回答。空闲时continue不得恢复旧播放。

同批序号不可遗漏、重复或引用别批；程序校验短代号、状态和映射。这里只定义输出含义，正式Schema与异常回退仍需配套实施。

## 4. 第二次JEV：材料与片场产出

### 4.1 输入材料

1. 旧JEV片场。
2. 本轮及此前积累、尚未整理的现场输入，附程序声音归属和第一次判断。
3. 主认知片场的参考快照，以其中与当前人物、交往接续有关的内容为主。
4. 必要的实际播放事实与人工纠正，由程序标注。

主认知片场作为本次新增的重要参考，不只在特殊人物疑问时才允许读取。已确定读取已有完整片场快照，不默认筛选或另设摘要；第一次JEV不承担读取这份长参考的成本。其他候选资料若确有辨人疑问再取，不默认加入全部回忆、工具材料和档案。

第二次不等待本轮主认知写场完成：使用当时已经完成的主认知片场。之后新完成的主认知片场作为下一次后台整理参考，不单独触发循环调用，不为追求同步而阻塞快速反应。

### 4.2 写一份当前对话的片场

产出是连贯的短片场，可以分段，但不要求固定环境描写或每句单独列字段。保留当前人物、说话和接续关系、关键原话含义、明确事实、暂定归属、仍待回答的问题，以及影响判断的时间。原话可以忠实概括或短引，不是每轮永久逐字转存。

**不要求第二次显式识别或命名场景。** 第二次写好当前人物、发言、关系、接续及有依据的环境和声音来源线索，保留“可能”“不确定”等含义即可；不必写“家庭场景”“会议场景”或“可能处于某场景”，也不单列场景类型、场景置信度与场景推理。

第一次读输入和片场时，在内部假设可能的情境，辅助比较人物候选、理解称呼及判断对话指向。例如现场参与者怎样接话、是否存在电视对白或远端通话，都可作为理解线索；不要求把这种假设输出成标签、解释或推理过程。情境是假设，不是人物身份的独立确认，也不能排除新来者或压过当前相反证据。

若输入明确说“电视开着”或程序提供来源线索，第二次可以保留这个已有事实及不确定程度；不为了满足场景分类而编造环境，也不把电视剧角色的家庭情境当成麦克风现场。只收到文本和程序标注时，不假称听出未提供的音色、距离或方位。各类线索仍融入同一份JEV片场，不增加另一份场景报告。

目标800字符以内，硬上限1000字符；字数按Python len，含标点、空格、换行，不等于token。先合并重复、清理失效旧细节，再精简叙述；关键否定、未决事项、事实与推测的区别、实际播出状态不能为凑字数删掉。

```json
{"scene": "本次整理后的完整JEV片场正文……"}
```

只写一份完整版本，不同时写长报告、短评或三个长度版本。来源事件、更新时刻、覆盖到哪条输入及原始长ID由程序在片场外保存，不占正文；人物暂定、关键事件时间等会改变判断的含义仍须在正文说清。

超过1000字符时不直接硬截断：验收不通过，保留上一版及全部待处理输入，再重新整理。不得把不完整产出当成已覆盖积累输入。

## 5. 来不及就积累：后台调度

整理需求跟随主认知自然轮次：一批输入进入主认知，就登记一次第二次JEV整理需求。实际执行按主认知写场的忙时积累、合并整理方式处理；同频率是同轮触发需求，不要求后台调用次数或完成时刻完全相同。待处理输入是有进度的事件队列，不每个转写碎片都排一个重复任务。

未进入主认知的现场背景也保存，但不单独调用第二次；到下次主认知轮次一起整理。没有新主认知轮次时保留积累，不自行增设定时整理。

- 新输入先入待整理队列，第一次JEV继续使用最新已验收片场及必要未覆盖输入，不等待后台。
- 后台空闲时取一次快照：旧JEV片场、当时待处理事件、已完成的主认知片场参考，合并调用第二次JEV。
- 整理期间的新输入继续积累，不把它们误算进当前任务已经处理的范围。
- 产出通过字数、版本与基本结构验收后，原子替换JEV片场，只推进本次实际覆盖的事件进度；有新积累就再合并处理一次。
- 失败或超时不推进进度、不清空队列。忙时允许合并通知，不允许把对应原始事件丢掉。

一次后台只处理一个快照，旧版本结果不能覆盖新人工纠正。原始日志照常保留，工作队列与片场不是长期记录的替代品。积压量、最早未处理时间、处理截止位置、失败与溢出都要可观察，避免“后台一直忙但外面看不见”。

返回开头的意思是更新后的JEV片场用于后续第一次判断。不强制每个已处理批次同步重跑第一段，也不倒改已经交付的回应，否则又增加等待与重复。若之后要复判特定未决输入，必须标明原始来源并单独调度。

### 6.2 第二次JEV

固定提示词：804字符。

```text
你是匠石的第二次JEV，后台整理一份供第一次JEV使用的JEV片场，不生成回应，不调用工具，不修改人物档案。
材料是旧JEV片场、截至本次快照尚未整理的输入及入口标注、第一次JEV判断、程序实际播出和人工纠正，以及主认知片场参考。新增材料可能来自多轮，要按时间一起整理；已整理内容不重复写。主认知片场只是参考，不能把旧话当新输入，也不能把主认知计划当实际播出。
写出当前对话情境：谁在说、谁与谁交往、怎样承接、已经实际发生什么、还在等待什么。环境只在有依据且影响判断时留下，无需套固定场景模板。相关原话可短引或忠实概括，称呼纠正和关键问题保持原意；不用逐字抄满所有发言。
```

## 7. 验证与实施边界

本轮只改讨论稿。实施需同步改请求组装、第一次输出解析与应用、工具需求及档位联动、第二次材料取得、JEV片场存储与验收、积累队列及诊断记录，不能只替换提示词。

验证包括：普通问候、多人旁聊、未知姓名、声音与语义冲突、片场尚未更新的连续接话、实际部分播出、主认知新旧片场参考、后台忙时多轮积累、失败重试、旧结果晚到及工具反馈待交付。场景用例覆盖家庭来访者、会议新人、公共场所旁人、电视与现场混合、远端通话、场景变化及信息不足，检查是否帮助辨人而没有把背景人物错认成现场熟人。记录第一段两种来源的实际字符/token和延迟，第二段字数与覆盖进度，辨人、指向及工具需求判断是否正确。
