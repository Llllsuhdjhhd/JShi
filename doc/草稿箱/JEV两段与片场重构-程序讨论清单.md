# JEV两段与片场重构：程序讨论清单

**实施状态更新（2026-10-06）：** 已开始并完成本轮程序修改与自动检查，详情见[实施记录](JEV两段与主认知三档-实施记录.md)。下文中的“未改程序/草案未上线”是讨论时状态；历史真实请求不是新方案效果报告。


状态：部分已确定，2026-10-06。按用户最新意见更新；没有改程序。对应方案：[两段JEV与JEV片场草稿](JEV输入输出与两段判断片场-重构草稿.md)。

## 1. 已确定的方向

第一次JEV主要读输入与JEV片场，快速判断人物、指向及主认知提示词档位，再交主认知；第二次后台结合积累输入、旧JEV片场及主认知片场参考，产出一份完整JEV片场。正文目标800字符以内、上限1000字符，来不及则积累后合并整理。主认知三档：1完整、2去工具、3在2基础上简写；人物参考都保留。

下面讨论实现边界，不重新提出五档、不把第二次变成同步等待，也不把第一段再塞满人物背景。

最新讨论结果：C读完整主认知片场、D跟随主认知轮次触发并允许积累、E内部人物编号待定后补确认关联、F工具与三档一起改，已确定。A已明确由第一次JEV综合声纹和片场作最终人物判断，可支持或反驳声纹初判；B已明确未整理输入输出继续保留并作为输入接续使用。具体声纹阈值、证据不足时的降级条件和积压规模处理仍需落实。E中的持久化及重启恢复细节尚未全部确定，不能把编号规则的确认当成这些细节也已确认。

## 2. 已确定策略与待落实细节

### A. 人物归属：第一次JEV是最终判断点

**策略已明确。** 声纹先判断，达到约定相似度门槛时，可以把对应人物作为已确认的声音初判；第一次JEV再结合当前及未整理输入输出、声音依据、上次JEV片场作综合判断，能进一步支持这个归属，也能有依据地反驳它。第二次JEV整理补充材料，提供给后续第一次判断，不另设一个最终归属裁决点。

顺序是：声音初判 → 第一次JEV综合判断 → 程序按本轮结论应用归属。第二次片场 → 后续第一次JEV的背景材料。主认知使用最终入口归属，不再承担第三次人物复判。

这取代此前“声纹confirmed一律不可被JEV改变”和“首版JEV只能暂定”的建议。声纹初判与最终归属必须分字段保存：例如voice_person、voice_status与final_person、final_status，保留初判来源和第一次结论，避免JEV改完后看不出曾经有过冲突。

这里的“最终”指本轮交给主认知的归属，仍可为确定、暂定或未知，不意味着一定要选一个人，也不意味着以后永远不能修正。第一次否定声音初判但没有足够依据确定另一人时，可以把本轮降为待定；不能被迫随便换成排名第二的人。支持初判也不能把同一猜测反复整理当成新增证据。

实现还要明确：声纹门槛与候选竞争条件；第一次反驳时应留下简短依据；冲突如何影响确定程度。这些属于这套已确定策略的参数与输出规则，不再讨论“JEV有没有最终判断权”。人工明确登记或关联与模型声音初判不是同一种来源，人工纠正的优先级需独立说明，本轮未决定让模型随意覆盖人工关联。

本轮归属更新也不等于自动修改长期声纹库、把音频当作训练样本或合并所有历史人物。后几项沿用或另行明确程序规则，避免一次判断错误污染以后声音依据。

### B. 未整理原话仍在：片场整理不是原话保存

**理解已澄清。** 尚未经过第二次JEV整理，不表示输入输出消失。现场原话、入口标注及匠石实际播出的内容仍保留；第一次的“输入”来源应涵盖本批及尚未入片场的接续材料，不能只留新一句而把前一轮相关提问漏掉。

例如匠石已问“要我帮你查杭州天气吗？”，对方答“要”：第二次即使没来得及把提问写进片场，程序仍保留这个实际播出事件。第一次读未整理输入输出时就能看到提问和回答。之前的例子假定只传最新一句，遗漏了用户要求继续保留的输入输出，故撤回“片场未整理就会没有前文”的说法。

原始记录保存与模型本次读取是两件事：现有代码有近期上下文及实际播放记录，但第一段上下文长度有上限，并非所有已存记录都会自动进入请求。新实现要依据JEV片场覆盖进度，将尚未整理的输入输出正确纳入输入，已整理历史由片场承接；不能把“数据库里有”误当作“本次已经传了”。

撤回此前400字符补充上限与“是否允许保留最近几句”的待答问题。保留未整理接续是本方案的基本规则，不再把它当额外模块。具体长时间积压时怎样分批组装、避免重复和遗漏，仍需在请求组装与覆盖进度机制里落实；不通过静默硬截断制造材料缺口。

准备生成、尚未播出与实际播出仍分开：原始输出可以保存，但只有实际播出的部分才能作为对方听过的交往事实。

### C. 第二次参考主认知片场，取完整还是取短？

**已确定：读取整个主认知片场。** 第二次不要求很快，可用多轮积累后的材料统一整理；不再默认先做筛选或另设摘要模型。

主认知片场可能包含多日事件、未开口事项和暂定推断；不能照搬成当前现场，也不能把主认知准备说的话当成已播出。新方案第二次本来就承担整理工作，应当允许它获得较充分参考。

读取当时已经提交的完整主认知片场及其时间标注。未整理的主认知事件、工具结果全文、全部回忆不因此默认另行附加；积累输入由JEV自己的待办提供。

触发跟随下面D的主认知轮次，不把“主认知片场刚完成更新”设成无条件再次调用第二次的循环。下一次后台整理再读取当时完整版本，前台不等待。

### D. 第二次什么时候调用，是否每轮都调用？

**已确定：跟随主认知的自然轮次触发。** 一批输入进入主认知处理，就同时登记一次JEV第二次整理需求；不为每个语音识别碎片各开一次调用。实际后台运行沿用主认知写场那种忙时积累、合并整理的节奏。

“同频率”落实为同一轮次产生整理需求，不要求两个后台模型调用次数严格相等，也不要求同时完成：后台忙时，三轮需求可合并成一次JEV整理，包含这三轮尚未整理的材料。主认知继续回应，不等它。

所有现场输入仍保存到JEV待办。未进入主认知的旁人发言不单独触发后台调用，但可作为下次整理的积累背景；如果一直没有新的主认知轮次，就保留待办，不额外自行增加定时整理。服务关闭时如何保存、是否完成最后一批，属于E的待定恢复细节。

第二次拿当时已提交的完整主认知片场，不等本轮主认知写场结束，避免把“同频率”变成同步等待。程序播出和纠正事件继续积累，忙时合并；长期大量积压才按自然时间段拆分。

### E. 关页面或服务重启后，积累输入和片场保留吗？

**人物编号规则已确定；持久化与恢复仍有细节待讨论。** 编号是程序存储人物的内部标识，不是另一个叫“匿名”的身份类别。人物未确定就标未确定，之后确定了，在同一记录上写入已确认关联。

比如内部对象编号对应P2，起初姓名未确定；后来可靠依据确认是lux，就更新这条记录的姓名、确认状态与依据。不能因为“之前未确定”就丢掉编号或再建一个无关联人物。片场和历史可通过程序关联理解旧编号，但原始记录当时的待定状态仍保留用于分析。

长期内部对象ID与发给模型的短代号是两层。保存内部ID与映射，模型用短代号节省字数；不能因为界面重新打开就丢掉已有映射。不同声音究竟是否对应同一内部对象，仍依据程序证据，编号本身不能证明连续性。

当前人物复核队列与短建议主要在会话内存中；主认知待写场有持久化结构。新方案既然要求积累，不能只依赖有限内存队列。

**建议**：待整理事件与已验收JEV片场写入本地，按会话隔离，保存版本、来源和覆盖进度，重启后可续整理；原始日志按原有规则保留。工作队列完成后删除相应待办记录，不把每份工作缓存永久累积。保留诊断版本的期限沿用项目现有策略，若没有明确策略再单独确定。

此前“新会话不沿用旧匿名编号”的笼统表述撤回。应保留可靠内部人物关联；需要另外判断的是旧场面是否仍是当前场面，而不是把已存人物关联一并丢掉。跨会话是否继承正在等待的提问、关页面时未整理事件如何恢复、诊断缓存保留多久，尚未决定。

### F. 工具判断和三档改动，要一起落地吗？

**已确定：工具与主认知三档一并修改。** 此项已纳入同一实施范围，不再作为是否一起改的待答问题；整项程序实施还需明确剩余参数、持久化与异常处理。

第一次JEV只选择主认知提示词档位，不输出tool_needed，不决定具体是否使用工具。可能需要工具功能时保留完整1档；实际调用、复用已有结果或补查由主认知判断。程序已有待交付工具状态也须保留完整1档。

统一三档提示词、Schema、材料组装与选档；有工具需求或相关反馈待处理强制1档。工具需求不确定也选1，避免无工具Schema漏掉能力。主认知2/3档不传工具动态材料、不允许工具输出字段。出现新需求而选错时应有可观察的升级路径，不能让模型输出无效工具键；若需要第二次主认知调用，应只在确有漏判时发生并记录，不作为每轮默认步骤。

当前五档是数字越大越完整，三档相反。因此合批选更完整档应按新优先级合并，通常取有效档位的最小值；缺失或无效覆盖回退1。不能沿用当前max合并或“低档加tool模块”的规则。历史日志保留方案版本，不直接重新解释旧level。

### G. 场景由第一次内部假设，不要求第二次写标签

**按用户最新意见修正：** 撤回前一版“第二次明确识别和写出场景类别”的要求。第二次写好JEV片场，保留人物、原话含义、交往关系、环境及声音来源线索和不确定性，不强制写家庭、办公、会议等类别，也不写“可能在某种场景”的总结来凑字段。

第一次提示词提醒模型：根据输入与片场，在内部假设可能的交往情境，用来辅助人物与对话指向判断。无需输出场景名、场景分数、分类报告或思考过程；不增加场景Schema字段或第三次模型调用。

这样保留了片场中的多种可能，不需要第二次先把材料压成单一场景，再让第一次受这个标签约束。家庭来访者、现场与电视混合、远端通话等情况仍通过保留的事实和接续线索理解。实际是否改善准确率仍需实跑，不能先当成已验证效果。

依据不足时情境假设保持可修正，不单独证明身份，不排除新人；明确的环境事实可以写进片场，但电视剧情环境不能自动当成现实现场。没有音频特征时不假称分析了音色、方位或距离。

调度继续跟随主认知轮次、忙时合并，不因增加这句提示而新增“场景分类”任务或额外触发机制。

## 3. 建议由程序处理的边界，不增加模型任务

| 问题 | 建议做法及原因 |
| --- | --- |
| 谁实际听见了什么 | 依据实际播放事件；部分播放只记录实际播出部分。准备生成、准备询问不算发生 |
| 当前状态变化 | 第一次调用前取快照，控制执行前再核对当前播放与会话版本，避免旧stop作用到新回应 |
| 事件时间与排序 | 接收时间、实际播放时间统一时基；保留事件顺序，不混用音频毫秒和绝对时间；场景记录更新时间另存 |
| 后台期间又来输入 | 每个任务固定覆盖事件集合，新事件另留待办；只确认本次集合，不用“当前队列全部清空” |
| 持久化中途崩溃 | 片场正文、版本与覆盖进度一起提交，恢复后按事件ID去重；写片场成功不等于待办一定已经清理成功 |
| 人工纠正在后台调用期间发生 | 旧结果不能覆盖纠正。受影响快照失效，保留相关待办并用新依据整理 |
| 输出超过1000字符 | 不硬截断；保留上版与待办，有限次数重试压缩；连续失败退避并显示异常，不无限占用模型 |
| 不同对象隔离 | 用程序对象映射绑定P代号；不同声音、不同会话的未知对象不合并 |
| 第二次片场的人物结论 | 保留原判断来源与确定程度，作为第一次参考；不由片场文字直接修改归属。最终入口结论由第一次给出，自由文字语义不能只靠JSON校验保证 |
| 长期积压 | 显示待办量、最旧事件年龄及最后成功时间；分批处理，保留原始来源，不靠静默丢任务消除积压 |
| 非语音输入 | 同一输入信封，来源标明键盘等；无声纹不能造声音依据。已有独立输入通路先保持行为，明确接入范围 |

最后一项需要实施前确定：首版以当前语音入口为范围，还是同时改键盘入口？建议先统一数据类型，但先接语音，其他入口按现有机制使用，避免本轮扩成所有输入流程重写。

## 5. 并行不等于没有速度影响

第二次和主认知即使线程分开，也可能共用模型服务额度、连接池或推理资源。后台请求太频繁或太大，仍会拖慢第一段。建议明确前台优先，后台单并发、忙时合并、失败退避；先看现有模型服务能否实现请求优先或独立限额，再决定是否需要换后台模型。

不在本轮顺便重做主认知回忆组装。记录第一段、主认知、第二段各自的排队时间与生成时间，避免把总延迟都归给prompt字符数。800/1000是正文约束，完整请求还包含Schema及接口额外包装。

## 6. 实施顺序与验收

1. 落实已确定策略的阈值、归属输出和覆盖进度，确定恢复细节及语音接入范围，补正式输入输出Schema、版本与异常回退契约。
2. 先完成三档与工具联动、JEV片场存储和待办覆盖机制，再接新两段流程；功能开关允许回退旧路，由版本区分数据。
3. 用已保存真实请求做组装回放，确认材料没有错配、重复扩张或丢关键时间；构造例子必须与真实输出区分。
4. 实跑普通对话、多人旁聊、辨人冲突、播放被打断、后台积累、人工纠正、重启恢复及工具反馈，比较旧流程与新流程。

需要有行为验收和性能验收：前台不等后台；旧建议不升格确认；队列事件不丢；片场上限有效且未决事项保留；三档Schema一致；工具需求能到完整档；无多余重复回应。速度记录至少包括中位数及较慢请求分布，同时看误判和漏判，不能只看一句问候变快。

本稿给出的默认建议是可讨论的方案，不表示已经决定或测试通过。尚未修改程序、配置、运行数据或提交代码。
