# 05 修正交接说明（供其他分支修改 05 使用）

> 这份说明是跨分支交接用的，不修改本分支的 05 文档。
> 目标：让 05 退回纯认知，事件闭环统一交给 09 记忆系统。

## 1. 背景结论

记忆系统 09 已重新校准为：

- 记忆是匠石的稳定核心能力；
- 09 定义四步端口：存储（`ingest_activity`）/ 回忆（`recall`）/ 整理（`consolidate`）/ 做梦（`dream`）；
- **事件闭环归 09**：05 不再负责「事件是否结束 / 完整事件快照 / 已存标记」；
- 对象系统与 01 统一，不建独立角色系统；
- 不触发抽象事件，抽象事件相关一律不实现；
- fork REMS3 只是未来可替换后端，主流程只依赖 `MemoryPort`。

## 2. 05 修订后的职责

05 保留：

1. 回应文本；
2. 追加召回请求（查询 / 预算 / 对象锚点 / 事件锚点 / 回忆档位）；
3. 对象确认（confirm / deny / uncertain）；

05 移除：

- 事件是否结束；
- 完整事件快照；
- 已存标记；
- 未完成事件的产出与维护。

这些统一交给 09 的 `ingest_activity`。

## 3. 05 文档需要改的点

对应 `doc/design/05-认知.md`：

1. §4 用途段表：删除「事件是否结束 + 完整事件快照 + 已存标记」这一行；
2. §6 事件结束 / 分割 / 记忆落位：改为「事件闭环由 09 `ingest_activity` 在阶段⑦ 统一执行，05 不产出判定」；
3. §9.2 模型响应：移除「事件结束判定与完整事件快照（含已存标记）」；
4. §11 验收标准：把「事件结束/分割由 07 判定、09 落位，05 不直接写事件状态」改为「05 不产出事件闭环，事件闭环由 09 收尾时执行」；
5. §12 关系：05 对 09 的依赖只保留「追加召回」，不再写「09 落位」。

## 4. 05 相关代码需要改的点

### 4.1 `src/jshi/models/base.py`

- 不新增事件闭环字段；
- 保留 `recall_requests`、`object_assessment`；
- `recall_evaluation` 不再由 05 同一轮模型响应输出，改由独立评价过程生成。
- `RecallRequest.level` / `object_ids` / `anchor_event_ids` 继续保留，用于追加召回。

### 4.2 `src/jshi/subject/process.py`

在 `experience` 阶段⑦ 收尾时，调用 09 的 `ingest_activity` 做事件闭环：

```text
memory.ingest_activity(
    subject_id,
    object_id=speaker.object_id,
    text=text,
    source_ids=(fact.id, activity.id, thought.id),
    occurred_at=None,
    activity_id=activity.id,
)
```

注意：

- `object_id` 来自 01 的对象解析结果；
- `source_ids` 至少包含输入事实 id 与活动 id，可追加认知内容 id；
- 调用放在活动完成前或收尾阶段，由分支自行决定，但必须只依赖 `MemoryPort`。

追加召回处继续透传给 09：

```text
memory.recall(
    subject_id,
    request.query,
    limit=request.budget or default,
    object_id=request.object_ids[0] if request.object_ids else None,
    level=request.level,
    anchor_event_ids=request.anchor_event_ids,
)
```

### 4.3 不再新增

- 不在 `ModelResponse` 增加 `sealed_events` / `unclosed_events` / `event_snapshot` / `stored_mark`；
- 不把未完成事件持久化到 05；
- 不实现边界检测或事件封存逻辑，那是 09 的事。

## 5. 依赖的 09 接口（只依赖形状，不依赖实现）

```text
MemoryPort:
  ingest_activity(subject_id, object_id, text, *, source_ids, occurred_at=None, activity_id=None)
      -> MemoryIngestResult
  recall(subject_id, query, *, object_id=None, level=1, limit=None, anchor_event_ids=())
      -> tuple[RecalledFragment, ...]
  consolidate(subject_id, *, budget=None, cursor=None) -> ConsolidationReport
  dream(subject_id, *, object_id=None, budget=None) -> DreamResult
```

05 只使用 `recall`；阶段⑦ 由主流程使用 `ingest_activity`。`consolidate` 与 `dream` 属于后台 / 内部活动，05 不调用。

回忆评价不并入 05 响应：召回发生后，由独立评价过程收集召回请求、补充片段、最终 thought 与来源链，再生成 `RecallEvaluation`。

## 6. 不要改的

- 不修改本分支 09 文档；
- 不引入 REMS3 依赖；
- 不把事件闭环写回 05；
- 不改变 05 现有的回应、追加召回、对象确认行为。
