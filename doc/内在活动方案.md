# 内在活动方案

2026-11-21 · 运行设计讨论稿

「内在活动」沿用项目原有总称。在内在认知之前设置一个**发现助手**，位置可以类比外部交往中位于主认知之前的 JEV。助手交出值得想的问题、缘由和原始材料出处。内在认知接题后围绕该问题收集现场，按现有六问的顺序思考。助手的接口先确定，其内部如何发现、比较和排序另行讨论。模块接点、既有入口的复用与迁移见[内在活动程序更改方案](./内在活动程序更改方案.md)。[项目原有定义](./历史文档/总体架构.md#9-内在活动)

## 1. 一次内在活动的完整流程

```text
当时留下线索 ─┐
后来收到反馈 ─┼→ 发现助手 ← 当天主认知、活动、语音、工具和回忆记录
闲时主动扫描 ─┤                 ↑
带新证据的旧问题 ┘        过去可比经历、已浏览范围、未解问题
                         │
                         └─ 交出候选问题、缘由及材料出处
                                │
                  没有候选 ──────┤
                  记录范围，结束  ↓
                     内在认知接题，先收集当时上下文、前后现场和相关回忆
                                ↓
                  ① 发生了什么 → ② 我的选择和结果 → ③ 为什么
                                ↓
                  ④ 是否可以做得更好 → ⑤ 以后怎样做 → ⑥ 值得留下什么
                                ↓
           只留过程／纠正或总结／假设或新问题／提出尝试
                                ↓
         值得留存的认识 → 结果评价 → 记忆或适当的经验出口
         开放问题 → 等待特定证据；行动建议 → 对应活动决定是否执行
                                ↓
               后来有新事实 → 关联原问题 → 重新进入发现助手
```

主对话需要当场澄清、停说或履行承诺时，由现有主流程处理。后台回看可以在之后研究同一次活动。闲时调用并不要求每天把每一段经历都交给模型深想，助手可以返回空候选，内在认知也可以结束一个没有充分依据的问题。

## 2. 发现助手交什么，哪些办法留待讨论

### 输入与原始材料

一轮主认知结束时可以选填一句「哪里让我在意」，程序关联当时的活动。工具晚到的结果、人的后续纠正以及回忆评价的再加工理由可以在出现时补入。全天无人提醒、每轮都没标记时，助手仍可主动取当天的留存记录。

| 来源 | 助手首先看什么 | 哪些细节需要能回到原件 |
| --- | --- | --- |
| 主认知与交谈 | 本轮面对的情形、已有判断、实际交付、对方后来怎样接续 | 当事人原话、相邻几轮和实际说出口的内容。模型的回应计划与实际交付分别保留。 |
| 工具与活动 | 原目的、第一次请求、返回、重试及后来是否完成 | 同一事项的连续经过。时长、可用资源、任务难度和失败原因可以各自不同。 |
| 语音 | 用户原话与转写、断句和实际播放之间可关联的时序 | 有原声时可回听。只有文字时，把是否叠音、停顿多长等判断保留为未知。 |
| 回忆与后续反馈 | 为什么取回、哪些条目实际呈现、是否用于当前判断、后来得到什么反馈 | 区分旧事发生时间、本次想起的时间、形成新解释的时间。一次检索返回多条只提供联系的线索。 |

可展开的活动目录、快速扫描和普通原段轮换，是此前讨论过的三种取材办法。例如按事项或连续交谈保留原段，先读当天已有的主认知结果与活动元信息，再按需取原话、工具回报或回忆条目。轮换可以让标题平常的一段话也有机会被发现。采用哪种办法另议。交接时应区分目录已列、助手实际看过的原段、内在认知拿到的材料和缺失的原件。

### 今天与过去怎样比较

下列例子假设以**今天为待看范围，今天之前的七天为历史参照**。采用历史比较时，今天的观察与历史基线分别保留。比较次数还要考虑今天过去了多久、同类任务有几次。样本量和比较条件随候选给出；具体窗口和算法留待讨论。

- 对主认知，可以看同类请求是否反复漏接一种条件，或今天是否有一次以往少见的顺利配合。对某人的交往习惯，先在身份可靠、情境可比的交往中找支持与反例。
- 对工具，可以比较相近目标、工具与约束下的重试次数，并检查原因。一次检索给了错误结果，与当时的工具请求漏写了地点，值得提出不同的问题。
- 对回忆，可以比较相近问题过去召回了什么、这次哪些材料实际进入认知。若目标、人物范围或可见材料已经变化，要将差异带给内在认知。
- 历史太少时标明「基线未知」。一句明确纠正、一个尚未核验的承诺，或者一个令匠石感兴趣的细节，仍可独立成为候选。符合常态和成功的活动同样参与轮换。

若需先用简单方式跑通，规则可以提取少量可核对的问题。例如原话给了两个限定、工具请求只带一个，或迟到回报与先前答复存在明显差异。可选的本地小模型可以快扫短材料、从普通原段提出规则没覆盖的问题，再给候选排序。接入方只依赖下述交付内容，既不要求每轮给主认知追加调用，也不绑定本地模型、评分公式或七天窗口。

### 怎样提题和排序，怎样交接

一个候选至少要说清 **想问什么、哪件事引发它、为什么值得现在看、到哪里看原件**。有历史比较时补上基线、覆盖范围和不确定性。有好奇却暂时说不清问题时，可以先保留线索，等一段新材料使它更明确。来自不同模块的证据指向同一个疑问，就合成一题。两个问题即便来自同一次活动，也可以分别保留。

对仍在影响人的事情、正在进行的任务、成功经验和兴趣，可以采用不同的优先级。例如下午还要查同一场馆，上午为什么查错馆名就值得先看。优先级的算法另议。**交付时要能解释候选为何入选，允许零项。** 内在认知接到问题即可收集与它有关的现场。原件显示题意有误时可以收窄或修正，材料暂不可得时可以延期。

## 3. 不同问题怎样统一处理

**接题 → 收集现场 → 按六问思考 → 决定结果去向。** 先按助手给出的出处取当时上下文、事件前后的原话或工具记录，再按需补相关旧经历。材料标明是谁在什么时候知道的，区分当时的事实、后来得到的结果和这次回看的解释。中途缺一份关键原件可以补取，无法取得时保留未知。

| 原六问的顺序 | 这一问要解决什么 | 允许留下的判断 |
| --- | --- | --- |
| ① 发生了什么 | 用已收集的现场还原处境、人物和前因。 | 说明当时实际可见的材料及缺口。 |
| ② 我当时怎么选，结果怎样 | 核对自己的选择、实际行动和可观察的结果。若题目是两段回忆为何相连，可问「我实际想起了什么，这怎样影响了当时的理解？」 | 计划、实际交付与后来反馈各自陈述。 |
| ③ 为什么会这样 | 比较自己的选择、环境和偶然因素，查找支持或反驳具体解释的材料。 | 多种解释都成立时保留不确定。 |
| ④ 我是否可以做得更好 | 比较当时可行的替代做法与代价。对于理解或联想，可以问「原来的理解还站得住吗？」 | 可以确认原判断合适，或提出有依据的修正。 |
| ⑤ 以后我应该怎样做 | 写清条件和行动。需要时可提出一次尝试、调用工具或后续交流，并指出该观察什么。 | 实际执行和效果等待后续独立记录。 |
| ⑥ 值得记下来并学习什么 | 决定是否留下纠正、总结、经验、假设或开放问题，并交代依据。 | 认识候选可以为空；待证问题写清还缺什么，值得保留的认识交既有评价。 |

单事复盘、跨事对照、用回忆寻找旧例，都是收集材料、回答六问时可用的方法。例如一次工具超时，前两问核对当时给的预算和实际等待。第三、四问怀疑自己的估算总是偏低时，可以补取同类任务及反例。第五问提出改变预估方式后，只有后续确实采用并有结果，才有依据回来验证。现行自省已有现场组装和六问；回忆的检索评价、再加工和认识去留各有现行用途，具体复用与兼容路径见[程序更改方案](./内在活动程序更改方案.md)。[现行六问](../src/jshi/skill/introspection.py)

### 共同的结果和出口

每次至少留下「这次查了什么、依据在哪里、目前能判断到哪里、下一步去向」。收尾可以是以下几种结果，多种可以并存：

- **只留过程。** 原判断合适、材料不足或没有值得修改之处，可以结束。若想继续，写明在等哪一种证据。
- **纠正或总结。** 修订先前认识，或把多个已知事实总结为一条附条件的经验。原事件和旧认识的来源仍可追溯。值得保存的结果进入现有认识评价，决定放弃、留样或落到可召回记忆、匠石个人经验、与特定人物的相处经验。[现有评价与结果去向](./回忆自省与动态标准.md#从一次自省到可选的结果)
- **另一种解释或新问题。** 明确按假设保存，写明支持它的片段和缺少的证据。后来到达的材料可能引发下一次检查。
- **建议尝试。** 学习、补充交流、工具使用或改进行为均可提出需要。对应活动决定是否采取；随后记录实际做了什么、是否有效以及代价。涉及系统参数或统计归因的问题交给有效性分析。

发现助手可以接收「已受理、已合并、缺什么、等什么」等处理反馈，减少重复提题。一次自省结论被多次想起仍只有同一个来源。新事实、真正的反例或有实质变化的问法，才足以重新打开同题。是否改人格、调整参数或声称已经学会，分别需要相应的长期证据和模块判断。

## 4. 从零标记开始的一次运行

以下数字和对话均是方案推演。假设匠石当天与林禾聊过几次，也用工具查过场馆，完全没留下标记。闲时，助手把当天已完成的活动与此前七天可比材料放在一起。上午查开放时间时，林禾原话点了分馆，匠石的第一次请求查的是总馆，随后才补上分馆名。假设过去一周只有三次同类查询，其中一次也需要重试。助手可以提出「今天第一次请求为什么漏了分馆名」，附上原话、两次请求和返回；历史样本很少，对习惯性失误的判断仍然开放。

同一批还有两个普通交谈原段。下午匠石想先去场馆，林禾问「你是担心赶不上吗？」傍晚匠石想走小路，林禾问「你是想避开人多的路吗？」一次猜中，一次猜偏。助手可提出「林禾的提问在什么情况下帮助我表达本意？」并附两段原话。如果次日还要查馆名，工具问题有实际时效；如果匠石当前更想理解这次相处，它也可以接第二题。

接下第二题后，内在认知按同一人物查看当天相关交往，补找一次林禾没有先问理由的情形。若材料仅支持「她先问时，我更容易说出自己的考虑」，先把结论限定在自己的体验。还可提出「下次我不确定她为什么这样选，也先问一句」的尝试。后来是否实际问了、对方如何回应，都要等后续活动留下证据。两次提问不足以确定林禾一贯的性格。若回看后发现两件事没有有用的共同点，只留过程也能结束。

## 5. 与当前项目怎样衔接

| 范围 | 已有实现 | 本方案的变化 |
| --- | --- | --- |
| 外部交往与主认知 | JEV 与主认知已有各自的入口职责。主动审视可唤起同一主认知判断是否开口、等待或对内处理。[主动审视](./say-hello主动思考.md) | 把类似的前后分工用到内在活动。拟增发现助手，以及主认知可以选填的事后回看线索。 |
| 自省、回忆与后台执行 | 已有共同执行器、对话优先、行为回顾、回忆评价和再加工、候选认识比较。已有闲时选材从有限窗口顺序取经历，回忆评审能提出继续再想的理由。[执行器](../src/jshi/reflection/executor.py) · [现有触发与待定事项](./回忆自省与动态标准.md#触发时间和后台并行) | 助手交题后，主模块复用现场组装、六问与结果评价。回忆有适合再想的线索时可移交同一问题；补接迟到回报时须通过相同出处关联原活动。 |
