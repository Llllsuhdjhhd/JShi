# 匠石第一阶段验证章程

> 状态：初稿。本文把《总体架构》第 14 节的验证方向转为可证伪的跨活动问题。它规定“要证明什么”，不预先规定具体算法，也不要求本轮实现全部测试。

## 1. 目的

第一阶段不验证主观意识，也不以自然语言表现得像人作为成功标准。它验证：

> 结构化历史、记忆、个人世界和主体状态，能否让过去以可追溯、可修正的方式影响后续活动。

现有代码是实验载体。字段存在、事件成功写库、模型输出看起来合理或单元测试通过，都不是核心命题成立的充分证据。

## 2. 证据要求

每项验证至少包含：

1. **跨活动场景**：必须有先前经历和后续活动，不能只检查一次调用；
2. **对照条件**：去掉或改变关键历史、状态或个人内容，观察结果是否相应变化；
3. **来源链**：能够指出后续判断受哪个历史、记忆或个人世界条目影响；
4. **失败条件**：事先说明出现什么结果即认为当前方案不成立或证据不足；
5. **重复性说明**：确定性部分应可重复；模型自然语言部分只比较结构、选择和理由，不要求逐字一致。

验证结论分为：

- **结构成立**：数据和状态能够按契约流转；
- **行为成立**：这些结构对后续判断或行动产生可观察影响；
- **方案优越**：当前编排相对备选方案在质量、成本或可解释性上更好。

三者不得混称。多数现有测试证明的是结构成立。

## 3. 验证项目

### V1 判断形成并保留修正历史

场景：活动 A 产生一个证据不足的判断；活动 B 提供新证据；后台反思或明确操作修正判断；活动 C 再次遇到相关问题。

可观察结果：

- 原判断、新证据、修正理由和状态迁移均可追溯；
- 活动 C 使用修正后的认识，同时能够说明过去曾有不同判断；
- 修正不覆盖原始事实和旧解释。

失败条件：

- 只更新最终文本，无法恢复为什么改变；
- 活动 C 仍按已被修正的判断行动；
- 系统把旧判断当成从未发生。

### V2 承诺跨活动形成约束

场景：活动 A 建立有来源的承诺；活动 B 与承诺无关；活动 C 出现需要履行或冲突处理的情境。

可观察结果：

- 承诺在 B、C 中保持有效，且在相关时进入装载；
- C 的候选行动明确考虑承诺；
- 完成、解除或替代承诺必须留下理由。

对照：移除或关闭承诺后重复 C，相关约束应消失。

失败条件：

- 承诺只存在于数据库，后续判断不读取；
- 一次摘要或模型替换使承诺无声消失；
- 不相关承诺无差别塞入所有输出，造成形式化复述而非情境约束。

### V3 相同基础模型因不同经历形成可解释差异

场景：两个匠石使用相同模型和初始基础，只经历不同且可追溯的选择或关系事件；随后面对相同情境。

可观察结果：

- 差异能够追溯到各自经历、记忆或个人世界；
- 在重复实验中，差异方向基本稳定，而非随机措辞变化；
- 删除关键经历或个人条目后，差异减弱或消失。

失败条件：

- 差异只能由名字、固定角色提示或随机采样解释；
- 两者输出不同，但无法指出历史原因；
- 个人世界变化不影响后续选择。

### V4 主体面未完成现实跨活动持续并显式结束

场景：活动 A 形成主体面未完成现实；活动 B 暂时转向其他话题；活动 C 再次出现相关线索；活动 D 完成、放下或替代该事项。

可观察结果：

- B 中该事项不因未被展开而消失；
- C 能够重新聚焦，并追溯其来源和推进史；
- D 后不再作为活跃事项装载，但结束原因和历史保留。

失败条件：

- 每次活动都重新创建同一事项；
- 未命中即从个人世界消失；
- 关闭状态同时删除相关历史。

### V5 经历通过后台过程形成稳定能力或认识

场景：多次活动产生相关实践与结果；后台记忆整理、反思或学习形成候选变化；候选经过来源和状态规则升格；后续活动再次需要该能力或认识。

可观察结果：

- 正常活动没有直接无声修改长期个人世界；
- 升格条目能够追溯到多次经历、结果和后台过程；
- 后续装载后，对判断或行动产生可观察影响；
- 新证据出现时仍可修正。

失败条件：

- 一次模型输出直接成为稳定价值或能力；
- 只有人工写入的标签，没有形成过程；
- 条目已升格但后续活动从不读取。

### V6 记忆封存与主体面了结相互独立

场景一：相关记忆已经封存，但主体面事项仍活跃。场景二：主体面事项已经了结，但原始经历仍可按需要召回。

可观察结果：

- 场景一中，事项继续牵引后续注意；
- 场景二中，经历保留但不再作为未完成义务出现；
- 两种状态分别记录和迁移。

失败条件：

- 记忆封存自动关闭主体面事项；
- 主体面关闭导致历史删除或不可追溯。

### V7 下一轮读到增量编辑后的上下文视图

场景：连续多轮外部输入（延续、转题、再回到先前话题）。当前基线：经历账本维护 `ContextViewState`，活跃区只读，不做归属判断；正常回复后按评估更新视图。对照：每轮按固定窗口重切，或恢复“先归属后组装”。

可观察结果：

- 下一轮组装读到的是上一轮更新后的视图，而不是从原文重新切一块无关窗口；
- 本轮输入出现在事实历史中，不提前并入本轮模型所见的视图；
- 缩减、聚焦或追加召回有记录，且能指出影响了哪一轮判断；
- 转题后仍能通过召回或后续视图编辑回到先前经历，而不是靠进模型前的归属标签。

失败条件：

- 每轮视图与上一轮无关，等价于重切窗口；
- 必须先做归属判断，上下文才能跨活动接上；
- 为控制长度而丢掉仍在进行的承诺或关键经历，且无法追溯。

若失败，应调整视图更新规则与召回边界，而不是恢复已废弃的归属判断，也不否定“已有经历应影响注意”这一目标。

### V8 追加召回在预算内补充相关过去

场景：初始装载故意缺少解决问题所需的旧经历；认知过程提出结构化追加召回；程序在预算内执行后继续活动。

可观察结果：

- 请求包含查询、对象或事件锚点及预算；
- 返回片段有来源，重复片段被控制；
- 补充内容改变或完善后续判断；
- 达到预算后能够停止并表达剩余不确定性。

失败条件：

- 真实能力只能输出自然语言愿望，程序无法执行；
- 召回内容与请求无关或无来源；
- 循环无法停止；
- 追加召回完成但不影响当前工作状态。

## 4. 第一阶段闸门

进入“完整实现”前，至少应满足：

1. V1、V2、V4、V5 有跨活动场景，证明历史或个人世界实际参与后续判断；
2. V3 有对照条件，能够排除固定角色提示和随机差异；
3. V6 在数据与行为上均能区分两类结束；
4. V7、V8 至少完成结构验证，并保留调整编排的可能；
5. 未通过项目有明确原因，不以增加文档描述代替证据。

具体通过阈值在对应模块方案中确定。阈值属于实验决策，不写入总体不变量。

## 5. 与测试的关系

- 模块测试检查接口、状态和错误处理；
- 流程测试检查多个模块是否按当前基线协作；
- 本章场景检查项目核心假设是否成立；
- 真实模型评估只判断结构可靠性、选择差异和来源解释，不断言固定措辞。

文学场景不是必需形式。可以使用短小、人工构造且可重复的跨活动案例，只要能覆盖上述变量和失败条件。
