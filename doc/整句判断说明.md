# 整句判断说明

最近更新时间：2026-10-30（北京时间）。

本文解释匠石当前已经接入的整句判断。下文双路声学／文本融合以Qwen链路为范围。2026-10-29新增火山在线声学辅助，见下一节；Deepgram和旧CPU识别路径仍未套用该流程。

## 火山在线声学辅助（2026-10-29）

三轮修复补充（2026-10-29 22:56，北京时间）：待续期间出现时序上在后的不同声音，或另一云端轨迹的未知发言，先释放旧待续再交新发言，避免A→B应答→A仍跨轮联合。断轮只保留原话，不把未知人物确认成新姓名。新增online_acoustic_window记录本地VAD起止与当时已输入音频位置；这些端点不等于语义完成，也不会把火山临时文字直接提交为最终输入。火山晚定稿仍需外部服务对照，当前后置会合不能消除这一等待。

同一份16kHz PCM同时用于火山发送、本地缓存和持续VAD；不另跑本地ASR，不等6秒窗口。火山最终转写经过现有声纹处理后，按原区间取音，由Smart Turn提供声音完成倾向。2026-10-30新增在线冲突校正：火山定稿只作为候选片段交付边界，不当作语义已完；声学complete时直接交付，unknown时保留未知交付，不调用语义。只有声学incomplete与候选边界冲突时，才调用本地Namo，读取同一可靠声音组的原始文字（按时间换行），预算沿用200ms。语义complete支持边界而放行，incomplete支持声学而暂存；语义unknown、异常、未配置、未加载、忙或超时则以unknown立即交付，不继续悬置。暂存仍受最早定稿起两秒期限限制。Qwen原有双路并行融合不变。

三路证据分开记录于 `online_completion`，包含候选边界、声学原判、语义是否调用、结果及耗时；不会把语义校正后的结果伪装成声学原判。这里是“冲突时第三路裁决”，不是把定稿状态强行算成“语义完成”后做无条件三票多数决。Namo是已有本地分类器，不新增提示词或在线模型请求。控制流验证与模型语义准确率分开：本地真实试跑发现中文例子仍可能误判，不能把模型裁决视为真值，尚未做新的在线场景质量回归。

完成或未知放行；明确未完暂存，同一可靠声音后续片段到达时联合原声再判断，原文字与片段不合成改写。默认声音会合等待预算600ms，超时或异常按未知放行；最多12秒音频／32段。2026-10-30起，在线路径按待续组中最早定稿返回的单调时钟计算默认2秒截止，不因全场持续人声或同人新片段刷新而无限保留。后台每50ms检查，模型会合与事件循环调度仍会产生少量超出；按 `hold_deadline` 释放时保留 `incomplete` 等判断，不声称语义说完。此项仅限制已收到定稿的本地等待，不缩短云端定稿等待，也不自动将预览升为定稿。文件结束释放全部待续原文；关闭和旧会话结果不得晚发。其他使用TurnCoordinator的本地路径保持原有空闲释放规则。

人物不可靠、重叠、音频缺失与转写修订不强行续接；修订前先释放已有暂存，沿用正式修订映射。正在JEV判断、主认知或播放／排队时旁路普通声学等待，交现有JEV撞车与停止控制。旁路不代表声音已完成。

使用现有 `JSHI_VOICE_TURN_STRATEGY=smart_turn/eager`；eager关闭此辅助。模型路径沿用 `JSHI_VOICE_LOCAL_DIR`，需Smart Turn与Silero VAD。不可用时记录原因并沿用火山；ready报告启用／不可用／关闭状态，页面显示结果。需重启语音服务加载本轮代码。

声音判断在火山最终文字到达后针对对应区间运行，VAD与火山接收期间持续推进；不是声学模型在转写前就能保证每个最终区间的结果。它辅助判断是否继续等，不将云端临时文字擅自升级为定稿，因此不能保证比火山更早得到最终文字。

## 1. 这里的“整句”判断什么

这里的“整句”更接近**当前话轮是否可能结束、这批材料是否可以先交给JEV1**，不要求一定是语法完整的长句。

“好”“不用了”“明天呢”都可能是当前交流中足够完整的发言；一段看似有句号的文字，也可能只是下一句话的前半部分。模型给的是预测，不是确定事实。

系统区分三个决定：

| 决定 | 负责模块 | 作用 |
| --- | --- | --- |
| 先切出多少声音处理 | Silero VAD＋切段策略 | 默认500ms静音，最长3.5秒一个处理窗 |
| 已有材料是否先提交 | 整句策略＋接续协调器 | 明确未完才暂存，完成或不确定及时交出 |
| 是否接话、继续等待或停止 | JEV1及后续交付流程 | 结合人物、前文、当前任务和播放状态判断 |

切段不等于说完，整句模块放行也不等于匠石马上开口。工程超时放行尤其不能解释成“模型确认对方已经说完”。

## 2. 当前涉及哪些模型

| 模型或组件 | 当前职责 | 与整句判断的关系 |
| --- | --- | --- |
| Silero VAD | 判断声音活动，产生处理窗 | 提供可处理的音频；不靠文字理解语义 |
| 本地说话人分析、声纹模型 | 生成说话人时段、重叠标记及声音组证据；默认声纹模型CAM++，也支持已有ERes2NetV2选项 | 帮助避免把不同人的待接续片段混在一起；不负责判整句 |
| WSL千问Qwen3-ASR | 将新音频片段组成一个batch转成文字 | 提供原话，不返回本项目可直接使用的语义说完标志 |
| **Smart Turn v3.2 CPU** | 从音频预测话轮结束的分数 | 当前默认整句模型，和千问转写并行 |
| **Namo Turn Detector v1 Multilingual** | 从ASR原文预测语义完整度 | 当前文字分支，支持中文，可通过off关闭 |
| JEV1配置的模型 | 判断交往、人物、接续和是否回应 | 下游进一步判断，可在整句模块放行后继续keep |

**当前已接入可关闭的Namo文本语义整句判断。** 它在千问返回文字后启动，同时Smart Turn音频分支可能仍在运行。TurnSense并未接入：核对[官方推理代码](https://github.com/Bairong-Xdynamics/TurnSense/blob/main/infer.py)后确认其输入实际为音频，之前把它称为纯文本模型的介绍与约55ms文本推理估算不适用。此前讨论的R2T2流式识别也尚未接入。

## 3. Smart Turn模型介绍

Smart Turn由Pipecat/Daily开源，用音频判断话轮是否结束。模型卡介绍其结构为Whisper Tiny编码器加一个浅层分类头，约800万参数；官方同时提供量化和非量化ONNX文件。本项目选择CPU版本，不在WSL千问GPU上额外加载这个模型。[官方模型卡](https://huggingface.co/pipecat-ai/smart-turn-v3)

它学习音频中的结束线索，不需要先看到ASR文本。不能把它简单等同于“检测音量变小”，也不能声称程序已经明确提取了某一个语调特征作为本次判决理由。当前能拿到的是模型分数，而不是可逐项核验的语言学解释。

本项目固定使用：

| 项目 | 当前值 |
| --- | --- |
| 模型仓库 | `pipecat-ai/smart-turn-v3` |
| 文件 | `smart-turn-v3.2-cpu.onnx` |
| 下载版本 | `f766f81` |
| 本机文件大小 | 8,679,182字节，约8.68MB |
| 本机SHA-256 | `2bb026316b14a660486a75b1733cd3fbab8c2fd0314dc9af7be49f8cca967e4f` |
| 推理引擎 | ONNX Runtime，`CPUExecutionProvider` |
| 特征处理 | Transformers的`WhisperFeatureExtractor`，只提取音频特征，不生成转写文字 |
| ONNX线程 | 当前单次会话内线程2、会话间线程1，顺序执行模式 |
| 默认位置 | `.jshi/voice_models/smart-turn-v3.2-cpu.onnx`；可随`JSHI_VOICE_LOCAL_DIR`改变模型根目录 |

官方模型仓库列出的许可为BSD-2-Clause；具体模型文件和用法应以对应版本的官方资料为准。[模型文件与许可](https://huggingface.co/pipecat-ai/smart-turn-v3/tree/main)

### Namo文本模型介绍

当前选择`videosdk-live/Namo-Turn-Detector-v1-Multilingual`，固定版本`59245aac1f0a0f170277ebecc32ddaea418083b4`。这是基于mmBERT的多语言文本轮次分类器，官方列有中文支持，使用量化ONNX模型。输入是转写文字，不接收原音频；输出两类logits，官方映射为0=继续、1=结束，程序softmax后使用第1类概率。[官方模型与用法](https://huggingface.co/videosdk-live/Namo-Turn-Detector-v1-Multilingual)

本机模型`namo-turn/model_quant.onnx`为308,985,714字节，约309MB，随附分词器；ONNX Runtime只用CPU，每个会话内线程2、会话间线程1。启动时加载并预热，实时阶段不临时下载模型。实际耗时见本文测试记录，不能沿用TurnSense的54.65ms评测。

## 4. 模型吃什么、返回什么

### 输入

1. 16kHz、单声道音频，在Python侧转换为float32采样。
2. 当前声音组之前尚未放行的音频，加上本次新音频。
3. 最多保留末尾8秒供整句模型读取；不足8秒时在前面补零。
4. 提取Whisper音频特征，再交给ONNX模型。

8秒是**整句模型的上下文长度**，不是VAD处理窗：一个新窗最长3.5秒，仍可以和前面待接续的窗共同形成整句判断上下文。官方也建议在VAD出现停顿后，用当前话轮的上下文判断，而不是仅拿很短的尾音。[官方使用说明](https://github.com/pipecat-ai/smart-turn#notes-on-input-format)

**当前实现的边界：**上下文由说话人分析得到的语音片段拼接而成，不是完整保留所有间隔的连续8秒录音；中间的部分静音或其他人的声音可能不在拼接结果里。这可能影响节奏线索，后续需用真实对话验证。

### 输出

Smart Turn输出一个0～1的结束分数，程序称为`probability`。当前阈值为0.5。下面描述声音单路行为；开启Namo后按第15节融合：

| 条件 | 程序状态 | 后续动作 |
| --- | --- | --- |
| 分数≥0.5 | `complete` | 先交JEV1，不继续为了凑句而等 |
| 分数＜0.5 | `incomplete` | 暂存，等待接续或兜底释放 |
| 超时、异常、没有适用证据 | `unknown` | 交JEV1进一步判断 |

这个分数不是“对这句话有多少把握”的通用准确率，也不是“字都识别对了”的置信度。`unknown`来自程序的故障或适用性处理，不是Smart Turn自身的第三个分类。

如果原始输出不是有效的有限概率，按异常处理，不拿无效分数阻塞输入。其他扩展策略返回不支持的状态时，也转成unknown保留材料，不按`invalid`直接删除录音或原话。

## 5. 实际流程与并行时序

```text
持续收音 → Silero切段500ms/3.5秒 → 声音分析
   ├─ Smart Turn：声音完整度 ──────────────────┐
   └─ 千问：一次batch → Namo：文字语义完整度 ──┤
                                              ↓
                                     双路融合 → JEV1前组装
```

当前Smart Turn在声音分析完成之后启动，和千问转写重叠运行；它没有提前覆盖VAD等待或声音分析时间。多个人仍组成一个千问batch，不为每个人并发发起独立ASR请求。

整句分支只有一个工作线程，同一轮不同声音组的判断在该线程内依次运行。因此单人约70ms不能直接推成多人整批也约70ms；多人或CPU繁忙时可能触发预算回退。

### 并行是否增加等待

千问和Smart Turn从声音分析完成后并行；Namo在千问返回、原片段完成本地组装后立即启动，**不先等Smart Turn**。假设千问耗时A、声音判断耗时B、文本判断耗时S，正常会合时间近似为`max(B, A+S)`。

因此Smart Turn耗时被ASR覆盖时，新增等待通常接近Namo时间；如果声音分支更慢，Namo也能覆盖其剩余等待。声音预算仍为启动后600ms，文本预算独立为文本任务启动后200ms，均只等待剩余预算，不截断ASR，也不能强行取消正在执行的ONNX调用。某一路超时或异常时，使用另一条有效证据；都没有有效证据时放行给JEV1。

两条分支各只有一个工作线程和一个在途任务，旧任务未完成时不再排入新任务；晚回结果不能写入新轮次缓存，不能把旧会话的判决套到新输入上。

## 6. 判未完之后，下一段如何衔接

第2层缓存由`TurnCoordinator`维护，每个可关联的声音组分别保存：原转写片段、原音频、原时间位置和诊断信息。

接续依据按优先级为：

1. 已有`voiceprint_id`；
2. 本地`speaker_cluster_id`；
3. 两者都没有，不只凭临时`track_id`硬接。

重叠语音或明确标记身份不确定的输入也不硬接，按unknown交JEV1。本地声音组不等于实名确认；聚类本身仍可能误判，不能将其当成绝对同人证明。声音组或身份标识改变时，也可能无法自动接上旧组。

假设同一声音组先后有A、B两段：

```text
A → 千问转写A；Smart Turn判断A未完 → 缓存A
B → 千问只转写B；Smart Turn读取A音频＋B音频
      ├ 完成／不确定：放行A、B两条原片段
      └ 未完：继续保留A、B
```

**千问不会因为整句未完而反复重转写A。** 本轮新增文字与缓存原文共同提供给文本策略。Namo只读取同一声音组按原始时间排序的原文，以换行分隔片段，不补造句号、不润色、不发送人物ID或内部字段。只在模型副本中保留末尾最多512个token，程序仍保留全部原片段。

放行时保持每段人物、起止位置和原文，按时间排序交到JEV1前的组装环节。不会将不同人物的文字无标记地连接成一句。大量暂存片段集中放行时，输入队列使用背压，避免因队列满直接丢片段。

## 7. 哪些情况不能一直等

| 条件 | 当前处理 | 释放原因 |
| --- | --- | --- |
| 判断完成或不确定 | 立即放行 | 模型理由或回退理由 |
| 模型未在预算内完成／旧任务仍忙 | unknown放行 | `audio_timeout_or_unavailable` |
| 音频模型异常 | unknown放行 | `audio_error:异常类型` |
| 文本语义分支超时或异常 | 使用声音有效结果；没有则unknown放行 | `semantic_timeout_or_unavailable`或`semantic_error:异常类型` |
| 新旧片段的音频位置间隔大于4秒 | 旧组释放；本轮不强行继承旧音频判断 | `continuation_gap` |
| 单组累计达到或超过12秒音频，或32条有文字片段 | 放行给JEV1 | `pending_limit` |
| 待接续超过配置时限 | 在后续处理／轮询时放行 | `hold_limit` |
| 采集结束 | 释放全部剩余片段 | `capture_end` |

默认待接续时限为2秒，**从最近一批转写片段进入该组缓存后计时**，不是从麦克风最后一个人声样本起计时。没有新窗的轮询，仅在VAD当前没有持续检测到人声时执行时限释放；新窗处理完也会检查其他组的期限。因此它不是一个严格的“声学静音2秒”定时器，也不是整个说话至响应的2秒承诺。

12秒／32段是在加入本次片段后检查的释放阈值，不会把原文或音频强裁成恰好12秒；Smart Turn实际读取的仍只有末尾8秒。

这些工程兜底只表示“继续交给下游判断”，不提升`incomplete`为语义完整事实。普通JEV组包的`collection_complete`仍为null；两路的完整分数和融合原因留在诊断，不作为已经说完的确定事实写入模型材料。

## 8. JEV1再次判未完，如何接续

这是另一层缓存，不能和第2层音频暂存混为一谈：

| 层次 | 暂存内容 | 等待之后怎样使用 |
| --- | --- | --- |
| 整句模块 | 尚未投给JEV1的原片段、音频和计时 | 新音频到来后重新判整句，放行后首次作为本批输入进入JEV1 |
| JEV1的keep接续 | 已经投过JEV1、但暂不处理的原话及人物、时间 | 下一次通过既有近期接续材料带回，不重复作为新的当前发言 |

JEV1的keep原话会进入会话缓存，即使后台片场整理成摘要，后续仍可提供原文。当前通过既有`input.unwritten`字段提供；兼容单条JEV使用对应近期上下文。

程序在发送模型前去掉无用长ID；内部仍用原输入编号与当前材料、已有未整理材料去重。人物使用既有短代号，时间关系保留。另一人发言不会直接消费这一人的待接续；同一人物后续已被明确处理时消费相关缓存。

这层缓存最多32段／8000字，默认沿用300秒接续时效；超过容量会移出最早的待接续项，超过时效不再带回。显式停止、断开也会清空。因此它不是无限期原文记忆，不能保证跨新会话继续接回；正式原始记录与这份短期缓存是不同的存储。

JEV1的keep还可能表示保持当前任务，并非每次都意味着语言学上的“半句”。

## 9. 策略接口与当前可切换项

切段、声音整句、文本语义分别注册，互不绑定：

| 模块 | 当前策略 | 行为 |
| --- | --- | --- |
| 切段 | `fixed` | 使用配置的静音窗口和最长窗，默认500ms／3.5秒 |
| 切段 | `patient` | 静音窗口至少1000ms，最长窗仍按配置 |
| 整句 | `smart_turn` | 当前音频整句模型，按分数判定 |
| 整句 | `eager` | 不调用音频整句模型，声音证据unknown；语义启用时仍按语义判断 |
| 文本语义 | `namo` | 读取同组待接续文字及新文字 |
| 文本语义 | `off` | 不加载、不调用文本模型，保持声音单路 |

新增音频策略实现`TurnPolicy.analyze_audio(samples)`并注册到`TURN_POLICIES`；文本策略实现`SemanticTurnPolicy.analyze_text(transcripts)`并注册到`SEMANTIC_POLICIES`；融合由`fuse_decisions`统一处理。旧`TurnPolicy.decide`钩子保留。切段策略实现`SegmentPolicy.settings(config)`，注册到`SEGMENT_POLICIES`。

接口已经保留，但没有把尚未实现的策略当成现成功能。当前已有Smart Turn＋Namo双路判定，但没有对两个模型分数求平均。TurnSense和自适应语速阈值仍未接入。

## 10. 配置、准备与生效

```dotenv
JSHI_VOICE_SEGMENT_STRATEGY=fixed
JSHI_VOICE_END_WINDOW_MS=500
JSHI_VOICE_MAX_WINDOW_MS=3500
JSHI_VOICE_TURN_STRATEGY=smart_turn
JSHI_VOICE_TURN_THRESHOLD=0.5
JSHI_VOICE_TURN_TIMEOUT_MS=600
JSHI_VOICE_TURN_MAX_HOLD_MS=2000
JSHI_VOICE_SEMANTIC_TURN=namo
JSHI_VOICE_SEMANTIC_THRESHOLD=0.5
JSHI_VOICE_SEMANTIC_TIMEOUT_MS=200
```

提高整句阈值，通常会有更多输入进入未完暂存；降低阈值，更容易提前提交。提高阈值不等于准确率必然更高，必须同时看误切、等待和JEV进一步暂缓的情况。

首次准备：

```powershell
python -m pip install -e ".[voice-local,voice-turn]"
.\jshi.cmd voice-setup --vad --diarize --turn --semantic-turn
```

语义关闭：`JSHI_VOICE_SEMANTIC_TURN=off`，不加载或调用Namo，维持原声音判断；声音关闭可选`JSHI_VOICE_TURN_STRATEGY=eager`，此时只用语义；两者都关闭则已有材料直接交JEV1。开关修改后重启Windows服务，不需重启千问。显式选择namo但缺文件时会提示准备模型，不偷偷切换策略。

`voice-turn`提供ONNX Runtime和特征处理依赖；`--semantic-turn`准备并验证Namo及分词器；`--turn`下载并验证固定版本CPU权重。选择smart_turn但模型缺失时会报准备错误，不偷偷切成另一策略。需要不依赖此模型时，可显式改为`JSHI_VOICE_TURN_STRATEGY=eager`。

修改配置后重启Windows匠石、刷新网页，WSL千问无需因为整句策略而重启。`/status`中的`speech_policies`显示选择，当前scope为`qwen_local_pipeline`。

## 11. 页面与耗时记录

当前Qwen路径不是逐字流式ASR。每次千问batch返回新文字后，先完成本轮并行会合，再发布转写预览；如果整句分支尚未完成，预览也可能受剩余等待预算影响。

明确未完时页面提示“已转写，等待接续”；放行后再进入人物证据准备及timeline显示。这几个时点不能都叫“ASR出字”。

数据目录的`voice_latency.jsonl`记录判断事件和最终输入计时。查看整句相关字段时注意：

| 字段 | 含义 |
| --- | --- |
| `turn_state`／`turn_probability`／`turn_reason` | 本次策略状态、模型分数及理由 |
| `turn_audio_ms` | 整句任务的计算耗时；多声音组时是整个任务时间，不能给每段重复相加 |
| `turn_join_wait_ms` | 千问返回后，额外等待整句分支的耗时 |
| `turn_semantic_ms`／`turn_semantic_join_wait_ms` | 文本任务总计算时间／最后会合时仍需等待文本结果的时间 |
| `turn_audio_state`／`turn_semantic_state` | 分别记录两路原判断；语义关闭明确为disabled，不计为双方一致 |
| `turn_semantic_enabled` | 文本分支是否启用 |
| `turn_hold_ms` | 原转写返回至片段释放的间隔，可能同时包含会合等待与后续暂存，不是纯模型计算 |
| `turn_release_reason` | 最终为何放行：完成、超时、接续间隔、暂存上限等 |
| `transcription_batch_ms`／`http_batch_ms` | 整批转写及HTTP往返；后者不是纯GPU推理时间 |

整句任务耗时小不代表总延迟一定小：还需看前面的收包、VAD、声音分析，后面的人物证据与浏览器显示。完整出字指标见[语音输入与交付](语音输入.md)。

## 13. 当前限制与下一步验证

- 0.5是偏及时提交的起始阈值，尚未用用户家庭对话校准。
- 多人时整句计算逐组执行；未归属或重叠输入偏向放行给JEV，不保证每段都经过模型判整句。
- 当前上下文是片段拼接，原始停顿保留不完整，需验证对韵律判断的影响。
- “能继续拼接”不能修复千问漏字、听错、漏掉否定词；这些属于转写质量问题。
- 稳定的下一步评估应同时标注是否误抢话、等待多久、需要多少次JEV keep，以及模型分支实际增加了多少等待，不能只比较单模型F1或推理毫秒数。

## 在线句尾保守接续更新（2026-10-30）

仅适用于火山在线入口，不改变下面千问 batch 的双路融合规则。

- 对末尾依存词／连接词（`的、一定要、需要、必须、按照、比如、因为、所以`）作有限的接续提示。忽略尾部标点及“呃／额／嗯”；少于四字及“是的／好的／对的／我的／你的／他的／她的”结尾不触发。提示不是可靠语法分类，会有漏判和误触发；仅请求有上限的等待，不补字、不改写原文。
- 提示命中后保留原声学判断，诊断最终状态为 incomplete、原因为 `online_open_tail_wait_bounded`。即使声学认为完成也先等续句。到时按原等待上限释放，不能把到时释放记成语义完成。
- 当前 Namo 中文控制例未通过质量验收，其 complete 不再覆盖声学 incomplete；保留原始语义判断及非权威标记。其他未知／超时仍按未知交付，不无限等待。
- 后续人物待定时，先释放较早的待接续片段，再交付待定片段，即使二者使用同一云端轨迹。诊断为 `unresolved_continuation_boundary`，不据此宣称换人，也不把前一个人的身份复制给短片段。
- 原文、音频范围、人物证据仍逐片保留；这是本地调度改动，未增加 JEV 模型字段或调用。普通 JEV 组包仍不把本地判断当成确定完整度。

## 15. 双路融合、关闭与拼接的程序约定

| 声音 | 语义 | 最终状态 | 动作 |
| --- | --- | --- | --- |
| complete | complete | complete | 一致完成，提交JEV1 |
| incomplete | incomplete | incomplete | 一致未完，暂存原片段 |
| complete | incomplete | unknown | 冲突交JEV1，不强加等待 |
| incomplete | complete | unknown | 冲突交JEV1，不强加等待 |
| 任一有效结果 | 另一条超时／不可用 | 沿用有效结果 | 支持单路运行 |
| 任一有效声音结果 | 语义off | 沿用声音结果 | 与原声音策略兼容 |
| 声音eager或不可用 | 有效语义结果 | 沿用语义结果 | 支持语义单路 |
| 都无有效结果 | 都无有效结果 | unknown | 保留并交JEV1 |

一致完成不生成虚构的“联合置信度”，原来的两路分数分别记录。单路判断不能标为双方一致。语义只有complete/incomplete两类，没有TurnSense的invalid第三类。

拼接使用`TurnFragment`将原转写、对应音频、诊断绑定为一个记录，避免三个平行列表错位。缓存按人物证据分组；内部用原音频起止、轨迹和音频种类识别同一物理片段，不按文字相同去重。

- 待提交的相同物理位置被重发或更正时替换对应片段，不再重复追加前文。
- 已释放的相同片段重发在有界缓存内去重；相同文字发生在不同时间仍保留，不能删掉真实重复表达。
- 同一物理片段的人物证据更正时只移动该片段，不把原人物的其他未完内容一起迁移。
- 未声明为修订的重叠音频位置，或新旧音频间隔大于4秒，先释放旧片段，新内容单独判断，避免叠加重复音频或跨活动拼接。
- 明确标记replaces的已交付ASR修订仍走现有修订入口，不当新句重复提交；本项目千问batch本身不产生流式修订。
- 文本分支读取不可变片段快照；旧任务晚回后不修改新缓存。会话reset增加代次，旧ticket不能发布旧会话结果。
- 第2层放行后，原片段仍分别交给JEV1，语义模型看到的换行文本不会覆盖原话、人物或媒体关联。

程序入口新增[semantic_turn.py](../src/jshi/voice/semantic_turn.py)，覆盖回归见[test_voice_semantic_turn.py](../tests/test_voice_semantic_turn.py)。


### JEV显式完整度返回（2026-10-22 14:30，北京时间）

JEV1批量入口现在返回`utterance_complete=complete/incomplete/uncertain`，与`control`独立；前两路判断仅负责上游调度，JEV继续独立终审。完整时消费同人待接续记录；未完或不确定保留原始记录，下次在`input.unwritten`提供原话和人物时间关联；不重转写旧音频、不跨人拼文字。停止仍优先清空。旧返回缺字段按uncertain兼容。完整度写入`voice_jev_diagnostics`及JEV调用记录，没有新增一次模型请求。当前原话保留上限仍为32段/8000字、300秒。单条旧协议未强制增加该字段，默认兼容为不确定。
