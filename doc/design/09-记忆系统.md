## 1. 定位

记忆是匠石的**稳定核心能力**之一：让过去以可追溯、受预算约束的方式参与当前活动，并支撑连续性。它的实现是独立、可替换的模块（当前进程内最小实现；REMS3 fork 已在 `C:\Users\40575\Desktop\prog\Jshi_memory` 独立实现端口），但记忆内容、来源和行为始终归属于匠石主体框架。

实现上，09 是**记忆薄壳**：稳定 `MemoryBackendPort` 并负责输入输出适配；边界检测、封存、残影、未完成事件、召回排序、遗忘等内部代谢全部委托给后端。

关键边界：

- 记忆 ≠ 个人世界：记忆保存可核查的原文与来源，个人世界保存长期判断、价值与承诺（见 08）；
- 事件只在 09 内部：主链路（02 / 03 / 05 / 07）不使用事件；未完成事件 / 残影是后端内部缓冲，不跨端口暴露；
- 记忆原文 ≠ 解释层：`content_raw` 永不改写；摘要、对象快照等解释层可重新生成，旧版本与来源保留；
- 后端可替换：REMS3 fork 是可选实现，不是架构前提；未接入时用进程内最小实现，主流程行为不变。

## 2. 职责与边界

### 2.1 09 做什么

- 定义并稳定四步记忆端口：存储（`ingest_batch`）/ 回忆（`recall`）/ 整理（`consolidate`）/ 做梦（`dream`）；
- `ingest_batch` 接收 30 构造的 `MemoryBatch`，逐 input 走后端代谢（边界检测、封存、对象时间线、`stored_marks`），返回 `BackendIngestResult`；
- `recall` 只读 + 记忆恢复：按对象过滤、档位与预算返回片段；命中事件强化遗忘因子（唯一写操作）；
- 所有记忆单元带 `subject_id`，对象复用 01 的 `object_id`，来源链可追溯；
- 主体记忆合法：经历可无外部对象，`objects` / `object_ids` 可为空，不阻断投递。

### 2.2 09 不做什么

- 不触发抽象事件：不做频繁子集挖掘、ASF、`source_events`、抽象合成；
- 不建独立角色系统，不抽取对象：对象一律来自 01 的对象映射表，文本出现未知名字时保持原样或返回候选，不自行解析；
- 不决定主体面是否了结：主体面未完成现实 / `concern` 已废除（D-007），记忆封存不等于任何主体面状态；
- 不管理认识状态与状态迁移（06）；
- 不静默改写事实原文，不物理删除原文（遗忘只降可见性）。

### 2.3 记忆来源与主体记忆

- **记忆来源唯一**：匠石长期记忆的写入只经 30 投递（外部活动经历）与未来内部路径（反思等，占位）；任何模块不得直接写记忆后端；
- **主体记忆合法**：经历可以没有外部对象（如看到落日、内心感触、反思），此时 `object_ids` 为空，归属仍由 `subject_id` 保证；30 批次允许 `object_ids` 为空；
- **反思与记忆分开**：反思是内部活动，目前占位、不自动沉淀为长期记忆；未来沉淀走内部投递路径，须显式实现后再放开。

## 3. 概念

### 3.1 记忆单元（MemoryEvent）

已闭环事件落位后的最小记忆单位。它是具体的事实记录，不是抽象事件；`content_raw` 是输入原文（的字面片段），永不改写。

### 3.2 对象记忆时间线（ObjectMemoryEntry）

按 01 的 `object_id` 组织同一对象在多次事件中的一句摘要快照，支撑对象过滤召回与对象状态装载。**无情感**（情感只属于主体，事件级 `emotion` 单独落库）。

### 3.3 回忆档位（1–9）

| 档位 | 语义 | 返回片段上限（占位） |
|------|------|----------------------|
| 1–3 | 线索级：少而浅 | 3 |
| 4–6 | 情境级：中等上下文 | 5 |
| 7–9 | 深挖级：更多上下文 | 8 |

- 阶段③ 使用当前策略快照的档位（无快照则 1）；
- 05 不再指定本轮更高档；档位调整只经有效性分析 → 本策略接口；
- `limit` 是硬上限，可覆盖档位推导；具体映射由 09 定义。

### 3.4 未完成事件

未完成事件 / 残影是**后端内部工作缓冲**，不进入 09 对外端口，也不进入组装。`ingest_batch` 只在事件闭环时落位；`unclosed_count` 反映缓冲规模。

### 3.5 遗忘与记忆恢复

遗忘是降低、限制或停止某些内容的可见性，不等于删除原文。当前通过 `memory_status`（sealed / suppressed）表达；recall 不新增记录、不登记 recall_log，但被召回的记忆强化遗忘因子（回忆加强记忆，符合常理）。

## 4. 接口契约

`MemoryBackendPort` 是主流程依赖的唯一稳定端口；`consolidate` / `dream` 为后台接口（占位）。详细字段以《记忆层契约》为准，本节约其形状。

```text
MemoryBackendPort:
  ingest_batch(batch: MemoryBatch) -> BackendIngestResult
  recall(subject_id, query, *, object_id=None, level=1, limit=None, anchor_event_ids=())
      -> tuple[RecalledFragment, ...]
  consolidate(subject_id, *, budget=None, cursor=None)   # 占位
  dream(subject_id, *, object_id=None, budget=None)      # 占位
```

回忆策略快照在 **09 薄壳**，不进 `MemoryBackendPort`（避免强迫后端改契约）：

```text
RecallStrategyStore
  get(subject_id) -> RecallStrategy
  apply(subject_id, strategy, *, source_report_id)
```

`RecallStrategy` 最小字段：`default_level`（1–9，即强度）、`limit`（可选）。无快照时 03 传 `level=1`。`apply` 只影响后续 `recall` 的入参，带 `source_report_id`。由有效性分析系统写入；05 不写。后端 `recall` 形状不变。

```python
class MemoryExperience:
    subject_id: str
    text: str                          # 经历原文（多轮可整段进入，不切分、不改写）
    objects: dict[str, str] = {}       # 对象映射表：名字/称呼 → 01 object_id（含没说话的）
    source_ids: tuple[str, ...] = ()   # 来源链，必带
    occurred_at: datetime | None = None
    segment_id: str | None = None      # 30 侧经历段 id，用于 stored_marks 回填
    origin: str = "external"           # external | internal | dream

class MemoryBatch:
    subject_id: str
    experiences: tuple[MemoryExperience, ...]  # 有序：对话 / 经历先后顺序

class BackendIngestResult:
    subject_id: str
    stored_marks: dict[str, list[str]] # segment_id -> 本轮封存事件 id 列表（封存几个填几个）
    sealed_event_ids: list[str]
    role_ids: list[str] = []           # 本轮登记/更新的 01 对象，可为空
    unclosed_count: int = 0
    errors: list[str] = []             # 非致命错误
```

`RecalledFragment` 至少包含：`event_id`、`text`（原文，溯源）、`content`（按 `summary_level` 选出的摘要文本，供预算 / 组装）、`kind`、`object_id`、`source_ids`、`score`、`summary_level`。

### 4.0 后端对象约束

`MemoryBackendPort` 不得新建角色系统或对象系统：

- 后端只接收 01 已解析的 `object_ids`；
- 检测到文本中出现新对象时，只保持原样或返回候选；对象创建、暂定、确认、拒绝、载体关联全部归 01；
- 后端内部不持久化独立 `role_id`；`subject_id` 永远不是 `object_id`。

## 5. 行为规则与核心功能要求

1. 原文保全：`content_raw` 永不改写，追加可追溯；
2. 对象统一：所有记忆单元与召回都使用 01 的 `object_id`，不另建角色系统；
3. 主体归属：所有记忆单元必须带 `subject_id`，来源链可追溯到活动与经历段；
4. 无抽象事件：不做频繁子集挖掘、ASF、`source_events`、抽象合成；
5. 事件闭环归后端内部：05 只产出认知，不产出「未完成 / 闭环事件」；07 不处理事件；
6. 召回只读 + 记忆恢复：不新增记忆单元、不登记 recall_log；强化遗忘因子是唯一写操作；
7. 遗忘只降可见性，不物理删除原文；
8. 失败隔离：单次 ingest / recall 失败不污染历史、承诺或个人世界；批次内逐 input 隔离，单个失败进 `errors`；
9. 可替换：进程内最小实现与 REMS3 fork 实现同一端口，替换后主体框架行为不变。

## 6. 数据结构（逻辑）

### 6.1 记忆单元

| 字段 | 说明 |
|------|------|
| `memory_event_id` | 记忆单元稳定标识 |
| `subject_id` | 归属匠石，恒在 |
| `object_ids` | 01 对象标识集合（可为空 = 主体记忆） |
| `content_raw` | 事实原文（含名字；不归一化、不改写） |
| `summaries` | 多级摘要（至少 L1 可用，稳定后再扩展） |
| `source_ids` | 来源链 |
| `occurred_at` | 发生时间（`create_time` 保留为摄入时间） |
| `origin` | external / internal / dream（字符串，保留扩展） |
| `emotion` | 事件级主体情感（8 维 + arousal / valence；对象无情感） |
| `memory_status` | sealed / suppressed（遗忘只降可见性） |
| `segment_id` | 30 侧经历段 id（stored_marks 台账用） |

### 6.2 对象记忆时间线

| 字段 | 说明 |
|------|------|
| `object_id` | 01 对象标识 |
| `name` | 呈现用名字（与输入映射表一致） |
| `event_id` | 关联记忆单元 |
| `summary` | 该对象在本事件中的一句摘要快照 |
| `occurred_at` | 发生时间 |

无情感、无遗忘因子（遗忘在记忆单元层）。

### 6.3 stored_marks 台账

`segment_id → 本轮封存事件 id 列表`；纯台账，不含游标状态（30 侧凭它自维护 `memory_start`）。

## 7. 与 03 / 05 / 07 / 30 的边界

- 03 通过 `MemorySource` 透传 `recall`，不内嵌记忆检索规则；阶段③ 使用当前策略快照的档位（无快照则最低档），按说话人 `object_id` 过滤；活跃区不作为记忆查询基准；展示名由 03 用 01 档案 join；
- 05 产出回应；不同轮补召回、不调 `recall`；记忆打分入库给有效性分析；
- 07 收尾后由编排层调 30；30 构造 `MemoryBatch`（按经历段映射 `MemoryExperience`，`origin` 分型）并调用 `ingest_batch`；09 确认接管后 30 凭 `stored_marks` 推进 `memory_start`；
- 未完成事件 / 残影是后端内部缓冲，不跨端口暴露；主链路不接触。

## 9. 验收标准

- `MemoryBackendPort` 四步接口齐全，主流程只依赖端口；
- 记忆单元带 `subject_id`，对象复用 01 `object_id`，来源可追溯；
- `ingest_batch` 批次可投递：主体记忆（`objects` 空）与对象映射表（与是否说话无关）均正确；`stored_marks` 列表与 `segment_id` 一一对应；批次内失败隔离（Jshi_memory 侧已由 `tests/unit/test_ingest_batch.py` 覆盖）；
- `recall` 只读 + 记忆恢复；对象过滤正确，档位映射可验证，显式 `limit` 可覆盖；
- 不产生抽象事件，不维护独立角色系统；原文不改写，遗忘不删原文；
- 进程内实现可替换为 REMS3 fork 后端，主体框架行为不变；后端替换不改变薄壳端口。
