## 1. 定位

记忆是匠石的**稳定核心能力**之一：让过去以可追溯、受预算约束的方式参与当前活动，并支撑连续性。它的实现是独立、可替换的模块（当前进程内最小实现；REMS3 瘦身版 fork 已在 `C:\Users\40575\Desktop\prog\Jshi_memory` 独立开发中），但记忆内容、来源和行为始终归属于匠石主体框架。

实现上，09 是**记忆薄壳**：稳定 `MemoryPort` 并负责输入输出适配；边界检测、封存、残影、未完成事件、召回排序、遗忘等内部代谢全部委托给后端。

关键边界：

- 记忆 ≠ 个人世界：记忆保存可核查的原文与来源，个人世界保存长期判断、价值与承诺（见 08）；
- 记忆 ≠ 事件生命周期：事件是「未了结 / 已了结的事」（07），记忆是围绕这些经历的原文与线索组织（09）；
- 记忆原文 ≠ 解释层：摘要、关系认识与自我叙事属于解释层，可重新生成，旧版本与来源必须保留；
- 插件只是实现：记忆插件可以进程内或进程外，但必须满足 §4 的端口与 §5 的核心功能要求，不拥有主体状态的最终写入权。

## 2. 职责与边界

### 2.1 09 做什么

- 定义并稳定四步记忆端口：存储 / 回忆 / 整理 / 做梦，作为薄壳对后端做适配；
- `ingest_activity` 负责把活动经历做**事件闭环**并落位为记忆单元（05 不再负责事件闭环）；
- 召回按对象过滤、近因优先、词重叠加权，支持 1–9 档位与预算；
- 整理是后台过程，只产出候选，不覆盖原文；
- 做梦是无外部输入时的内部联想接口，本期占位；
- 所有记忆单元带 `subject_id`，对象复用 01 的 `object_id`，来源链可追溯。

### 2.2 09 不做什么

- 不触发抽象事件，抽象事件相关（`source_events`、频繁子集挖掘、ASF、insight）一律不实现；
- 不维护独立角色系统，对象系统与 01 统一；
- 不决定主体面是否了结（归 07 / 02）；
- 不管理认识状态与状态迁移（06）；
- 不静默改写事实原文，不物理删除原文（遗忘只降可见性）。

### 2.3 记忆来源与主体记忆

- **记忆来源唯一**：匠石长期记忆的写入只经 30 投递（外部活动经历）与未来内部路径（反思等，占位）；任何模块不得直接写记忆后端。
- **主体记忆合法**：经历可以没有外部对象（如看到落日、内心感触、反思），此时 `object_ids` 为空，归属仍由 `subject_id` 保证；封存时事件角色列表可只含主体。30 批次允许 `object_ids` 为空，不因无对象阻断投递。
- **反思与记忆分开**：反思是内部活动，目前占位、不自动沉淀为长期记忆；未来反思沉淀走内部投递路径，同样可为主体记忆，须显式实现后再放开。

## 3. 概念

### 3.1 记忆单元（MemoryEvent，已封存）

已闭环事件落位后的最小记忆单位。它是具体的事实记录，不是抽象事件。

### 3.2 对象记忆时间线（ObjectMemoryEntry）

按 01 的 `object_id` 组织同一对象在多次事件中的摘要快照，支撑对象过滤召回与对象状态装载。

### 3.3 回忆档位（1–9）

| 档位 | 语义 | 返回片段上限（占位） |
|------|------|----------------------|
| 1–3 | 线索级：少而浅 | 3 |
| 4–6 | 情境级：中等上下文 | 5 |
| 7–9 | 深挖级：更多上下文 | 8 |

- 阶段③ 使用最低可用档（默认 1）；
- 阶段⑤ 的追加召回可由模型请求指定更高档位；
- `limit` 是硬上限，可覆盖档位推导；具体映射由 09 定义。

### 3.4 未完成事件

未完成事件是主体面的工作缓冲，由 05 / 07 维护，**不进入 09 长期记忆存储**；09 的 `ingest_activity` 只在事件闭环时落位。

### 3.5 遗忘

遗忘是降低、限制或停止某些内容的可用性，不等于无记录删除。当前最小实现不执行删除；未来通过 `memory_status`（sealed / suppressed）表达可用性变化。

## 4. 接口契约

`MemoryPort` 是主流程依赖的唯一稳定端口，四步接口如下：

```text
ingest_activity(subject_id, object_id, text, *, source_ids, occurred_at=None, activity_id=None)
    -> MemoryIngestResult

recall(subject_id, query, *, object_id=None, level=1, limit=None, anchor_event_ids=())
    -> tuple[RecalledFragment, ...]

consolidate(subject_id, *, budget=None, cursor=None)
    -> ConsolidationReport

dream(subject_id, *, object_id=None, budget=None)
    -> DreamResult
```

### 4.0 后端对象约束

`MemoryBackendPort` 不得新建角色系统或对象系统。

- 后端只接收 01 已解析的 `object_ids`；
- 检测到文本中出现新对象时，只返回 `unresolved_object_refs` 候选；
- 对象创建、暂定、确认、拒绝、载体关联全部归 01；
- 后端内部不得持久化独立 `role_id`；
- `subject_id` 永远不是 `object_id`。

后端接口形状：

```text
MemoryBackendPort.ingest(batch: MemoryBatch)
    -> BackendIngestResult

MemoryBackendPort.recall(request: BackendRecallRequest)
    -> BackendRecallResult
```

其中 `MemoryBatch.object_ids` 必须来自 01。`MemoryBatch.object_sources`（对象 id → 经历段 id）随 16 的经历段透传，09 不得另建对象体系。

### 4.1 存储 / 事件闭环

`ingest_activity` 接收一次外部活动的经历，内部完成边界检测与封存，返回新封存的记忆单元。

入参：

- `subject_id`：归属匠石；
- `object_id`：来自 01 的对象标识；
- `text`：01 归一化后的经历文本（名字 / 称呼 /「我」已替换为 id；未识别部分保留原文；原始文本在事实历史，经 `source_ids` 关联）；
- `source_ids`：活动 / 认知内容 / 事实的来源链；
- `occurred_at`：发生时间（默认落位时间）；
- `activity_id`：活动锚点（可选）。

出参 `MemoryIngestResult`：

- `sealed_events`：本轮封存的记忆单元；
- `stored_marks`：事件 id → memory_event_id 的已存标记，供 07 / 02 回填。

未完成事件只作为本次处理的工作缓冲，不在出参中长期暴露。

### 4.2 回忆

`recall` 只读已有记忆，按对象过滤、档位与预算返回片段。

- `query`：查询文字；
- `object_id`：对象过滤（可空，空则跨对象）；
- `level`：1–9 档位；
- `limit`：显式上限，未给时按 `level` 推导；
- `anchor_event_ids`：事件锚点（预留，本期记录但不参与过滤）。

`RecalledFragment` 至少包含：`event_id`、`text`、`kind`、`object_id`、`source_ids`、`score`、`summary_level`。

### 4.3 整理

`consolidate` 是后台整理入口，只产出候选摘要 / 关系 / 封存建议，不覆盖原文、不生成抽象事件。返回 `ConsolidationReport`，写入由后续明确流程执行。

### 4.4 做梦

`dream` 是内部活动接口，占位。输出属于「想象 / 考虑中」内容，带来源，默认不写入长期记忆；若未来保留，须标记来源为内部活动，不进入抽象统计。

## 5. 行为规则与核心功能要求

1. 原文保全：`content_raw` 永不改写，追加可追溯；
2. 对象统一：所有记忆单元与召回都使用 01 的 `object_id`，不另建角色系统；
3. 主体归属：所有记忆单元必须带 `subject_id`，来源链可追溯到活动与认知内容；
4. 记忆面 / 主体面分开：记忆封存不等于主体面了结；
5. 事件闭环归 09：05 只产出认知，不再产出「未完成 / 闭环事件」；
6. 召回只读，不写长期记录；
7. 遗忘只降可见性，不物理删除原文；
8. 失败隔离：单次记忆操作失败不污染历史、承诺或个人世界；
9. 可替换：进程内最小实现与 fork REMS3 后端实现同一端口，替换后主体框架行为不变。

## 6. 数据结构

### 6.1 记忆单元（逻辑）

| 字段 | 说明 |
|------|------|
| `memory_event_id` | 记忆单元稳定标识 |
| `subject_id` | 归属匠石 |
| `object_ids` | 01 对象标识集合 |
| `content_raw` | 归一化文本（01 产出；原始文本在事实历史，展示名由 03 用 01 档案回填） |
| `summaries` | 先 L1 单层，稳定后再扩展 L1..Ln |
| `source_ids` | 来源链 |
| `activity_id` | 活动锚点 |
| `occurred_at` | 发生时间 |
| `memory_status` | sealed / suppressed |

### 6.2 对象记忆时间线（逻辑）

| 字段 | 说明 |
|------|------|
| `object_id` | 01 对象标识 |
| `memory_event_id` | 关联记忆单元 |
| `snapshot` | 该对象在本事件中的一句摘要 |
| `occurred_at` | 发生时间 |

当前最小实现可先沿用事实历史与个人内容表；fork REMS3 后端接入时再落独立记忆表，并做数据迁移。

## 7. 与 03 / 05 / 07 的边界

- 03 通过 `MemorySource` 透传 `recall`，不内嵌记忆检索规则；03 把 09 返回的归一化片段回填名字后进模型（见 03 §3.5）；
- 03 阶段③ 使用最低档，按说话人 `object_id` 过滤；活跃区不作为记忆查询基准；
- 05 只产出回应、追加召回、对象确认；追加召回把 `level` / `object_ids` / `anchor_event_ids` / `budget` 透传给 09；
- 05 不再负责事件闭环；阶段⑦ 收尾时由主流程调用 `memory.ingest_activity(...)`；
- 07 负责数据管控：何时投递、上次是否完成、数据是否足够、游标推进与重试；09 薄壳及后端负责记忆内部代谢；
- 09 的整理与做梦属于后台 / 内部活动，不阻塞正常活动。

## 8. 占位与未来

本期实现（端口 + 最小进程内实现）：

- 稳定 `MemoryPort` 四步接口；
- `InProcessMemoryBackend`：事实历史 + 词检索 + 对象过滤 + 档位；
- `MemorySource` 透传 `recall`；
- `ingest_activity` 先以最小封存逻辑落位，不做真实边界检测；
- 整理与做梦先返回占位结果。

未来接入：

- fork REMS3 瘦身版作为 `Rems3MemoryBackend`；
- 去除抽象事件、ASF、频繁子集挖掘、独立角色系统；
- 把 `role_id` 映射替换为 01 的 `object_id`；
- 真实边界检测 / 80-20 分裂 / 未完成工作缓冲（若需要）；
- 摘要层级、遗忘因子、向量检索与独立记忆表。

## 9. 验收标准

- `MemoryPort` 四步接口齐全，主流程只依赖端口；
- 记忆单元带 `subject_id`，对象复用 01 `object_id`，来源可追溯；
- 05 不再产出事件闭环，`ingest_activity` 能完成落位；
- 对象过滤正确，档位映射可验证，显式 `limit` 可覆盖；
- 不产生抽象事件，不维护独立角色系统；
- 召回只读，原文不改写，遗忘不删原文；
- 进程内实现可替换为 fork REMS3 后端，主体框架行为不变；后端替换不改变薄壳端口。

## 10. 与其他模块的关系

- 依赖：00（输入信封与对象标识）、01（对象标识）、05（追加召回需求）、07（主体面事件状态）；
- 被依赖：03（初始记忆线索装载）、05（追加召回）、02（未来被剔除事件落位）、14（统计与调参）；
- 概念边界：记忆 ≠ 个人世界；记忆原文 ≠ 解释层；召回 ≠ 认识状态迁移；记忆封存 ≠ 主体面了结。

- 新增记忆后端只需实现 `MemoryPort`；
