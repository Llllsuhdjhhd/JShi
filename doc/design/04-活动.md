# 04 活动（Activity）

> 模块文档。术语以《概念词汇》为准，流程位置见《00 流程总览与输入边界》阶段④。
>
> 状态：定稿骨架。活动是一轮工作单元；`wait` 是回复方式，不是活动状态。

## 1. 定位

活动是一次从建立到收尾的工作单元：接受触发，带着本轮工作集走认知与行动，由 07 关闭。

下一轮外部输入建立**新活动**。连续性靠 16 的既往视图和历史记录，不靠把同一条活动挂起。

## 2. 职责

04 只做：

- 建立活动；
- 保存活动状态，并留下状态迁移审计；
- 关联触发来源（`trigger`）与来源链。

关闭由 07 执行；06 把 `response_plan` 标到活动上。04 提供字段，不负责生成回应、不负责收尾判断。

04 不做：认知内容、状态组装、行动分发、记忆投递。意图系统占位（`intention_ids`）。

## 3. 状态

```text
open → completed | abandoned
```

- `open`：已建立、尚未收尾；
- `completed`：07 正常关闭。`response_plan.mode` 为 `respond` / `think` / `ignore` / `wait` 均如此；
- `abandoned`：中途放弃（占位，当前主链路不用）。

`wait` 属于 06 的回复方式，**不是**活动状态。不要把活动停在等待，下一轮再接着跑同一条记录。

## 4. 接口

```text
Activity
  subject_id
  kind              # external | internal
  trigger           # 本轮触发的事实 id
  status            # open | completed | abandoned
  response_statuses # 由 06 写入，04 只保存
  intention_ids     # 占位
  id
  created_at
  updated_at
```

`kind=internal` 供反思等内部入口，当前占位。

## 5. 记录与验收

- 记录：`activity_created`；状态迁移由 07 在收尾时审计；
- 外部活动能建立、运行、由 07 关闭为 `completed`；
- 状态迁移可追溯；
- 下一轮输入创建新活动，不复用已关闭的活动 id。

## 6. 与其他模块的关系

- 依赖：00 入口与触发事实；
- 被依赖：05（`activity_id`）、06（标记回复）、07（关闭）、10（按已标记的计划分发）。
