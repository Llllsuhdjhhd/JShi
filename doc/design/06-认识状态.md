# 06 活动状态标示

> 模块文档。术语以《概念词汇》为准，流程位置见《00 流程总览与输入边界》阶段⑤ 之后、⑥ 之前。
>
> 状态：定稿。文件名仍为「认识状态」，本模块契约是活动回复标记（D-005）。原认识状态机暂缓，现有 `EpistemicStatus` 不是本模块契约。

## 1. 定位

06 只做一件事：校验本轮 `response_plan`，把合法的回复状态标到活动上，并留下审计。

它不生成回应，不判断认知是否值得采信，也不碰本轮上下文、活跃区或记忆。

明确不做：

- 不读、不执行 `object_assessment`、`context_assessment`、`memory_ratings`。这些条目不经 06。缩减/聚焦由 16 在 10 之后执行（补丁可空）。05 不同轮补召回。
- 不写经历段（`subject_reply` / `subject_state` 由 10 写入）。
- 不读取、不改写 16 的活跃区。
- 不投递记忆（07 → 30）。
- 不改活动生命周期：`wait` 只是回复方式，不把活动挂起。关闭由 07 执行。

## 2. 回复计划

05 输出一份 `response_plan`。06 只消费这三项：

| 字段 | 含义 |
|------|------|
| `mode` | `respond` / `think` / `ignore` / `wait`：本轮如何对外 |
| `reason` | 推荐理由，供审计与人工覆盖 |
| `items` | 通道列表：`verbal`（语言）或 `embodied`（肢体），各带 `text` |

- `think`：本轮不对外说（对外没有该发生的交往行为）；活动仍结束。
- `ignore`：本轮明确不给位置；活动仍结束。
- `wait`：本轮等后续输入或外部结果，**不是**让模型继续想（那是 `think`），也**不是**用沉默顶该说的那句话（该说则 `respond`）。活动仍结束。下一轮外部输入创建**新活动**，靠 16 保存的活跃区与历史接上。

mode × channel 约束：

| mode | verbal | embodied |
|------|--------|----------|
| respond | ✅ | ✅ |
| think | ❌ | ✅ |
| ignore | ❌ | ✅ |
| wait | ❌ | ✅ |

- `respond`：`items` 至少一个；`reason` 可空。
- `think` / `ignore` / `wait`：无 `verbal`；`reason` 必填；`embodied` 可选。

06 校验上述组合；未知值与非法组合忽略并记录。当前把 `mode` 与各合法 `items.channel` 展平写入 `Activity.response_statuses`，完整计划写入审计。

## 3. 与相邻模块的分工

1. 05 产出 `response_plan`（以及对象确认、召回请求、缩减/聚焦方案）。后三者不交给 06。
2. 06 校验 `mode` 与 `channel`，标记活动，记录 `activity_response_state`。
3. 10 仅在有合法 `verbal` 时落 `language_action`；`think` / `ignore` / `wait` 不说话，但仍可按 item 触发 embodied 接口。
4. 16 在 10 之后按方案编新活跃区；07 关闭活动；30 投递记忆。

标记发生在 05 给出最终计划之后、10 分发之前。

## 4. 行为规则

- `response_plan` 是候选推荐；
- 未知 mode/channel、以及静默 mode 带 `verbal`，忽略并记录；
- `respond` 无 item、静默 mode 无 `reason`，仍标记合法字段，并在审计里记下缺失；
- 校验后把最终状态标到活动，并记录来源、理由与 items；
- 保留人工介入点 `06-response-status`（默认自动）：人工可确认、修改或否决；覆盖时记录前因后果；人工给出的未知值与非法组合同样忽略；
- 不生成回应内容，不判断回应质量，不改活动生命周期。

## 5. 接口契约

输入：

- `activity_id`：目标活动；
- `response_plan`：`mode` / `reason` / `items`；
- `human_override`：可选人工最终状态（tuple[str]）。

输出：更新后的 `Activity` + 审计记录。

数据落点：

- `Activity.response_statuses: tuple[str, ...]`（mode 与 channel 的扁平多选，默认空）；
- 主体历史 `activity_response_state`：activity_id、recommended、final、reason、items、unknown、illegal、缺失标记、source（model_recommended / human_overridden）；
- 人工覆盖时另记 `intervention_record`（15 占位）。

## 6. 记录、评价与参数

- 记录：`activity_response_state`；人工覆盖时 `intervention_record / intervention_summary`（15 占位）；
- 评价：状态命中率、模型推荐与人工最终状态的差异率、wait 比例等，供 14 统计（旁路，不进入主流程）；
- 参数：mode 与 channel 枚举当前固定；人工介入点 `06-response-status` 开关（默认自动）。

## 7. 占位与未来

- 人工介入开关执行（15 未实现，本期占位）；
- `embodied` 实际触发机器人动作（13 形态未实现）；
- 若将来要把 `wait` 做成「同一活动暂停、下次输入恢复」，须改 04 生命周期并写决策记录；本期不采用；
- 活动上是否改为直接保存 `response_plan` 而不展平（待验证）；
- 未来可扩展新 mode（如 refuse），本期不引入。

## 8. 验收标准

- 模型输出 `response_plan` 后，06 只标记合法 mode/channel 与合法组合，未知值与非法组合忽略并记录；
- 活动上可读回 `response_statuses`，审计可读回完整计划；
- 人工覆盖后最终状态与来源可追溯；
- 06 不生成回应、不写经历、不改活跃区、不投递记忆、不改变活动生命周期。

## 9. 与其他模块的关系

- 依赖：04（活动字段）、05（`response_plan`）；
- 被依赖：10（按已标记的计划分发）、13（未来形态执行）、14（统计）；
- 与 15 合作：人工介入点统一登记；
- 概念边界：回复状态 ≠ 活动生命周期；06 标记 ≠ 认识状态机。06 也不负责经历、活跃区或记忆。

## 10. 待验证问题

- `wait` 是否改为同一活动挂起再恢复（须先有明确恢复入口）；
- `think` 是否需要与反思续接（不在 06 补做召回；05 已取消同轮补召回）；
- mode 与 channel 展平到同一列表是否足够清晰；
- 人工介入点默认自动是否合适。
