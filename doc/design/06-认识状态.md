# 06 认识状态

> 模块文档。术语以《概念词汇》为准，流程位置见《00 流程总览与输入边界》阶段⑤ 之后。
>
> 状态：初稿，待讨论定稿。本文只用文字与表格描述契约，不出现实现代码。

## 1. 定位

本模块回答：**匠石对某项认知内容持什么态度，以及这种态度如何合法地变化**。

认知内容（推断、评价、想象等）产生后属于匠石，但**不等于匠石已经相信或愿意据此行动**。认识状态记录"这项内容处于什么地位"，并通过有理由、有审计的迁移，让认知内容逐步成为立场或事实判断。

关键原则：**状态变化必须显式发生**，不能由模型输出静默改变；每次迁移有理由、有来源、可追溯。

## 2. 状态集合

| 状态 | 含义 | 说明 |
|------|------|------|
| 出现 | 内容刚产生 | 初始态之一（预留） |
| 考虑中 | 正在权衡，尚未采信 | 模型推断、评价的默认初始态 |
| 暂时接受 | 证据有限，先接受使用 | 可据此进行有限行动，随时可修正 |
| 接受 | 证据充分，可据此行动 | 进入后续判断与行动的可靠依据 |
| 拒绝 | 证据否定或判定错误 | 终态，不再恢复 |
| 搁置 | 暂不处理，可恢复 | 挂起但保留来源 |
| 修正 | 被新理解替代 | 终态，原始内容保留、新内容另行记录 |

感知（已接受的他人报告）是特例：它产生即已接受，不经过考虑中。

## 3. 状态迁移表

| 从 \ 到 | 考虑中 | 暂时接受 | 接受 | 拒绝 | 搁置 | 修正 |
|---------|--------|----------|------|------|------|------|
| 出现 | ✓ | | | ✓ | ✓ | |
| 考虑中 | | ✓ | ✓ | ✓ | ✓ | |
| 暂时接受 | | | ✓ | ✓ | ✓ | ✓ |
| 接受 | | | | ✓ | | ✓ |
| 搁置 | ✓ | ✓ | | ✓ | | |
| 拒绝 / 修正 | | | | | | |

规则：

- 拒绝、修正为终态：一旦进入不再迁出（新证据产生新内容，不复活旧内容）；
- 搁置可恢复（回到考虑中或暂时接受），也可直接拒绝；
- 接受只能被拒绝或修正，不能被搁置；
- 迁移必须带理由与来源，写审计；无理由迁移视为无效。

## 4. 行为规则

1. 认知内容产生时，初始状态按种类确定：感知 = 已接受；推断、评价、想象 = 考虑中；反思输出 = 考虑中；
2. 每次迁移由显式操作触发（程序接口），迁移前校验来源状态，非法迁移拒绝；
3. 每次迁移写两条记录：状态迁移审计（transitions）与主体历史 `epistemic_transition`（含内容标识、前后状态、理由、来源）；
4. 修正不改写原始内容：被修正的内容保留原貌，新理解作为新内容记录，通过迁移建立关系；
5. 模型输出不自动改变状态：模型只能提议（未来），程序按状态机执行，人工介入点可确认（15）；
6. 状态影响使用：已接受或暂时接受的内容才可作为行动依据；考虑中内容只作背景（03 认识状态源未来装载已接受/暂定认知）；
7. 状态不因时间自动变化（自动搁置/归档为未来策略，见 §8）。

## 5. 接口契约（文字描述）

### 5.1 对外能力

- 查询内容当前状态；
- 执行状态迁移：给定内容标识、目标状态、理由、来源，校验合法后执行并审计；
- 查询某内容的状态迁移史；
- 列出处于某状态的内容（未来，供 03 装载）。

### 5.2 迁移校验

- 目标状态必须属于来源状态允许的迁移集合；
- 理由必填；
- 来源可选但推荐（迁移依据的事实/认知内容）。

## 6. 记录、评价与参数

- 记录：`epistemic_transition`（内容标识、from、to、reason、来源）、transitions 审计表；
- 评价：迁移合理性（理由是否充分）、滞留时间（考虑中内容长期未迁移的时长）、迁移来源覆盖率；由 14 统计；
- 参数：未来可调——自动搁置阈值（考虑中内容多久未处理自动搁置）、批量迁移策略；调整由 14 统一执行并留审计；
- 人工介入点：`06-transition`（状态迁移需人工确认时，见 15 登记表，默认自动）。

## 8. 验收标准

- 非法迁移被拒绝（如接受 → 搁置、终态迁出）；
- 每次合法迁移有理由、来源与审计记录，可追溯；
- 修正不覆盖原始内容；
- 感知初始已接受、推断初始考虑中；
- 模型输出不静默改变状态；
- 状态查询与迁移史可读。

## 9. 与其他模块的关系

- 依赖：05（认知内容）、15（人工介入确认，未来）；
- 被依赖：03（认识状态源，未来）、10（行动依据：接受/暂定才可行动）、11（治理检验状态一致性）、14（统计）；
- 概念边界：认识状态 ≠ 事实真相；内容被修正 ≠ 旧内容从未发生；状态迁移 ≠ 历史改写。

## 10. 扩展性预留

- 新增状态需同步迁移表与初始态规则；
- 批量迁移接口（后台整理）；
- 状态持久化与版本迁移；
- 迁移建议的结构化协议（模型提议 + 程序执行）。

## 11. 待验证问题

1. 状态粒度是否足够（是否需要"部分接受 / 条件接受"等中间态）；
2. 谁有权提议迁移（模型 / 治理 / 人工），提议的优先级与冲突处理；
3. 自动搁置阈值是否引入，以及搁置内容的再唤醒路径；
4. 已接受内容被修正时，行动历史是否需联动标记。
