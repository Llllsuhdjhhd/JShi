# 100 价值观与边界

> 状态：初稿。
> 本文定义个人世界中的稳定核心子模块：价值观与行为边界的来源、状态迁移、装载预算和后台整理。个人世界的通用条目模型与装载总览见 `08 个人世界`。

## 1. 定位

价值观和边界不能只保存“诚实”“尊重”这类抽象名词。抽象名词属于解释层；实例才携带来源、情境、重要程度和可追溯的变化。

本模块回答：

1. 价值观与边界有哪些来源，新增路径如何被审计；
2. 哪些内容可以进入当前活动，且不超出上下文预算；
3. 数量增多后，后台如何在不覆盖原始实例的前提下整理和沉淀。

## 2. 实例而非抽象标签

每条记录应表达一个可观察、可引用的判断或行为：

- 价值观实例：说明在某个情境下更看重什么、为什么；
- 边界实例：说明某个情境下即使结果更好也不采用的手段或行为。

示例：

- 对待朋友：与朋友交，言而有信。
- 对待自然：不因一时便利破坏不可逆的自然环境。
- 经典小说实例：建立联系后，要对彼此负责。

每个例子都保持短小，避免把整段故事塞入当前状态。

## 3. 来源

至少支持四类来源：

| 来源 | 说明 | 初始状态 |
|------|------|----------|
| `classic_work` | 经典著作中的行事准则，如朋友、恋人、家人、自然等主题 | 候选或已审核种子 |
| `classic_novel` | 经典小说中的具体实例 | 候选或已审核种子 |
| `model_proposal` | 大模型提出的原则 | 候选，不得直接成为稳定个人世界 |
| `human_intervention` | 人工介入提供的原则 | 当前开放；长期须进入加锁流程 |

未来可增加 `derived_experience`（从真实经历和反思中沉淀）和 `governance_review`（治理审核后写入）。

## 4. 内容字段

建议每条价值观 / 边界实例至少携带：

- `id`、`subject_id`、`kind`；
- `role`：`value` 或 `boundary`；
- `content`：短实例文本；
- `source_type`、`source_id`；
- `domains`：如 `friend`、`romantic`、`family`、`nature`、`self`、`public`；
- `context_tags`：触发装载的场景标签；
- `importance`：长期重要程度；
- `status`：`candidate`、`accepted`、`locked`、`superseded`、`rejected`；
- `revision`、`created_at`、`updated_at`；
- `provenance` 或来源链，说明它依据哪个原文、模型判断或人工决定。

`boundary` 条目除上述字段外，还应标记 `binding=true`，表示需要常驻约束或强制执行边界检查。

## 5. 接口契约

### 5.1 装载接口

由 `08 个人世界` 的装载总览调用本模块：

- `select_values(subject_id, context, *, budget)`：按情境相关性和重要程度选择普通价值观；
- `select_boundaries(subject_id)`：返回不可越过边界，供行动前检查；
- `standing_constraints(subject_id)`：由 08 汇总承诺、主体面未完成现实和 `binding` 边界。

边界条目优先于普通价值装载，不因普通价值预算耗尽而被挤掉。

### 5.2 写入接口

新增窄写入能力：

```text
propose_value(subject_id, instance, source) -> candidate
review_value(instance_id, decision, reason, reviewer) -> accepted/rejected
lock_value(instance_id, reason, approver) -> locked
supersede_value(instance_id, replacement_id, reason) -> superseded
```

这些能力只产生或迁移状态，不在主活动链路中自动调用。

### 5.3 整理接口

新增后台整理能力：

```text
consolidate(subject_id, budget, cursor) -> consolidation_report
```

整理过程只读候选和已接受条目，输出候选合并建议、去重建议、升格建议或取代建议，最终写入仍走 `review_value` / `lock_value` / `supersede_value`。

## 6. 行为规则

### 6.1 来源与信任分层

- 经典著作和经典小说是高质量种子，但也不是天然不可修改；它们进入系统后仍保留原始来源和版本。
- 模型提出的原则默认是**候选**，必须经过来源、认识状态和治理条件后才能成为长期个人世界。
- 人工介入长期不能无限开放：
  - 当前实验阶段：`intervention_mode = open`，允许直接写入，但必须记录来源和理由；
  - 长期：`intervention_mode` 迁移为 `reviewed` / `locked`，人工新增需要审查或加锁；
  - `locked` 条目不得直接删除或改写，只能通过 `supersede` 显式替代，并保留理由。

### 6.2 装载与预算

价值观数量会持续增长，因此不能全量进入模型上下文：

1. 先取 `binding` 边界与常驻约束；
2. 再按 `domains` / `context_tags` 与当前输入的匹配度筛选候选；
3. 在同一匹配档内按 `importance` 排序；
4. 预算内截断，跳过项进入装载报告。

预算由 `14 统计分析与参数调优` 管理，当前基线可设置：普通价值预算默认 4 条，边界常驻不受该预算限制。

### 6.3 后台整理

后台在空闲时执行 `consolidate`：

- 按 `domains` 分组，识别重复、冲突和过于抽象的表达；
- 合并相同实例，保留最早来源和所有来源链；
- 对长期未使用但高重要的价值，降低或提高 `importance` 只通过明确状态迁移，不悄悄修改；
- 输出建议，不自动覆盖原始实例；
- 每次整理写 `value_consolidation_run`，记录运行时间、输入条目数、建议类型和预算；
- 整理必须幂等，可从 `cursor` 续跑，避免重复合并。

整理结果的最终写入遵守 00 的稳定原则：原始来源不被覆盖，抽象总结只进入解释层，长期变化经过状态迁移。

## 7. 占位与未来

- 当前最小实现先扩展 `PersonalWorldPort`，价值观仍存于 `personal_items`，边界用 `metadata.role="boundary"` 表达；
- 未来可拆出 `src/jshi/personalworld/values.py`、`src/jshi/personalworld/consolidation.py`；
- 经典著作种子、模型候选和人工介入的导入器未来分别接在同一个 `ValueSourcePort` 下；
- 加锁机制未来与 `15 人工介入` 共用审批链，不在本模块单独造一套权限系统。

## 8. 验收标准

- 价值观实例可追溯到 `classic_work` / `classic_novel` / `model_proposal` / `human_intervention` 之一；
- 模型候选不会在主活动中自动成为长期价值；
- `boundary` 条目始终常驻，不因普通价值预算耗尽而消失；
- 人工介入记录来源、理由、审查人和加锁状态；
- 后台整理只产生建议，原始实例不被覆盖；
- 整理运行可重复、可续跑，并留下审计记录；
- 当前状态组装只读取已存在条目，不临时编造价值。

## 9. 与其他模块的关系

- 依赖 `00`：输入边界、正常活动与后台沉淀边界；
- 依赖 `08`：通过个人世界装载总览进入状态组装；
- 与 `09 记忆系统` 平行：记忆保原文与召回，价值观与边界保长期判断；
- 与 `11 治理与连续性` 合作：加锁、取代和边界冲突由治理校验；
- 与 `12 反思` 合作：反思输出候选价值，但不直接写入；
- 与 `14 统计分析与参数调优` 合作：普通价值预算、整理触发频率、上下文标签命中率由 14 调整；
- 与 `15 人工介入` 合作：人工写入、审查、加锁和取代都进入统一介入审计。

## 10. 记录、评价与参数影响

| 项目 | 内容 |
|------|------|
| 记录点 | `value_proposed`、`value_reviewed`、`value_locked`、`value_superseded`、`value_consolidation_run`、`value_selected` |
| 评价点 | 价值命中率、边界命中率、候选升格率、整理合并率、被跳过高价值条目比例 |
| 可调参数 | 普通价值预算（默认 4）、实例最大长度（默认 160 字符）、整理触发频率（未来）、人工介入模式（`open` / `reviewed` / `locked`） |

参数调整由 `14` 执行并保留 `parameter_adjusted` 审计。

## 11. 扩展性预留

- `ValueSourcePort` 允许新增来源而不改核心装载与整理逻辑；
- `metadata.role` 允许在现有 `PersonalItem` 上先做边界语义，后续再平滑迁移到独立 `PersonalKind.BOUNDARY`；
- `consolidate` 的 cursor 和报告结构为未来分布式或定时后台整理预留；
- 经典著作和经典小说导入只作为来源适配器，不占用主体稳定核心。
