# 16 经历账本

> 模块文档。术语以《概念词汇》为准。
>
> 状态：初稿（D-009）。保存原始经历，并保存 05 按当前风格整份重写的活跃区正文。账本落盘（与 `subject.sqlite3` 同库）；重启后 02 仍读上一份活跃区。批次构造已迁到 30（见《30 记忆数据管控》），16 只提供未投递经历段与游标，不让 09 自己分类。现场口径见《提示词风格与活跃区全改》。

## 1. 定位

16 保存原始经历，并维护当前活跃区。

它只负责：

- 追加经历；
- 保存原文与来源；
- 保存 05 交出的整份活跃区正文（不再调用模型、不再按段 id 拼装）；失败则保留上一份；
- 提供经历片段与当前活跃区给其他模块；
- 把经历段、待合并、当前活跃区、消费者游标与 30 台账落盘，进程结束不丢。未过 `memory_start` 的段仍在账本里，30 冲刷条件不变，不提前 ingest。

它不负责：

- 决定模型看哪些材料（那是 03 组装 + 05 重写）；
- 决定哪些经历进入记忆（30）；
- 判断事件边界；
- 创建对象；
- 封存记忆。

活跃区按**主体**一份，不按对象各存一份，不按风格包各存一份，也不在换说话人时整份切换。它是 05 按选中风格写好的现场正文，不是 08 / 09 / 账本的真源副本。现场里的原文不强保。重写只改活跃区，不删账本、不删记忆、不改个人世界档案。未投递段即使已不在活跃区，仍留在账本里供 30 取用。风格包切换是硬切，覆盖这一份正文。

## 2. 核心概念

### 2.1 ExperienceSegment

```text
ExperienceSegment
  segment_id
  sequence
  subject_id
  actor_kind              # external | subject | system
  output_kind             # external_input | subject_reply | subject_state | subject_silent | internal
  actor_object_id
  mentioned_object_ids
  text_raw
  objects                  # 对象映射表 { 名字/称呼 → object_id }，覆盖没说话的人；可空
  state_delta
  response_plan
  source_ids
  occurred_at
  status
```

新经历追加后进入待合并，不在追加当下改活跃区。进入现场以 05 整份重写为准，以免认知过程中改掉刚听见的话。

原文 `text_raw` 永不改写；`objects` 映射表由输入侧提供、随段透传（与是否说话无关）。记忆投递仍用原文，`object_ids` 由映射表值去重得到。活跃区正文按风格重写，不强保与 `text_raw` 一致。

### 2.2 活跃区

16 保存的是 05 交出的**整份现场正文**，不是段级引用列表，也不从原文重切。

```text
ContextViewState
  version
  context_text             # 权威：05 按当前风格重写的全文；超长截断后保存
  speaker_object_id        # 本轮说话人（程序侧，供审计；正文里按风格叙述）
  style_pack_id            # 写出这份正文时的风格包配置名（审计；不进提示词）
  last_applied_sequence
```

`segment_refs` / `recall_excerpts` / `focused_refs` 不再作为编排依据。读旧库若仍有这些字段，只当历史，不按补丁应用。

更新方式：

- 本轮新输入、若有的本轮回应先入账（原文），待合并只服务账本与 30，不自动拼进活跃区；
- 05 交出整份 `context_text`。16 保存并升 version。开口后若另交一份，覆盖已保存正文，供下一拍 02；
- 编排层不为现场再调主认知模型；
- `text_raw` 与 01 / 08 真源不因保存现场而改写；
- 正文为空或未交出：保留上一份活跃区，不清空；
- 超过 `active_window_chars` 时从正文末尾截断（程序硬上限）。05 应把现场写短；截断不按文采挑选；
- 下一轮 02 读的就是这份正文。

独立再评估与有效性分析不在本轮 16 主路径上等待。已无同轮补召回循环。

### 2.3 记忆游标与批次

记忆游标只属于 30。投递不影响活跃区。

交给 09 的批次由 30 构造：只取 `memory_start` 之后未投递的经历段，按段映射 `MemoryExperience` 并以 `origin` 分型。16 不打包、不分类，只提供 `list_experiences` 与游标。

### 2.4 对象来源

对象 id 只透传 01。对象来源随经历段流转，09 不得另建对象体系。

```text

```

`save_rewritten_context` 保存 05 正文并升 version。空正文或未调用：保持上一份。硬上限截断后写入。

旧名 `apply_context_assessment` 不再用于主链路。`allow_edit` 仅用于测试隔离，主链路为真。

注意：批次构造、`memory_start` 和投递台账属于 30，不属于 16。

## 5. 行为规则

1. 经历只追加，不改写；账本落盘，关进程再开仍是同一份；
2. 阶段② 读到的必须是上一轮编好的活跃区（空仅当从未编排或已复位）；
3. 原始文本永不删除；未投递段不因重启丢失；
4. 对象 id 只透传 01；活跃区记录 `speaker_object_id` 供审计，正文按风格叙述对象；
5. 重写只改活跃区正文，不改原始经历、不改 09 / 08 真源；
6. 记忆投递不改变经历账本与活跃区；不把活跃区当新经历；
7. 30 的游标推进必须是显式确认后的行为；
8. 归档只标记，不物理删除。

## 7. 验收标准

- 16 维护一份活跃区正文；落盘后新进程 02 读到同一份；
- 保存现场时不再调用模型、不再按段引用拼装；
- 空正文不清空上一份；
- 16 不执行记忆封存，不创建对象，不把活跃区交给 30；
- 原始经历不因现场重写而丢失；未投递段不因关进程丢失；
- 30 不重复投递同一段经历；对象来源链可追溯。
