# 16 经历账本

> 模块文档。术语以《概念词汇》为准。
>
> 状态：初稿。保存原始经历，并保存按 05 方案编好的活跃区。账本落盘（与 `subject.sqlite3` 同库）；重启后 02 仍读上一份活跃区。批次构造已迁到 30（见《30 记忆数据管控》），16 只提供未投递经历段与游标，不让 09 自己分类。

## 1. 定位

16 保存原始经历，并维护当前活跃区。

它只负责：

- 追加经历；
- 保存原文与来源；
- 按 05 的上下文补丁（删除段 / 删除回忆摘录 / 聚焦）编排并保存新活跃区（不再调用模型）；
- 提供经历片段与当前活跃区给其他模块；
- 把经历段、待合并、当前活跃区、消费者游标与 30 台账落盘，进程结束不丢。未过 `memory_start` 的段仍在账本里，30 冲刷条件不变，不提前 ingest。

它不负责：

- 决定模型看哪些材料（那是 03 组装 + 05 方案）；
- 决定哪些经历进入记忆（30）；
- 判断事件边界；
- 创建对象；
- 封存记忆。

活跃区按**主体**一份，不按对象各存一份，也不在换说话人时整份切换。活跃区是引用加现场正文，不是把 08 / 09 原文再存一份当真源。缩减只让条目离开活跃区，不删账本、不删记忆、不删个人世界。未投递段即使已不在活跃区，仍留在账本里供 30 取用。

## 2. 核心概念

### 2.1 ExperienceSegment

```text
ExperienceSegment
  segment_id
  sequence
  subject_id
  actor_kind              # external | subject | system
  output_kind             # external_input | subject_reply | subject_state | subject_silent | internal
  actor_object_id
  mentioned_object_ids
  text_raw
  objects                  # 对象映射表 { 名字/称呼 → object_id }，覆盖没说话的人；可空
  state_delta
  response_plan
  source_ids
  occurred_at
  status
```

新经历追加后进入待合并，不在追加当下改活跃区。并入发生在按 05 方案编排时，以免认知过程中裁掉刚听见的话。

原文 `text_raw` 永不改写；`objects` 映射表由输入侧提供、随段透传（与是否说话无关）。活跃区与上下文使用原文；记忆投递时 `object_ids` 由映射表值去重得到。

### 2.2 活跃区

16 保存的不是「每次从原文重切的窗口」，而是一份**段级引用列表**（整段进 / 整段出，不做句子级编辑）。

```text
ContextViewState
  version
  context_text             # 派生：按 segment_refs + recall_excerpts 渲染，不单独存储编辑状态
  segment_refs             # 有序：在场经历的段 id
  recall_excerpts          # ((memory:ref, text), ...) 仍在场的回忆摘录
  speaker_object_id        # 对象；删除不得拿掉
  focused_refs             # 段级聚焦引用
  last_applied_sequence
```

更新方式：

- 本轮新输入、若有的本轮回应先入账、待合并；
- 05 交出**补丁**（`context_assessment`：`remove` 删除段 / `drop_recall` 删除低价值回忆摘录 / `focus` 聚焦段）——只输出变更，不重写全文，省 token；
- 编排层不再调模型，16 `apply_context_assessment` 按补丁编排：合并待并入段 → 应用删除 / 聚焦 / 回忆摘录更新；
- 删除针对段 id 或 `memory:ref`，不做句子级定位；
- 对象、身份与常驻约束的引用不得被删除；
- 超过 `active_window_chars` 时由程序**物理硬上限**兜底：剔除最旧的非保护段（05 空方案时活跃区不会无限增长）；
- 下一轮 02 读的就是这份新活跃区。

追加召回循环期间不调用本接口做裁剪。

### 2.3 记忆游标与批次

记忆游标只属于 30。投递不影响活跃区。

交给 09 的批次由 30 构造：只取 `memory_start` 之后未投递的经历段，按段映射 `MemoryExperience` 并以 `origin` 分型。16 不打包、不分类，只提供 `list_experiences` 与游标。

### 2.4 对象来源

对象 id 只透传 01。对象来源随经历段流转，09 不得另建对象体系。

## 3. 与 02 / 05 / 30 的关系

## 4. 接口契约

```text
ExperienceLedgerPort
  append_external(...)
  append_subject_reply(...)
  append_subject_state(...)
  append_subject_silent(...)
  append_internal(...)

  current_context_view(...)
  apply_context_assessment(subject_id, assessment, *, recall_excerpts, speaker_object_id, protected_refs)

  list_experiences(...)
```

`apply_context_assessment` 本轮始终编排新活跃区（先合并待并入段，再应用补丁）。补丁形状：

```text
ContextAssessment
  remove:      tuple[str, ...]   # 段 id 或 memory:ref（删除）
  drop_recall: tuple[str, ...]   # memory:ref（低价值回忆摘录移出）
  focus:       tuple[str, ...]   # 段 id（聚焦）
```

`allow_edit` 仅用于测试隔离，主链路为真。

注意：批次构造、`memory_start` 和投递台账属于 30，不属于 16。

## 5. 行为规则

1. 经历只追加，不改写；账本落盘，关进程再开仍是同一份；
2. 阶段② 读到的必须是上一轮编好的活跃区（空仅当从未编排或已复位）；
3. 原始文本永不删除；未投递段不因重启丢失；
4. 对象 id 只透传 01；活跃区保留 `speaker_object_id`；
5. 缩减 / 聚焦只改活跃区，不改原始经历、不改 09 / 08 真源；
6. 记忆投递不改变经历账本与活跃区；
7. 30 的游标推进必须是显式确认后的行为；
8. 归档只标记，不物理删除。

## 6. 记录、评价与参数

- 记录：`experience_segment_appended`；活跃区 version 变化；
- 评价：经历段覆盖率、上下文引用率、回忆摘录留存率；
- 参数：`active_window_chars`。批次阈值属于 30。

## 7. 验收标准

- 16 维护活跃区，可含回忆摘录；落盘后新进程 02 读到同一份；
- 按 05 方案编排时不再调用模型；
- 对象引用不会因 trim 从活跃区消失；
- 16 不执行记忆封存，不创建对象；
- 原始经历不因上下文裁剪而丢失；未投递段不因关进程丢失；
- 30 不重复投递同一段经历；对象来源链可追溯。
