# 16 经历账本

> 模块文档。术语以《概念词汇》为准。
>
> 状态：初稿。保存原始经历，并保存按 05 方案编好的活跃区。`build_memory_batch` 仍暂留在账本供 30 调用；批次分型（`new_input` / `new_response` / `in_context_recalls`）归 30，本模块不让 09 自己分类。

## 1. 定位

16 保存原始经历，并维护当前活跃区。

它只负责：

- 追加经历；
- 保存原文与来源；
- 按 05 的缩减 / 聚焦方案编排并保存新活跃区（不再调用模型）；
- 提供经历片段与当前活跃区给其他模块。

它不负责：

- 决定模型看哪些材料（那是 03 组装 + 05 方案）；
- 决定哪些经历进入记忆（30）；
- 判断事件边界；
- 创建对象；
- 封存记忆。

活跃区是引用加现场正文，不是把 08 / 09 原文再存一份当真源。缩减只让条目离开活跃区，不删账本、不删记忆、不删个人世界。

## 2. 核心概念

### 2.1 ExperienceSegment

```text
ExperienceSegment
  segment_id
  sequence
  subject_id
  actor_kind              # external | subject | system
  output_kind             # external_input | subject_reply | subject_state | subject_silent | internal
  actor_object_id
  mentioned_object_ids
  text_raw
  text_normalized          # 01 归一化文本（名字 / 称呼 /「我」→ id）；原文 text_raw 不变
  state_delta
  response_plan
  source_ids
  occurred_at
  status
```

新经历追加后进入待合并，不在追加当下改活跃区。并入发生在按 05 方案编排时，以免认知过程中裁掉刚听见的话。

原文 `text_raw` 永不改写；`text_normalized` 由 01 落位时提供（语音 / 文字同一规则）。活跃区与上下文使用原文；记忆投递使用 `text_normalized`。

### 2.2 活跃区

16 保存的不是「每次从原文重切的窗口」，而是一份持续编辑的工作上下文。

```text
ContextViewState
  version
  context_text
  segment_refs
  recall_excerpts          # ((id, text), ...) 仍在场的回忆摘录
  speaker_object_id        # 对象；缩减不得拿掉
  excluded_sentence_refs
  focused_refs
  last_applied_sequence
```

更新方式：

- 本轮新输入、若有的本轮回应先入账、待合并；
- 05 交出缩减方案与聚焦方案（针对本轮上下文全体，含回忆）；
- 编排层不再调模型，16 `apply_context_assessment` 按方案编排：合并待并入经历、应用 trim/focus、更新回忆摘录；
- 对象与常驻约束的引用不得因 trim 从活跃区消失；
- 下一轮 02 读的就是这份新活跃区。

追加召回循环期间不调用本接口做裁剪。

### 2.3 记忆游标与批次

记忆游标只属于 30。投递不影响活跃区。

交给 09 的批次必须在 30 分型（新输入、新回应、本轮用过的回忆），16 不把无标记上下文打包给 09。`build_memory_batch` 暂留在 16 是债务，不是 09 的分类入口。

### 2.4 对象来源

对象 id 只透传 01。对象来源随经历段流转，09 不得另建对象体系。

## 3. 与 02 / 05 / 30 的关系

```text
16
  -> 保存原始经历
  -> 按方案保存活跃区

02
  -> 读取上一份活跃区
  -> 交给 03

05
  -> 交出缩减 / 聚焦方案（不执行）

编排层
  -> 最终认知之后调用 apply_context_assessment

30
  -> 只读新增经历
  -> 分型后投递 09
  -> 不改活跃区
```

## 4. 接口契约

```text
ExperienceLedgerPort
  append_external(...)
  append_subject_reply(...)
  append_subject_state(...)
  append_subject_silent(...)
  append_internal(...)

  current_context_view(...)
  apply_context_assessment(subject_id, assessment, *, recall_excerpts, speaker_object_id, protected_refs)

  list_experiences(...)
```

`apply_context_assessment` 本轮始终编排新活跃区（合并待并入段）；方案里的 trim/focus 一并执行。`allow_edit` 仅用于测试隔离，主链路为真。

注意：`build_memory_batch`、`memory_start` 和投递台账属于 30，不属于 16。

## 5. 行为规则

1. 经历只追加，不改写；
2. 原始文本永不删除；
3. 对象 id 只透传 01；活跃区保留 `speaker_object_id`；
4. 缩减 / 聚焦只改活跃区，不改原始经历、不改 09 / 08 真源；
5. 记忆投递不改变经历账本与活跃区；
6. 30 的游标推进必须是显式确认后的行为；
7. 归档只标记，不物理删除。

## 6. 记录、评价与参数

- 记录：`experience_segment_appended`；活跃区 version 变化；
- 评价：经历段覆盖率、上下文引用率、回忆摘录留存率；
- 参数：`active_window_chars`。批次阈值属于 30。

## 7. 验收标准

- 16 维护活跃区，可含回忆摘录；
- 按 05 方案编排时不再调用模型；
- 对象引用不会因 trim 从活跃区消失；
- 16 不执行记忆封存，不创建对象；
- 原始经历不因上下文裁剪而丢失；
- 30 不重复投递同一段经历；对象来源链可追溯。
