# 有效性分析系统

> 旁路系统，不进入主活动流程。原名「独立评价系统」已废止，以免与模型现场打分（评价）撞名。
>
> 状态：初稿（D-008）。第一只分析器：记忆质量。其余分析器并列预留。

## 1. 定位

有效性分析系统收集主流程与现场打分产生的材料，在自己的时机做综合分析，写出报告，并在授权范围内给出策略建议。

主流程只负责**产生信息**（口头、打分、补丁、投递结果）。本系统负责**收集、分析、归档**。它不挡说话，不改已经发生的历史。

## 2. 核心原则

1. **不阻塞主流程**。不可用、延迟或失败时，七阶段继续。
2. **不穿插在 05 / 06 / 10 / 07 之间**。分析在旁路。
3. **分析器彼此独立**。无固定先后；一只失败不影响另一只。触发规则各写各的（阈值、间隔、空闲，需要时加抖动）。「彼此无关、互不等待」不等于用纯随机当主策略。
4. **分析不等于现场打分**。05 的 `memory_ratings` 是当场判断；本系统出的是综合报告与策略建议。
5. **结果可追溯**。每份报告记录时间、输入材料、分析器、模型与版本。
6. **不自动改主体状态**。不改 08、不改经历原文。回忆策略经 09 策略接口落地，只影响**后续**召回。

## 3. 框架

```text
EffectivenessPort
  record_ratings(subject_id, activity_id, ratings)   # 主流程投入现场打分
  pending_gap_query(subject_id) -> str               # 读尚未处理的 gap
  consume_gap(subject_id)                            # 消费 gap
  run_due(subject_id)                                # 扫描到期的分析器，可空转
```

当前实现 `InProcessEffectiveness`：单一记忆质量分析器（`memory_analyzer.py`），材料 =
`memory_ratings`（逐条打分 + 整轮 coverage / gap_query）。**无多分析器注册表**；其余
分析器（活跃区管理 / 对象确认 / 投递）为预留，见 §6。

触发由 `memory_analyzer.should_run` 决定：累积 N 条未分析打分、或距上次报告超过 T。调度器在活动收尾后调用 `run_due`，不把分析器串成流水线。

显式触发（人工 / 治理）可以立刻跑某一只，仍不挡主流程。

## 4. 报告

```text
EffectivenessReport
  report_id
  subject_id
  analyzer          # 如 memory_quality
  created_at
  materials_ref     # 用了哪些打分 / 事件
  findings          # 综合结论（结构化 + 短文）
  strategy          # 可选；记忆分析器给出回忆策略建议
  model_tag         # 所用模型；无模型则为空
  analyzer_version
```

报告存档，不进经历、不进活跃区、不进 05 上下文。

## 5. 记忆分析器（第一只）

### 5.1 材料

05（或开口后独立再评估）入库的 `memory_ratings`：逐条 relevance / helps_understanding / used_in_reply / misleading / redundant / object_fit，以及整轮 coverage / gap_query。可附带 03 实际召回条数、档位快照。

### 5.2 过程

```text
触发（打分累积 / 时间 / 空闲）
  → 取未分析的打分
  → 按配置选用模型（可关模型、走规则汇总）
  → 综合质量报告
  → 回忆策略建议（最小：default_level 即强度、limit）
  → 经 09 策略接口写入快照（带 source_report_id）
  → 报告存档
```

模型可配，不是每只分析器都必须调大模型。

### 5.3 与 09

09 薄壳提供策略快照的读 / 写，**不改** `MemoryBackendPort`。03 召回把快照中的 `level` / `limit` 传入已有 `recall()`。策略只影响之后的检索，不重算旧打分、不改已投递记忆。

14 日后可接管更广调参；本轮策略先落 09，避免空转一层未实现的 14。

## 8. 验收标准

- 主流程不等待本系统；失败不阻断活动；
- 分析器可单独启用 / 停用；
- 记忆分析器能从入库打分生成可追溯报告；
- 策略写入 09 后，后续 03 召回使用新档位；已发生的口头与经历不变；
- 文档与代码称「有效性分析系统」，不再称「评价系统」指本模块。

## 9. 评价基准（示例库）与策略输出

### 9.1 输出是策略，不是分数

记忆分析器**不输出一个质量分**，而是输出一段召回策略（`MemoryRecallStrategy`）。质量分、
coverage、unrelated 比例等只是**推导该策略所用的一组证据**，放在报告的 `findings` /
`evidence`，不作为头条结论。

策略字段对齐记忆引擎实际消费的召回入参，使它能落到 REM（Rems3）上，而不是一句空泛建议：

```text
MemoryRecallStrategy
  default_level  # 1–9 召回强度；09 薄壳读取 → recall(level=...)
  limit          # 召回预算（片段上限）→ recall(limit=...)
  summary_level  # REMS 多级摘要档位（如 "L1"）；引擎支持时生效
  recall_mode    # balanced | precision | coverage（策略取向，映射到 level 方向）
  confidence     # 0..1，基于示例库校准（这→策略的把握，不是“分数”）
  reason         # 为什么这样定
  evidence       # 触发推导的信号（含质量分、各失败分量与参考阈值）
  basis          # "baseline:vN"（示例库校准）| "heuristic"（无基准回退）
```

可执行参数（`default_level` / `limit`）落到 09 薄壳；全量策略（含 `recall_mode` /
`summary_level` / `confidence` / `basis`）随报告归档，保证可追溯。

### 9.2 评价基准由“带标注示例库”决定，不写死魔法数

统一测量基准：`RatingFeatures`（`rated_count` / `unrelated_ratio` / `misleading_ratio` /
`redundant_ratio` / `helps_avg` / `coverage` / `has_gap`），并导出两条复合失败信号
`precision_failure` / `coverage_failure`（质量分只是二者的综合）。运行时与示例库用**同一套**
特征定义，保证可比。

`RatingExample` 是一条**带标注**的召回案例：上下文 + 特征 + 真值标签（`good` / `poor`
）+ 真值策略 + 理由。示例库（JSONL）由离线/人工标注而成，**本系统不实时**。

`calibrate(examples)` 离线求参考基准 `BaselineStats`：

- 每条失败信号在“标注好”与“标注差”两类的参考**分离阈值**（取好样本高位分位与差样本
  低位分位的中间值；两类重叠取均值中点；样本不全回退默认）——阈值由数据决定，不再写死
  “无关占比过半”这类魔法数。
- “标注差”各类相对当前档位的典型调整量（precision 差 → 降档，coverage 差 → 升档）。
- 质量分 p10..p90 分位（作为证据 / 置信度参考，不是结论）。

`MemoryQualityEvaluator.evaluate(...)` 做**分位对比**：哪条失败信号越过它的参考阈值，就朝那个
取向给策略（precision → 降档、coverage → 升档、都未越过 → 保持），并给出置信度与证据。

### 9.3 无基准回退

示例库为空 / 未提供时，`heuristic_strategy` 走旧规则兜底（仍输出统一策略对象，`basis` 为
`heuristic`），保证「加了基准之前系统照常」、不挡说话。

### 9.4 如何积累“很多例子”

运行时通过 `InProcessEffectiveness(candidate_path=...)` 把每轮现场打分收集成**未标注候选**示例
（`quality_label="unlabeled"`）。离线把它们标注成 `good` / `poor` 并给出真值策略后，写入
`examples_path` 即成为基准库；下次启动 `InProcessEffectiveness(examples_path=...)` 自动校准。
