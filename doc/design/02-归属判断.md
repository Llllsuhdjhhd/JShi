# 02 归属判断

> 模块文档。术语以《概念词汇》为准，流程位置见《00 流程总览与输入边界》阶段②。
>
> 状态：初稿，待与 03 状态组装、09 记忆系统共同校准后定稿。现有占位代码只验证接口可接线，不证明当前启发式或流程顺序已经成立。

## 1. 定位

本模块回答一个问题：**这条输入延续或归属到哪些已有的主体面关切（未完成现实·主体面）**。

位置在阶段②：落位之后、组装之前。目的：延续性输入（"继续""昨天那件事……"）不先做全量回忆与个人世界组装，而是直接以命中的关切为中心组装——让"主体面决定什么值得继续注意"落到活动起点。

## 2. 输入与输出

### 2.1 输入

`judge(subject_id, input_text, speaker, standing_constraints, recent_activity=None)`

- `input_text`：刚落位的输入；
- `speaker`：说话人对象（来自 01：object_id / label / 未知标记）；对象是谁先确定，归属再判断延续哪条线；
- `standing_constraints`：常驻约束清单（承诺 + 已有主体面关切），**不读全量个人世界与记忆**；
- `recent_activity`：最近一次活动（用于"上次对话延续"的衔接判断，可空）。

> **与 01 模式三（记忆匹配识别）的边界**：01 解决"重名时谁在说"（落位前、读候选对象记忆）；02 解决"延续哪个关切"（落位后、只读常驻清单与最近活动，不做记忆匹配）。两者阶段、目的、读取范围不同，不混用。

### 2.2 输出 AttributionResult

| 字段 | 取值 | 说明 |
|------|------|------|
| concern_ids | tuple[str] | 命中的关切 id（可多个，可为空） |
| confidence | 0.0 ~ 1.0 | 归属置信度（选择组装支路的依据） |
| basis | tuple[str] | 依据（single_active_concern / lexical_overlap / recent_activity 等） |
| status | none / candidate | 结果默认候选，可修正 |

## 3. 行为规则

1. **当前基线为先归属后组装**：本模块先于完整回忆与个人世界组装；只读常驻约束清单，不扩大上下文。若后续验证需要轻量召回辅助归属，须通过决策记录调整边界；
2. **对象收敛**：归属先按说话人对象过滤常驻清单——只在该对象的关切实体上做结构候选；对象未知 / 新对象 → 退化为全清单；
3. **两段式判定**：
   - 结构候选（程序，快）：唯一关切延续（短输入）、词汇重叠、最近活动衔接；
   - 语义确认（可选，占位）：候选不唯一或歧义时，由模型做轻量确认；模型输出默认"考虑中"；
4. 命中（concern_ids 非空）→ 关切中心组装；未命中 → 全量组装；
5. 未命中的关切仍以清单形式在场（防无声消失），只是不展开、不进召回；
6. 结果暂定，可显式修正（`attribution_revised`）；
7. 归属判断**不新建关切**：新主体面关切仍由认知活动之后显式 `propose-open`；
8. 内部输入（source=internal）不经过外部语义链路。

> 归属置信度是**组装支路选择依据**，不设阻断门禁（对象置信度门禁在 01）。与 01 一致：置信度为活动内瞬时值，动态计算、不落库；`input_attributed` 事件记录当时值。

### 归属修正（attribution_revised）

归属结果默认候选，可显式修正：

- 触发者：程序（结构证据变化）、模型（认知阶段判定）、用户（明确纠正）；
- 时机：活动进行中发现焦点漂移（输入转向另一关切）、认知后获得新证据；
- 记录内容：原归属 concern_ids → 新归属 concern_ids、理由、来源（认知内容 / 事实 id）；
- 修正只改变归属，不改写事实原文与已落位记录。

## 4. 归属与组装

- 命中 → 关切中心组装（03）：焦点关切的来源与推进史 + 承诺 + 按重要性截断的个人世界；
- 未命中 → 全量组装（03）：身份 + 个人世界 + 开放事项清单 + 记忆召回；
- 活动（04）只挂载命中的关切 id；多个命中时占位挂载全部命中，未来可按主 / 次权重细化；
- 焦点漂移：活动过程中输入转向另一关切 → 显式修正归属（`attribution_revised`），不无声漂移。

## 5. 占位与未来

- 当前占位：
  - 对象收敛：有已知 object_id 时，按"关切文本与说话人 label/别名 的文本关联"过滤清单；结构化"关切-对象"关联在 07 关切生命周期中明确；
  - 唯一活跃关切 + 短输入（≤20 字）→ 命中（置信度 0.5，依据 single_active_concern / short_input）；
  - 词汇重叠（≥2 字片段）→ 命中（置信度 0.3 + 0.2 × 命中数，上限 1.0，依据 lexical_overlap）；
  - 否则未命中（status=none）；
  - 无语义确认。
- 未来：模型语义确认、多关切权重分配、焦点漂移检测、流式输入下的归属更新。

## 6. 验收标准

以下前六项是结构验收，证明当前基线按契约运行：

- 唯一关切 + 短输入 → 命中，走关切中心组装；
- 词汇重叠 → 命中；
- 同一输入来自不同对象 → 归属结果不同（对象收敛生效）；
- 对象未知 / 新对象 → 退化为全清单归属；
- 无关切 → 未命中，走全量组装；
- 多关切时可返回多个命中；
- 未命中的关切仍在清单中（不消失）；
- 归属结果记录 `input_attributed`，可显式修正；
- 内部输入不经过本模块。

结构验收不等于方案有效。方案有效性按《第一阶段验证章程》V7 检查：

- 与简单全量组装或轻量召回后归属作对照；
- 比较正确关切保持、误归属、漏归属、召回相关性和上下文成本；
- 对歧义、转题、多关切和短续接输入分别观察；
- 若没有可观察收益，允许调整归属与组装顺序，但不得取消来源记录、显式修正和“不在归属阶段新建关切”等稳定原则。

## 7. 与其他模块的关系

- 依赖：常驻约束清单（08 个人世界）、说话人对象（01 识别结果）、落位结果（00 阶段①）；
- 被依赖：状态组装（03）选择支路、活动（04）挂载关切；
- 概念边界：归属判断 ≠ 新关切提议（`propose-open` 在认知之后，见 07 关切生命周期）。

## 8. 扩展性预留

- 语义确认（模型）接口预留；
- 多关切权重、焦点漂移、流式归属更新预留；
- 归属判断为可替换端口（AttributionPort），替换实现不改主流程。
