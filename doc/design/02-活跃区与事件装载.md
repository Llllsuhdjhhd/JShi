# 02 活跃区与活动窗口

> 模块文档。术语以《概念词汇》为准，流程位置见《00 流程总览与输入边界》阶段②。
>
> 状态：定稿。02 只交出既往 `ContextViewState`，不是整块活跃区；采纳 I-006（初次与复位同一流程）。
> 文件名未改，改名留目录整理。

## 1. 定位

本模块回答：**本轮把 16 里哪一份既往上下文交给 03**。

02 不是整块活跃区。本轮工作现场 = 既往视图 + 本轮输入。02 只读并交出既往窗口；本轮原话由 03 经 `input_text` 带入组装与模型，不经过 02，也不在②并入视图。

02 只从 16 读取 `ContextViewState`，交给 03。它不生成上下文，不按预算重截原文，不调用模型，不推进记忆游标，不消费本轮输入。

## 2. 概念

### 2.1 谁维护上下文

- 原始经历在 16，只追加、不删；
- 模型所见的既往窗口是 16 持续编辑的 `ContextViewState`，不是每次从账本重切一段窗口；
- 02 不保存自己的窗口起点，也不维护 `active_zone_start`。

### 2.2 02 读到的视图

读到的是**上一轮结束时**的既往窗口，不含本轮刚入账、仍待合并的原文。

```text
ContextViewState
  version
  context_text
  segment_refs
  excluded_sentence_refs
  focused_refs
  last_applied_sequence
```

字段以 16 为准。02 原样交给 03，不改 `ContextViewState`。

### 2.3 初次使用与复位

主体第一次活动，或经历账本 / 上下文视图被复位清空之后，**不另开启动流程**。仍走与此后相同的七阶段；02 仍只调用同一条只读接口。

空的 `ContextViewState` 合法。不要为「第一次」预填假上下文、跳过 01，或把本轮输入提前并进视图。复位视同初次：账本为空、视图为空，规则不变。复位指清空经历与视图后的再启动，不是活动的 `wait`。

## 3. 行为规则

1. 阶段② 调用 16 `current_context_view`，只读；
2. 初次与复位不设特例，空视图也合法；
3. 不调用模型，不改视图；
4. `need_trim` / `need_focus` 由 05 提出，正常回复之后由 16 `apply_context_assessment` 更新，不在本轮②执行；
5. 阶段⑦ 不由 02 推进游标：记忆游标属 30；上下文版本由 16 维护；
6. `load` 只接收主体标识，不接收本轮原文，也不按长度重切。

## 4. 接口契约

```text
ActiveZonePort.load(subject_id)
    -> ContextViewState
```

不再提供 `advance`。不再接收 `input_text` / `limit_chars`。长度与增量编辑由 16 的 `ContextViewState` 承担。

## 5. 记录、评价与参数

- 记录：`context_window_loaded`（记下读到的 version、segment_refs）；
- 评价：视图是否覆盖本轮所需经历、经历段引用率，由 14 统计；
- 参数：`active_window_chars` 在 16；02 无独立窗口参数。

## 6. 验收标准

- 02 不调用模型；
- 02 不重切原文、不删原文、不消费本轮输入；
- 02 返回的是 16 的当前 `ContextViewState`，不含本轮待合并原文；
- 02 不推进 `memory_start`；
- 未知主体、初次活动、复位后的空账本，均返回空视图，且走同一 `load`。

## 7. 与其他模块的关系

- 依赖：16 ExperienceLedger；
- 被依赖：03 状态组装（把本视图与 `input_text` 一并装入工作集）；
- 概念边界：02 只读取既往窗口；16 维护视图；05 提出意见；30 管理记忆游标。复位若发生，由清空 16 的经历与视图完成，02 无单独复位接口。
