# 02 活跃区与活动窗口

> 模块文档。术语以《概念词汇》为准，流程位置见《00 流程总览与输入边界》阶段②。
>
> 状态：定稿。02 只从 16 读取上一份活跃区，不生成、不重切、不调用模型。采纳 I-006（初次与复位同一流程）。
> 文件名未改，改名留目录整理。

## 1. 定位

本模块回答：**本轮把 16 里哪一份上一活跃区交给 03**。

活跃区是上一轮按 05 方案编好的工作上下文（经历、仍保留的回忆摘录等），不是「仅经历窗口」，也不是本轮尚未组装完的全体。本轮原话、本轮对象、本轮 08/09 初始装载由 03 再叠上去，形成本轮上下文。

02 只读并交出 16 的当前活跃区。它不生成上下文，不按预算重截原文，不调用模型，不推进记忆游标，不消费本轮输入。

## 2. 概念

### 2.1 谁维护活跃区

- 原始经历在 16，只追加、不删；
- 活跃区是 16 持续保存的编排结果（`ContextViewState`），不是每次从账本重切；
- 02 不保存自己的窗口起点，也不维护 `active_zone_start`。

### 2.2 02 读到的内容

读到的是**上一轮结束时**的活跃区，不含本轮刚入账、仍待合并的原文。

```text
ContextViewState
  version
  context_text             # 派生：按 segment_refs + recall_excerpts 渲染
  segment_refs             # 有序：在场经历的段 id（段级，不做句子级编辑）
  recall_excerpts          # 仍在场的回忆摘录 (id, text)
  speaker_object_id        # 活跃区中的对象，删除不得拿掉
  focused_refs             # 段级聚焦引用
  last_applied_sequence
```

字段以 16 为准。02 原样交给 03，不改。

### 2.3 初次使用与复位

主体第一次活动，或经历账本 / 活跃区被复位清空之后，**不另开启动流程**。仍走与此后相同的七阶段；02 仍只调用同一条只读接口。

空的活跃区合法。不要为「第一次」预填假上下文、跳过 01，或把本轮输入提前并进活跃区。复位视同初次。复位指清空经历与活跃区后的再启动，不是活动的 `wait`。

## 3. 行为规则

1. 阶段② 调用 16 `current_context_view`，只读；
2. 初次与复位不设特例，空活跃区也合法；
3. 不调用模型，不改活跃区；
4. 缩减与聚焦由 05 提出，本轮最终认知之后由 16 按方案编排新活跃区，不在本轮②执行，也不在追加召回循环里执行；
5. 阶段⑦ 不由 02 推进游标：记忆游标属 30；活跃区版本由 16 维护；
6. `load` 只接收主体标识，不接收本轮原文，也不按长度重切。

## 4. 接口契约

```text
ActiveZonePort.load(subject_id)
    -> ContextViewState
```

不再提供 `advance`。不再接收 `input_text` / `limit_chars`。编排与增量编辑由 16 承担。

## 5. 记录、评价与参数

- 记录：`context_window_loaded`（记下读到的 version、segment_refs、recall_excerpts 的 id）；
- 评价：活跃区是否覆盖本轮所需材料，由 14 统计；
- 参数：容量在 16 / 14；02 无独立窗口参数。

## 6. 验收标准

- 02 不调用模型；
- 02 不重切原文、不删原文、不消费本轮输入；
- 02 返回的是 16 的当前活跃区，不含本轮待合并原文；
- 02 不推进 `memory_start`；
- 未知主体、初次活动、复位后的空账本，均返回空活跃区，且走同一 `load`。

## 7. 与其他模块的关系

- 依赖：16 ExperienceLedger；
- 被依赖：03 状态组装（上一活跃区 + 本轮输入 + 对象 + 身份 + 08 + 09）；
- 概念边界：02 只读取上一份活跃区；16 按 05 方案保存新活跃区。复位由清空 16 完成，02 无单独复位接口。
