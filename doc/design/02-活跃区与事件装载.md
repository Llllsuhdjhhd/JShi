# 02 活跃区与活动窗口

> 模块文档。术语以《概念词汇》为准，流程位置见《00 流程总览与输入边界》阶段②。
>
> 状态：定稿，按 16 的 `ContextViewState` 重校。

## 1. 定位

本模块回答：**本轮把 16 里哪一份当前上下文交给 03**。

02 只从 16 读取 `ContextViewState`，交给 03。它不生成上下文，不按预算重截原文，不识别事件，不调用模型，不推进记忆游标。

## 2. 概念

### 2.1 谁维护上下文

- 原始经历在 16，只追加、不删；
- 模型看到的上下文是 16 持续编辑的 `ContextViewState`，不是每次从账本重切一段窗口；
- 02 不保存自己的窗口起点，也不维护 `active_zone_start`。

### 2.2 02 读到的视图

```text
ContextViewState
  version
  context_text
  segment_refs
  excluded_sentence_refs
  focused_refs
  last_applied_sequence
```

字段以 16 为准。02 原样交给 03，不改 `ContextViewState`。

### 2.3 事件不属于 02

事件、未完成事件、事件边界、事件封存全部属于 09。02 不理解“事情是否了结”。

## 3. 行为规则

1. 阶段② 调用 16 `current_context_view`，只读；
2. 首次输入不设特例，空视图也合法；
3. 不做归属判断，不调用模型，不识别事件；
4. `need_trim` / `need_focus` 由 05 提出，正常回复之后由 16 `apply_context_assessment` 更新，不在本轮②执行；
5. 阶段⑦ 不由 02 推进游标：记忆游标属 30；上下文版本由 16 维护。

## 4. 接口契约

```text
ActiveZonePort.load(subject_id, input_text)
    -> ContextViewState
```

不再提供 `advance`。长度与增量编辑由 16 的 `ContextViewState` 承担。

## 5. 记录、评价与参数

- 记录：`context_window_loaded`（记下读到的 version、segment_refs）；
- 评价：视图是否覆盖本轮所需经历、经历段引用率，由 14 统计；
- 参数：`active_window_chars` 在 16；02 无独立窗口参数。

## 6. 验收标准

- 02 不调用模型；
- 02 不重切原文、不删原文；
- 02 返回的是 16 的当前 `ContextViewState`，不含事件；
- 02 不推进 `memory_start`。

## 7. 与其他模块的关系

- 依赖：16 ExperienceLedger；
- 被依赖：03 状态组装；
- 概念边界：02 只读取；16 维护视图；05 提出意见；30 管理记忆游标。
