# 02 活跃区与活动窗口

> 模块文档。术语以《概念词汇》为准，流程位置见《00 流程总览与输入边界》阶段②。
>
> 状态：初稿，按“活跃区不含事件”重校。

## 1. 定位

本模块回答：**匠石当前带着哪一段原始活动进入模型**。

活跃区只从 `ActivityLedger` 读取一段原始活动窗口，控制长度后交给 03。它不识别事件，不维护未完成事件，也不做事件聚焦。

## 2. 概念

### 2.1 活动窗口

- 窗口内容：`ActivitySegment`，包括外部输入、匠石回复、主体状态、静默和内部活动；
- 窗口起点：`active_zone_start`；
- 窗口长度：按字符数限制，当前默认 2000；
- 窗口只读：02 不写回原始日志。

### 2.2 事件不属于 02

事件、未完成事件、事件边界、事件封存全部属于 07 / 09 记忆侧。02 只负责把原始活动给模型，不理解“事情是否了结”。

## 3. 行为规则

1. 阶段② 从 `ActivityLedger.active_window()` 读取窗口；
2. 首次输入不设特例，空窗口也合法；
3. 活跃区不做归属判断，不调用模型；
4. 活跃区不识别事件，不做事件筛选；
5. 阶段⑦ 只推进 `active_zone_start`，不做事件剔除；
6. 长度由 `active_window_chars` 控制，超出部分由窗口截断，不删除原文。

## 4. 接口契约

```text
ActiveZonePort.load(subject_id, input_text, *, limit_chars=None)
    -> ActiveZoneView(segments, start_sequence, budget_chars)

ActiveZonePort.advance(subject_id, through_sequence)
    -> int
```

## 5. 记录、评价与参数

- 记录：`context_window_loaded`；
- 评价：窗口长度、窗口覆盖率、活动段引用率，由 14 统计；
- 参数：`active_window_chars`，由 14 统一调整并留审计。

## 6. 验收标准

- 02 不调用模型；
- 02 返回原始活动段，不含事件；
- 活跃区从 `active_zone_start` 之后开始；
- 长度超过限制时不删除原文，只截断窗口；
- 阶段⑦ 推进活跃区游标，下一轮窗口不重复已处理活动。

## 7. 与其他模块的关系

- 依赖：16 ActivityLedger；
- 被依赖：03 状态组装；
- 概念边界：活跃区 ≠ 事件；活动窗口 ≠ 记忆。
