# 02 活跃区与事件装载

> 模块文档。术语以《概念词汇》为准，流程位置见《00 流程总览与输入边界》阶段②。
>
> 状态：初稿（新方向：事件统一称呼、活跃区、输入不做归属判断），待讨论定稿。

## 1. 定位

本模块回答：匠石当前"在看什么、能想起什么"——哪些事件（未完成 + 完成）进入工作上下文（活跃区），超预算时如何剔除，被剔除后如何召回。

两个关键决定：

- **默认不做归属判断**：新输入到达时不调用模型判断它属于哪个事件（避免模型耗时）；**模型归属占位保留，默认关闭，可配置启用**；输入直接进入活动，由模型在认知阶段结合活跃区自行聚焦；
- **事件统一称呼**：取消「关切」，匠石的事情统称事件；未完成事件 = 尚未了结的事情。

**阶段边界**：阶段② 只**装载**活跃区事件视图并**标记本次输入**，不涉及活跃区调整；筛选、剔除、落位与召回发生在后续环节（认知阶段模型筛选，收尾由程序执行并记账）。

## 2. 概念

### 2.1 事件（事情单元）

- 事件是匠石的一件事情，状态：未完成 / 完成；
- 完成 = 事情完结（显式）或长时间无回应（自动归档）；
- 完成 ≠ 删除：保留来源与历史，可召回。

### 2.2 活跃区（Active Zone）

- 活跃区 = 工作上下文中常驻的事件区，包含**未完成事件 + 完成事件**；
- 活跃区比（`active_zone_ratio`）：长度 ≈ 模型上下文 × ratio，默认参考 1/66，**软约束**；可配置，未来由调参系统（14）统计分析后动态调整，调整留审计；
- 弹性：超预算剔除允许一次误差（如超 1 条事件或小幅比例），不机械精确。

## 3. 行为规则

1. **初始化无特例**：第一次输入时活跃区为空，装载结果是空事件视图 + 标记本次输入，流程与后续输入完全一致（装载 → 组装 → 活动 → 认知 → …）；不设初始化分支，也不因空活跃区改变后续阶段；
2. **新输入默认不做归属判断**：落位后直接装载活跃区事件视图并**标记本次输入**（作为新输入进入工作集），不调用模型（零额外延迟）；模型归属占位保留、默认关闭，可配置启用；
3. 程序侧只做窄而硬的事：按 id 维护事件视图、预算核算、剔除/落位执行、召回执行、记账；**不做关键词匹配**；
4. **筛选由模型进行**：认知阶段（模型思考时）阅读活跃区 + 输入，决定相关事件、需要剔除或召回的事件（程序提供候选）；
5. 超预算剔除有弹性：超过活跃区比时剔除低优先级事件（占位按 `updated_at` 排序，未来由模型选择）；被剔除事件**落位到记忆**（保留 id、摘要、来源、状态），可经回忆机制召回；
6. 完成的事件不强制立即移出：预算允许时保留在活跃区（刚了结的背景）；
7. 新事件：认知后显式创建（原 `propose-open` 语义），带来源；
8. 程序侧文字匹配只用**对象 id**（输入携带的说话人对象标识），不用其它关键字；显式事件 id 引用（输入或最近活动携带）可直接装载/召回。

## 4. 与模型 / 程序分工

| 层 | 职责 |
|----|------|
| 程序（窄而硬） | 阶段②：活跃区装载 + 标记本次输入（不调整）；后续：预算核算、剔除/落位执行、按 id 召回、记账（`event_loaded` / `event_evicted` / `event_recalled`） |
| 模型（认知阶段） | 事件相关性判断与聚焦、是否召回、剔除选择（程序提供候选） |

## 5. 占位与未来

- 占位：活跃区 = 活跃事件列表（未完成 + 最近完成），预算 = context × 1/66 软上限；剔除按 `updated_at`（无模型筛选）；召回仅支持 id 引用；
- 未来：模型筛选与剔除选择、弹性策略参数化、超时归档、活跃区视图持久化。

## 6. 验收标准

- 输入不调用模型做归属（无额外 LLM 延迟）；
- 活跃区在预算内：事件全部在场；
- 超预算：剔除低优先级事件（有弹性），被剔除事件可按 id 召回；
- 完成事件在预算允许时保留；
- 新事件创建、事件完成、剔除、召回均可追溯。

## 7. 与其他模块的关系

- 依赖：事件存储（08 个人世界 / 07 事件生命周期）、输入信封（00）、记忆召回（09）；
- 被依赖：状态组装（03 装载活跃区）、活动（04 挂载相关事件 id）；
- 受调参系统（14）影响：`active_zone_ratio` 等参数可被统计分析后动态调整，调整须有审计记录；
- 概念边界：活跃区 ≠ 全部记忆；事件（事情单元）≠ 历史记录（HistoryRecord）。

## 8. 扩展性预留

- 弹性剔除策略、模型筛选协议、动态活跃区比、流式更新预留；
- 事件 id 引用为程序侧唯一文字匹配方式。
- 参数（活跃区比、弹性阈值等）由调参系统（14）统计各阶段信息后动态调整（占位）。

### 8.1 记录、评价与参数

- 记录：`event_loaded`、`event_evicted`、`event_recalled`、`activity_events_attached` 均写入主体历史；
- 评价：剔除与召回效果由模型意见 + 客观指标（剔除率、召回命中率、活跃区占用）评价，供 14 分析；
- 参数：活跃区比（默认 1/66）、条数预算（默认 8）、弹性（默认 1 条）为可配置占位，调整由 14 统一执行并留审计。
