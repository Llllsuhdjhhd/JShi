# 独立评价系统

> 状态：初稿
> 定位：旁路系统，不进入主活动流程。

## 1. 定位

独立评价系统负责收集活动过程中产生的信息，并在合适的时机生成评价。

它不是主流程中的一个步骤。主流程只负责**产生信息**，评价系统负责**收集、判断、记录**。

## 2. 核心原则

1. **不阻塞主流程**

   评价系统不可用、延迟或失败时，主流程继续执行。

2. **不穿插在 05 / 06 / 10 / 07 之间**

   评价可以是：

   - 事件触发收集；
   - 定时收集；
   - 显式请求收集。

3. **只消费主流程产生的信息**

   评价系统不反向要求主流程等待它。

4. **所有评价结果可追溯**

   每条评价必须记录来源事件、时间、输入材料和评价器版本。

## 3. 评价触发方式

```text
事件触发：
  主流程 emit(event)
  评价系统收到事件后决定是否收集

定时触发：
  后台调度器按频率扫描待评价事件

显式触发：
  人工或治理模块主动请求评价
```

## 4. 统一接口

```text
EvaluationEventPort
  emit(event: EvaluationEvent)

EvaluationCollectorPort
  collect(subject_id, *, cursor=None, since=None)
    -> tuple[EvaluationEvent, ...]

EvaluationWriterPort
  write(evaluation: EvaluationResult)
```

## 5. EvaluationEvent

```text
EvaluationEvent
  event_id
  subject_id
  activity_id
  event_type
  occurred_at
  payload
  source_ids
```

可产生评价事件的点：

| 事件类型 | 来源 | 说明 |
|----------|------|------|
| `recall_requested` | 05 / 主流程 | 模型请求追加召回 |
| `recall_executed` | 09 / 上下文协调层 | 召回执行完成 |
| `thought_materialized` | 05 | 最终 thought 生成 |
| `epistemic_transitioned` | 06 | 状态迁移完成 |
| `language_action_recorded` | 10 | 回复行动记录完成 |
| `memory_batch_ingested` | 09 | 记忆批次投递结果 |
| `memory_batch_failed` | 09 | 记忆批次失败 |

## 6. EvaluationResult

```text
EvaluationResult
  evaluation_id
  subject_id
  activity_id
  evaluation_type
  result
  reason
  source_event_ids
  evaluator_version
  created_at
```

## 7. 与回忆评价的关系

`RecallEvaluation` 是独立评价系统的一个具体类型，不应由 05 输出。

正确链路：

```text
05 召回发生
  -> emit(recall_requested)
  -> 主流程继续

09 召回执行
  -> emit(recall_executed)
  -> 主流程继续

评价系统稍后收集这些事件
  -> 生成 RecallEvaluation
  -> 写入 recall_evaluated
```

## 8. 与 14 / 15 的关系

- 14 统计评价结果并调参；
- 15 负责人工介入点；
- 独立评价系统负责收集与生成评价，不直接改参数，不直接人工确认。

## 9. 验收标准

- 主流程不等待评价系统；
- 评价系统不可用不阻断活动；
- 评价来源可追溯到具体事件；
- 同一事件可被定时、事件或显式方式收集；
- 评价结果不自动改变主体状态。
