# 05 认知

> 模块文档。术语以《概念词汇》为准，流程位置见《00 流程总览与输入边界》阶段⑤。
>
> 状态：校准中（D-008）。文件名仍含「追加召回」，本模块**不再**同轮补召回、不再为召回二次调模型。

## 1. 定位

本模块回答：**匠石如何看见本轮上下文，并交出对外回应。**

基础认知模型即心智：它看见的是 03 装好的全体。主路径一次调用只保证交出 `response_plan`（语言 / 动作）。活跃区管理、记忆现场打分、对象确认是**独立条目**：可顺手填、可空、可在开口之后另调模型再评估。彼此无固定顺序，一条失败不连坐口头。

05 不做：检索记忆、投递记忆、改 08 长期条目、把方案编成新活跃区、标记活动、同轮再召回再认知。

编排层拿到 `response_plan` 即走 06 → 10。其余条目不阻塞这条路。

外部活动的基础认知走 skill（`CognitionSkill`，由 `SkillModelPort` 包成 `ModelPort`）：主调用产出回应 JSON。解析失败则本轮 `think`、verbal 为空，失败记入 `metadata.skill_fallback`，不把模型原文当说话。内部活动（反思）不套本 schema。所用模型与 skill 版本记在 `model_tag`（I-004）。

## 2. 本轮上下文与活跃区

本轮上下文 = 03 工作集的全体。回忆只含 **03 已装入的线索**（按说话人、当前策略快照的最低档），不含同轮补召回。

至少包括：

- 本轮输入
- 对象（说话人：`object_id`、`label`、`aliases`、`status`）
- 主体身份
- 已装入的个人世界
- 回忆（03 初始装载）
- 上一份活跃区里仍在场的经历

缺对象则外部对话无意义。对象必须在请求里单列，缩减不得把它从新活跃区拿掉。

文本形态：模型与上下文一律使用原文。多轮对话整段作为 `input_text` 进入，提示词聚焦最后一句为待回答。对人只用名字，默认不出现 `object_id`。

活跃区是**按方案编好、供下一轮继续面对的工作上下文**，由 16 保存、02 读取。缩减只让条目离开活跃区，不删账本、不删记忆、不删个人世界。承诺与边界等常驻约束，缩减不得拿掉。

```text
上一活跃区 + 本轮输入 + 对象 + 身份 + 个人世界 + 03 已装回忆
    → 本轮上下文（心智看见的全体）
    → 05 主调用：response_plan（必出）
    → 06 → 10
    → 16：有补丁则用，无补丁则并入本轮输入/回应，硬上限兜底
```

本轮原话先作为 `input_text` 进模型，不在认知开始前并入上一份活跃区。并入发生在 16 编排新活跃区时。

## 3. 输入

阶段⑤ 开始时，编排层已经有：

| 输入 | 来自 | 角色 |
|------|------|------|
| 工作集 | 03 | `input_text`、`speaker`、`subject_state`、`fragments`、上一活跃区 |
| 活动 | 04 | `activity_id` |
| 感知 | 与 `input_text` 同一原文 | 已接受的对方表达 |

02 不在 05 里再读。08 / 09 的初始装载已在 03 完成。05 不再向 09 提出本轮检索。

## 4. 模型请求

```text
ModelRequest
  purpose            # 外部活动 / 反思
  input_text         # 本轮刺激
  speaker            # object_id, label, aliases, status
  subject_state
  fragments
  context            # 可寻址（分片 id、经历段引用、回忆引用）
```

发给模型时：稳定规则、身份与 08 正文在 `system`；本轮原话与上一活跃区在 `user`。`ModelRequest.speaker` 仍单列。工作集里的身份/对象分片不因 HTTP 省略而删除。

本轮原话进账本时不加说话人名前缀。不纳入流式分段（I-001）。

独立再评估（§6）用各自的请求，不复用「必须同时填完四条」的主 schema。

## 5. 四条产出

各条经过程序校验后再分发。模型输出 ≠ 已接受事实 ≠ 已经写入。

| 条 | 字段 | 消费者 | 主路径 |
|----|------|--------|--------|
| 1 回应 | `response_plan`（mode / reason / items） | 06 → 10 | **必出** |
| 2 活跃区管理 | `context_assessment`（remove / drop_recall / focus） | 16 | 可空；可开口后独立再评估 |
| 3 记忆现场打分 | `memory_ratings` | 入库，给有效性分析 | 有在场 `memory:` 才填；可开口后独立再评估 |
| 4 对象确认 | `object_assessment` | 01 | 无冲突可跳过；可开口后独立再评估 |

不再产出 `recall_requests`。不再并列 `need_recall`。

**缺材料**只记在打分的 `coverage` / 缺口查询里，不在本轮取记忆、不二次认知。需要时，收尾之后或下一拍 03 再取（见 §8）。

`wait` 结束本轮活动，不是「再想一轮」。

容量参数由 14 / 魔法书管理，不在 05 展开算法。

## 6. 独立再评估

活跃区管理、记忆现场打分、对象确认**彼此独立**：无固定先后，一只失败不影响另外两只，也不回滚已经发出的口头。

可以：

- 主调用顺手带上（不校验为必填）；
- 本轮跳过；
- 开口之后（06/10 之后，或活动已关闭）另调模型重新评估。

独立再评估是旁路：不挡 06 / 10 / 07 / 30。所用模型可配（I-004），不必与主认知同一档。

晚到的结果如何落地：

- 活跃区补丁：若本轮 16 已保存，补丁写到已保存活跃区，供**下一拍** 02 读取；不重放本轮口头。
- 记忆打分：只入库，不改本轮口头、不改长期记忆。
- 对象确认：回填 01；本轮口头已按当时档案说，升格影响后续轮。

无冲突时对象确认应跳过，不要每轮另开一次「你是谁」评估。

## 7. 记忆现场打分

只打**已经在场**的 `memory:` 条目。没有则本条空，不要为打分去召回。

每条：

| 指标 | 取值 |
|------|------|
| `event_id` / 引用 | 对应在场条目 |
| `relevance` | related / partial / unrelated |
| `helps_understanding` | 0 无助 / 1 略有助 / 2 改变了理解 |
| `used_in_reply` | unused / alluded / Relied（开口后再评更准） |
| `misleading` | bool |
| `redundant` | bool |
| `object_fit` | match / other / none |

整轮：

| 指标 | 取值 |
|------|------|
| `coverage` | sufficient / thin / missing |
| `gap_query` | 缺什么、关于谁（人名或短句）；**不执行召回** |

打分是当场判断，不是有效性分析报告。报告与回忆策略由有效性分析系统事后做。

`drop_recall` 仍是活跃区补丁（建议移出活跃区），不改变长期记忆，也不表示「还缺材料」。

## 8. 回忆三层（05 只参与打分）

1. **认知前**：03 按说话人、当前 09 策略快照装一撮线索。这是本轮 05 能看见的唯一 09 来源。
2. **开口后**：本轮口头只用已在场材料。缺口只记账。需要时收尾之后或下一拍 03 再取。问及第三人（I-011 修订）：不在本轮二次认知；「我想起」发生在下一拍。
3. **后台**：有效性分析累积打分或到期后出报告与策略，经 09 策略接口落地。不进七阶段。

05 不调用 `MemoryPort.recall`，编排层也不在 05 之后为了再认知而召回。

## 9. 对象确认

模型判定说话人候选。confirm → 01 已确认；deny → 拒绝；uncertain → 保持暂定。不改写事实原文。不经 06。

渠道已指定本轮说话人时，按这个人说话；provisional 可以 confirm。不要把 uncertain 理解成每轮必问「你是……吗？」。只在重名未消歧、渠道与正文打架、或对方否认时，才用 `respond` 问清是哪一位（问句在回应条，不另开 mode）。见 01 §4.3。

独立再评估不得把无冲突的已指定说话人改成盘问。

`lookup_by_name` 仍供开口后 / 下一拍按名字补档案，不在 05 里为查询新建对象。

## 10. 上下文补丁：编新活跃区

心智以**补丁**形式给出删除与聚焦（省 token，不重写全文）：

```text
context_assessment
  remove:      要删除的段 id / memory:ref
  drop_recall: 本轮评价为低价值的回忆摘录
  focus:       要聚焦的段 id
```

空补丁合法。16 无补丁时仍合并待并入段（本轮输入以及若有的本轮回应），硬上限兜底。

主路径：10 之后 16 编排，不再为补丁调主认知模型。独立再评估见 §6。

## 11. 记忆投递（05 不执行）

05 可以读已在场回忆，不写记忆，不调用 `ingest`。

记忆收的是**新发生的**：新输入、新回应。不得把整份活跃区再当新记忆存一遍。

批次构造在 30。路径：07 → 30 → 09。

## 12. 记录、评价与参数

用词：05 产出的是**打分 / 候选**；综合报告属于有效性分析系统，不叫「对评价的评价」。

- 记录：请求摘要、最终 `response_plan`、记忆打分、对象确认、缩减与聚焦方案、来源链、skill 解析失败、独立再评估的模型版本；
- 有效性材料：记忆打分入库，由有效性分析系统消费；05 不写策略、不调档位；
- 参数：回忆档位归 09 策略快照；活跃区容量归 16 / 14；05 不调这些数。

## 13. 验收标准

- 模型请求含单列说话人，以及可寻址的本轮上下文；
- 最终主调用含 `response_plan`；无 `recall_requests`；不为召回二次调用 05；
- 活跃区补丁、记忆打分、对象确认可空；有则失败隔离；
- 05 自身不执行召回检索、不投递记忆、不编新活跃区、不标记活动；
- 独立再评估不阻塞 06 / 10 / 07；
- 对象与常驻约束不被缩减拿掉；
- 对象确认回填可追溯。

## 14. 与其他模块的关系

- 依赖：03（本轮上下文材料）、04（活动）、01（说话人候选）；
- 被依赖：06 / 10（只消费 `response_plan`）、01（确认回填）、16（补丁，可空）、有效性分析系统（记忆打分）；
- 02 不在 05 再读；08 不在 05 写入；09 不在 05 检索；
- 概念边界：本轮上下文 ≠ 仅经历窗口；方案 ≠ 已写入的活跃区；现场打分 ≠ 有效性分析报告；新输入 / 新回应 ≠ 上下文中的回忆。
