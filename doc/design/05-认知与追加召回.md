# 05 认知与追加召回

> 模块文档。术语以《概念词汇》为准，流程位置见《00 流程总览与输入边界》阶段⑤。
>
> 状态：定稿骨架。05 产出回应计划，以及对本轮上下文的补丁（删除段 / 删除回忆摘录 / 聚焦，模型响应字段 `context_assessment`）；召回检索、活跃区落盘、记忆投递和活动标记归下游。

## 1. 定位

本模块回答：**匠石如何看见本轮上下文，并交出回应计划与下一份活跃区的编排方案**。

基础认知模型即心智：它看见的是 03 装好的全体，不是「仅经历窗口」。一次响应给出 `response_plan`、上下文补丁（删除 / 聚焦），以及可选的召回请求与对象确认。

05 只做：组装模型请求、调用模型、按用途段校验后交出。

外部活动的基础认知走 skill（`CognitionSkill`，由 `SkillModelPort` 包成 `ModelPort`，主流程接口不变）：一次调用产出各用途段 JSON，程序校验枚举与通道后再分发。解析失败则本轮 `think`、verbal 为空，失败记入响应 `metadata.skill_fallback`，不把模型原文当说话。内部活动（反思）不套本 schema。对象确认不另开 skill。所用模型与 skill 版本记在 `model_tag`（I-004）。

05 不做：检索记忆、投递记忆、改 08 长期条目、把方案编成新活跃区、标记活动。

编排层（主流程）决定是否按召回请求再调一次 05；最终方案出来后，**不再调用模型**，按缩减与聚焦编出新活跃区。

## 2. 本轮上下文与活跃区

本轮上下文 = 03 工作集的全体，追加召回并入后仍是这一份。至少包括：

- 本轮输入
- 对象（说话人：`object_id`、`label`、`aliases`、`status`）
- 主体身份
- 已装入的个人世界（价值、承诺等）
- 回忆（初始线索 + 本轮追加召回）
- 上一份活跃区里仍在场的经历

缺对象则外部对话无意义。对象必须在请求里单列，缩减不得把它从新活跃区拿掉。

文本形态：模型与上下文一律使用原文（记忆片段原文即含名字）。多轮对话整段作为 `input_text` 进入，提示词聚焦最后一句为待回答；回忆查询保持原文，对象过滤仍用 `object_id`。

活跃区是**按方案编好、供下一轮继续面对的工作上下文**，由 16 保存、02 读取。它可以含经历，也可以含仍被保留的回忆摘录等。它是引用加现场正文，不是把 08 / 09 / 16 原文再存一份当真源。缩减只让条目离开活跃区，不删账本、不删记忆、不删个人世界。

承诺与边界等常驻约束，缩减不得拿掉。

```text
上一活跃区 + 本轮输入 + 对象 + 身份 + 个人世界 + 回忆
    → 本轮上下文（心智看见的全体）
    → 05：response_plan + 缩减方案 + 聚焦方案
    → 不再调模型，按方案编排（含本轮新输入，以及若有的本轮回应）
    → 新活跃区（16 保存）
```

本轮原话先作为 `input_text` 进模型，不在认知开始前并入上一份活跃区，以免补召回循环里裁掉刚听见的话，也避免同一句出现两次。并入发生在按方案编排新活跃区时。

## 3. 输入

阶段⑤ 开始时，编排层已经有：

| 输入 | 来自 | 角色 |
|------|------|------|
| 工作集 | 03 | 本轮上下文的材料：`input_text`、`speaker`、`subject_state`、`fragments`、上一活跃区 |
| 活动 | 04 | `activity_id`，本轮输出挂在这上面 |
| 感知 | 与 `input_text` 同一原文 | 已接受的对方表达；不另造第二路刺激 |

02 不在 05 里再读。08 / 09 的初始装载已在 03 完成。

## 4. 模型请求

```text
ModelRequest
  purpose            # 外部活动 / 反思
  input_text         # 本轮刺激
  speaker            # object_id, label, aliases, status（单列，不埋进分片才算有）
  subject_state      # 身份、立场、价值、承诺
  fragments          # 03 已编排的可读材料（含个人世界、回忆线索等）
  context            # 本轮上下文全体；条目可寻址（分片 id、经历段/句引用、回忆引用）
```

`context` 必须能指到具体条目，缩减与聚焦才可执行。说话人必须单列：对象确认对着具体候选，不能在分片里猜是谁。

## 5. 模型响应（用途段）

各段经过程序校验后再分发。模型输出 ≠ 已接受事实 ≠ 已经写入。

| 优先级 | 用途段 | 消费者 | 地位 |
|--------|--------|--------|------|
| 1 | `response_plan`（mode / reason / items；说话在 verbal.text；不另落 thought） | 06 → 10 | 必出 |
| 2 | `context_assessment`（上下文补丁）：`remove`（删除段）/ `drop_recall`（删除低价值回忆摘录）/ `focus`（聚焦段），段级引用寻址，只输出变更、不重写全文 | 编排层 → 16 编新活跃区 | 必出 |
| 3 | `recall_requests`（查询、档位、对象、锚点、预算） | 编排层 → 09 | 仅当初始装载不够 |
| 4 | `object_assessment`（confirm / deny / uncertain） | 01 | 对着单列说话人 |
| 5 | 重要性排序 | 14 | 占位 |

召回只保留 `recall_requests`。不再并列 `need_recall` 布尔。有请求就是要补；没有就是不用补。

**信息不足**（要不要向 09 补材料）与**已回溯记忆的质量**（在场的 `memory:` 摘录留不留、重不重）是两件事。前者只出 `recall_requests`；后者只出 `drop_recall` 与 `importance_ranking`。不要因为「整体不够」去 drop，也不要用 drop 代替召回。

缩减与聚焦彼此独立，可以同时有。方案须列出可寻址目标（分片 id、经历段/句引用、回忆引用等），并说明怎么退、什么留下作为注意中心。

若本轮仍有召回请求，当前这份 `response_plan` 与上下文方案都还不是最终结果；编排层补片段后再调 05。`wait` 不是「再想一轮」：补记忆在本轮 06 之前；`wait` 结束本轮活动。

容量参数（如活跃区比）由 14 管理，不在 05 展开算法。

## 6. 追加召回

本节只处理**信息不足**：要不要向 09 补材料。已在场回忆摘录的去留与打分见 §7 的 `drop_recall`，不要写进 `recall_requests`。

```text
05 交出 recall_requests
  → 编排层调 09 recall
  → 新片段并入本轮上下文，标为回忆
  → 不重跑 03，不回写本轮工作集注册表
  → 这一循环里不执行缩减或聚焦
  → 再次调用 05
```

编排层当前策略：最多再认知一次。轮数不是 05 的能力。

追加召回仍是只读已有记忆。补进来的条目在上下文里必须标成回忆，不得与本轮输入混成一类无标记文本。

对方问起另一个人（朋友、名字、关系）而材料不够，走本节，不是身份盘问。`object_ids` 用那人已有档案 id；对不上则只写 `query`，**不要**为此新建对象。编排层只补全模型已经提出的请求，不根据用户原话自动召回。召回后的第二次认知，口头须依据 `memory:` 片段，允许「我想起…」，不念 `event_id`；召回为空才可以说对不上。

## 7. 上下文补丁：编新活跃区

心智以**补丁**形式给出本轮上下文的删除与聚焦（省 token，不重写全文）：

```text
context_assessment（上下文补丁）
  remove:      要删除的段 id / memory:ref
  drop_recall: 本轮评价为低价值的回忆摘录（建议移出活跃区）
  focus:       要聚焦的段 id
```

之后：

1. 不再调用模型；
2. 编排层把补丁交给 16，16 先合并待并入段、再按补丁更新活跃区（段级，不切句）；
3. 本轮新输入以及若有的本轮回应一并进入这次编排；
4. 这是本轮工作，不是留到下一轮再想。

回忆摘录的质量评价本体走独立评价旁路（`recall_evaluated`）；`drop_recall` 只是 05 对**已经在场的**回忆摘录的上下文建议，不改变长期记忆，也不表示「还缺材料」（缺材料走 `recall_requests`）。05 不执行编排，只交出补丁。执行在最终认知之后、不再调模型；补充召回循环期间不裁。

## 8. 对象确认

模型判定说话人候选。confirm → 01 已确认；deny → 拒绝；uncertain → 保持暂定。不改写事实原文。不经 06。

渠道已指定本轮说话人时，按这个人说话；provisional 可以 confirm。不要把 uncertain 理解成每轮必问「你是……吗？」。只在重名未消歧、渠道与正文打架、或对方否认时，才用 `respond` 问清是哪一位（轻量路径，不加新 mode）。见 01 §4.3。占位模型不产出判定则跳过。

**召回形式**（对齐《记忆层契约》/ 09）：`RecalledFragment` 含 `event_id`（去重键）、`text`（原文）、`content`（按 `summary_level` 选出的摘要，供预算/组装）、`kind`、`object_id`、`source_ids`、`score`、`summary_level`。主仓进程内实现 `content` 落回原文、`summary_level` 为 None（真后端接入后提供多级摘要）。

**去重**：初始召回（03 MemorySource 装进工作集）与追加召回**按 `event_id` 共用去重集**；追加召回不再取回已在工作集的记忆，避免同一记忆在模型上下文出现两次。跨源（活跃区 `memory:ref` 摘录 vs 重召）去重暂未做，留待后续。

## 9. 记忆投递（05 不执行）

05 可以读回忆，不写记忆，不调用 `ingest`。

记忆收的是**新发生的**：新输入、新回应。不得把整份活跃区再当新记忆存一遍。

批次构造在 30（见《30 记忆数据管控》与《记忆层契约》）：30 只取 `memory_start` 之后**未投递的经历段**，按段映射 `MemoryExperience`，`origin` 标签即分型（`internal` → internal，其余 → external）。09 不再判别「这段是输入还是回忆」。

活跃区里的回忆摘录不是新经历段，**天然不进批次**：同一段回忆可以在新活跃区里有一份引用，但不会作为新记忆再次投递。

路径：07 → 30 → 09。来源标签在组装与召回时已经有（本轮刺激、`source=memory` / 追加召回、16 经历段）；30 按标签装箱，不靠模型事后分类。

## 10. 记录、评价与参数

- 记录：请求摘要、最终 `response_plan`、召回请求、对象确认、缩减与聚焦方案、来源链、skill 解析失败（`skill_fallback`）；
- 评价：不在 05 内生成；材料交给独立评价（旁路，不阻塞）；
- 参数：回忆档位语义归 09；活跃区容量归 16 / 14；编排轮数归主流程。05 不调这些数。

## 11. 验收标准

- 模型请求含单列说话人，以及可寻址的本轮上下文；
- 最终响应含 `response_plan`、缩减方案、聚焦方案；
- 05 自身不执行召回检索、不投递记忆、不编新活跃区、不标记活动；
- 追加召回循环中不裁剪；最终方案之后不再调模型即编排；
- 交给 09 的批次若含回忆，必须已分型；
- 对象与常驻约束不被缩减拿掉；
- 对象确认回填可追溯。

## 12. 与其他模块的关系

- 依赖：03（本轮上下文材料）、04（活动）、01（说话人候选）；
- 被依赖：06（标记 `response_plan`）、10（分发）、01（确认回填）、编排层调 09 召回、16（按方案保存新活跃区）、30（分型批次）；
- 02 不在 05 再读；08 不在 05 写入；
- 概念边界：本轮上下文 ≠ 仅经历窗口；方案 ≠ 已写入的活跃区；召回 ≠ 投递；新输入 / 新回应 ≠ 上下文中的回忆。

## 13. 占位与牵连

本轮不纳入：流式分段消费（I-001 的流式部分；一次调用多用途段已由 skill 落地）、用途段人工介入（15）、重要性排序执行（14）、主观评价过程。

03 本轮输入与对象必装；常驻承诺仍由 08 保证（避免每轮把已缩减的普通价值灌回，细节归 03）。30 / 09 批次分型：`new_input` / `new_response` / `in_context_recalls`。
