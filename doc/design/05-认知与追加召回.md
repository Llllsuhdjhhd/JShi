# 05 认知

> 模块文档。术语以《概念词汇》为准，流程位置见《00 流程总览与输入边界》阶段⑤。
>
> 状态：校准中（D-008；D-009）。文件名仍含「追加召回」，本模块**不再**同轮补召回、不再为召回二次调模型。风格包与活跃区整份重写见《提示词风格与活跃区全改》。

## 1. 定位

本模块回答：**匠石如何看见本轮上下文，并交出对外回应。**

基础认知模型即心智：它看见的是 03 装好的全体。主路径一次调用交出 `response_plan`（语言 / 动作），以及**整份新活跃区正文**（按当前风格包重写）。对象确认仍可空、可开口后独立再评估。本轮**不做**记忆现场打分。

05 不做：检索记忆、投递记忆、改 08 / 01 真源、把现场正文 ingest 进 09、标记活动、同轮再召回再认知。不另开一轮「木头心智」。风格包只改写法和现场，主体仍是匠石。

编排层拿到 `response_plan` 即走 06 → 10。其余条目不阻塞这条路。

外部活动的基础认知走 skill（`CognitionSkill`，由 `SkillModelPort` 包成 `ModelPort`）：主调用产出回应 JSON。解析失败则本轮 `think`、verbal 为空，失败记入 `metadata.skill_fallback`，不把模型原文当说话。内部活动（反思）不套本 schema。所用模型与 skill 版本记在 `model_tag`（I-004）。

## 2. 本轮上下文与活跃区

本轮上下文 = 03 工作集的全体。回忆只含 **03 已装入的线索**（按说话人、当前策略快照的最低档），不含同轮补召回。

至少包括：

- 本轮输入
- 对象（说话人：`object_id`、`label`、`aliases`、`status`）
- 主体身份
- 已装入的个人世界
- 回忆（03 初始装载）
- 上一份活跃区里仍在场的经历

缺对象则外部对话无意义。对象必须在请求里单列。01 档案与 08 承诺的**实质**不得改；它们在新活跃区里须按当前风格**重写进去**，不是留在现场外的原文块，也不得从现场里丢掉这个人、否掉这条承诺。

材料层交给模型的是原文（本轮 `input_text`、本轮新回忆、01/08 真源）。上一份活跃区已是按风格写过的现场，不必仍是账本原文。多轮对话整段作为 `input_text` 进入，提示词聚焦最后一句为待回答。对人只用名字，默认不出现 `object_id`。提示词只称匠石，不出现风格包配置名。

活跃区是**按当前风格整份重写、供下一轮继续面对的工作上下文**，由 16 保存、02 读取。重写只改现场正文，不删账本、不删 09、不改 08。分析不对齐现场与 09，对齐召回触发流水。

```text
上一活跃区 + 本轮输入 + 对象真源 + 身份 + 08 真源 + 03 已装回忆
    → 本轮上下文（心智看见的全体）
    → 05 主调用：response_plan（必出）+ 整份新活跃区正文（必出）
    → 06 → 10
    → 16：保存该正文；失败则保留上一份；硬上限截断
```

本轮原话先作为 `input_text` 进模型，不在认知开始前并入上一份活跃区。以重写后的形态进入现场，发生在 16 保存时。

## 3. 输入

阶段⑤ 开始时，编排层已经有：

| 输入 | 来自 | 角色 |
|------|------|------|
| 工作集 | 03 | `input_text`、`speaker`、`subject_state`、`fragments`、上一活跃区 |

| 感知 | 与 `input_text` 同一原文 | 已接受的对方表达 |

02 不在 05 里再读。08 / 09 的初始装载已在 03 完成。05 不再向 09 提出本轮检索。

## 4. 模型请求

```text
ModelRequest
  purpose            # 外部活动 / 反思
  input_text         # 本轮刺激
  speaker            # object_id, label, aliases, status
  subject_state
  fragments
  context            # 可寻址（分片 id、经历段引用、回忆引用）
```

发给模型时：稳定规则、当前风格包的写法要求、身份与 08 真源在 `system`；本轮原话、上一活跃区、本轮新回忆在 `user`。`ModelRequest.speaker` 仍单列。工作集里的身份/对象分片不因 HTTP 省略而删除。风格包由主体配置提供，不写进说话人字段。

本轮原话进账本时不加说话人名前缀。不纳入流式分段（I-001）。

独立再评估（§6）用各自的请求，不复用「必须同时填完四条」的主 schema。

## 5. 四条产出

各条经过程序校验后再分发。模型输出 ≠ 已接受事实 ≠ 已经写入。

| 条 | 字段 | 消费者 | 主路径 |
|----|------|--------|--------|
| 1 回应 | `response_plan`（mode / reason / items） | 06 → 10 | **必出**；按当前风格开口 |
| 2 新活跃区 | 整份现场正文 | 16 保存 | **必出**；按当前风格重写全体（含对象与承诺的叙述） |
| 3 记忆现场打分 | `memory_ratings` | — | **本轮不做**；字段可空 |
| 4 对象确认 | `object_assessment` | 01 | 无冲突可跳过；可开口后独立再评估 |

不再产出 `recall_requests`。不再并列 `need_recall`。不再交出 `remove` / `drop_recall` / `focus` 补丁。

**缺材料**不在本轮取记忆、不二次认知。需要时，收尾之后或下一拍 03 再取（见 §8）。召回了什么、由哪次输入触发，记在材料层流水，不靠本条打分。

`wait` 结束本轮活动，不是「再想一轮」。

容量参数由 14 / 魔法书管理，不在 05 展开算法。

## 6. 独立再评估

对象确认与口头**彼此独立**：确认失败不回滚已经发出的口头。活跃区正文与口头同一次主调用交出；正文解析失败则 16 保留上一份现场，不挡口头。本轮不跑打分，也不为打分开独立再评估。

可以：

- 主调用顺手带上（不校验为必填）；
- 本轮跳过；
- 开口之后（06/10 之后，或活动已关闭）另调模型重新评估。

独立再评估是旁路：不挡 06 / 10 / 07 / 30。所用模型可配（I-004），不必与主认知同一档。

晚到的结果如何落地：

- 活跃区：主路径已保存整份正文。开口后若另写一份现场，覆盖已保存活跃区，供**下一拍** 02 读取；不重放本轮口头。
- 记忆打分：本轮不入库。
- 对象确认：回填 01；本轮口头已按当时档案说，升格影响后续轮。不改对象档案的事实字段以外的确认状态规则，见 01。

无冲突时对象确认应跳过，不要每轮另开一次「你是谁」评估。

## 7. 记忆现场打分

**本轮不做。** 字段可空。不要为打分去召回。有效性分析以后改吃召回触发流水，见《提示词风格与活跃区全改》§7。

下列指标保留为以后若恢复打分时的形状，本轮主路径不填：

每条：

| 指标 | 取值 |
|------|------|
| `event_id` / 引用 | 对应在场条目 |
| `relevance` | related / partial / unrelated |
| `helps_understanding` | 0 无助 / 1 略有助 / 2 改变了理解 |
| `used_in_reply` | unused / alluded / Relied（开口后再评更准） |
| `misleading` | bool |
| `redundant` | bool |
| `object_fit` | match / other / none |

整轮：

| 指标 | 取值 |
|------|------|
| `coverage` | sufficient / thin / missing |
| `gap_query` | 缺什么、关于谁（人名或短句）；**不执行召回** |

打分是当场判断，不是有效性分析报告。报告与回忆策略由有效性分析系统事后做。

本轮无 `drop_recall`。从现场拿掉某条回忆只表现在整份重写里，不改长期记忆。

## 8. 回忆三层（05 本轮不打分）

1. **认知前**：03 按说话人、当前 09 策略快照装一撮线索，并记下触发流水。这是本轮 05 能看见的唯一 09 来源。
2. **开口后**：本轮口头只用已在场材料。需要时收尾之后或下一拍 03 再取。问及第三人（I-011 修订）：不在本轮二次认知；「我想起」发生在下一拍。
3. **后台**：有效性分析以后用触发流水做报告与策略，经 09 策略接口落地。不进七阶段。本轮不靠现场打分推进。

05 不调用 `MemoryPort.recall`，编排层也不在 05 之后为了再认知而召回。

## 9. 对象确认

模型判定说话人候选。confirm → 01 已确认；deny → 拒绝；uncertain → 保持暂定。不改写事实原文。不经 06。

渠道已指定本轮说话人时，按这个人说话；provisional 可以 confirm。不要把 uncertain 理解成每轮必问「你是……吗？」。只在重名未消歧、渠道与正文打架、或对方否认时，才用 `respond` 问清是哪一位（问句在回应条，不另开 mode）。见 01 §4.3。

独立再评估不得把无冲突的已指定说话人改成盘问。

`lookup_by_name` 仍供开口后 / 下一拍按名字补档案，不在 05 里为查询新建对象。

## 10. 整份重写活跃区

心智交出**整份新现场正文**（按当前风格整理本轮看见的全体：上一现场、本轮原话、新回忆、对象与承诺的叙述）：

```text
rewritten_context
  context_text    # 下一轮 02 要读的全文
```

16 只保存、截断，不再按段引用拼装，不再调模型。正文解析失败或为空：保留上一份活跃区，不清空。

切换风格包是硬切：下一轮 05 用新写法要求把当前现场与材料层真源整写一遍，仍覆盖主体这一份活跃区。

主路径：10 之后 16 保存。独立再评估见 §6。

## 11. 记忆投递（05 不执行）

05 可以读已在场回忆，不写记忆，不调用 `ingest`。

记忆收的是**新发生的**：新输入、新回应。不得把整份活跃区再当新记忆存一遍。

批次构造在 30。路径：07 → 30 → 09。

## 12. 记录、评价与参数

用词：本轮 05 不产出现场打分；召回触发流水由 03 记。综合报告属于有效性分析系统。

- 记录：请求摘要、所用风格包配置名（审计用，不进提示词）、最终 `response_plan`、新活跃区是否交出、对象确认、来源链、skill 解析失败；
- 有效性材料：本轮不入库打分；分析以后用召回触发流水；
- 参数：回忆档位归 09 策略快照；活跃区容量归 16 / 14；风格包由主体配置选择；05 不调这些数。

## 13. 验收标准

- 模型请求含单列说话人、当前风格包的写法要求（提示词中无配置名）、以及本轮上下文；
- 最终主调用含 `response_plan` 与整份新活跃区正文；无 `recall_requests`；不为召回二次调用 05；
- 记忆打分本轮空；对象确认可空；现场正文失败则保留上一份，不挡口头；
- 05 自身不执行召回检索、不投递记忆、不写 16、不标记活动、不改 01/08 真源；
- 对象是谁、承诺内容与是否有效，不得因重写而改变；
- 对象确认回填可追溯。

## 14. 与其他模块的关系

- 依赖：03（本轮上下文材料）、04（活动）、01（说话人候选）；
- 被依赖：06 / 10（只消费 `response_plan`）、01（确认回填）、16（保存整份现场正文）；
- 02 不在 05 再读；08 不在 05 写入；09 不在 05 检索；
- 概念边界：本轮上下文 ≠ 仅经历窗口；新现场正文 ≠ 已写入的活跃区（写入在 16）；新输入 / 新回应 ≠ 09 原文；风格包 ≠ 另一个主体。
