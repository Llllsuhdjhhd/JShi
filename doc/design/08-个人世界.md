# 08 个人世界

> 状态：初稿。
> 本文是个人世界的**统筹入口**，只定义个人世界如何被组织、装载和进入当前状态；各组成部分的细节由独立子模块负责。

## 1. 定位

个人世界使不同匠石在使用相同基础认知时仍形成差异。它不是一个巨型仓库，而是一组相互独立、但统一装载的长期内容系统。

08 负责：

- 统一个人世界条目的基础模型、来源、状态和版本；
- 决定一次活动装载哪些条目、以什么顺序和预算进入状态组装；
- 汇总承诺、主体面未完成现实和不可越过边界为常驻约束；
- 给 `03 状态组装` 提供稳定装载视图。

08 不负责：

- 某类个人世界内容如何产生、如何整理、如何加锁；
- 记忆原文的保管和召回；
- 事件本体的生命周期。

## 2. 拆分原则

个人世界内容较多，按“一个子系统一套稳定接口”拆开，便于后续单独实现和替换。08 只做协调，不把细节塞在一起。

当前拆分关系：

| 编号 | 子系统 | 是否已展开 |
|------|--------|------------|
| 09 | 记忆系统 | 已有独立模块 |
| 100 | 价值观与边界 | 本轮展开为详细设计 |
| 101 | 关系与承诺 | 预留 |
| 102 | 能力 | 预留 |
| 103 | 审美 | 预留 |
| 104 | 自我理解 | 预留 |

`concern` 在长期迁移到 `07 事件生命周期`，不在个人世界内部长期保留。`PersonalKind.MEMORY` 只表示“指向记忆系统的引用”，不等于 09 记忆系统本身。

## 3. 统一条目模型

当前最小实现继续使用 `PersonalItem`，字段如下：

| 字段 | 含义 |
|------|------|
| `id` | 条目标识 |
| `subject_id` | 所属匠石 |
| `kind` | 个人世界类型 |
| `content` | 条目内容 |
| `source_ids` | 来源链 |
| `status` | 活动状态 |
| `metadata` | 类型相关附加字段，如 `importance`、`role` |
| `revision` | 版本 |
| `created_at` / `updated_at` | 时间 |

各子模块可以在 `metadata` 中先扩展自己的字段；当某类内容足够复杂后，再迁移为独立存储或独立 `PersonalKind`。

## 4. 接口契约

08 保留现有个人世界装载接口，并对子模块进行协调：

- `select(subject_id, query, *, budget)`：选择普通个人世界条目；
- `standing_constraints(subject_id)`：返回常驻约束；
- `select_boundaries(subject_id)`：单独返回不可越过边界，供行动前检查；
- `report(subject_id, budget)`：输出本次装载报告，交给 `03 状态组装`。

子模块只需实现各自的选择 / 写入 / 整理能力；08 不假设它们内部怎么实现。

## 5. 装载与预算

个人世界条目数量可能很大，不能全量进入模型上下文：

1. 常驻约束优先：承诺、主体面未完成现实、`binding` 边界；
2. 普通条目按当前情境匹配度筛选；
3. 同一匹配档内按 `importance` 排序；
4. 预算内截断，跳过项进入装载报告；
5. 边界条目不因普通内容预算耗尽而丢失。

预算参数由 `14 统计分析与参数调优` 管理，当前不把具体数值写死为稳定规则。

## 6. 正常活动与后台沉淀的边界

- 正常活动只读取已有个人世界，不临时编造长期价值、关系、能力、审美或自我理解；
- 正常活动产生的候选理解先进入历史和认知状态；
- 各子模块的后台过程负责整理、审查、升格、取代和加锁；
- 原始来源和旧版本必须保留，派生解释不能覆盖原始记录。

## 7. 验收标准

- `03 状态组装` 能通过 08 统一装载各子模块内容；
- 常驻约束始终在场；
- 普通条目按情境和预算截断，跳过项可追踪；
- 各子模块失败不会污染整个个人世界装载；
- 正常活动不会无声改写长期个人世界。

## 8. 与其他模块的关系

- 依赖 `00`：正常活动与后台沉淀边界；
- 被 `03 状态组装` 调用；
- 与 `09 记忆系统` 平行，负责长期判断而非原文召回；
- 与 `07 事件生命周期` 协作，`concern` 长期迁移到事件本体；
- 与 `11 治理与连续性`、`12 反思`、`14 统计分析与参数调优`、`15 人工介入` 通过各自子模块协作。

## 9. 记录、评价与参数影响

| 项目 | 内容 |
|------|------|
| 记录点 | 个人世界装载报告、各子模块写入/迁移记录 |
| 评价点 | 装载命中率、跳过率、常驻约束覆盖、子模块失败率 |
| 可调参数 | 普通内容预算、常驻约束策略、情境标签匹配方式 |

具体子模块的参数在各自文档中登记，08 只保留总览。

## 10. 扩展性预留

- 新增个人世界子模块时，只需在 08 注册装载源，不修改主流程；
- 101–104 已预留编号，后续按“一个子系统一份详细设计”展开；
- 各子模块先通过 `metadata` 演进，再决定是否拆成独立 `PersonalKind` 或存储表。
