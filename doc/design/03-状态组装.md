# 03 状态组装

> 模块文档。术语以《概念词汇》为准，流程位置见《00 流程总览与输入边界》阶段③。
>
> 状态：初稿，待讨论定稿。本文只用文字与表格描述接口，不出现实现代码。

## 1. 定位

本模块回答一个问题：**一次活动进模型之前，匠石以什么状态面对这条输入**。

它把多个来源——身份、个人世界、事件、记忆、认识状态、对象信息——中**已经存在**的内容收集起来，合并为一个只读的**工作集**和一份**主体状态快照**，交给后续认知阶段。

关键边界：03 是**组装编排者**，不是任何装载逻辑的实现者。记忆怎么检索、价值怎么排序、事件怎么筛选，分别属于 09、08、07/02 自己的实现；03 只负责发起请求、收集结果、合并去重、预算汇总和记账。

## 2. 职责与边界

### 2.1 03 做什么

- 向各装载源发出组装请求；
- 收集各源返回的装载片段；
- 按规则合并去重；
- 核算预算（常驻与按预算两类）；
- 生成主体状态快照与统一工作集；
- 记账 `current_state_assembled`（含各源装载明细，供 14 统计分析）。

### 2.2 03 不做什么

- 不实现记忆检索、价值排序、事件筛选等装载逻辑；
- 不调用模型；
- 不编造未完成事件或任何长期个人内容；
- 不写入长期记录（`current_state_assembled` 记账除外）；
- 不做认知阶段的追加召回（那是 05 的职责，03 只提供工作集扩展接口）。

## 3. 装载源

当前设计固定六个装载源；每个源是一个独立模块，可单独实现、替换，互不牵连：

| 源 | 装载内容 | 常驻 / 预算 | 实现方 | 本期状态 |
|----|----------|-------------|--------|----------|
| 身份源 | 身份档案、叙事、当前立场 | 常驻（不占预算） | 01 / 身份系统 | 由现有身份档案提供 |
| 个人世界源 | 价值、承诺、关系、能力、审美、自我理解 | 承诺常驻；其余按重要程度与预算 | 08 | 按重要程度排序、预算内截断（最小实现） |
| 事件源 | 未完成事件 + 完成事件 | 未完成常驻；完成按活跃区预算 | 07，视图由 02 提供 | 直接使用阶段② 活跃区视图 |
| 记忆源 | 历史事实线索召回 | 线索级档位 + 对象过滤 + 预算 | 09 | 阶段③ 用最低可用档出线索；深挖由 05 追加 |
| 认识状态源 | 已接受 / 暂定认知的背景 | 常驻 | 06 | 占位为空 |
| 对象源 | 说话人对象档案摘要 | 可选 | 01 | 占位为空 |

## 4. 统一装载源接口（文字描述）

为了不让 03 依赖每个模块各自的具体接口，设计采用**一个统一的装载能力**：

### 4.1 装载能力

每个装载源都提供同一个能力：**装载**。装载源接收一份组装请求，返回一组装载片段，并说明自己实际使用了多少预算。

### 4.2 组装请求包含

- 主体标识：哪个匠石；
- 输入文字：本次输入原文；
- 说话人对象标识：本次输入来自哪个对象（记忆源按对象过滤、对象源摘要使用）；
- 活跃区视图：阶段② 的装载结果，事件源直接使用，不重复读取；
- 组装额外预算：活跃区之外内容（个人世界、记忆、认识状态、对象）的装载预算，默认 = 活跃区预算 × 1/2（占位换算见 §5.4）；
- 回忆档位：本次装载使用的回忆力度（1–9，阶段③ 用最低可用档，见 §5.5；具体档位语义由 09 定义）；
- 可选的显式引用：输入信封或活动上下文携带的事件标识、对象标识（未来）。

### 4.3 装载片段包含

| 字段 | 说明 |
|------|------|
| 来源类型 | 身份 / 个人世界 / 事件 / 记忆 / 认识状态 / 对象 |
| 标识 | 片段在存储中的唯一标识 |
| 内容 | 进入工作集的文本 |
| 子类型 | 源内分类，如价值、承诺、事件状态、认知状态 |
| 状态 | 活跃 / 完成 / 考虑中 / 已接受等 |
| 重要程度 | 供排序与未来预算使用 |
| 来源链 | 该片段依据的历史或认知来源，可追溯 |
| 是否常驻 | 常驻片段不占预算（身份、承诺、未完成事件） |

### 4.4 新装载源的接入

以后出现新的装载来源（例如场景、工具结果），只需实现同一个装载能力并在组装器注册，03 本身不改。

## 5. 组装器行为

### 5.1 流程

1. 接收组装请求（含阶段② 活跃区视图）；
2. 调用各装载源：各源相互独立，接口不规定顺序，可并行；占位实现先顺序执行（本地存储读取开销小，并行收益低、复杂度高），未来源服务化或实测有收益时启用并行；
3. 收集装载片段；
4. 合并去重；
5. 生成主体状态快照与统一工作集；
6. 受约束偶然性横向作用于组装结果（位置与现状一致）；
7. 记账。

单个装载源失败（异常或超时）时，03 记录失败原因，继续使用其余源的结果；失败不阻断整个组装（失败隔离）。

### 5.2 合并去重规则

- 同一标识的片段只保留一次；
- 保留优先级：事件源 > 个人世界源 > 记忆源；
- 承诺与未完成事件不重复出现：未完成事件由事件源负责，个人世界源跳过同类条目；
- 完成事件只出现在事件源，不作为未完成现实进入主体状态快照。

### 5.3 预算规则

- 常驻内容始终在场：身份、承诺、未完成事件；
- 其余内容按预算装载：事件按活跃区预算、个人世界按重要程度截断、记忆按查询预算；
- **组装额外预算**（活跃区之外的内容）默认 = 活跃区预算 × 1/2：活跃区 8 条 → 额外 4 条（占位条数）；未来按 token 换算为 活跃区 ≈ 上下文 × 1/66，额外 ≈ 活跃区 × 1/2 ≈ 上下文 × 1/132（软约束）；
- **系数说明**：1/2 是实验占位假设，没有理论依据；参数形式（与活跃区挂钩、随上下文缩放）合理，具体系数须由 14 在验证后调整；
- 总预算由 03 控制，各源自行决定在自己的份额内装什么；
- 超预算的跳过项进入记账报告，供 14 分析。

### 5.4 上下文参数统一管理

所有与上下文相关的参数统一登记、统一管理，模块不自行拍常数：

| 参数 | 占位默认 | 说明 |
|------|----------|------|
| 活跃区比 | 上下文 × 1/66 | 02 的活跃区预算（软约束） |
| 组装额外装载比 | 活跃区 × 1/2 | 03 的额外预算（≈ 上下文 × 1/132） |
| 追加召回预算 | 轮次与片段上限 | 05 的追加召回占位 |
| 个人世界装载预算 | 模块内配置 | 08 的内部预算 |
| 阶段③ 回忆档位 | 线索级（最低可用档） | 09 回忆接口的力度，1–9 |
| 追加回忆档位 | 由模型请求指定 | 05 追加召回时可选择合适档位 |

参数调整须留审计记录，并由 14 统计分析系统动态调整；当前均为可配置占位值，不进入稳定原则。

### 5.5 回忆基准与档位

- **回忆基准**：阶段③ 的记忆线索以**当前说话人对象**为过滤基准，**近因优先**（最近优先），输入文字的词重叠只作为排序加权；**活跃区内容不作为查询基准**——活跃区已经是已装载的过去，再用它查询属于重复装载，违背增量原则；
- **为何不特判短输入**：输入过短（如"继续"）时无需单独规则——近因优先本身就是低信号场景的默认策略，特判属于补丁式规则，反而增加复杂度；
- **回忆档位**：记忆系统回忆接口按 1–9 档（1 极低 ~ 9 最高）；阶段③ 使用**最低可用档**（线索级，少而浅）；模型在认知阶段追加召回时，可在请求中指定**合适的档位**（可高于最低档），程序校验预算后执行；
- **档位语义**：每档具体对应多少片段、多深的内容，由 09 记忆系统定义；03 只约定"低档出线索、高档出深挖"这一分工，不在 03 拍具体档位编号。

### 5.6 输出

- **统一工作集**：全部装载片段的合并视图，是进模型上下文的主要材料；
- **主体状态快照**：身份摘要、当前立场、价值、承诺、未完成事件文本，带来源标注；
- **装载报告**：每个源的装载数、预算、片段标识、跳过项，写入记账历史。

## 6. 与阶段② / 阶段⑤ 的边界

- 阶段② 的活跃区视图作为组装请求的一部分传入，事件源直接消费，不重复读取；
- 03 只做**初始装载**；认知阶段发现不足时，由 05 提出追加召回，通过**工作集追加**接口扩展工作集（03 定义接口，不执行检索）；
- 追加内容仍是候选背景，不自动成为立场；
- 阶段③ 不携带文本召回片段：记忆源默认不主动召回。

## 7. 占位与未来

本期实现（占位 → 最小）：

- 统一装载能力 + 适配器包装现有实现（身份档案、个人世界、活跃区视图）；
- 认识状态源、对象源占位为空；
- 预算按条数（额外 = 活跃区 × 1/2）；
- 组装器顺序调用各源（本地占位阶段），接口保持并行兼容；
- 单源失败记录原因，不影响其余源（占位规则）。

未来接入：

- 真实记忆引擎（09）、个人世界排序引擎（08）、事件本体独立（07）；
- 认识状态背景装载（06）；
- 对象档案摘要（01）；
- 按 token 的预算换算与动态调整（14）；
- 按实测启用并行装载（源服务化后）；
- 增量装载、流式装载。

## 8. 验收标准

- 阶段③ 不调用模型；
- 同一活动只读已有记录：除记账外不新增事件、个人条目或历史；
- 常驻内容始终在场：身份、承诺、未完成事件；
- 阶段③ 记忆线索按说话人对象过滤、近因优先、使用最低可用档；活跃区不作为查询基准；
- 追加召回支持模型指定回忆档位（1–9），程序校验预算后执行；
- 组装额外预算按活跃区 × 1/2 核算，超预算跳过项进入报告；
- 预算内截断生效，装载报告可追溯（各源装载数、标识、跳过项）；
- 去重正确：同一事件不在事件源与个人世界源重复出现；
- 新装载源接入无需修改组装器；
- 单个源失败不影响其余源，失败原因有记录（失败隔离）；
- 初始工作集不包含文本召回片段（追加召回由 05 完成）；
- 工作集可被 05 通过追加接口扩展，扩展后记账可追溯。

## 9. 与其他模块的关系

- 依赖：01（身份档案、对象信息）、02（活跃区视图）、08（个人世界装载）、09（记忆，回忆档位语义由 09 定义）、07（事件本体，未来）、06（认识状态，未来）；
- 被依赖：04（活动使用工作集）、05（消费工作集并追加）、14（读取装载报告调参）；
- 概念边界：工作集 ≠ 长期记忆；快照 ≠ 身份本身；初始装载 ≠ 追加召回。

## 10. 扩展性预留

- 新装载源注册制，03 核心不改；
- 预算从条数升级到 token；
- 增量装载与流式装载；
- 并行装载（各源独立、合并阶段再做汇总）；
- 上下文裁剪策略：总预算由 03 控制，各源内部如何取舍由各源自己决定。
