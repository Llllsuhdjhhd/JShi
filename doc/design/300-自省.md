## 1. 定位

自省是匠石**在没有直接外部请求时回头看自己**的活动：当时是什么情形、我怎么选的、结果如何、
我能不能做得更好、以后该怎么做、值不值得记下来并学会。

- 它的对象是**自己的经历与选择**（由刺激引发，见 §2），不是系统功能的统计结论（后者属 400）；
- 它与**主流程并行**，与**做梦**等后台过程并行；不挡说话，不占主流程的拍；
- 它产出的是**候选**（认识、自我认识、行为倾向），不直接改写人格、参数与长期个人世界；
- **「学会」不在本模块**：自省只判断"值不值得学"并交出候选，长期变化由 500 学习负责；
- 它不是功能分析与调参（400 的事），不是记忆整理（30 / 09 的事），不是治理（11 的事）；
- 它属于《概念词汇》的「内在活动」；输出带来源、状态与版本（「后台沉淀」约束）。

## 2. 触发（由刺激发起，不按计划）

自省不按计划跑，由刺激引发：

| 触发源 | 说明 | 典型及时性 | 现状 |
|--------|------|-----------|------|
| 事件的结果触发 | 某一轮的结果 / 失败 / 意外（07 收尾） | 尽快（意外可升急） | **先做** |
| 闲时的随机回忆 | 无外部输入时回顾一段旧经历 | 缓 | **先做** |
| 边界被触碰 | 一次活动踩到自己的 `binding` 边界（拒绝 / 换说法 / 声明不谈） | 急 | 可接（100 边界常驻） |
| 认识被修正 / 驳回 | 认识状态迁移到 REVISED / REJECTED | 尽快 | 可接 |
| 同类事件重复 | 同一对象 / 同一场景短期内反复同一问题或同一失败 | 缓 | 可接 |
| 承诺到期或被违反 | 08 的 `COMMITMENT` 条目 | 急 | 可接 |
| 人工 / 治理显式要求 | 15 人工介入、11 治理校验点 | 按人要求 | 可接 |
| 对象关系显著变化 | 新对象首次出现、长期未联系的对象回来 | 缓 | 可接 |
| 强烈情绪触发 | 情绪强度过阈 | 急 | JShi 尚无情绪模块，等有了再接 |

共同点：**触发源在自省之外**。自省侧只决定"接不接受这次触发"——按等级给门槛、按预算给上限、
按主题去重（同一件事一段时间内不重复自省）。

**只认"已发生、已有记录"**：触发源必须是已经留下记录的东西，不是"未了结"的常驻状态
（D-007 废除 concern 后，不从这里把"未完成现实"放回来）。

**先做有的、简单的**：先接**事件结果**与**闲时回顾**这两个；其余可接的按需要加，情绪等落地再接。

**不是触发源的三类**：

- 做梦产物——**做梦归做梦**，它是独立的后台过程，不触发自省；
- 记忆侧信号（即将淡出 / 情绪唤醒高 / 久未回顾）——属"闲时回顾"的**选材偏置**，不是独立触发源；
- 召回质量、工具质量等功能信号——归 400，不是自省的触发源。

> 功能性的那部分（回忆质量、魔法数、耗时、工具质量、模型评估）由计划与统计驱动，不属本模块，
> 见 §6 与 400。

### 2.1 入口与信封：每个源怎么接

**原则**：源只做一件事——把自己的特殊性翻译成一个**统一信封**。信封之后（队列 / 排程 / 现场 /
六问 / 产出 / 记录）对源一无所知。

**信封字段**（每个源都必须填满）：

| 字段 | 说明 |
|------|------|
| `trigger` | 哪个源（枚举值） |
| **条目** `entry_ref` / `entry_at` / `entry_text`（+ 可选 `object_id`） | 被考察的那条记录、它发生的时间、它的文本 |
| `default_level` / `default_urgency` | 建议的投入与及时性（判定层可覆盖） |
| `evidence` | 源看到的原始信号（mode / 工具结果 / 边界 id / 迁移前后状态…）：现场要用、溯源要用、400 也要用 |
| `dedup_key` | 主题键（冷却 / 去重） |
| `source_ids` | 证据 id，供溯源 |

**三种时刻（moment）**——入口不是 9 个源各跑各的，而是三个时刻统一扫：

| moment | 什么时候 | 谁调 | 哪些源响应 |
|--------|----------|------|------------|
| `after_activity` | 07 收尾后 | 主流程一行钩子 | 事件结果、同类重复、认识被修正 |
| `idle` | 没有外部输入时 | 宿主显式调（以后定时 / 夜间挂这里） | 闲时回顾、承诺到期、对象关系变化 |
| `explicit` | 人 / 治理要求 | CLI、15、11 | 人工、治理 |

**探测器住在哪**：集中放 300（`reflection/sources/`），各自**只读**别的模块的数据（账本 /
认识迁移 / 承诺条目），由 300 自己 pump。**两个例外**：事件结果要在 `experience()` 末尾加一行钩子
（那个时刻在别人的流程里），人工要有 CLI 入口。这样每个源能单独测，通用过程用假信封测。

**入口层统一处理三件事**（否则每个源会各踩一遍）：

1. **同一条记录合并**：一次活动可能同时命中"没开口""踩到边界""工具失败"→ 合成**一条**自省
   （条目 = 该活动，`evidence` 里列全部信号），否则会同时开三条自省回顾同一件事；
2. **聚合型源**（同类重复、对象关系变化）：条目是窗口 / 对象，不是一条活动 → 去重键用窗口键 /
   对象键，冷却更长，只在 `after_activity` / `idle` 扫；
3. **时间型源**（承诺到期、闲时）：不依赖外部输入 → 只能 `idle` 扫，绝不挂主流程钩子。

**逐源接法**：

| 源 | 信号今天有吗 | moment | 条目 | 去重键 | 默认 投入/及时 |
|----|--------------|--------|------|--------|----------------|
| 事件结果 | △ 弱信号：工具 `ToolStatus` 非 `ok` 可用；`mode=think` **不作信号**（正常沉默），且"结果好不好"常要下一轮才知道（§11-C20 / C21） | after_activity | `activity:<id>` | activity id | 中 / 尽快 |
| 闲时回顾 | ✓ 现成（宿主时刻 + 账本） | idle | `segment:<id>` | segment id | 低 / 缓 |
| 认识被修正 / 驳回 | ✓ 现成（`transition_cognition` 的迁移） | after_activity | `cognition:<id>` | cognition id | 中 / 尽快 |
| 同类事件重复 | ✓ 可从账本算（要先定"同类"与窗口） | after_activity / idle | `window:<对象>:<模式>:<起止>` | 窗口键 | 高 / 缓 |
| 对象关系变化 | △ 可算（"多久算久"要定） | idle | `relationship:<object_id>` | object id | 中 / 缓 |
| 人工 / 治理 | ✓ 现成（CLI；11 / 15 占位） | explicit | `manual:<主题>` | 归一化主题 | 高 / 尽快 |
| 强烈情绪 | ✗ 无情绪模块 | idle | `emotion:<event_id>` | event id | 中高 / 急 |
| 边界被触碰 | ✗ **今天没有信号**（§11-C16） | — | `activity:<id>` | boundary id | 中高 / 急 |
| 承诺到期 / 被违反 | △ 条目在，缺期限与"违反"字段（§11-C17） | idle | `commitment:<id>` | commitment id | 中高 / 急 |

> 「边界被触碰」为什么没信号：06 记的 `response_statuses` 只有
> `respond / think / ignore / wait / verbal / embodied`——**没有"拒绝 / 踩边界"这个状态**，
> 拒绝是写在 `respond` 的文本里的。要接这个源，得先给 05 的输出加一个"本次触到哪条边界"的字段。

## 3. 分级与资源

### 3.1 投入分级

自省**分等级**，等级越高投入越大、允许用的材料越多、越值得留档：

| 等级 | 典型触发 | 例子 | 大致投入 |
|------|--------|------|----------|
| 低 | 空闲 / 随机 | 闲时回顾一段旧经历 | 只读取，规则优先，能不调模型就不调；产出可丢 |
| 中 | 事件结果 | 一轮的结果出乎意料 | 可用一次模型，针对单一经历 |
| 高 | 计划 / 人工 / 治理 | 一段时期的经历整理、反复出现的老问题 | 多材料汇总，显式预算，结论必须留档 |

> 档位名称与最终阈值待定；**三级预算先用占位值**（模型次数 / 时间上限 / 材料段数 / 冷却），
> 登记进魔法书，交 400 调参并留审计，不写死在 300 里。
>
> **六问不缩 = 步骤不减、深度可变**：任何等级都走完六问，但**深度随等级变**——低档可以只做
> ①② 的规则摘要，④⑤⑥ 标"未评"，**字段必须在**，不能少问（见 §4.2）。
> 低档的定位是**简单跑**：不调模型，只留一条记录 + 摘要，不要求产出可复用资产（见 §11-B5）。

### 3.2 及时性分级

**及时性和投入是两个独立维度**：投入答"做多深"，及时性答"什么时候必须做完"。
强烈冲突这类情形要的是**及时**，不是"更深"。

| 及时性 | 什么时候跑 | 例子 |
|--------|------------|------|
| 急 | 触发后**马上**开跑，排在自省队列最前；力争在**下一次相关交互（或下一拍）之前**跑完 | 强烈冲突、失约、踩到边界 |
| 尽快 | 当前活动收尾、或下一个空闲窗口就跑 | 一轮结果出乎意料、认识被修正 |
| 缓 | 等空闲 / 夜间，资源紧时可不跑 | 闲时回顾、同类重复、对象关系变化 |

规则：

- **急不等于深，深不等于急**：常见组合是"急 + 中/高"（冲突），也有"缓 + 高"（一段时期的整理）；
- **及时性只改排程，不改"让路"**：主流程要用资源时，任何及时性的自省都让路、都可中断；
  "急"是"排在自省队列最前、尽力赶上下一拍"，不是"抢主流程的算力"；
- **急的可以先做浅的**：time-box 跑一轮，事后（缓档）再补一轮深的；同一主题的锁 / 冷却
  要允许"急的浅一轮 + 缓的深一轮"这种组合，别把补的那轮挡掉；
- **赶不上就不算数**：急的自省若在下一拍组装(03)前没落地，就只留记录，不改本轮；
- **判定权不在 300**：及时性由**个人世界**（08 / 100：边界 `binding`、承诺、价值条目自带的分量）
  与**匠石的心智**（当场判断）决定；300 只接收 `急 / 尽快 / 缓` 并据此排程，另留触发源默认值作回退。
  这套判定机制**待完善**（§11-C15）。

### 3.3 资源纪律（硬规则）

- 自省与主流程、做梦**并行**；主流程要用资源时，自省**让路**：可中断、可丢弃半成品，
  中断不算失败、不欠账；
- **等级低、不重要的自省，重点在"有效利用资源"**：用闲置的算力和时间做低成本回顾，
  而不是产出深度结论；能不调模型就不调；
- 高等级自省必须有**显式预算**（模型调用次数、时间、材料条数），超预算即停并留痕；
- 同一主题设**冷却**，避免反复自省同一件事；
- **空转合法**：想不出什么可自省的，什么也不做就结束；
- 自省自己也要被观测（耗时、模型调用、材料条数），否则无法判断它是否在抢资源。

### 3.4 并行

触发源多，**自省活动并行**：

- 一次触发建一条自己的 04 `kind=internal` 活动，彼此不等待，也不等主流程；
- 因此需要：① 同一考察主题加**锁 / 冷却**，不让两条自省同时回顾同一件事；② 资源按**全局配额**分
  （是否上令牌桶见 §11-B4），不由单个活动自己说了算；③ **及时性决定排队次序**（急 → 尽快 → 缓），
  同等及时性按触发时间先来先做；
- 现场是**快照**：自省跑的过程中出现的新输入、新活动不并入这条自省的现场。

## 4. 模式（五步 + 归因）

### 4.1 现场：自省看见什么

自省不是空想，先把"当时"的现场拼出来。以**被考察的条目**（那件事、那段经历）为中心：

```text
① 当时的上下文     这件事发生时，我正在面对什么
                   （取自账本里那段时间的经历段，不是今天的活跃区）
② 前后现场         这件事之前与之后那一小段时间的现场情况
                   （按时间窗取的经历段：对方说的话、我的言语与动作、我的内部状态段）
③ 回溯记忆         拿这件事去 09 召回相关回忆，补背景与类似经历
────────────────────────────
① + ② + ③ 拼成"现场" → 交给六问的 ①「什么」
```

- **"当时"= 被考察条目发生的时间段**（多长由条目本身定，不是固定窗口）；
- 现场**按时间取，不按段数取**：取账本里 [开始 − Δ, 结束 + Δ] 这段时间内的经历段；
  Δ 是魔法数（先占位，交 400 调）；
- 例：一次由情绪引发的事件——先看当时的上下文，再看这件事前前后后的现场情况，
  再去回溯记忆搜寻相关回忆，三者拼成现场；
- 现场是自省的**材料**，不是自省的结论；它只读，不改写、不回灌活跃区；
- 材料不足就不硬编：宁可降级或不做，不凭空空想。

### 4.2 六问（五步 + 归因）

```text
① 什么            发生了什么；先把 4.1 拼出的现场熟悉一遍
                  （对象、场景、前因、当时看见的材料）
② 我的选择与结果   我当时怎么选的、结果如何
                  （魔法数也套进这个语境：当时取的是什么值、效果如何，不当冷数字看；
                    但调参结论归 400，自省只回顾"我当时的取舍"）
③ 为什么（归因）   可能的原因，分开写：我能控制的 / 环境的 / 偶然的
④ 我是否可以做得更好  哪里可以不同、代价是什么（不空泛自夸或自责）
⑤ 以后我应该怎么做   三个出口（六问仍是六问）：
   ⑤a 条件—动作：什么情形下做什么
   ⑤b 要不要借助外部工具（要什么能力、什么条件下用、值不值那个代价）→ 200
   ⑤c 要不要与某个对象进一步交流（道歉 / 回话 / 解释 / 确认：对谁、要点、什么时候）
       → 落 承诺 / 活跃区 / 关系，见 §5 的红线
⑥ 是否值得记下来并学习  值得 → 交出候选给 500；不值得 → 只留这次自省的记录
```

规则：

- **六问不缩 = 步骤不减、深度可变**：任何等级都走完六问、字段一个不少；低等级靠"少取材料、
  不调模型、④⑤⑥ 标未评"来省，**不靠少问**；
- 六问是骨架，不是填空模板；
- **归因必写**：把"我能控制 / 环境 / 偶然"分开，避免事后偏差（把当时不可能知道的记成"早该知道"），
  也避免把运气当能力去学；
- **归因要防自利偏差**：给自己归因会系统性偏乐观，所以 ③ 还要写一句
  "**如果是别人做的，我会怎么归因**"（或标明把握有多大）；
- ⑤a 尽量写成"条件—动作"对，便于以后验证是否真的照做；
- **⑤b 用不用工具，按《概念词汇》「工具」的三条判据**（在主体边界之外 / 主体自己办不到 /
  有代价有不确定），且**经 200 才算工具**：叫模型、召回记忆、装载个人世界、写场都不是工具；
- **⑤c 交往需求不新增载体**（D-007：不许把"未完成现实"换个名字放回来）：按"离现在多远"落——
  最近一两拍内的事，下一轮活跃区自然带着，不必另存；跨时间的义务落**承诺**；长期的关系 /
  自我认识变化落 ⑥ 的候选。自省只**建议**，不直接写承诺或关系（D-004）；
- **第 ⑥ 步的"学"只到候选为止**：自省不直接写长期内容，交 500；模型候选不会自动成为
  长期价值、记忆或人格（对齐 100 §10 与 00 §2.1）；
- 每一步都要**带来源**：哪段经历、哪份报告、哪次打分。

## 5. 产出与去向

| 产出 | 落点 | 说明 |
|------|------|------|
| 这次自省本身（触发源、等级、材料、六问结论） | 04 `kind=internal` 活动 + 历史记录 + 16 经历账本（`append_internal`，现未接线） | 内在活动的来源与结果必须留痕 |
| 候选认识 | `CognitiveContent` | 认识状态仍只到「考虑中」 |
| ⑥ 判定"值得学"的候选 | 交 **500 学习** | **形态与最终去向后续再定**；自省不决定写到哪 |
| ⑤b 要不要用工具 | 200 自省入口（`origin=introspection`） | 自省只交"要用 + 一句意图"；可以没有对人的口头 |
| ⑤c 与某个对象的进一步交流（道歉 / 回话 / 解释 / 确认） | 近事 → 下一轮活跃区自然带着，不必另存；跨时间的义务 → **建议**一条承诺；长期变化 → 走 ⑥ | 只**建议**，不直接写承诺 / 关系 |

**⑤c 的红线**：交往需求只能落进已有的四样连续性载体（**活跃区 / 召回 / 承诺 / 关系**），
**不新增**"待办 / 未完成"概念，也不得形成"必须跟进"的机制——什么时候说、说不说，仍由下一轮的 05 决定
（D-007）。

**明确不做**：不自省写长期事实；不自省改参数；不自省替 09 整理记忆；不自省对人或对象开口；
**不做功能分析与调参结论**（那是 400）。
