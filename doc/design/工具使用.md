# 工具使用（设计文档）

> 模块文档。术语以《概念词汇》为准，流程位置见《00 流程总览与输入边界》。
>
> 状态：初稿已按讨论改口径（I-017）。编号 **200** 为工具模块总调度；内部可再分为 205 策划、206 引擎适配、210 记挂。已进 00 模块地图。
>
> **实现状态与设计口径分开写。** 主流程通道已落地：05 只出 `use_tool`/`need`；写场后 `intake`；03 原样装 `list_visible` 的正文为 `tool_input`；不叫醒。策划仍为规则占位（echo）。未接 205 真模型、Pi 流式入账、210 合适人话。

边界原则：

- **D-004**：能力实现只出候选与过程反馈，无长期写入权。200 / Pi / 记挂都不写 08、不改认识状态、不对人开口。
- **D-007**：记挂不是 concern。不进 08、不挂起活动、不每轮全量装入工作集。03 只装 200 交出的、该对象、可见、有上限的人话（`tool_input`），不改写。

## 1. 定位

工具使用让匠石在 05 或自省判定「要用工具」之后，把这件事交给 **200** 落到现实，并把过程跟随收进记挂；值得看见的跟随经 03 回到心智。

对外通信只经 200。05、03、自省不直连 Pi，不直连记挂账本。

| 角色 | 做什么 | 不做什么 |
|------|--------|----------|
| **05** | 判定要不要用；一句 `need`；对人说话（口头须带上工具需求） | 不填模板/参数、不等工具、不跑工具 |
| **200** | 总调度：收下交接、策划定义、发出请求、把跟随交给记挂、对 03 交出可见人话 | 不对人开口、不写活跃区 |
| **205** | 按定义模板填好一份定义（可再问模型） | 不跑 Pi |
| **206** | 对引擎（现为 Pi）：发会话、把事件译成反馈 | 不改 Pi 内核 |
| **记挂（210）** | 一次工具请求发出之后的跟随：收 estimate/progress/result，判断是否对 03 可见 | 不做定义、不选模板、不填参数 |
| **Pi** | 工具**内容**（skill / command 的实际执行） | 不发明匠石的定义槽位、不直连 05 |
| **10** | 只分发已校验的口头和肢体 | 不执行工具 |

调试：CLI `jshi tool` 仍是第三条路径，不经主体过程。

## 3. 术语（不要混）

**交接（intake）**  
05 或自省交给 200 的那一份背景，供策划用。还不是记挂。含：对象、活动、现场引用、`need`、本轮口头（外部路径应有）。

**定义模板**  
匠石侧预置。通用基础模板规定槽位（意图、预估时间/费用、可能结果、风险、参数等）；专用模板在此之上。200/205 按模板填好，才叫一份**定义**。

**工具内容**  
Pi 内部的 skill / command / 扩展。负责真正去搜、跑、调。目录可用 `get_commands`，与定义模板不是同一套「模板」。

**工具请求**  
200 按定义向引擎发出的那一次调用（代码里的 `ToolRequest`）。

**记挂**  
请求**已经发出之后**的跟随：跟着这一次请求收反馈、判断是否给 03 看。不做策划。无请求则无记挂。

**引擎**  
可替换执行端口。当前真实现是 Pi；Stub 只给测试。设计不写成「只能是 Pi」。

## 4. 核心口径

1. 05 只说「要用」和一句 `need`。外部路径上，口头必须有，且口头本身带上工具需求。
2. 200 读的是交接，不再向 05 要定义。现场引用只作处理依据，不拷进当前活跃区。
3. 先交接、再策划、**发出请求之后才建记挂并跟随**。
4. 策划失败：还没有请求，也就没有记挂。200 经同一对外口把失败摘要交给 03/05，不假装成工具跟随。
5. 调用一开始就有 `estimate`。数字与风险来自定义模板 + 该工具自己的说明（Pi 的 `description` / `SKILL.md`），不改 Pi 内核去加字段。
6. 同步只约束 **200 内部**（一条 Pi 会话按事件顺序读、反馈马上入账）。主流程、自省可以多次、交错 `intake`。05 这一拍仍不等 200 跑完。
7. 不改 Pi 内核。过程进度用已有 `tool_execution_*` 事件；206 边读边交给记挂。
8. 对 05 的材料经 03 的 **`tool_input`** 装载，不是【在途工具】长节，不进片场。200 决定何时交出、交出一句合适的人话；匠石决定是否告诉对方。不叫醒、不插内部活动。

## 6. 流程

```text
外部这一拍
  … → 05 回复调用：response_plan + 可选 use_tool/need
  → 06 → 10（口头须带工具需求）→ 写场
  → 若要用：200.intake(交接)     ← 不等待执行
  → 07 completed

200（可与后续活动并行；内部同步读流）
  保存交接
  205 按模板填定义（读交接 + 工具说明）
  定义无效 → 可见失败摘要，经 03 回 05；结束
  定义有效 → 发出请求、建记挂、立刻写 estimate
  206 同步读 Pi 流，事件即时写入该记挂
  记挂评估是否对 03 可见（评估不挡读流）

03 下一轮（外部正常组装，不叫醒）
  list_visible(当前对象) → tool_input（原样；无则整路不出现）
  05 决定是否告诉对方他先前问的结果
```

一次指示可拆多条定义、多条请求、多条记挂。各条跟随并行。

自省入口（300）同样 `intake`，可以没有对人的口头。自省是 300，不并入 200。

## 7. 05 这一拍

提示词增加：本轮要不要用工具。规则从简：需要外部世界、当前上下文不够、能用一句话说清时才标要用。

输出（可空，不是 10 的通道）：

```text
use_tool    要用则为真；省略或假 = 不用
need        一句话意图（为什么用、要什么）；不是模板名，不是参数
```

不要：`template`、`params`、`expected_result`、`budget`、`ask`。那些由 205 填。

外部路径：`use_tool` 为真时，`response_plan` 须有口头，且口头说出工具需求。禁止只在内部打标、对人一声不吭。内部自省不受这条约束。

05 本轮不等 200。活动不因工具变成 `waiting`。工具结果不进本轮 verbal，不改写场正文。10 不调用工具。

已装载的工具反馈（03 的 `tool_input`，来自 200）应让 05 看见。具体怎么处理由匠石决定，合适的时候告诉对方。不要当成片场里已经说过，也不要当成对方刚说的话。不要无故再开同样一条。写场调用不带这一路。

## 9. 定义模板与一开始的反馈

通用基础模板至少含：意图、预估时间、预估费用、可能结果、风险/副作用、参数槽、期望形态。专用模板继承这些槽，侧重点不同。

**调用一开始**（请求发出、内容尚未跑或刚开跑）就必须有一条 `estimate`，由 205 按模板槽位写出，立刻写入该条记挂。

估价来源：

1. 定义模板的槽位（形状归匠石）；  
2. Pi 侧该工具自己的说明：`get_commands` 的 `description`，必要时读 `path` 指向的 `SKILL.md`。Pi **没有**结构化的时间/费用字段，约定写在说明文本里。

不改 Pi 内核去新增协议字段。自带 bash 等只有短描述时，205 用通用模板填默认（时长未知、有执行风险），不要去改 Pi。

`ask=propose_only` 仍保留在请求信封上，主路径默认 `execute`。先报价再决定是否跑内容，由 200 内部选用，不回到 05 填。

## 10. 引擎与 Pi（不改内核）

206 只翻译：发 `prompt`、按 LF JSONL 读事件、译成信封。

Pi 已有：`tool_execution_start` / `update`（累计 `partialResult`）/ `end`。目标是 **边读边入记挂**，不要攒到 `agent_settled` 再整包写。

进度能密到什么程度，取决于该 skill 会不会打过程输出。只有 start/end 时，跟随里就只有开始和结束。要更密，改的是那个 skill 的说明与输出习惯，不是 Pi 内核。

适配器应注意：`timeout_s` 接到读循环；避免 `stderr=PIPE` 堵死。属 206，不属新模块。

预算、权限字段在信封里预留；Pi 适配尚未用它们约束执行。失败按模板降级并给原因。

## 11. 同步

「同步」只指 200 内部：每一条已发出的请求，对应一次引擎会话，按事件顺序收，反馈马上入账。

主流程、自省会多次、交错调用 200。200 必须可重入：多条记挂并行，不得一把全局锁堵住第二次 `intake`。05 这一拍仍然不等待。

记挂上「是否对 03 可见」若再调模型，排在记挂自己的队列，**不挡** 206 读 Pi 流。

## 12. 记挂（跟随）

在 **200 已经发出工具请求** 时建立，跟着这一次 `request_id`。

不做：选模板、填参数、策划、对人说话、改活跃区。

做：只增反馈流；判断这条更新是否进入 `list_visible`；按对象保管；可注销（已处理完、05 取消、失败关掉、过期）。

多条请求 = 多条记挂，可同时跟随。

给 03 的不是 Pi 原文流水，而是 200 写好的一句人话（`summary`）。03 原样装入 `tool_input`，不改写、不加标题。同一 `task_id` 同一条可见反馈只装一次。

策划失败不是记挂。程序崩溃可丢进行中的子进程；若请求已发出，账本行仍在（跟随中、无终态）——可接受，巡检后补。

## 13. 经 03 回到 05

可见跟随走 03 的 **另一路输入** `tool_input`，与对方的 `input_text` 并列。不是 08，不是活跃区正文，不是对方原话，不是回忆，不要【在途工具】标题。

- **200 给出**：什么情况下、什么时候交出；并给出一句合适的人话（可以像匠石要说的）。
- **03**：按接口取 `summary`，原样装上。没有则这一路不出现。不改写，不叫醒，不开内部活动。等下一轮正常组装即可。
- **匠石（05）**：提示词写明——具体怎么处理由你决定，合适的时候告诉对方他先前问的结果。对人开口仍只走 `response_plan`。

写场调用不带 `tool_input`，以免写进片场当已经出口。

不要为工具反馈插内部输入 `source=system/tool`。晚一轮看见，接受。

## 14. 接口契约（对齐现有信封；调用方改为 200）

`ToolRequest` / `ToolFeedback` 仍以 `src/jshi/tool/contract.py` 为准。编排层不再由 05 JSON 填全请求；05 只交指示，200 补 `subject_id`、`activity_id`、`origin`、`ask` 等。

### 14.1 `ToolRequest`

| 字段 | 说明 |
|------|------|
| `request_id` | 关联；发出时生成 |
| `subject_id` / `activity_id` / `turn` | 溯源 |
| `origin` | `external_05` \| `introspection` |
| `need` | 来自交接 |
| `template` | 定义所用专用模板名（匠石侧），或引擎内容名；由 205 填 |
| `params` / `budget` / `permission` / `expected_result` / `ask` / `meta` | 205 填；主路径 `ask=execute` |

### 14.2 `ToolFeedback`

信封：`event_id`、`request_id`、`kind`、`at`、`version`、`meta`；按 kind 带 `estimate` / `progress` / `result` 之一。

| kind | 主要字段 |
|------|----------|
| `estimate` | `cost_est`、`time_est_ms`、`resource_est`、`benefit`、`downside`、`need_confirm` |
| `progress` | `stage`、`step`、`partial`、用量、`note` |
| `result` | `status`、`result`、`summary`、`ideal`、`error` 等 |

`ToolStatus`：`ok` / `partial` / `failed` / `budget_exceeded` / `rejected` / `aborted`。

### 14.3 交接与记挂（设计）

交接字段见 §8。记挂在请求发出后建立，至少含：`task_id`、`request_id`、`subject_id`、`object_id`、`origin`、跟随状态、`need` / 所用模板、`field_ref`、口头摘录、反馈列表、是否对 03 可见、`updated_at`。

200 对外：`intake` / `list_visible(subject_id, object_id)`（上限建议 8）/ `cancel`。
