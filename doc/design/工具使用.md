## 1. 定位

工具使用让匠石在 05 或自省判定「要用工具」之后，把这件事交给 **200** 落到现实，并把过程跟随收进记挂；值得看见的跟随经 03 回到心智。

对外通信只经 200。05、03、自省不直连 Pi，不直连记挂账本。

| 角色 | 做什么 | 不做什么 |
|------|--------|----------|
| **05** | 判定要不要用；一句 `need`；要不要先对人说由自己决定 | 不填模板/参数、不等工具、不跑工具 |
| **200** | 总调度：收下交接、策划定义、发出请求、把跟随交给记挂、对 03 交出可见人话 | 不对人开口、不写活跃区 |
| **205** | `ToolPlanSkill`：选模板、填参数、写估价；按 `field_ref` 现读现场正文；从引擎目录检索后点名 `command` | 不跑 Pi、不对人开口、不把现场写入交接 |
| **206** | 对引擎（现为 Pi）：发会话、把事件译成信封并写入对应 210 | 不改 Pi 内核、不思考 |
| **记挂（210）** | 一次请求发出后的账本：收阶段性事实，通知 200 | 不选模板、不包装、不对人开口 |
| **包装** | `ToolWrapSkill`：读这一本 210，产出 `{visible, summary}` | 不跑 Pi、不读其它记挂 |
| **Pi** | 工具**内容**（skill / command 的实际执行） | 不发明匠石的定义槽位、不直连 05 |
| **10** | 只分发已校验的口头和肢体 | 不执行工具 |

调试：CLI `jshi tool` 仍是第三条路径，不经主体过程。对话里 `/tool`（及 `/tool list` / `/tool plan` / `/tool raw` / `/tool <id>`）只读 05 指示、200 交接、205 策划材料、引擎反馈、记挂与包装；壳外用 `jshi tool-log`。

## 3. 术语（不要混）

**工具**  
把一件**只有离开主体边界才办得到**的事，交给主体之外的执行体去做，并把结果带回主体的能力。
三条**同时成立**才算工具：① 在主体边界之外（要的信息或要造成的影响不在匠石自己的记录、心智与
个人世界里）；② 主体自己办不到 / 不该自己办（凡"想一想、查自己已有的记录"能解决的都不是）；
③ 有代价、有不确定、可能不可逆（时间 / 费用 / 额度，可能失败或被拒，改动了外面可能收不回来）。
再加一条归属判据：**经 200 才算工具**。一句话口径：**「离开主体才办得到吗？有代价吗？经 200 吗？」**

| 事 | 算工具吗 | 为什么 |
|----|----------|--------|
| 搜网页、查天气、发消息、下单、控制设备 | **是** | 三条全中，且经 200 |
| 叫大模型生成 / 做认知 | 不是 | 走 `ModelPort`，是「能力实现」，不经 200 |
| 召回记忆、读账本、装载个人世界 | 不是 | 主体自己的记录，无外部性、无代价 |
| 开口说话、做肢体动作 | 不是 | 那是 10 的行动（`response_plan` 的 verbal / embodied） |
| 问第三人（I-011 追加召回） | 不是 | 认知侧召回，不是外部执行 |
| 调记忆引擎 REMS | 不是 | 记忆是匠石自己的一部分（可替换实现，不是外部工具） |

**交接（intake）**  
05 或自省交给 200 的那一份背景，供策划用。还不是记挂。含：对象、活动、现场引用、`need`、本轮口头（有则带上，没有也合法）。

**定义模板**  
匠石侧预置。通用基础模板规定槽位（意图、预估时间/费用、可能结果、风险、参数等）；专用模板在此之上。200/205 按模板填好，才叫一份**定义**。

**工具内容**  
Pi 内部的 skill / command / 扩展。负责真正去搜、跑、调。目录可用 `get_commands`，与定义模板不是同一套「模板」。

**工具请求**  
200 按定义向引擎发出的那一次调用（代码里的 `ToolRequest`）。

**记挂（210）**  
请求**已经发出之后**的账本：跟着这一次请求收阶段性事实（不要思维链），有新事实就通知 200。不做策划、不包装。无请求则无记挂。多本可并行。

**引擎**  
可替换执行端口。真实现是 Pi；Stub 给测试与默认主流程。`JSHI_TOOL_ENGINE=stub|pi` 切换。设计不写成「只能是 Pi」。

## 4. 核心口径

1. 05 只说「要用」和一句 `need`。**要不要先对对方说、怎么说，由 05 自己决定，程序不强制**（`use_tool` 为真也允许一声不吭地内部去打标）。
2. 200 读的是交接，不再向 05 要定义。现场引用只作处理依据，不拷进当前活跃区。
3. 先交接、再策划、**发出请求之后才建记挂并跟随**。
4. 策划失败：还没有请求，也就没有记挂。200 经同一对外口把失败摘要交给 03/05，不假装成工具跟随。
5. 调用一开始就有且仅有一条 `estimate`，由 200 按 205 的槽位写入记挂。引擎不报价、不 yield `estimate`，只报真实进度与结果。数字与风险来自定义模板 + 该工具自己的说明（Pi 的 `description` / `SKILL.md`），不改 Pi 内核去加字段。
6. 同步只约束 **200 内部**（一条 Pi 会话按事件顺序读、反馈马上入账）。主流程、自省可以多次、交错 `intake`。05 这一拍仍不等 200 跑完。
7. 不改 Pi 内核。过程进度用已有 `tool_execution_*` 事件；206 边读边交给记挂。
8. 对 05 的材料有两条路：**主路是交付进片场**——200 把可见事实修饰成工具块（`（我知道）…`），写场时由程序追加进该对象的片场，此后随场面推进自然过期；**`tool_input` 只承载尚未进片场的那一条**。都不是【在途工具】长节。不叫醒、不插内部活动。

## 6. 流程

```text
外部这一拍
  … → 05 回复调用：response_plan + 可选 use_tool/need
  → 06 → 10 → 写场
  → 若要用：200.intake(交接)     ← 不等待执行
  → 07 completed

200（可与后续活动并行；内部同步读流）
  保存交接
  205 ToolPlanSkill（读交接 + 现读现场正文 + 匠石槽位 + 引擎目录检索后点名）
  定义无效 → 可见失败摘要，经 03 回 05；无 210
  定义有效 → 发出请求、建 210、由 200 立刻写一条 estimate
  206 读引擎流，事件即时写入**这一本** 210（丢掉思维链）
  有阶段性事实 → 该本的包装队列 → ToolWrapSkill → 写回 visible/summary
  包装不挡 206 读流；多本各排各的队

03 下一轮（外部正常组装，不叫醒）
  list_visible(当前对象) → tool_input（原样；无则整路不出现）
  05 决定是否告诉对方他先前问的结果
```

一次指示可拆多条定义、多条请求、多条记挂。各条跟随并行。

一个多步计划由 200 确定性调度，不调模型：`depends_on` 就绪即启动；`mode=sequential` 而某步漏写依赖时，程序按声明顺序补链（`normalize_plan`）；依赖成环即当场失败。**只有 `OK` 算完成并解锁后续**，`PARTIAL` / `FAILED` / `ABORTED` / `REJECTED` / `BUDGET_EXCEEDED` 冻结计划（已启动的兄弟步骤照跑，不连带取消）。取消是「先冻结计划，再取消已启动步骤」，取消路径不产生任何新的外部动作。详见 `方案(coding)/200-计划落账与调度语义.md`。

自省入口（300）同样 `intake`，可以没有对人的口头。自省是 300，不并入 200。

## 7. 05 这一拍

提示词增加：本轮要不要用工具。规则从简：需要外部世界、当前上下文不够、能用一句话说清时才标要用。

输出（可空，不是 10 的通道）：

```text
use_tool    要用则为真；省略或假 = 不用
need        一句话意图（为什么用、要什么）；不是模板名，不是参数
```

不要：`template`、`params`、`expected_result`、`budget`、`ask`。那些由 205 填。

外部路径：**不强制口头**。`use_tool` 为真时可以先对人说「我去查一下」，也可以先不说、查到再说；两者都由 05 按场面决定。程序不因缺口头而拒绝 `intake`，也不因有口头而要求打标。内部自省同样不强制。

05 本轮不等 200。活动不因工具变成 `waiting`。工具结果不进本轮 verbal，不改写场正文。10 不调用工具。

已装载的工具反馈分两种形态：**已交付进片场、以 `（我知道）` 开头的块**（是匠石已经知道的事实，不是他说过的话）与**尚未交付的那条 `tool_input`**（03 的辅路，来自 200）。两种都应让 05 看见；具体怎么处理由匠石决定，合适的时候告诉对方他先前问的结果。片场里的块不是「我说」，`tool_input` 不是对方原话、不是回忆、不是活跃区正文，都不要并进【此时的输入】。

**判断是否用工具时，只看本轮实际情况；前一次工具使用（成功或失败）不得影响本次判断。** 例子：同一件事刚问过且已答，可直接用回忆；本轮某件事查询失败，不表示别的需求也不能提。写场调用不带 `tool_input`。

## 9. 定义模板与一开始的反馈

通用基础模板至少含：意图、预估时间、预估费用、可能结果、风险/副作用、参数槽、期望形态。专用模板继承这些槽，侧重点不同。

**定义模板不做选择（2026-09-12 拍板，已编码 2026-09-13）。** 只有一份默认模板 `generic`；205 **不要求模型点名模板**，也不因模板名判失败。后续即使增加模板，**暂不引入「选择」这一步**，仍直接用默认。代码落点：`ToolPlanSkill.DEFAULT_TEMPLATE`（`skill/tool_plan.py`），`instruction` 已去掉「选模板」，`plan_intake` 不再校验模板名；catalog 仍留 `generic` / `echo` 供材料说明。**真执行（206）不看 `template`，只认 `command`。**

**调用一开始**（请求发出、内容尚未跑或刚开跑）就必须有一条 `estimate`，由 205 按模板槽位写出，由 200 立刻写入该条记挂。引擎不得再写一条。

估价来源：

1. 定义模板的槽位（形状归匠石）；  
2. Pi 侧该工具自己的说明：`get_commands` 的 `description`，必要时读 `path` 指向的 `SKILL.md`。Pi **没有**结构化的时间/费用字段，约定写在说明文本里。

不改 Pi 内核去新增协议字段。自带 bash 等只有短描述时，205 用通用模板填默认（时长未知、有执行风险），不要去改 Pi。

`ask=propose_only` 仍保留在请求信封上，主路径默认 `execute`。先报价再决定是否跑内容，由 200 内部选用，不回到 05 填。

## 10. 引擎与 Pi（不改内核）

206 只翻译：发 `prompt`、按 LF JSONL 读事件、译成信封。

Pi 已有：`tool_execution_start` / `update`（累计 `partialResult`）/ `end`。目标是 **边读边入记挂**，不要攒到 `agent_settled` 再整包写。

进度能密到什么程度，取决于该 skill 会不会打过程输出。只有 start/end 时，跟随里就只有开始和结束。要更密，改的是那个 skill 的说明与输出习惯，不是 Pi 内核。

适配器：`timeout_s` 接到执行读循环；`list_timeout_s`（默认 5 秒）接到 `get_commands`。超时落 `result/failed`「工具执行超时」。`cancel` 杀该次子进程。可执行文件不存在或列目录失败则空目录，不让 `talk` 起不来。避免 `stderr=PIPE` 堵死。属 206，不属新模块。prompt 用引擎 `command`，不要把匠石模板名当成 Pi 命令名。`field_ref` 与 `expected_result` 写入 prompt，字段保留。

预算、权限字段在信封里预留；Pi 适配尚未用它们约束执行。失败按模板降级并给原因。

**用 Pi 的坑另见《Pi 使用注意点》**（`doc/design/Pi使用注意点.md`）：静默空目录、不等 EOF、整棵进程树、沙箱 `spawn EPERM`、`tier=eager` 导致检索分支不可达等。那份只讲**用**，不讲装。

## 11. 同步

「同步」只指 200 内部：每一条已发出的请求，对应一次引擎会话，按事件顺序收，反馈马上入账。

主流程、自省会多次、交错调用 200。200 必须可重入：多条记挂并行，不得一把全局锁堵住第二次 `intake`。05 这一拍仍然不等待。

包装 skill 排在**该本 210** 自己的队列，**不挡** 206 读流，也不用一把全局锁堵住第二次 `intake`。`visible` 是包装输出，不另开 skill。

## 12. 记挂（210）

在 **200 已经发出工具请求** 时建立，跟着这一次 `request_id`。号留下，就是账本。

不做：选模板、填参数、策划、写人话、对人说话、改活跃区。

做：只增反馈流（阶段性事实，不要思维链）；有新事实通知 200；保存当前 `visible` / `summary`；按对象保管；可注销。

多条请求 = 多本 210，可同时跟随。一本交接也可拆多本 210。不同对象按 `object_id` 隔离。同一本上后一句 `summary` 覆盖给 03 看的那条；同一 `task_id` 在一轮组装里只占一条（不是两句并排）。**未交付**的每轮仍走 `tool_input`；**已交付进片场**的改由片场承载，不再走 `tool_input`（见 §13）。进度包装可以可见，status 仍为 `open`；`notified` 只在终态且可见时打。注销走 `cancel`（停会话 + 账本）。交付、过期与回写都在 200 内部收口，03 契约不动。

账本两段：**前半**是引擎跟随（反馈流要阶段性事实，不要思维链）；**后半**是 05 的回应（`responses`，只增）。给 03 的不是 Pi 原文，而是包装 skill 写回的 `summary`（须 `visible`）。策划失败不是记挂。程序崩溃可丢进行中的子进程；账本行仍在——可接受，巡检后补。jsonl 是追加快照：单次写入便宜，文件体积随每次包装再写一整份记录而涨。长会话、高频 progress 需要压缩或轮转时再做，本轮不自动紧缩。

## 13. 经 03 回到 05（两条路）

**主路：交付进片场。** 200 把可见事实修饰成**工具块**，写场时由程序追加进该对象的片场：

```text
（我知道）我已经查了明天杭州的天气，是多云转晴……
```

- **两种来源都走这条路**：引擎跟随写回的可见句，**以及策划失败句**（`plan_error`）。失败句也要经 200 修饰进片场，不能一直以裸句挂在 `tool_input` 上——那条裸句正是实测里「这一问有点怪」的来源。因此策划失败句的措辞也要像人话：有主语、不写字段名（见 §9）。
- **形态**：以 `（我知道）` 开头的一句人话，是**匠石当前知道的事实**，不是「我说」。单个块上限 240 字，同场最多 3 条。
- **对象专属**：不是当前对象产生的反馈，不进该对象的片场。
- **预算**：工具块**单独一档**，不占对白与情景那 2000 字；字数行分两行报（片场 / 工具块）。
- **过期**：指「**该条对当前场面过期**」——随片场压缩掉落即算过期，不需要 TTL，也不用 200 再维护「已交付/已过期」状态表。中间反馈对 03 过期时，**记挂照旧全量保留**。
- **硬约束**：工具块**不得写成「我说：…」**。写成「我说」会让下一轮匠石以为自己早已出口；这正是本节目的一条旧防线，只换形式、不取消。

**辅路：`tool_input`。** 只承载**尚未进片场的那一条**（交付前的即时可见，以及片场这轮没接下块时的回退）。与对方的 `input_text` 并列；不是 08、不是活跃区正文、不是对方原话、不是回忆、不要【在途工具】标题。

- **200 给出**：`ToolWrapSkill` 对这一本 210 交出 `{visible, summary}`。可见 = 这句话可进 `list_visible`。
- **03**：取尚未交付的 `summary` 原样装上；没有则这一路不出现。不改写、不叫醒、不开内部活动。
- **交付时点**：写进片场即算交付；此后同一 `task_id` 不再走 `tool_input`（避免同一句出现两次）。片场没能接下（本轮既无输入也无回应）时**撤销交付**，下一轮仍走 `tool_input`。
- **匠石（05）**：提示词写明——具体怎么处理由你决定，合适的时候告诉对方他先前问的结果。对人开口仍只走 `response_plan`。

**回写**：这一轮该对象可见的每一本，都把 **05 的回应**追加进该本记挂（`mode` / `reply` / `action`），**不要求回应提到工具**；没开口（think / ignore / wait）也留一条轮次。一本记挂 = 一次工具使用的完整过程（跟随 + 回应）。

不要为工具反馈插内部输入 `source=system/tool`。晚一轮看见，接受。

## 14. 接口契约（对齐现有信封；调用方改为 200）

`ToolRequest` / `ToolFeedback` 仍以 `src/jshi/tool/contract.py` 为准。编排层不再由 05 JSON 填全请求；05 只交指示，200 补 `subject_id`、`activity_id`、`origin`、`ask` 等。

### 14.1 `ToolRequest`

| 字段 | 说明 |
|------|------|
| `request_id` | 关联；发出时生成 |
| `subject_id` / `activity_id` / `turn` | 溯源 |
| `origin` | `external_05` \| `introspection` |
| `need` | 来自交接 |
| `template` | 匠石侧定义模板名（槽位说明）；由 205 填 |
| `command` | 引擎侧工具内容名（Pi command / skill）；有引擎目录时必选其中已有的名字 |
| `field_ref` | 现场引用；206 写入 prompt；保留，不删 |
| `params` / `budget` / `permission` / `expected_result` / `ask` / `meta` | 205 填；主路径 `ask=execute`。`expected_result` 写入引擎 prompt。 |

### 14.2 `ToolFeedback`

信封：`event_id`、`request_id`、`kind`、`at`、`version`、`meta`；按 kind 带 `estimate` / `progress` / `result` 之一。

| kind | 主要字段 |
|------|----------|
| `estimate` | `cost_est`、`time_est_ms`、`resource_est`、`benefit`、`downside`、`need_confirm` |
| `progress` | `stage`、`step`、`partial`、用量、`note` |
| `result` | `status`、`result`、`summary`、`ideal`、`error` 等 |

`ToolStatus`：`ok` / `partial` / `failed` / `budget_exceeded` / `rejected` / `aborted`。

### 14.3 交接与记挂（设计）

交接字段见 §8。记挂在请求发出后建立，至少含：`task_id`、`request_id`、`subject_id`、`object_id`、`origin`、跟随状态、`need` / 所用模板、`field_ref`、反馈列表、`visible`、`summary`、`delivered_at`、`delivered_block`、`responses`、`updated_at`；属于多步计划时另有 `plan_id` / `step_id` / `plan_mode` / `depends_on` / `plan_index` / `plan_total`（单工具为空）。

- `delivered_at` / `delivered_block`：这条已经写进该对象的片场（交付时点），以及交付时的块正文。非空后不再走 `tool_input`；片场没接下时清空、下轮重来。
- `responses`：05 对该本工具反馈的回应，只增；一条形如 `{mode, reply, action, text}`。

200 对外：`intake` / `list_visible(subject_id, object_id)`（上限建议 8）/ `cancel`。交付、回写与撤销交付是 200 内部口（`pending_for_scene` / `deliver_to_scene` / `write_back_response` / `revoke_delivery`），03 仍只调那三口。

## 17. 验收（设计；未全部编码）

- 05 只用 `use_tool` + `need`；说不说、什么时候说，由 05 自己决定（程序不强制）。  
- 交接不是记挂；发出请求后才跟随。  
- 策划失败经 200→03，不是一条假跟随。  
- 请求一开始即有 `estimate`；进度边读边入账。  
- 03 只装该对象**尚未交付**的可见人话（`tool_input`，原样）；当前活跃区不被旧现场替换。写场调用不带 `tool_input`。  
- 10 与 08 不承担执行或保管跟随。  
- Stub 引擎反馈：`progress` → `result`（无 estimate）；走 200 `ToolService` 时反馈流恰好一条 `estimate`，且在引擎反馈之前。`propose_only` 终态 `rejected`（引擎契约仍在）。
- `cancel` 停该次引擎会话；超时有终态。`summary` 有统一上限。
- **计划**：只有 `OK` 解锁后续；`PARTIAL` / `FAILED` / `ABORTED` / `REJECTED` 冻结计划且不启动后续；`mode=sequential` 缺 `depends_on` 由程序按声明顺序补链；依赖成环即失败（不建永远 `open` 的账）；`cancel` 先冻结计划再取消已启动步骤，取消路径不产生新动作、不进实测统计。
- **交付**：工具块以 `（我知道）` 开头追加进该对象片场；交付后同一 `task_id` 不再出现在 `tool_input`；对象不同的不交付；片场没接下时撤销交付、下轮重来。
- **回写**：这一轮可见的每一本都追加 05 的回应；没开口也留轮次。
