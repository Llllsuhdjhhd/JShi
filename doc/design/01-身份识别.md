# 01 身份识别（对象解析）

> 模块文档。术语以《概念词汇》为准，流程位置见《00 流程总览与输入边界》阶段①。
>
> 状态：已实现原型，设计校准中。现有代码用于验证本模块契约；原型通过测试不等于阈值与确认策略已经定稿。

## 1. 定位

本模块回答一个问题：**这条外部输入来自谁**。

答案最终以"对象标识 + 置信度 + 确认状态"的形式进入落位，并影响后续一切按对象组织的处理（事件装载、召回、关系情境）。本模块是输入边界（阶段①）的第一步，先于落位与所有后续环节。

## 2. 对象从哪里来：文字是最终形态

任何输入（语音、文字，未来的图像/视频）最终都以**文字**形态进入系统。对象信息随文字一起进入，其确定过程是**分层递进**的两段，先后关系而非并列：

1. **渠道层对象映射**（前置，未来）：输入通道本身携带的对象来源，在进入文字层之前映射为对象标识——
   - 语音 → 声纹识别；
   - 对话框 / App → 账号或登录会话（如已知好友）；
   - 设备、人脸等其它载体；
   渠道层把对象标识随输入一起送入文字层。
2. **文字层对象解析**（必经，当前实现重点）：文字是输入的最后形态，所有输入都在这里完成对象必填校验、按文本寻找或新建对象、置信度门禁。

### 对象必填规则

- 语音：渠道层识别（未来）在转写时嵌入对象；
- 文字：对象来自渠道（账号/会话，如对话框中的好友）或显式提供（对象标识 / 名字 / 称呼）；
- 两者皆无 → **无对象 → 拒绝**：这是输入信封契约错误，不落位、不创建活动，返回明确错误；
- 渠道层无法对应到已确认档案时，上游仍须提供可引用的访客、会话或设备对象标识；此时是**暂定对象**，不是“无对象”，进入置信度与确认流程（见 §4.2）。

本文不再用 `unknown` 同时表示“没有对象”和“身份未确认”。若代码或历史字段保留 `unknown`，其语义只允许是“已有暂定对象标识，但身份尚未确认”。

## 3. 对象如何确定：三种识别模式

识别按优先级逐级尝试，前一级无歧义即结束：

### 3.1 模式一：载体识别（强，唯一）

输入携带识别载体引用（声纹 / 人脸 / 设备 / 账号 / 会话）时，先在对象档案中按载体条目匹配：

- **载体引用唯一**：一个载体引用只属于一个对象，命中即唯一对象，直接给出对象名与 `object_id`，无重名问题；
- 未命中 → 新建暂定对象，并把载体信号存入其载体条目（未来可累积、可消歧）；
- 同一引用映射多个对象视为数据错误（占位校验，未来由合并机制处理）；
- 多个载体命中不同对象 → 证据冲突，按低置信进入确认流程（未来）；
- 占位实现为精确匹配（kind + value），未来接入嵌入相似度 / 声纹比对。

### 3.2 模式二：文字标识识别（名字 + 别名）

文字输入没有 id 时，按输入中的名字 / 称呼匹配 `label + aliases` 得到候选集：

- 唯一候选 → 直接给对象（provisional，渠道层匹配为 confirmed）；
- 多个候选（重名，如多个"张三"）→ 进入模式三消歧；
- 增加别名后，"名字 + 别名"的组合碰撞概率远低于单名；
- 未匹配 → 新建暂定对象，来源 = 该次输入的事实 id。

### 3.3 模式三：记忆匹配识别（重名消歧，占位）

对重名候选集中的每个对象，用当前输入与其**关联记忆**（过去对话 / 事件 / 关系情境）做相关性匹配，给出置信最高者：

- 最高者显著领先 → 返回该对象（置信度中等，占位）；
- 分数接近或都低 → 低置信（0.0），进入确认流程，**不得任取其一**；
- 依赖按对象组织的记忆召回（09 记忆系统）；当前为占位实现（按对象过滤事实历史 + 词重叠打分）；
- 相当于在识别方式中增加一个"记忆匹配"识别模式。

正文中自动发现新对象（如"我认识了一个朋友叫小张"）属于认知阶段的实体解析，未来接入，本模块不做。

## 4. 可信程度：置信度、门禁与确认

### 4.1 置信度（每次活动动态计算）

文字携带对象**不自动等于置信度 1**。置信度**不存库**，是每次活动由识别过程按"识别来源 × 档案状态"动态计算的瞬时值；档案状态变化（暂定 → 已确认）会自然改变后续活动的置信度。

| 识别来源 | 无档案（新建候选） | 暂定档案 | 已确认档案 |
|----------|--------------------|----------|------------|
| 渠道匹配（声纹 / 账号会话，未来） | 0.70 | 0.70 | 0.95 |
| 显式名字匹配 | 0.60 | 0.65 | 0.85 |
| 暂定来源不足 | 0.00 | 0.00 | 0.00 |

未来增强：累积确认次数、长期关系权重可进入计算，仍不存单次置信度。

模式三（记忆匹配消歧）为新增识别模式：占位置信度 0.55 ~ 0.60，按候选对象记忆相关性动态计算；无法区分时为 0.0。

### 4.2 置信度门禁

候选置信度低于阈值 `min_object_confidence`（默认 0.5）→ **不进入后续活动**：

- 记录原因（`subject/object_rejected`），不创建活动、不进入认知；
- 可先走**身份确认回合**（轻量交互，未来）：达标后继续，否则拒绝；
- 暂定对象证据不足时视为低置信，走同一路径；完全没有对象已在输入契约校验阶段拒绝，不进入本门禁。

### 4.3 认知确认

确认由**认知活动**承担（阶段⑤）：基础认知模型对说话人候选做判定（confirm / deny / uncertain）。模型是匠石的内生认知基础，判定属于认知内容、默认"考虑中"，经认识状态迁移或显式记录后生效；它不是独立的外部确认系统。确认结果追加记录 `subject/object_identity_assessed`，不改写事实原文。

## 5. 接口契约

### 5.1 输入

`resolve(subject_id, text, object_ref, channel=None, carriers=())`：

- `object_ref`：说话人显式引用（对象标识 / 名字 / 称呼），必填；
- `channel`：渠道信号（未来：声纹 / 设备 / 上下文线索）；
- `carriers`：输入携带的识别载体信号列表（`{kind, value}`），未来由形态 / 渠道层提供（声纹 / 人脸 / 设备 / 账号 / 会话），供 §3.1 载体匹配使用；
- 内部输入（source=internal）不经过本模块，直接标记 `system`。

### 5.2 输出 SpeakerCandidate

| 字段 | 取值 | 说明 |
|------|------|------|
| label | 显示名 | 按档案或提供的名字 |
| object_id | 对象标识 | 有效外部输入必须可引用；身份可以尚未确认 |
| confidence | 0.0 ~ 1.0 | 见 §4.1 |
| status | provisional / confirmed / rejected | 默认候选；无对象不构成候选 |

### 5.3 存储：对象档案

- `ObjectProfileRepository`（可替换接口）；
- 推荐实现：**SQLite**——在 `subject.sqlite3` 中新增 `object_profiles` 表，与主体数据同库，便于按对象组织召回与关系情境；测试可用内存 / JSON 实现；
- 字段：object_id、label、aliases（称呼/别名）、channel、**carriers（识别载体条目：kind / value / source）**、source（导入 / 文本新建）、status（provisional / confirmed / rejected）、created_at、updated_at；**不存单次置信度**；若为兼容原型数据保留 `unknown`，须按“暂定对象”迁移解释；
- **唯一性语义**：object_id 全局唯一且不可变；识别载体引用唯一（一个载体引用只属于一个对象，占位校验冲突）；**aliases 可重复**——重名合法，按名字匹配返回候选集，由载体 / 渠道 / 上下文 / 认知确认消歧；
- **识别载体只存引用，不存原始生物数据**（如声纹 / 人脸特征标识），原始数据与隐私治理见协作流程 §7；
- **写入时机**：新对象在通过置信度门禁、进入落位时首次落库为 provisional（来源 = 输入事实 id）；认知确认 confirm → 升级 confirmed，deny → 标记 rejected（保留审计）；被门禁阻断的输入不落库；已存在对象只更新状态，不重复创建；
- 暂定档案确认后合并进已知对象，合并显式记录（未来）。

## 6. 行为流程

1. 输入到达：校验对象引用（渠道或显式），两者皆无 → 作为无效信封拒绝（不落位、不创建活动）；
2. 文字层解析：按名字/别名匹配已有档案 → 复用；未命中 → 产生新对象候选（暂定，**不立即落库**）；
3. 置信度门禁：低于阈值 → 记录 `subject/object_rejected` 并阻断（身份确认回合，未来）；
4. 落位：`fact/external_input` 携带 object 字段，原文永不改写；**新对象此时落库为 provisional**（记录 `subject/object_resolved`）；
5. 认知确认：模型判定 → `subject/object_identity_assessed`；confirm → 升级 confirmed，uncertain → 保持 provisional，deny → 标记 rejected（均追加记录，不改写原文）；
6. 内部输入（source=internal）标记 system，不经过本模块。

## 7. 占位与未来

- 当前占位：文字对象必填校验、置信度门禁、SQLite 档案（寻找/新建暂定对象）；占位模型不参与确认；
- 未来接入：渠道层对象映射、身份确认回合、档案合并、正文实体解析新建对象、多模态线索、流式累积识别。

## 8. 验收标准

- 文字输入缺失对象 → 拒绝（明确错误，不落位、不创建活动）；
- 提供已知对象 → 匹配档案，落位携带 object_id；
- 提供新名字 → 基于文本新建暂定对象，来源可追溯，且在默认阈值下可进入活动；
- 暂定对象低置信（如 0.0）→ 不进入后续活动，记录原因；不得与“无对象”混同；
- 认知确认：模型判定 confirm 后 status 升 confirmed，记录可追溯；
- 内部输入标记 system。

## 9. 与其他模块的关系

- 依赖：ObjectProfileRepository（SQLite）、输入信封（00）、基础认知模型（确认）；
- 被依赖：记录入口落位（00 阶段①）、按对象组织的召回与关系情境（09、03）；
- 概念边界：本模块 = 渠道说话人 + 文字对象解析；REMS 角色抽取 = 文本叙事实体。

## 10. 扩展性预留

- 识别器输入基于输入信封扩展，新增模态不破坏接口；
- `channel` / `carriers` 字段为声纹、人脸、设备、账号、上下文线索预留；
- 识别载体匹配占位为精确匹配，未来接入嵌入相似度 / 声纹比对等真实匹配；
- 置信度阈值、确认回合、合并机制、正文实体解析、流式累积预留；
- 存储经仓库接口可替换（SQLite 为推荐实现）。

## 11. 待验证问题

以下内容仍是原型策略，不因 01 代码已实现而自动定稿：

1. 各识别来源的置信度数值和默认阈值是否适合真实渠道；
2. 低置信暂定对象应直接阻断，还是进入受限的身份确认活动；
3. 对象档案合并、否认和纠错如何保持历史可追溯；
4. 不同形态提供的对象引用能否满足同一输入信封契约。

本轮只校准这些原则，不修改 01 的实现细节；后续以真实输入样本和误识别代价决定策略。
