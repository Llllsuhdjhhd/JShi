# 01 身份识别（对象解析）

> 模块文档。术语以《概念词汇》为准，流程位置见《00 流程总览与输入边界》阶段①。
>
> 状态：初稿，待讨论定稿。

## 1. 定位

本模块回答一个问题：**这条外部输入来自谁**。

答案最终以"对象标识 + 置信度 + 确认状态"的形式进入落位，并影响后续一切按对象组织的处理（归属判断、召回、关系情境）。本模块是输入边界（阶段①）的第一步，先于落位与所有后续环节。

## 2. 对象从哪里来：文字是最终形态

任何输入（语音、文字，未来的图像/视频）最终都以**文字**形态进入系统。对象信息随文字一起进入，其确定过程是**分层递进**的两段，先后关系而非并列：

1. **渠道层对象映射**（前置，未来）：输入通道本身携带的对象来源，在进入文字层之前映射为对象标识——
   - 语音 → 声纹识别；
   - 对话框 / App → 账号或登录会话（如已知好友）；
   - 设备、人脸等其它载体；
   渠道层把对象标识随输入一起送入文字层。
2. **文字层对象解析**（必经，当前实现重点）：文字是输入的最后形态，所有输入都在这里完成对象必填校验、按文本寻找或新建对象、置信度门禁。

### 对象必填规则

- 语音：渠道层识别（未来）在转写时嵌入对象；
- 文字：对象来自渠道（账号/会话，如对话框中的好友）或显式提供（对象标识 / 名字 / 称呼）；
- 两者皆无 → **缺失 → 拒绝**：不落位、不创建活动，返回明确错误；
- 渠道层识别失败（unknown）：对象存在但未确认，进入置信度门禁流程（见 §4.2）。

## 3. 对象如何确定：寻找与新建

对象的寻找与新建都基于文字：

- **寻找**：按输入中的名字 / 称呼（aliases）匹配对象档案；命中 → provisional（渠道层匹配为 confirmed）；
- **新建**：输入给出的名字未匹配档案 → 基于该名字创建暂定对象档案，来源 = 该次输入的事实 id；
- 正文中自动发现新对象（如"我认识了一个朋友叫小张"）属于认知阶段的实体解析，未来接入，本模块不做。

## 4. 可信程度：置信度、门禁与确认

### 4.1 置信度（每次活动动态计算）

文字携带对象**不自动等于置信度 1**。置信度**不存库**，是每次活动由识别过程按"识别来源 × 档案状态"动态计算的瞬时值；档案状态变化（暂定 → 已确认）会自然改变后续活动的置信度。

| 识别来源 | 无档案（新建候选） | 暂定档案 | 已确认档案 |
|----------|--------------------|----------|------------|
| 渠道匹配（声纹 / 账号会话，未来） | 0.70 | 0.70 | 0.95 |
| 显式名字匹配 | 0.60 | 0.65 | 0.85 |
| unknown | 0.00 | 0.00 | 0.00 |

未来增强：累积确认次数、长期关系权重可进入计算，仍不存单次置信度。

### 4.2 置信度门禁

候选置信度低于阈值 `min_object_confidence`（默认 0.5）→ **不进入后续活动**：

- 记录原因（`subject/object_rejected`），不创建活动、不进入认知；
- 可先走**身份确认回合**（轻量交互，未来）：达标后继续，否则拒绝；
- unknown 视为低置信，走同一路径。

### 4.3 认知确认

确认由**认知活动**承担（阶段⑤）：基础认知模型对说话人候选做判定（confirm / deny / uncertain）。模型是匠石的内生认知基础，判定属于认知内容、默认"考虑中"，经认识状态迁移或显式记录后生效；它不是独立的外部确认系统。确认结果追加记录 `subject/object_identity_assessed`，不改写事实原文。

## 5. 接口契约

### 5.1 输入

`resolve(subject_id, text, object_ref, channel=None)`：

- `object_ref`：说话人显式引用（对象标识 / 名字 / 称呼），必填；
- `channel`：渠道信号（未来：声纹 / 设备 / 上下文线索）；
- 内部输入（source=internal）不经过本模块，直接标记 `system`。

### 5.2 输出 SpeakerCandidate

| 字段 | 取值 | 说明 |
|------|------|------|
| label | 显示名 | 按档案或提供的名字 |
| object_id | 对象标识或 None | unknown 为 None |
| confidence | 0.0 ~ 1.0 | 见 §4.1 |
| status | unknown / provisional / confirmed | 默认候选 |

### 5.3 存储：对象档案

- `ObjectProfileRepository`（可替换接口）；
- 推荐实现：**SQLite**——在 `subject.sqlite3` 中新增 `object_profiles` 表，与主体数据同库，便于按对象组织召回与关系情境；测试可用内存 / JSON 实现；
- 字段：object_id、label、aliases（称呼/别名）、channel、source（导入 / 文本新建）、status（unknown / provisional / confirmed / rejected）、created_at、updated_at；**不存单次置信度**；
- **写入时机**：新对象在通过置信度门禁、进入落位时首次落库为 provisional（来源 = 输入事实 id）；认知确认 confirm → 升级 confirmed，deny → 标记 rejected（保留审计）；被门禁阻断的输入不落库；已存在对象只更新状态，不重复创建；
- 暂定档案确认后合并进已知对象，合并显式记录（未来）。

## 6. 行为流程

1. 输入到达：校验对象来源（渠道或显式），两者皆无 → 拒绝（不落位、不创建活动）；
2. 文字层解析：按名字/别名匹配已有档案 → 复用；未命中 → 产生新对象候选（暂定，**不立即落库**）；
3. 置信度门禁：低于阈值 → 记录 `subject/object_rejected` 并阻断（身份确认回合，未来）；
4. 落位：`fact/external_input` 携带 object 字段，原文永不改写；**新对象此时落库为 provisional**（记录 `subject/object_resolved`）；
5. 认知确认：模型判定 → `subject/object_identity_assessed`；confirm → 升级 confirmed，uncertain → 保持 provisional，deny → 标记 rejected（均追加记录，不改写原文）；
6. 内部输入（source=internal）标记 system，不经过本模块。

## 7. 占位与未来

- 当前占位：文字对象必填校验、置信度门禁、SQLite 档案（寻找/新建暂定对象）；占位模型不参与确认；
- 未来接入：渠道层对象映射、身份确认回合、档案合并、正文实体解析新建对象、多模态线索、流式累积识别。

## 8. 验收标准

- 文字输入缺失对象 → 拒绝（明确错误，不落位、不创建活动）；
- 提供已知对象 → 匹配档案，落位携带 object_id；
- 提供新名字 → 基于文本新建暂定对象，来源可追溯，且在默认阈值下可进入活动；
- 低置信（如 unknown / 0.0）→ 不进入后续活动，记录原因；
- 认知确认：模型判定 confirm 后 status 升 confirmed，记录可追溯；
- 内部输入标记 system。

## 9. 与其他模块的关系

- 依赖：ObjectProfileRepository（SQLite）、输入信封（00）、基础认知模型（确认）；
- 被依赖：记录入口落位（00 阶段①）、按对象组织的召回与关系情境（09、03）；
- 概念边界：本模块 = 渠道说话人 + 文字对象解析；REMS 角色抽取 = 文本叙事实体。

## 10. 扩展性预留

- 识别器输入基于输入信封扩展，新增模态不破坏接口；
- `channel` 字段为声纹、设备、上下文线索预留；
- 置信度阈值、确认回合、合并机制、正文实体解析、流式累积预留；
- 存储经仓库接口可替换（SQLite 为推荐实现）。
