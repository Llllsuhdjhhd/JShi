# 记忆层契约（Jshi_memory 实现参考）

> 状态：**已实施（2026-08-23）**。Jshi_memory（REMS3 fork）已按本契约实现 `MemoryBackendPort`（`src/rems/port.py`、`REMSPipeline.ingest_batch` / `recall`）；本仓库 `doc/design/09-记忆系统.md` 已按本契约重写。`stored_marks` 与 `RecalledFragment` 按实现定稿为下列形状。
> 关联：00（输入边界）、16（经历账本）、30（记忆数据管控 / 220 投递策略）、概念词汇（记忆 / 主体记忆 / 对象映射表）。

## 1. 定位

- 记忆是匠石的**可替换后端**：主流程只依赖端口形状，不绑定任何引擎；
- 后端 = Jshi_memory（REMS3 fork），实现 `MemoryBackendPort`；JShi 保留进程内 `InProcessMemoryBackend` 兜底，随时可换；
- 硬约束：**无抽象事件**；**不建角色系统**（对象一律用 01 的 `object_id`）；只做记忆，不决定主体面；原文保全。

## 2. 写入契约（记忆 ingest）

```python
class MemoryExperience:
    subject_id: str                     # 归属匠石，恒在
    text: str                           # 经历原文（含名字；多轮可整段进入，不切分）
    objects: dict[str, str] = {}        # 对象映射表：名字/称呼 → 01 object_id（含没说话的）
    source_ids: tuple[str, ...] = ()    # 来源链：事实 / 活动 / 认知 id，必带
    occurred_at: datetime | None = None
    segment_id: str | None = None       # 30 侧经历段 id，用于 stored_marks 回填
    origin: str = "external"            # external | internal | dream

class MemoryBatch:
    subject_id: str
    experiences: tuple[MemoryExperience, ...]  # 有序：对话/经历先后顺序

class BackendIngestResult:
    subject_id: str
    stored_marks: dict[str, list[str]]  # segment_id -> 本轮封存事件 id 列表（封存几个填几个）
    sealed_event_ids: list[str]
    role_ids: list[str] = []            # 本轮登记/更新的 01 对象，可为空
    unclosed_count: int = 0
    errors: list[str] = []              # 非致命错误
```

约定：

- `text` 是原文，**不归一化、不改写、不切分**；单轮是多轮的特例；
- `objects` 覆盖文本涉及的所有对象，**与是否说话无关**；可为空（= 主体记忆）；
- `source_ids` 必带，保证来源可追溯；
- `stored_marks`：一段经历封存几个事件就填几个（`segment_id → 事件 id 列表`）；本轮未封存任何事件（全部留在未完成缓冲）则不写该项，不算错误；
- 30 构造 `MemoryExperience` 时按经历段映射：`text_raw → text`、`objects → objects`、`source_ids → source_ids`、`segment_id = 经历段 id`、`origin` 按 `output_kind`（external_input / subject_reply / subject_state / subject_silent → `external`；internal → `internal`）。

## 3. 读取契约（回忆 recall，预留）

```python
recall(
    subject_id: str,
    query: str,
    *,
    object_id: str | None = None,
    level: int = 1,
    limit: int | None = None,
    anchor_event_ids: tuple[str, ...] = (),
) -> Sequence[RecalledFragment]
```

- `RecalledFragment` 至少含：`event_id`、`text`（原文，溯源）、`content`（按 `summary_level` 选出的摘要文本，供预算 / 组装）、`kind`、`object_id`、`source_ids`、`score`、`summary_level`；
- 查询保持原文；对象过滤用 `object_id`（可空 = 跨对象，含主体记忆）；
- 回忆**只读 + 记忆恢复**：不新增记忆单元、不登记 recall_log；被召回的记忆强化遗忘因子（回忆加强记忆）是唯一写操作。

## 4. 记忆单元（后端内部）

| 字段 | 说明 |
|------|------|
| `memory_event_id` | 记忆单元稳定标识 |
| `subject_id` | 归属匠石，恒在 |
| `object_ids` | 01 对象标识集合（来自输入映射表，可为空 = 主体记忆） |
| `content_raw` | **原文**（含名字；不归一化、不改写） |
| `summaries` | 先 L1 单层，稳定后再扩展 |
| `source_ids` | 来源链 |
| `activity_id` | 活动锚点（可选） |
| `occurred_at` | 发生时间 |
| `memory_status` | sealed / suppressed（遗忘只降可见性，不删原文） |

对象记忆时间线（ObjectMemoryEntry）：`object_id` → 该对象在一事件中的一句摘要快照，按时间组织。

**未完成事件 / 残影**：后端内部工作缓冲，不跨端口暴露；主链路（02/03/05/07）不接触。

## 5. 后端必须遵守

1. **原文保全**：`content_raw` 永不改写；
2. **对象来自 01**：不抽取、不建档、不建角色系统；文本中出现未知名字时保持原样或返回候选，不自行解析；
3. **无抽象事件**：不做频繁子集挖掘、ASF、`source_events`、抽象合成；
4. **主体记忆合法**：`object_ids` 可为空，事件角色列表可只含主体；
5. **记忆 / 回忆独立**：`ingest_batch` 与 `recall` 互不耦合；`consolidate` / `dream` 为后台接口（本轮占位）；
6. **失败隔离**：单次 ingest / recall 失败不污染历史、承诺或个人世界；
7. **可替换**：与 JShi 的 `InProcessMemoryBackend` 实现同一端口形状，替换后主流程行为不变。

## 6. 四步端口

```text
MemoryBackendPort:
  ingest_batch(batch: MemoryBatch) -> BackendIngestResult
  recall(subject_id, query, *, object_id, level, limit, anchor_event_ids)
      -> tuple[RecalledFragment, ...]
  consolidate(subject_id, *, budget=None, cursor=None)   # 占位
  dream(subject_id, *, object_id=None, budget=None)      # 占位
```

## 7. 投递路径（经历如何进入记忆）

```text
外部活动/内部活动 → 16 经历段（text_raw + objects + source_ids，原文不改写）
  → 07 收尾 → 30 run_once
  → 30 build_memory_batch：按冲刷策略（220）取未投递段，映射 MemoryExperience（透传 text + objects）
  → ingest_batch(batch)
  → 返回 BackendIngestResult（stored_marks：segment_id → 事件 id）
  → 30 凭 stored_marks 推进 memory_start、标记台账
```

投递成功或失败都不改 16 的原文与活跃区；失败保留批次与原文，允许重试。

## 8. 验收标准（Jshi_memory 侧）

- 单元测试覆盖：四类经历段（external / reply / state / silent / internal）可 ingest；
- **主体记忆**：`objects` 为空时正常封存，`object_ids` 为空，不阻断；
- 对象映射表：`objects` 值正确进入 `object_ids`（与是否说话无关）；
- `stored_marks` 与 `segment_id` 一一对应（封存几个填几个；完全未封存不写该项）；
- 原文不被改写（`content_raw` == 输入 `text`）；
- 无抽象事件相关代码残留（不出现 `mine_and_synthesize`、ASF、`source_events`）；
- 不调用角色抽取（输入即对象，后端不做名字 → id）；
- 原有 `tests/unit` 基线不回归。

已通过（2026-08-23）：`tests/unit/test_ingest_batch.py` 覆盖主体记忆、对象映射表、原文保全、`stored_marks` 列表、失败隔离。

## 9. 与 REMS3 fork 的对应

| 本契约 | REMS3 对应 |
|--------|-----------|
| `ingest_batch` | `MetabolismService.process_input` + `EventService.seal_event`（批次适配：逐 input 走代谢） |
| `recall` | `RecallPipeline`（BGE-M3 多路召回 + RRF + 遗忘因子/记忆恢复 + 摘要档位，见 Jshi_memory design/1010） |
| `consolidate` | `tier1_refresh` + 摘要补全 / 整理（无抽象） |
| `dream` | `DreamEvolutionSkill` + `jobs/dream_consolidation` |
| 对象映射表 | 替代 REMS3 角色抽取：`role_id` = 01 `object_id`，输入即对象 |
