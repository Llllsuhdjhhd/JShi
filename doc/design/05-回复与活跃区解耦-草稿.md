# 05 回复与写场解耦（草稿 · 已定方向：拆法乙）

> 状态：**草稿（方向已定）· 代码已实现（含人格写场指令拆分）**。实现方案见 `方案(coding)/05-回复与活跃区解耦.md`。

## 1. 目标

把阶段⑤ 里「**这拍的回复**」（response_plan / reply）与「**写场/现场提炼**」
（活跃区重写 / 片场增量）拆成**两次独立调用**：

1. **回复调用（先出）**：交出 `response_plan`（木头）/ `reply/action`（人格）；可流式（I-001）。
2. **写场调用（独立）**：交出该轮现场提炼；本轮的回复为输入之一（写「我说：…」）。

## 2. 木头 vs 人格（实现差异，决定分发与写场机制）

| | 回复 | 写场（现场提炼） | 载体 |
|---|---|---|---|
| **木头（默认）** | `response_plan` | **整份重写** `rewritten_context`；16 `save_rewritten_context` 覆盖 | 现在：同一个 JSON 一次调用 |
| **人格（苏西坡/斯密斯）** | `mode/reply/action/reason` | **块级增量** `edit` + 程序追加本轮输入与 reply/action（`_apply_zone_edit`→`zone.apply_edit`） | 现在：同一个 JSON 一次调用 |

拆分后：两条路径都变成**两次调用**——回复调用 + 写场调用。

## 3. 设计（拆法乙）

### 3.1 两次调用的分工

```
调用1 · 回复（先出、可流式）
  木头  → {mode,reason,items}          → response_plan      → 06 → 10
  人格  → {mode,reply,action,reason}   → response_plan      → 06 → 10

调用2 · 写场（现场提炼；以调用1的回复为输入）
  木头  → {rewritten_context: 整份}    → 16 save_rewritten_context（覆盖）
  人格  → {edit: 增/删/改}             → zone.apply_edit（del/mod→add→追加本轮输入与 reply/action）
```

- 调用2 用**独立模型请求**；写场失败或为空 → 木头沿用上一份活跃区、人格片场不动，**都不吞调用1的回复**。
- 调用2 只做写场，不产出回复、不做对象确认、不召回。

### 3.2 分发规则：人格隐藏木头的写场

- **选中某人格（斯密斯/苏西坡）** → 只执行**该人格**的写场（edit + 程序追加）；**木头的活跃区整理路径不跑**。
- **选中木头** → 走木头整份重写（`rewritten_context`）。
- **二者互斥**：绝不会在人格局同时跑木头写场。这是程序按 `style_packs` 选中的包分发，不靠模型猜。

### 3.3 时序保证（重点）

- **写场(N) 必须在 N+1 轮回复/提示词生成之前完成**。下一轮提示词要读上一轮的现场，所以现场提炼是
  **阻塞在本轮结束前**的步骤，不能异步飘到下一轮之后。
- **回复(N) 不等 写场(N)**：回复先出、先交付；写场在其后、本轮内完成。
- 在现行同步主流程里这一点天然满足（写场在 `⑥行动` 之后、本轮返回之前执行）；拆分后需保持该顺序，
  不得把写场挪到活动结束后、或在 N+1 轮提示词生成时才做。

### 3.4 材料层与 30→09 不变（与活跃区形态无关）

- **30→09 记忆落库吃「新输入 + 新口头」**（`input_text` + 本轮回复），**不把整份活跃区/片场当新记忆**。
- 木头的材料层其它功能（09 按 `input_text` 召回、01/08 真源、账本 `text_raw` 只追加、对象确认）**全部保留**，
  **不受活跃区是整份重写还是增量的影响**。
- 本次拆分**只动 05 的现场层**；`text_raw`、09 已存原文、01 档案、08 承诺与价值、30 批次构造均不变。

### 3.5 写场失败的容错（重试一次 + 保留输入与回忆）

- 调用② 写场失败 → **重试一次**；仍失败 → 木头沿用上一份活跃区、人格片场不动，不挡调用① 的回复。
- **重试与失败都不丢输入与回忆**：本轮 `input_text`、已召回回忆仍留在材料层（账本 `text_raw` / 03 组装），
  供下一轮或本次重试继续使用。

## 4. 行为定义（按选中包）

| | 木头（整份重写） | 人格（块级增量 + 程序追加） |
|---|---|---|
| 调用1 · 回复 | `response_plan` 必出、可流式 | `reply/action` 必出 |
| 调用2 · 写场 | 整份 `rewritten_context`；空/失败→沿用上一份 | `edit` + 程序追加；`edit=[]`/失败→片场不动 |
| 时序 | 回复先出；写场本轮内完成，供 N+1 轮读取 | 同左 |
| 写场失败 | 重试一次；仍失败→沿用上一份，不挡回复 | 重试一次；仍失败→片场不动，不挡回复 |

## 6. 验收（文档层）

- 回复调用与写场调用是两次独立请求；回复调用后 06→10 可走，不等待写场调用。
- 写场(N) 完成后才进入 N+1 轮提示词生成；N+1 轮读到的现场 = N 轮写场结果。
- 人格选中时，木头写场路径不执行；木头选中时走整份重写。
- 写场失败 → 重试一次；仍失败 → 木头沿用上一份、人格片场不动，且不丢输入与回忆，回复不受影响。
- 30→09 仍收 `input_text` + 新口头，不把整份活跃区当记忆。
- 06/10 只消费 `response_plan`；写场失败不影响 06→10。

## 7. 已定决策与待确认

**已定：**
- 拆法乙（两次调用）；木头 & 人格都拆，默认木头也从 1 次→2 次调用。

- 写场(N) 完成前，N+1 轮提示词不生成；回复(N) 不等写场(N)。
- 30→09 收新输入+新口头，材料层与活跃区形态无关。
- 写场失败重试一次；仍失败→沿用上一份/片场不动，不丢输入与回忆。
- D-009 修订（补一句）。
