# 主体过程实验

## 1. 实验目的

当前实现不以“已经创造一个人”为结论，而验证最小主体闭环：

> 匠石能否把认知、选择、行动和结果持续归属于自己，并让这些经历真实影响后续活动。

总体概念见[《匠石总体图景》](总体架构.md)。术语以[《概念词汇》](概念词汇.md)为准；其中「关切」已收束为「未完成现实」的主体面。

## 2. 已实现对象

### 个人内容

用于保存记忆、价值、关系、承诺、未完成现实（主体面，实现字段暂为 `concern`）、能力、审美和自我理解。每项内容具有来源、状态、修订版本和时间；价值、审美等条目可携带重要程度（`importance`，暂存于 metadata），装载时按重要程度排序。

### 当前活动

用于保存一次外部活动或内在活动的触发原因、已挂载的未完成现实（主体面）、意图和完成状态。一次活动不等同于一个永久记忆。

### 认知内容

用于保存感知、回忆、推断、想象、评价和意图，并区分其认识状态和证据来源。

### 状态变化

用于记录认知内容或个人内容为何从一个状态转为另一个状态。旧状态及变化理由不会被最终状态覆盖。

### 两种历史

- 事实历史保存输入、语言行动和外部结果；
- 主体历史保存认知出现、认识状态变化、反思及个人内容变化。

### 占位系统

身份识别、归属判断、意图、受约束偶然性、结果反馈、治理与连续性检验、反思均已提供独立接口（`port.py`）与占位实现：主流程已按最新流水线串联，内部细节待真实系统接入。各系统可独立替换，不改动主流程顺序。

## 3. 当前主体循环

外部活动目前按以下方式运行：

1. **阶段① 身份系统识别 + 落位**：识别说话人对象（输出候选对象与置信度；未确认标为未知对象），将完整文字输入落位到事实历史（`external_input`，原文永不改写，携带对象标识）；
2. **阶段② 归属判断**：只读常驻约束清单（承诺 + 已有主体面未完成现实），先判断本输入延续或归属到哪个已有关切（可多个；结构候选 + 可选的轻量语义确认，结果暂定、可修正），**先于回忆与个人世界组装**；
3. **阶段③ 当前状态组装**（只读已有记录，两条支路）：命中关切 → 关切中心组装（焦点关切的来源与推进史 + 承诺 + 按重要程度截断的个人世界）；未命中 → 全量组装（身份 + 个人世界 + 开放事项清单 + 记忆召回）。**不在此步编造新的未完成现实**；
4. **阶段④ 活动建立**：建立当前活动，仅挂载命中的关切标识；
5. **阶段⑤ 认知活动（可追加召回）**：将输入记录为已感知的他人报告；使用基础认知模型形成认知内容并初始标记为“考虑中”；若模型提出追加召回请求，程序执行追加召回（只读、预算内、记账 `recall_extended`）后继续认知，直至产出或达到轮次上限；
6. **阶段⑥ 行动与结果**：记录语言行动；结果反馈为占位钩子（未实现）；
7. **阶段⑦ 收尾与沉淀**：保存事实历史与主体历史、状态迁移审计，完成活动；治理/连续性检验为占位钩子（未实现）。

本轮若要形成**新的**主体面未完成现实，须在认知之后显式调用 `propose-open`（或等价接口），并带上认知/事实来源标识。记忆面的未封存片段（若接入外部记忆引擎）与主体面了结相互独立。

记忆默认使用项目内事实历史的最小召回实现（`MemoryPort` / `InProcessHistoryMemory`）。外部引擎可选，非本实验必做项。

反思活动会组装当前状态、读取近期历史，调用同一认知基础形成一项“考虑中”的评价。反思结果不会自动改写长期人格。反思经反思系统占位接口执行。

## 4. 当前可验证行为

- 一个想法可以从考虑中转为暂时接受、接受、拒绝、搁置或修正；
- 每次状态变化保留理由；
- 主体面未完成现实和承诺可以跨活动持续；
- 未完成现实或承诺的完成和解除必须显式记录；
- 使用相同模型但拥有不同个人内容的匠石，可以形成可追溯的不同认知结果；
- 输入落位携带对象标识（身份识别为占位实现，默认未知对象）；
- 延续性输入可先归属到已有主体面关切（关切中心组装），未命中时走全量组装；
- 认知活动可提出追加召回请求：程序执行、记账并受轮次上限约束；
- 意图、结果反馈、治理与连续性检验为占位钩子，行为可注入替换；
- 内在反思与外部事实分开保存。

## 5. 使用方式

在项目根目录设置 Python 路径：

```powershell
$env:PYTHONPATH="src"
```

创建一个基础型匠石：

```powershell
python -m jshi.app.cli create stone
```

添加主体面未完成现实或承诺：

```powershell
# 认知之后、带来源地记录未完成现实（主体面）
python -m jshi.app.cli propose-open stone "继续理解朋友最近的疲倦" --source <认知标识>

# 也可添加承诺等其它个人内容
python -m jshi.app.cli add-personal stone commitment "下次继续询问他的近况"
```

预览进模型前的当前状态（含身份识别与归属判断，不调用模型、不落库）：

```powershell
python -m jshi.app.cli preview-state stone "今天有些疲倦"
```

进行一次外部活动：

```powershell
python -m jshi.app.cli experience stone "今天有些疲倦"
```

进行一次内部反思：

```powershell
python -m jshi.app.cli reflect stone "回顾刚才的交流"
```

查看个人世界和历史：

```powershell
python -m jshi.app.cli personal stone
python -m jshi.app.cli history stone
python -m jshi.app.cli history stone --kind fact
python -m jshi.app.cli history stone --kind subject
```

将一项认知转为暂时接受：

```powershell
python -m jshi.app.cli transition <认知标识> provisional "目前证据有限，先暂时接受"
```

## 6. 模型配置

没有配置远程模型时，程序使用离线测试模型，只用于验证框架。

使用兼容 OpenAI 对话接口的模型时，可以设置：

```powershell
$env:JSHI_MODEL_ENDPOINT="接口地址"
$env:JSHI_MODEL_API_KEY="密钥"
$env:JSHI_MODEL_NAME="模型名称"
```

在项目概念中，该模型提供匠石的内生认知基础；接口部署位置不决定主体归属。

## 7. 记忆实现说明

当前实验用项目内历史与个人内容即可验证主体闭环。若后续接入外部记忆引擎（例如 REMS），视为可选增强：由引擎承担原文保管与召回等，匠石仍负责认识状态、主体历史、承诺与主体面未完成现实。未接入时，不得把「必须使用某一引擎」或「必须自建与引擎同构的多层记忆」当作本实验的缺口。

## 8. 当前限制

- 个人世界装载使用最小实现：承诺与开放事项始终装载，其余条目按重要程度排序、预算内截断；没有实现成熟的注意机制；
- 重要程度（`importance`）暂存于 `metadata`，尚未升格为正式字段；
- 模型输出整体记录为一项认知内容，尚未自动拆分多项推断、评价和意图；
- 认识状态主要由明确操作改变，尚未实现可靠的自动变化原则；
- 反思不会自动形成长期记忆、能力或价值变化；
- 尚未实现外部行动结果的自动反馈；
- 尚未区分记忆面未封存与主体面未完成现实的双面存储（概念已定，实现仍用 `concern` 表示主体面）；
- 尚未实现持续输入、多模态、实时认知和模型迁移；
- 身份系统识别为占位实现：说话人默认 `human`/未知对象，确认机制、对象档案、导入与合并均未实现；
- 原始输入落位尚未显式经过记忆接口（当前直接写入历史表）；对象标识以 `content` 字段携带，尚未升格为正式字段；
- 归属判断为占位实现：仅结构候选（唯一关切延续 / 词汇重叠），模型语义确认与归属修正接口待接入；
- 追加召回预算为模块级常量（轮次/片段上限），尚未升格为配置项；
- 意图系统、治理与连续性检验仍为占位，尚无实际行为；
- 当前实验只能验证可观察的主体连续关系，不能证明主观意识。

这些限制属于后续实验问题，不应通过未经验证的自动规则过早填补。文档只记录已约定的项目共识；探路性讨论若未写入本章或《总体架构》《概念词汇》，不构成实现义务。
