# 主体过程实验

## 1. 实验目的

当前实现不以“已经创造一个人”为结论，而验证最小主体闭环：

> 匠石能否把认知、选择、行动和结果持续归属于自己，并让这些经历真实影响后续活动。

总体概念见[《匠石总体图景》](总体架构.md)。术语以[《概念词汇》](概念词汇.md)为准；主体面未完成现实 / `concern` 已废除（D-007）。

当前代码首先验证记录、来源、状态和模块接线。它是用于逼近上述目标的实验框架，不代表“经历真实影响后续活动”已经完整成立。项目级证据要求见[《第一阶段验证章程》](第一阶段验证章程.md)。

## 2. 已实现对象

### 个人内容

用于保存记忆、价值、关系、承诺、能力、审美和自我理解。每项内容具有来源、状态、修订版本和时间；价值、审美等条目可携带重要程度（`importance`，暂存于 metadata），装载时按重要程度排序。

### 当前活动

用于保存一次外部活动或内在活动的触发原因、意图占位和完成状态。活动不挂载事件。一次活动不等同于一个永久记忆。`wait` 也会关闭本轮活动；下一轮外部输入新建活动。

### 认知内容

用于保存感知、回忆、推断、想象、评价和意图，并区分其认识状态和证据来源。外部主链路落感知条目，并产出 **回应计划**（`response_plan`）；不另落一条名为 thought 的推断记录。`think` 是回应计划的一种 mode，不是独立存储对象。反思活动仍落一条“考虑中”的评价。

### 状态变化

用于记录认知内容或个人内容为何从一个状态转为另一个状态。旧状态及变化理由不会被最终状态覆盖。

### 两种历史与经历账本

- 事实历史保存输入、语言行动和外部结果；
- 主体历史保存认知出现、认识状态变化、反思及个人内容变化；
- 经历账本保存原始经历流，并维护当前上下文视图（`ContextViewState`）。活跃区只读该视图，不重切原文。

### 占位系统

身份识别、意图、受约束偶然性、结果反馈、治理与连续性检验、反思均已提供独立接口（`port.py`）与占位实现。归属判断已废弃，主流程不再调用。各系统可独立替换，不改动主流程顺序。

## 3. 当前主体循环

外部活动目前按以下方式运行：

1. **阶段① 对象解析 + 落位**：识别说话人对象（候选与置信度；低于门禁则阻断）。完整文字落入事实历史（`external_input`，原文永不改写），并追加到经历账本。本轮输入不提前并入本轮模型所见的上下文视图。
2. **阶段② 活跃区装载**：从经历账本读取当前 `ContextViewState`。不调用模型，不重切原文，不调整视图，不识别事件。
3. **阶段③ 当前状态组装**：只读已有记录，装入身份、上下文视图、个人世界与记忆线索。不装载事件，不编造主体面未完成现实（该概念已废除）。
4. **阶段④ 活动建立**：建立外部活动（trigger=事实 id）；意图占位；不挂载事件。
5. **阶段⑤ 认知活动（可追加召回）**：将输入记为已感知的他人报告；模型产出 `response_plan`。若提出追加召回，主流程调 09 执行（只读、最多一轮、记账），05 不自己检索。不落 thought。
6. **阶段⑤→⑥**：06 校验并标记 `response_plan`。06 不是认识状态机。
7. **阶段⑥ 行动与结果**：按计划并列分发语言 / 动作 / 结果反馈。仅 `respond` 走语言通道；`think` / `ignore` / `wait` 关掉语言，embodied 仍可发。经历账本追加回复或状态；`respond` 后按评估更新上下文视图。结果反馈与机器人为占位。
8. **阶段⑦ 收尾**：07 关闭活动为 `completed`（含 `wait`）。然后 30 尝试投递记忆批次（失败不使活动失败）。治理/连续性检验为占位。

不设主体面未完成现实 / `concern`（D-007）：主链路不装载、不编造，也不提供 `propose-open` 入口。记忆面的未封存片段（若接入外部记忆引擎）只是后端内部缓冲，不进入组装。

记忆默认使用项目内事实历史的最小召回实现（`MemoryPort` / `InProcessHistoryMemory`）。外部引擎可选，非本实验必做项。

反思活动会组装当前状态、读取近期历史，调用同一认知基础形成一项“考虑中”的评价。反思结果不会自动改写长期人格。反思经反思系统占位接口执行。

### 3.1 当前实现对应正常活动

上述七阶段主要描述正常活动：

- 活动开始时装载已有个人世界与记忆；
- 活动内部可以维持临时工作状态并追加召回；
- 活动结束时记录输入、感知、回应计划、行动和状态；主链路不另落 thought；
- 新理解默认是候选认知，不因活动完成而成为长期价值、能力或自我理解；
- 跨活动连续性靠上下文视图与历史，不靠挂起未关闭的活动。

### 3.2 后台沉淀尚未形成完整实现

目标架构中的记忆整理、反思、学习和治理属于后台过程。它们应读取历史与候选内容，整理证据并提出状态变化或个人世界升格。当前 `reflect` 只产生一项“考虑中”的评价，尚未实现完整沉淀。

后台过程未来应遵守：

1. 原始历史不被覆盖；
2. 候选变化具有具体来源；
3. 不同内容按事实核查、推断证据或反思性认可采用不同依据；
4. skill、模型或工具只产生候选结果，主体框架执行结构校验、状态迁移和最终写入；
5. 已沉淀内容在后续正常活动中通过召回或个人世界装载发挥作用。

## 4. 当前可验证行为

- 感知与反思等已落库的认知内容，可以从考虑中转为暂时接受、接受、拒绝、搁置或修正；每次状态变化保留理由；
- 承诺可以跨活动持续；完成和解除必须显式记录；
- 使用相同模型但拥有不同个人内容的匠石，可以形成可追溯的不同结果；
- 输入落位携带对象标识；渠道未提供对象时须用 `--speaker`；
- 下一轮可读取上一轮更新后的上下文视图；本轮输入不进入本轮模型所见视图；
- 活动可追溯 `response_plan` 与活动回复标记；CLI 打印活动 id 与 mode；
- 认知可提出追加召回：程序执行、记账，最多一轮；
- 意图、结果反馈、治理与连续性检验为占位钩子，行为可注入替换；
- 内在反思与外部事实分开保存。

这些条目主要属于结构验证。只有在跨活动对照中显示具体历史、记忆或个人内容改变了后续判断，才属于行为验证。

## 5. 使用方式

在项目根目录设置 Python 路径：

```powershell
$env:PYTHONPATH="src"
```

创建一个基础型匠石：

```powershell
python -m jshi.app.cli create stone
```

添加承诺等个人内容：

```powershell
# 也可添加承诺等其它个人内容
python -m jshi.app.cli add-personal stone commitment "下次继续询问他的近况"
```

预览进模型前的当前状态（含对象解析与上下文视图，不调用模型、不落库；不含归属判断）：

```powershell
python -m jshi.app.cli preview-state stone "今天有些疲倦" --speaker 朋友
```

进行一次外部活动：

```powershell
python -m jshi.app.cli experience stone "今天有些疲倦" --speaker 朋友
```

进行一次内部反思：

```powershell
python -m jshi.app.cli reflect stone "回顾刚才的交流"
```

查看个人世界和历史：

```powershell
python -m jshi.app.cli personal stone
python -m jshi.app.cli history stone
python -m jshi.app.cli history stone --kind fact
python -m jshi.app.cli history stone --kind subject
```

将一项认知转为暂时接受：

```powershell
python -m jshi.app.cli transition <认知标识> provisional "目前证据有限，先暂时接受"
```

## 6. 模型配置

没有配置远程模型时，程序使用离线测试模型，只用于验证框架。

使用兼容 OpenAI 对话接口的模型时，可以设置：

```powershell
$env:JSHI_MODEL_ENDPOINT="接口地址"
$env:JSHI_MODEL_API_KEY="密钥"
$env:JSHI_MODEL_NAME="模型名称"
```

在项目概念中，该模型提供匠石的内生认知基础；接口部署位置不决定主体归属。

## 7. 记忆实现说明

当前实验用项目内历史与个人内容即可验证主体闭环。若后续接入外部记忆引擎（例如 REMS），视为可选增强：由引擎承担原文保管与召回等，匠石仍负责认识状态、主体历史与承诺。未接入时，不得把「必须使用某一引擎」或「必须自建与引擎同构的多层记忆」当作本实验的缺口。

## 8. 当前限制

- 个人世界装载使用最小实现：承诺等按重要程度排序、预算内截断；没有成熟的注意机制；
- 重要程度（`importance`）暂存于 `metadata`，尚未升格为正式字段；
- 主链路不落 thought；模型输出以 `response_plan` 为对外契约。认识状态机暂缓，现有 `transition` 仍可用于已落库的感知/反思条目；
- `ModelResponse` 已接 `context_assessment`：每轮会合并待并入段并应用补丁；Echo / OpenAI 适配器仍只出空缩减/聚焦方案（真实模型尚未解析结构化 `context_assessment` 补丁段）；
- 批次构造与冲刷策略已在 30（`InProcessMemoryControl`），`memory_start` 由 30 维护；
- 组装不装载事件；CLI `preview-state` 仍打印「活跃区事件 id」，实际是活动段 id 的旧字段名；
- 反思不会自动形成长期记忆、能力或价值变化；
- 机器人与结果反馈仍为占位；
- 主体面未完成现实 / `concern` 已彻底废除（D-007）：代码、CLI 与测试均已移除；记忆侧未封存片段只是后端内部缓冲；
- 尚未实现持续输入、多模态、实时认知和模型迁移；
- 身份识别仍是原型：有效外部输入必须提供对象引用；未匹配已确认档案时形成暂定对象；
- 追加召回预算为模块级常量（最多一轮、片段上限），尚未升格为配置项；
- 意图系统、治理与连续性检验仍为占位；
- 当前实验只能验证可观察的主体连续关系，不能证明主观意识；
- 正常活动与后台沉淀在概念上已经分开，但尚无完整的记忆整理、候选审查和个人世界升格流水线。

这些限制属于后续实验问题，不应通过未经验证的自动规则过早填补。文档只记录已约定的项目共识；探路性讨论若未写入本章或《总体架构》《概念词汇》，不构成实现义务。
