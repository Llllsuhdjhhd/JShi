# Windows 开发资料迁移到 Mac

更新于 2026-11-23。第一节记录这台 Mac 的实际启用情况，后文保留 Windows 复制清单和恢复步骤。

### 这台 Mac 上的资料位置（2026-11-23 核对）

Windows 迁移副本在项目根部的 `.windows-migration-20261122/`。其中 `.jshi/` 保存迁入的主体库、记忆库和语音素材，`recordings/` 有原始录音及文字，`recent/` 和 `historical/` 有历次回放与测试产出。原 Windows 分支清单中的 25 个引用与当前克隆逐项一致，迁移时的 HEAD 为 `1a145f0`。同级目录还保留了两个记忆项目。

这台 Mac 的 CLI 通过项目根部私有的 `.env` 读取 `JSHI_DATA_DIR`，默认打开 `.jshi-mac/`。它从 Windows 迁入的整份 `.jshi/` 复制而来，适配前逐文件比对了 1,123 个文件的 SHA-256，共 2,811,918,286 字节，包括 SQLite 的 WAL。原始录音和配套转写仍在迁移目录的 `recordings/`。根部受 Git 跟踪的 `.jshi/` 是旧样例。回放时用 `--data-dir` 指定独立测试目录。

| 核对项 | 本机结果 |
|---|---|
| 主体与记忆 | `stone` 共 10,526 段经历。按旧路径复算并匹配两个模块的游标身份后，给两个主体逐项接续了 Mac 的游标。默认 dual 仍到 10525，legacy 仍到 10244，另一个历史测试主体两项均为 0。 |
| 历史记录 | dual 长期库有 1,338 条事件，对话记录库有 452 条事件。主体、对话、反思、未知输入、dual 长期、dual 近期历史与 legacy 长期这七个 SQLite 库均通过 `PRAGMA quick_check`。 |
| Mac 配置 | dual、legacy 使用各自迁来的目录和相邻项目源码。工作副本的 Python 路径指向项目 `.venv`，dual 的向量模型与重排模型在 CPU 运行。外部模型配置沿用迁入版本，本机 MLX 仍可在模型设置中选用。 |

在独立的 dual 副本上，通过 REMS 接口读回了最早和最近各一条长期事件，正文均与 SQLite 原记录一致。使用缓存权重离线预热后，以“最近聊过什么”检索，长期 512 维向量索引返回 3 条（请求上限 3），近期 Mem0 返回 20 条。这个验证覆盖数据接续和检索通路。语音整轮和外部模型调用耗时需用相同录音单独测量。当前 Mac 环境中，Mem0 的可选 spaCy 和 BM25 扩展未启用。

## 一、具体拷贝哪些

建议把以下三个目录完整复制到移动硬盘或 Mac，保持它们为同级目录。隐藏文件也要复制；只靠 Git clone 不包含所有本机数据。

```text
C:\Users\Lenovo\Desktop\project\
├─ JShi\                       必带：主程序、测试、累计数据
├─ JShi_memory_old_days\       必带：当前 dual 使用的记忆实现
└─ JShi_memory\                带走：legacy 旧记忆实现，保留回退能力
```

Mac 上可以放成：

```text
~/projects/
├─ JShi/
├─ JShi_memory_old_days/
└─ JShi_memory/
```

主项目中的内容按下表保留。这里“必带”表示复制完整目录，不是只取举例的文件。

| 内容 | 处理及用途 |
|---|---|
| `.git/`、`src/`、`tools/`、`doc/`、`tests/`、项目根目录文件 | 带走；保留提交历史、本地分支、代码、说明与测试。根目录已有录音和转写也带走。 |
| **整个 `.jshi/`** | **必带**。不要只取其中一个数据库。包含身份、记忆、进度、声纹、录音、模型设置、对话、工具状态、自省问题及结果等。 |
| `.jshi/rems-dual-20261117/` | 当前 dual 的数据；长期库与近期 Mem0 数据一起复制，不能只带长期库。 |
| `.jshi/rems/`、`.jshi/memory-inprocess/`（若存在） | 旧后端数据一起保留，避免切换时历史丢失。 |
| `.jshi/personal_speakers/`、声纹相关文件、`voiceprint-backups/` | 训练样本、分类器、声纹及备份；不能当缓存删除。 |
| `.jshi/recent_audio/`、`entry_test_assets/`、`vision/`、`voice_trials/` | 累计音频、场景、视觉及测试资料。 |
| `.jshi/backups/` 与其他历史子目录 | 这次迁移先完整带走，确认 Mac 恢复后再另行整理。 |
| **`test_runs/`、`work/`** | 本次也带走。这里除了日志、生成库，还有未入库的回放脚本、样例、分析和历史结果，不要整目录丢弃。 |
| `.env`、`.env.local` 及各项目本地配置（若存在） | 私下复制，用于重建配置；含凭据的文件不要上传仓库或公开分享。 |

旁边两个记忆项目同样先完整复制，包括它们各自的配置、未提交源码和数据。若不确定空间是否足够，先统计大小，不通过删掉累计资料来凑空间。

**可以省略或在 Mac 上重建：**各项目的 `.venv/`、`__pycache__/`、`.pytest_cache/`、纯构建输出 `build/`、`dist/`。`.tmp/` 通常是临时目录，但本项目有长期试验历史，拿不准用途时先带走，勿直接删除。模型权重可保留以减少重新下载；Windows 专用运行库仍须重新安装。

`JShi_memory_hindsight`、`JShi_memory_remote` 未出现在本次检查的本机记忆模块注册表中。它们不是当前 dual 启动所必需；若还要保留这些试验分支的工作和资料，也分别完整复制，不能以未注册推断其中没有重要数据。

## 二、复制前先正常退出

1. 正常退出 Windows 上 JShi，等待记忆写入和后台子进程收尾。也退出单独使用这些库的测试服务。
2. 确认相关进程、端口及文件占用已经释放。正式记忆库用非阻塞锁探测检查，探测后立即解锁；不要删除锁文件来假装释放。无法确认占用来源时先查明，勿强制结束所有 Python。
3. 再复制上述目录。SQLite、Qdrant 和 Mem0 要作为同一份停止写入后的快照复制；不要边运行边拖拽数据库，不要只复制 `.db` 而漏掉仍存在的 WAL 等配套文件。
4. 比较来源与目标的文件数、总字节数，并为重要数据库、声纹和录音生成并比对 SHA-256 清单。复制错误、拒绝访问或漏掉隐藏目录时，不能视为迁移完成。
5. Windows 原件保持不动，至少到 Mac 验证完成。累计资料和凭据通过私人介质迁移，不用 `git add -f` 把它们硬塞入 Git。

## 三、交给 Mac 侧重建环境时要说明

环境安装由 Mac 侧负责。请把本文件和三个项目目录一起交过去，明确以下项目配置问题：

- Windows 的 `.venv` 不可直接运行；重建环境并安装 JShi 及所选记忆项目的依赖。`jshi.cmd` 是 Windows 启动器，Mac 使用安装后的 `jshi` 命令。
- `.jshi/python-path.txt` 是旧 Windows 解释器路径，不可沿用；不要把它误认为数据丢失。保留原备份，Mac 使用自己的解释器。
- 当前 `.jshi/memory-modules.json` 的 `dual.source_root` 为 `../../JShi_memory_old_days`，`legacy.source_root` 为 `../../JShi_memory`，路径以该 JSON 所在目录为基准。采用上面的同级布局通常仍能解析；确认实际位置后再调整。各模块 `data_dir` 指向复制来的旧库，不要新建一个空目录冒充恢复。
- 当前 dual 设置含 `REMS_EMBEDDING__DEVICE=cuda`、`REMS_RECALL_RERANK_DEVICE=cuda`。Mac 不能沿用 CUDA；先由对应实现支持的 CPU 配置验证恢复，再评估其他加速方式。旧 CUDA/ONNX 二进制不能直接照搬使用。
- 保持原 embedding 模型、向量维度和集合对应关系。不要为更快启动随意换模型后直接查询旧向量；确需换模型，应另建索引并核验。
- 检查 `.env`、模型配置及外部工具中的盘符绝对路径；Windows 的工具命令也可能需要替换。麦克风和扬声器重新选择，不沿用旧设备编号。

### 特别注意：跨电脑后的记忆消费游标

本项目的模块游标身份包含**模块名、后端、代码根目录和数据目录的绝对路径哈希**（见 `src/jshi/memory/modules.py`）。即使复制完整数据库，换到 Mac 后路径不同，也会生成新的游标身份。

**Mac 首次正式启动前，须核对并迁移原主体各模块的消费位置到新路径身份。**先在数据副本上检查 `.jshi/subject.sqlite3` 中已保存的模块游标，并结合原库导入范围核验。不能只改路径就假定独立游标自动继承，也不能随意把全部模块设置成 `bootstrap_cursor: current`；旧模块种子或从零回放可能重复处理历史。项目当前没有提供一键跨路径游标迁移命令，应由 Mac 侧开发者基于备份完成这一项适配后再开放对话。

## 四、Mac 上怎样核验

先用复制数据的另一份副本验证，保留未经启动的迁移原件；不要同时用两个客户端打开同一 Qdrant 目录。

1. 比较 Git 提交、本地未提交文件和测试目录；确认 `test_runs/`、`work/` 及隐藏累计目录都存在。当前主测试目录已有版本控制，但历史测试资料大量被忽略，单独 clone 不能恢复它们。
2. 在独立临时目录运行离线测试，入口见 `tests/README.md`。不要让测试打开正式累计记忆库。REMS live 和真实模型回放需单独配置，区分离线通过与真实服务验证。
3. 用 `jshi memory-modules` 查看配置，此命令不打开数据库。游标适配完成后，在核验用副本上尝试 `jshi vision stone --memory-module dual --asr online --tts online`，确认选择的是旧库。
4. 查几条能在原始记录中核对的早期和近期记忆，确认人物归并、来源与声纹样本；确认自省待办及记忆消费位置合理。启动成功不等于数据已验证完整。
5. 回放既有场景，检查语音、工具及停止播放；测试结束正常退出，确认自己的进程和占用释放。通过后再转为正式使用。
