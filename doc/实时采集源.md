# 实时采集源

桌面交谈页控制输入模式和对话。来源决定实时麦克风与摄像头在什么设备上。同一时刻只选一个来源，可以有多台设备同时在线等待选用。

## 来源、连接与通道

| 概念 | 当前实现 | 生命周期 |
| --- | --- | --- |
| 采集源 | `CaptureSource(kind, device_id)`。桌面为 `desktop/local`，手机用 `phone` 加主机根据配对身份生成的设备标识。 | 由接入方式确定。手机重连沿用配对身份，重新配对产生新标识。 |
| 采集会话 | `CaptureSession` 绑定一个采集源和主机生成的 `capture_id`，每次连接另发一个私有上传令牌。 | 从占用到释放。恢复同一段对话或由同一设备重连，均创建新的采集会话。 |
| 媒体通道 | 麦克风 PCM 走持有会话的连接，画面走单独的上传请求。前后镜头、桌面视频与手动选取的照片分别标注。 | 通道按需开启。静音和摄像头开关作用于选中的来源。 |

设备身份用于区分接入端。讲话人身份由已有的语音流程判定。公开的采集编号用于关联音频和画面，上传令牌只交给持有会话的页面。

## 连接与切换

1. 手机在独立的设备连接上报到。桌面通过 `GET /api/capture-sources` 枚举在线设备。选择来源只设置下一次采集的位置。离线选项禁用，连接建立时主机再次核实来源。
2. 桌面从原交谈页开启 `/voice`，使用原有的识别、播报和说话人设置。选择手机时，桌面传入 `source` 设备标识，主机将唯一采集会话绑定到该手机。转写、回复、播报、文字输入和调试继续使用桌面连接。开始视频时主机另发一个仅在本次视频开启期间有效的令牌。
3. 结束对话后，手机保持在线待机。使用中切换来源时，桌面收尾后使用新来源恢复先前的模式。手机掉线时，桌面结束本次采集并保留来源选择。旧设备和旧连接的媒体不能进入下一次采集。
4. 图像处理和模型调用可以晚于设备切换。视觉库在更新实时画面和描述时核对采集编号，观察结果进入对话前也核对归属。同一会话切换镜头时，新画面等待对应镜头的描述。

## 桌面接口

桌面交谈页从 WebSocket 的 `ready` 事件取得 `stream`。调用 `POST /api/vision/frame` 时，应在 `X-Device-Stream` 中带上该令牌。`X-Visual-Source` 可选 `browser`（摄像头）或 `photo`（手动选择的图片）。电脑摄像头仅在选择本机时可以上传；手动选图由当前桌面对话提交。主机成功接收后返回 202，来源或会话不符时返回 409。

`GET /api/vision` 返回当前画面与公开的 `capture` 信息，包含来源种类和本次采集编号。桌面环境观察页通过它把控制指令发送给对应的交谈页面。手机接口见[手机设备](手机设备.md)。

## 接入另一种来源

以网络摄像头为例，适配器可以把已配置的摄像头映射为 `CaptureSource('network_camera', 'room-a')`。同类另一台设备使用自己的实例标识。接入层负责身份、协议、媒体格式和时钟映射，所有实时输入共用同一个 `CaptureSources` 和当前主体的视觉库。

- **上线与连接**。适配器先将可用设备登记到来源列表。只有桌面选中它并开启采集时，才在主机事件循环调用 `acquire`，为本次采集分配新编号。在视觉库选定该编号，设备准备好后才允许传输。仅有画面的设备也占用整个采集位置。
- **上传**。由适配器确定来源与镜头标记。分开传输的画面请求通过 `resolve(来源, 令牌)` 取得当前会话，然后调用共用的画面入口。令牌留在传输层，后台处理携带采集编号。
- **退出**。正常结束、失联和初始化失败都进入收尾路径。先关闭输入，再清理视觉现场和连接，最后释放原会话。延迟到达的旧请求不能借用新会话。
- **多画面**。将来若要同时理解多个机位，需要显式进入独立的合成功能，由它管理各机位、同步时间并标注输入归属。若将其输出接入普通交谈，合成结果作为一个新来源申请采集位置。

当前实现和验证覆盖电脑与手机。网络摄像头是扩展示例，单独的视频设备接入与多机位合成均属后续功能。
