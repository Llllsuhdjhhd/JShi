# 语音模块架构

双路整句更新（2026-10-22 14:00，北京时间）：千问转写后立即启动Namo文本语义判断，不先等Smart Turn；两路都complete提交、都incomplete暂存、冲突交JEV1，缺一路则使用另一路。JSHI_VOICE_SEMANTIC_TURN=namo启用，off关闭；文本预算200ms。更正：TurnSense官方推理输入是音频，本次文本模型为Namo。模型副本按同人原片段换行组装，不改原话、不发送人物ID。 详见《[整句判断说明](整句判断说明.md)》。

最近更新时间：2026-10-22 14:00（北京时间）。

当前Qwen路径：fixed切段策略默认500ms静音、最长3.5秒；每窗仍只发一次千问batch，Smart Turn CPU整句检测在独立线程与转写并行。默认阈值0.5，complete或unknown即组装交JEV1；明确incomplete保留同一可靠声音组的原片段和音频上下文，下次只转写新音频、联合判断，原话不跨人拼接。没有整句结果时最多从并行任务启动等600ms，超时放行给JEV1；未完且静音无新片段2秒、累计12秒音频、32段或采集结束时也释放，不丢输入。未归属、重叠及长间隔不强接续。JEV1仍可keep并保留原话，普通collection_complete仍为null，不把工程分段当成语义说完；没有恢复统一1秒文字等待。 修改后重启Windows匠石服务生效，WSL千问无需重启。

语音按采集、声音分析、转写、流程调度分层。采集方式不决定声纹模型，声纹模型不决定ASR模型。当前实现与可替换接口分开说明，不把预留接口当作已经接好的模型。

## 1. 数据流与模块边界

```text
浏览器/设备PCM ─ PcmCapture ─┐
WAV文件 ────── WavCapture ─┴─ AudioFrame（PCM + 会话内样本位置）
                                  │
           ┌──────────────────────┴────────────────────────┐
           │ Windows 分段路径                               │ 云端流式路径
           ▼                                                ▼
     SileroSegmenter                                 StreamingASRSession
     人声端点，不识字                                   火山 / Deepgram
           ▼                                           适配云端自带分段
     SpeakerAnalyzer                                         │
     分人、重叠标记、声纹证据                                │
           ▼                                                │
     Transcriber.transcribe_many                             │
     仅音频→文字，不接收人物身份                              │
           └─────────── Transcript + 本地人物证据 ────────────┘
                                  │
                         VoiceConversation / JEV / 主认知
```

旧CPU流式预览路径仍由 `LocalASR` 协调Zipformer与整句复核；它属于流程层。新Qwen路径不需要Zipformer来切段，也不加载SenseVoice作为Qwen的前置模型。

| 职责 | 程序位置 | 输入与输出 | 替换约定 |
|---|---|---|---|
| 公共数据 | `voice/contracts.py` | `AudioFrame`、`SpeechSegment`、`Transcript` | 与服务商无关；统一16kHz单声道16位小端PCM，时间为会话相对毫秒 |
| 采集适配 | `voice/capture.py`、`app/voice_capture.js` | 浏览器/设备PCM或WAV→音频帧 | 设备SDK、网络接收器先归一格式再接入；WAV已有程序接口，尚无网页上传入口 |
| 缓存与留存 | `voice/audio_buffer.py`、`voice/recent_audio.py` | 连续音频、按原时间切片 | 不加载模型；旧`match`方法仅转交独立匹配模块以兼容调用者 |
| 人声端点 | `voice/segmentation.py` | PCM→人声窗与起始时间 | `feed(pcm, final=...)`、`reset()`；当前独立适配为Silero |
| 声纹特征 | `voice/features.py` | 有效语音→向量 | `SpeakerEmbedder.embed(samples)`；当前sherpa-onnx适配支持CAM++、ERes2NetV2 |
| 聚合与身份 | `voice/speakers.py`、`voice/matching.py` | 向量/片段→会话声音组、登记匹配及证据 | `SpeakerIdentity.identify_timed/reset_session`；不读取ASR正文，不把会话编号当姓名 |
| 多人分析 | `voice/analysis.py` | 音频窗→`SpeechSegment`列表 | `AudioAnalyzer.analyze`；当前pyannote ONNX分段，独立于文本模型 |
| 本地整句转写 | `voice/transcription.py` | 音频数组列表→等长文本列表 | `Transcriber.transcribe_many`；SenseVoice由`OfflineTranscriber`适配 |
| Qwen转写 | `voice/qwen.py` | 同上 | 一次HTTP提交音频列表；原生batch，按短代号映射返回 |
| 云端流式转写 | `voice/streaming_asr.py`、`voice/deepgram.py`、`voice/volc.py` | 音频流→统一转写结果 | 统一`send_audio/results/finish/close`；云端自带分人属于该适配器能力 |
| 多音源分离 | `voice/sources.py` | 重叠音频→独立音轨→各自转写 | 可选pyannote；声音分离与说话人时间分段是两种能力 |
| 结果规范化 | `voice/transcripts.py` | 服务结果→去重、修订后的转写 | 不依赖云端连接与具体采集方式 |
| 流程与组装 | `voice/pipeline.py`、`voice/runtime.py` | 注入端点、分析器、转写器并关联输出 | 模型构建集中在组装入口；业务层使用统一结果 |
| 模型准备与目录 | `voice/model_assets.py`、`voice/backends.py` | 下载与后端能力登记 | 配置、命令行、状态接口共用后端目录 |

`voice/local.py` 与 `voice/diarization.py` 保留旧导入/调用兼容入口；核心实现已转移到各职责模块。新代码从所属模块导入。

## 2. 当前可选组合

| ASR选择 | Windows端分析 | 最终文字模型 | 选择方式 |
|---|---|---|---|
| `local` | 原CPU流式端点；有分段模型时先分人 | Zipformer；可选SenseVoice整句复核 | `--asr local` |
| `qwen` | Silero端点 + pyannote ONNX分段 + 声纹/增量聚合 | WSL Qwen3-ASR | `--asr qwen` |
| `online` | 可选本地声纹补充证据 | 火山流式及其多人时间线 | `--asr online` |
| `deepgram` | 可选本地声纹补充证据 | Deepgram流式及其多人时间线 | `--asr deepgram` |

声纹选择沿用 `JSHI_VOICE_SPEAKER_MODEL=cam++|eres2netv2`，页面也可按会话选择已准备的模型。分段聚类与身份比对同时切换到同一特征空间；两种模型的登记库分开，不能直接混用向量。

本次统一的是接口和组装边界，不宣称任意厂商协议可以直接互换。新增采集方式实现音频帧接口；新增声音分析实现`AudioAnalyzer`；新增整句ASR实现`Transcriber`；新增云端流式ASR实现流式协议适配器，并在`backends.py`及组装入口登记。FunASR、FSMN及其他模型尚未实现对应适配，不因出现在选型建议中就视为已接入。

ASR与TTS继续独立选择。`qwen`启动后可在页面切到已配置的云端ASR；CPU本地与Qwen当前仍按启动选项加载，切换这两者需重启，不会自动上传音频兜底。

## 3. 多人batch与时间

多个人的独立片段在同一处理窗内组成一个batch，一次HTTP发给WSL的`/v1/asr/batch`。服务端一次调用`model.transcribe(audio=[...])`，SDK一次将列表传给vLLM的`generate(batch, ...)`；不并发发HTTP，也不将多人音频拼成一条。默认每批最多8段，超过上限分小批依次处理；不足8段立即提交，不为凑批额外等待。

关联使用请求内短代号s1、s2等，ASR模型只收到各条音频；Windows保留原人物证据和时间，并在响应时核对全部代号。客户端同一时刻仅提交一个batch，WSL模型调用也串行接收批次；批内GPU调度由vLLM处理。批次接口通过`/v1/models`公布能力和上限，旧标准服务不能冒充batch。

程序入口：`voice/qwen_batch_server.py`；WSL启动脚本：`tools/start_qwen_batch_wsl.sh`。使用已安装的Qwen环境和权重，不另起一份模型与旧服务争用GPU。

Qwen独立路径持续接收音频，Silero默认按500ms静音、最长3.5秒切出处理窗。处理和HTTP发生在声音工作线程，浏览器控制消息继续接收；超过32秒未处理积压时明确报错，不静默丢帧。文件源与实时源复用同一条处理链；不同采集连接不能拼接成一个时间轴。

重叠分段保留重叠标记，不用混合声纹确认或登记人物。开启音源分离时，各音轨组成同一个batch重新转写（云端旧接口按轨依次转写），全部有效才替换原混合输入；失败、超时、结果不全时保留原输入。转写超时只表示等待失败，不保证远端GPU任务已经取消。

## 4. 验证

历史单条请求版本（2026-10-21 09:14）的真实公开测试音频通过本机WSL Qwen3-ASR及完整Windows前处理链，结果均为“甚至出现交易几乎停滞的情况。”；记录见 `work/qwen-live-smoke/report.json`。一次已热启动测试中直接转写约0.605秒，完整处理约0.653秒，不含实时等待语音结束的停顿，不作为多人或其他硬件的性能保证。

接口测试覆盖文件/实时PCM一致性、时间连续性、分析器和转写器独立替换、重叠不认人、HTTP音频封装、模型发现、单次原生批推理、分批上限与响应代号重排、返回异常及云端连接恢复。当前batch已完成中英文两段、单次HTTP请求的真实验证，报告见 `work/qwen-batch-live-report.json`；首次双段约6.678秒，随后单段完整链路约0.567秒。上述历史耗时不作为batch版本性能，单次测量也不保证多人场景延迟。多人的实际识别准确率仍需用真实多人录音验证。

## 4. 切段与整句策略

模型介绍、输入输出、并行时序、两层接续和当前限制详见《[整句判断说明](整句判断说明.md)》。

```text
PCM → Silero + SegmentPolicy（fixed默认500ms/3.5s）→ SpeakerAnalyzer
                                                         ├→ 千问：一次原生batch
                                                         └→ TurnPolicy.analyze_audio：Smart Turn CPU
                                                                  ↓ 会合
                                                  TurnPolicy.decide（可读取全部待接续文字）
                                                   ├ complete/unknown → JEV1前组装
                                                   └ incomplete → 按可靠声音组暂存
```

`segmentation.py`的`SegmentPolicy.settings(config)`与`SEGMENT_POLICIES`独立于`turns.py`的`TurnPolicy`和`TURN_POLICIES`。已有切段策略fixed/patient；已有声音整句策略smart_turn/eager；文本策略namo/off由`semantic_turn.py`的`SemanticTurnPolicy.analyze_text(transcripts)`与`SEMANTIC_POLICIES`独立注册，组合由`fuse_decisions`处理。文本判断在转写返回后立即启动，可以与尚未完成的声音判断重叠运行。Smart Turn在声音分析之后启动，与单个千问ASR batch重叠运行，不并发发送多个千问请求。

`TurnCoordinator`按已登记声纹或本地声音组保留待接续片段；重叠、未归属轨迹不按相同临时编号硬拼。每次千问只识别新音频，音频整句模型读取该声音组最近最多8秒上下文，原转写片段、时间、人物关系各自保留，放行时按原时间排序。长于4秒的音频间隔不强接续；单组累计音频最多12秒/32段；明确未完且空闲2秒、采集结束或上限时释放给JEV1进一步判断，不伪称语义完整、不丢弃invalid输入。

单个整句工作线程最多一个任务；总预测预算默认600ms（从启动算起，ASR之后只等剩余预算），超时、异常或忙碌时unknown放行，避免积压过期模型任务。原音频工作线程继续保持单次转写。原话暂缓不阻塞浏览器继续接收PCM。

JEV1的keep原话保存在会话待接续缓存（最多32段/8000字，沿用默认300秒接续时效）；即使第二次JEV将片场整理为摘要，下一次请求仍通过既有input.unwritten带回原话及人物、时间。与当前/未整理材料去重；其他人的新话不消费这一人的待接续，明确处理同一人后消费；显式停止/断开清空。固定system/user模板与Schema不增加新调用。

本机已安装ONNX Runtime并校验官方Smart Turn v3.2 CPU权重。公开中文样本的截半/全长冒烟记录见`work/smart-turn-smoke-20261022.json`：CPU约66–79ms；这是小样本功能验证，不是中文准确率或并行端到端保证。模型下载通过`voice-setup --turn`，依赖为`.[voice-turn]`。

当前千问8000端口未监听，未启动或改动WSL服务；真实双模型在线联调尚未完成，检查结果见`work/turn-pipeline-live-20261022.json`。已通过本机真实Smart Turn样本冒烟、模型/ASR并行屏障测试及片段接续回归；不能把这些测试当作真实端到端延迟实测。
