## 真正缺什么

大多数近期原话、已有片场和播放状态已经在主认知中。逐项对照发现，主要缺口是入口证据的来源与适用限制：是否沿用同一声音前段、是否只是重复拼接短音频、整段是否完成分人、MLP分值的含义。人名或人物“确定”本身不说明这些限制，也不证明正在对匠石说话。

缺字检索曾找到四组请求没带入的旧残句“你是使用多少砖场？”，但它没有被当前判断引用，和当前事项的关联不成立，故不补。已有播放中断信息不重复补。字符未出现只是候选缺口，不能自动当成有效缺失证据。

实际组包还存在“人物：确定；依据：入口未确认姓名”的矛盾。原因是jev_attribution没有对应的说明，落入默认文案。现已改为“JEV入口人物判断，证据与缺口见入口材料”，原判断及原始录音不改写。

46组的证据增量为0～64 token，中位数26，平均25.7；最大占对应主认知历史正文加现有入口说明的1.18%。这些是当前组包对历史实际请求的离线增量，不冒充46次新版在线调用。上面的矛盾说明修正另增加每个受影响输入8 token；不是所有输入都需要修正。

共享认识更新还有固定开销，不能藏在证据增量里：

| 现有调用 | 固定规则及Schema的新增输入token |
| --- | ---: |
| 主认知L1 | 214 |
| 主认知L2/L3 | 209 |
| JEV入口（split或combined） | 61 |
| JEV回应准备（实际走到时） | 61 |
| JEV写场（异步实际调用时） | 61 |

例如走L3主认知的一轮，以中位证据增量加一条依据文案修正计算：该主认知请求约增加209+26+8=243 token；加此前一次JEV入口共约304 token。实际若走了准备或写场，应另外计其开销。普通JEV直接短答不承担主认知的209 token。

认识更新本身按需发送。一次真实纠正输出的更新正文为94 token，scene_updates输出JSON为91 token，不能把这个个例当固定上限。未被对应写场吸收之前可能在多轮请求中携带，因此不是“一次全局付费”；吸收后由片场表达。正常无更新不新增模型调用；在途结果被更新作废时可沿用一次有界重判。额外输入token较少不代表模型思考和网络延迟必然不变。

## 已落实的通用传递

主认知每轮填写scene_updates，没有更新填[]；回应或沉默时都可填写最多两条，每条包含适用范围、新理解和依据。空数组字段约增加5个输出token。它是追加的内部认识事件，不是人物原话，不回写已经发生的发言，也不自动改人物档案或启动任务。解析兼容旧返回；模型漏填时不按程序猜测生成纠正。

事件保存在现有待写场材料的持久记录中。主认知写场和JEV各自消费：主认知先整理完成，不会使JEV漏读；JEV不必等后台写场，入口可以直接拿到未吸收的更新。在途旧判断与排队短答交付前检查版本；已实际播放的事实保留。模型使用人物短代号、输入条号和必要时序，原始关联留程序侧。

旧指令同时限定“六个输出字段”和要求“沿用入口归属”，与新纠正能力冲突。已统一主认知指令、Schema、解析与实际user材料，所有相关提示词当前全文、索引和计数同步。原实际请求保持原文并按版本标注。
