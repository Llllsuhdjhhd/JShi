# JShi 项目脉络

> 当前版：2026-09-26。本文根据 src/jshi 的目录、模块入口和 SubjectProcess 接线整理，只画模块级地图，不替代接口契约或逐文件说明。具体工作开始后，再读相关实现与测试细化。

## 项目在做什么

JShi 是一个长期陪伴型 AI 的主体过程实验。代码把一次交互拆成识别、状态读取与组装、认知、行动、上下文写回和收尾，并把主体记录与能力实现分开存放。它是实验框架，不以模块齐全或对话像人作为核心结论。

## 一轮交互的大致路径

CLI 接收输入并创建运行对象，SubjectProcess 编排主要流程：

1. 检查说话人或对象信息，解析对象并通过置信度门禁。
2. 记录外部输入，读取经历账本维护的上一份 ContextViewState。
3. CurrentStateAssembler 从身份、对象、上下文视图、个人世界、记忆和工具材料等来源组装当前状态。
4. 建立活动并调用认知模型，形成 response_plan。当前主流程只做一次主要认知调用。
5. 按回应计划分发语言或动作；结果反馈、机器人动作等部分仍是占位接线。
6. 更新活跃区/写场，记录工具意图和回应，关闭活动。
7. 收尾后尝试投递记忆批次；自省先入队，由宿主在活动间隙处理。

具体分支、字段和失败行为以 SubjectProcess.experience、CurrentStateAssembler 及相关测试为准。

## 模块地图

| 关注点 | 代码位置 | 粗略职责 |
|---|---|---|
| 应用入口与接线 | src/jshi/app、src/jshi/subject | CLI、运行配置；SubjectProcess 编排主流程，SubjectRepository 保存主体记录 |
| 主体与认知契约 | src/jshi/subject/domain.py、src/jshi/core、src/jshi/models | 活动、认知内容、个人条目、状态迁移和模型请求/回应的数据结构 |
| 对象与身份 | src/jshi/identity、src/jshi/objects、src/jshi/recognition | 主体身份、对象档案、对象识别与候选门禁 |
| 当前状态 | src/jshi/assembly、src/jshi/activezone、src/jshi/experienceledger | 汇集状态来源；读取和维护经历流及当前上下文视图 |
| 个人世界 | src/jshi/personalworld、src/jshi/privilege | 个人条目、价值/边界相关存取，以及提示规则和超级权限存取 |
| 记忆 | src/jshi/memory、src/jshi/memorycontrol | 记忆端口、召回协调、进程内与 REMS3 后端、批次投递和召回记录 |
| 认知与表达 | src/jshi/skill、src/jshi/style、src/jshi/responsemark、src/jshi/action | 模型能力适配、认知/写场/工具技能、风格包、回应标记和行动分发 |
| 工具使用 | src/jshi/tool | 工具交接、计划、执行引擎、任务记账、展示与包装；CLI 默认选择 Pi，可用配置切换占位引擎 |
| 旁路与后处理 | src/jshi/effectiveness、src/jshi/reflection、src/jshi/evaluation | 有效性报告与召回策略、自省队列和评价事件收集 |
| 接口占位与辅助能力 | src/jshi/attention、src/jshi/attribution、src/jshi/intent、src/jshi/feedback、src/jshi/governance、src/jshi/activityclose | 注意/偶然性、意图、结果反馈、连续性检查和活动关闭等端口或实现；attribution 在 SubjectProcess 中标为废弃兼容参数，主流程不再使用 |

模块文件通常按 port / inprocess / service / repository / backend 分层，但各模块成熟度不同；目录形式本身不代表完整实现。

## 持久化与可选后端

- CLI 默认数据目录是项目下的 .jshi，也可通过命令参数或 JSHI_DATA_DIR 改变。
- 主体数据由 SubjectRepository 写入 SQLite；身份、风格、活跃区、工具和评价等数据由各自存储实现管理。
- 记忆后端由 JSHI_MEMORY_BACKEND 选择，支持 inprocess 和 rems3；默认是 inprocess。REMS3 需要外部安装。
- 直接构造 SubjectProcess 与通过 CLI 启动的默认配置不完全相同；例如 CLI 的工具引擎默认 Pi，离线或测试需显式选择 stub。

本节只记录代码可见的选择入口。具体文件布局、事务边界和数据迁移规则，修改存储模块时再以实现为准补充。

本文不声称证明记忆、价值或承诺已经稳定影响真实模型行为。单元测试主要覆盖接口和流程结构；项目级行为结论需要跨活动场景、对照条件和来源链。细化一个模块时，先检查该模块代码、调用方、测试和运行配置，再把确认后的事实写入当前文档。
