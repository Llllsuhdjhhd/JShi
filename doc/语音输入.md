# 语音输入与交付

本次入口是本机浏览器：LARK A2 在系统中作为麦克风，电脑默认扬声器播放回应。
`talk` 的文字路径保持原契约；`voice` 把最终转写与说话人证据封装后送入同一个 `SubjectProcess.experience`。

## 运行

在项目目录、使用运行匠石的同一个 Python 环境：

```powershell
python -m pip install -e ".[voice-local]"
.\jshi.cmd voice-setup --tts --diarize
.\voice.cmd --asr local --tts local
```

`voice-setup` 下载官方的中文 int8 流式 CTC 模型和 CAMPPlus 声纹模型，总下载约 48 MB，存到 `.jshi/voice_models/`。
加 `--tts` 会另下载约 159 MB 的 Melo 中文/英文固定音色。识别与合成都使用 CPU，默认各 2 个线程。
加 `--refine` 另下载约 158 MB 的 SenseVoice 模型：小模型只做实时预览，最终整句由 SenseVoice 重新识别后进入主流程。
`JSHI_VOICE_REFINE=auto` 默认在模型存在时启用；`on` 要求存在模型，`off` 关闭整句复核。
`--diarize` 会包含整句模型并增加 pyannote ONNX 说话人分段模型。
存在这套模型时，本地音频按停顿或最长 6 秒窗处理：先分说话人时间段，再逐段转写、提取声纹。
整句停顿窗改为 1.2 秒，减少把短停顿拆成多轮；复核仍不能保证解决杂音、串音和多人重叠。
主体 id 默认取最近的文字会话，也可以指定 `voice.cmd <主体 id> --asr local`。
打开终端显示的 `http://127.0.0.1:8765`，点击“刷新设备”授权麦克风，选中 LARK A2，开始对话。
输出使用 Windows 当前默认扬声器；网页启用浏览器回声消除、降噪与自动增益。打断灵敏度可现场调整。
接收器是否呈现独立双通道、浏览器是否能分开采集，需要按实际设备测试。
默认第一通道，可选第二通道或混合；不宣称两个发射器自动对应两个身份。
“麦克风与声音检查”内可录制 5 秒试听，只留在当前网页。最新消息置顶，不自动滚动到末尾。

从 `.env.voice.example` 把字段补到已有 `.env`。本地识别与合成都不需要语音服务 Key；
主认知和 JEV 仍使用已有对话模型配置，这不是整个匠石离线运行。
`--tts online` 切换在线合成，需要 `JSHI_VOICE_API_KEY` 并开通相应合成服务/预置音色。
在线识别可装 `.[voice]` 后使用 `voice.cmd --asr online`，无需本地模型。
若配置了本地合成，仍需合成模型；两个后端可以独立选择。

本地合成按短句/分句生成后发送 PCM，不是字级增量生成；最长一段限制为 60 字。
播放器先停播，不等待 ONNX 运算结束；取消后正在计算的分句允许结束，结果丢弃，不继续计算后续分句。
固定音色支持调语速，不支持用自然语言改变情绪，也没有声音克隆。在线的 speaker/direction 配置不会改变本地音色。
模型来源：[sherpa-onnx Melo 中文/英文音色](https://k2-fsa.github.io/sherpa/onnx/tts/pretrained_models/vits.html#vits-melo-tts-zh-en-chinese-english-1-speaker)。
在本机 CPU、2 线程的一次短文本测试中，模型加载约 2.57 秒；第一段音频约 0.31 秒返回，
合成约 4.68 秒声音总耗时 1.66 秒。测试没有占用 GPU；这是单样本验证，不代表长对话或识别与合成并发时的延迟。

## 信封和多人

### 在线双向流式合成

火山合成 2.0 开通后，可使用 `voice.cmd --asr online --tts online`，在线合成默认走
`wss://openspeech.bytedance.com/api/v3/tts/bidirection`。
`JSHI_VOICE_TTS_TRANSPORT=websocket` 为默认值；`sse` 可选择原有整句输入的 SSE 接口。
ASR 与 TTS 授权分别开通，API Key 留在服务端；文本会发送到合成服务。

适配器支持异步文字片段输入和 PCM 音频增量输出。一条连接上顺序开启多个合成 session，避免每句重建连接；
取消时停止送文字、发送 CancelSession 并关闭连接，丢弃未读旧音频。下一条回应重新建立连接。
播放器本地停播不等待云端取消完成；只有实际播放器反馈才标记“已说完”。
当前主流程仍先取得完整的有序 response_plan，再按分句合成；没有把未完成 JSON 中的字符直接送给 TTS。
因此适配器支持流式文字输入，并不代表主模型到播放器已经做到逐 token 流式。

2026-10-03 使用当前 Key、`zh_female_vv_uranus_bigtts` 预置音色和 24 kHz PCM 实测：
首次音频从第一段文字发送起约 0.35 s；接入适配器后包含建连约 0.56 s，复用连接约 0.32 s。
第二段文字还未发送时已收到第一段音频。测试取消并关闭连接约 0.04 s，取消后的新合成成功。
这是几句短文本的单次实验，不是稳定延迟承诺，也不是播放器或整轮对话的延迟。
试听文件和详细测量保存在 `.tmp/voice-validation/`，属于测试产物，不写入人物记忆。

接口依据：[双向流式 TTS](https://docs.volcengine.com/docs/DoubaoVoice/bidirectional-streaming-text-to-speech-websocket?lang=zh)。

`core/envelope.py` 定义 parts（文字、音频引用）、输入/会话编号、来源、时间范围、最终状态、重叠标记与 speaker evidence。
主流程原话仍是转写文字，运输事实与实际播放进度放入独立 `transport_context`。
每段发言独立关联对象；同一麦克风不代表同一个人，分离编号只在一次会话内有效。
目前音频引用是会话内时间位置，不是可重放的持久录音；默认不保存原始音频。

未知声音使用临时轨迹/对象引用，表示身份未知，不表示已经识别出一个人。
未知身份或多轨同窗输入以“语音现场”作为内部参考对象，不为每段背景碎片创建一个人物档案，也避免把整窗归给最后说话的人。
主模型收到最近 24 条有起止时间的现场片段，自行决定回应、等待、忽略或只更新片场；不强迫每段都追问身份。
明确自我介绍（“我是 lux”“我叫 lux，……”）先与已有对象名字/别名比对。唯一命中关联原档案；重名先澄清。
本次会话的临时对象到已有对象的关联留事实记录，不改写过去的原话、不授予超级权限。
当前只承认明确自我介绍，不从“lux 让我来问”推断说话人就是 lux。
支持转写成“我是 L U X 你好”时提取 LUX、忽略字母间空格、按大小写无关匹配 lux。
名字匹配是会话关联；不能通过“讲只有你知道的旧事”来验证声纹。程序提供的关联不会被主模型的身份猜测覆盖。

本地声纹样本充足时，自我介绍后的特征保存到 `.jshi/voiceprints.json`，以模型指纹和对象 id 区分。
原始声音不落档案，档案只保存特征引用。换声纹模型后不会混用旧向量。
匹配同时检查最高相似度和不同对象之间的领先差；短语音或近似声音不能明确匹配时继续视为未知。
阈值默认 0.65、领先差 0.08 是初始实验设置，需要用家里实际声音验证，不是识别准确率承诺。
分段输出以声纹特征关联跨窗轨迹，保留每段的 session-relative start/end 毫秒与身份状态。
没有分段模型时，清晰单人输入在约 1.5 秒有效样本后可以先比对并显示身份；最终整句再确认。
开启分段时不对整窗混合声音提前绑定熟人，等待分段结果。窗口内部的 speaker 编号不当作跨窗身份。
被模型标成重叠的音频不用于身份匹配或登记；转写归属标为不可靠。本地模型不保证检测到全部重叠。
说话人分段不是音源分离：同时说话的电视与真人仍共享混合音频，尚未提取成两条干净音轨。
电视台词保留为现场材料，由主模型结合片场判断是否回应；不能仅凭陌生声音就把它认成电视。

在线默认走流式说话人分离。火山的短音频声纹组匹配是另一个单说话人模式，不能同时宣称是多人分离：

```dotenv
JSHI_VOICE_IDENTITY_MODE=voiceprint
JSHI_VOICEPRINT_GROUP=<已建立的声纹组 id>
```

在线注册可以使用 `jshi.cmd voice-enroll <已有对象 id> --audio-url <HTTPS 样本地址>`。
官方注册接口要求可下载的 5～30 秒单人音频 URL；当前没有自动上传音频到云存储的功能。
只有云端成功返回注册 id 后才关联本地档案；会话内介绍成功不代表云端声纹已经注册。

## 打断和 JEV

### 线上识别与本地身份关联试用

当前推荐先比较“火山流式识别 + 二遍整句复核 + 多人编号、本地声纹与本地合成”。
配置 `.env` 的 `JSHI_VOICE_API_KEY`，开通对应识别服务，重启后运行：

```powershell
.\voice.cmd --asr online --tts local
```

若以 `--asr local --tts local` 启动且已配置 Key，可在网页的“语音识别”中选择线上，下一次会话生效。
线上识别会上传会话音频；密钥保留在服务端。身份与记忆仍由匠石程序关联，不把云端编号当永久身份。
本地已安装 CAM++ 时，程序只在内存中保留最近 45 秒 PCM，按云端最终发言的毫秒时间戳取样做声纹匹配。
过期、不完整、过短或已标记重叠的样本不据此确认/登记声纹。云端没有标出的重叠仍可能导致误匹配，需实测。
显式自我介绍发生在最终转写进入主流程之前。唯一名字命中已有对象时直接关联记忆；新名字创建临时档案。
日常聊天不考问旧事、不要求证明身份。姓名关联不是权限验证；涉及权限或利益的操作另行验证。
如果样本足够，介绍后保存本地声纹向量；网页提示是否已保存。后续匹配使用同一份本地登记记录。
网页显示“本次自我介绍关联”和“已登记声纹匹配”两种依据。在线纯 ASR 安装没有本地模型时，只做会话名字关联。

接话关注权重是实验性软提示：自我介绍或定向回应后的对象在 90 秒内从 1.5 衰减到 1.0。
普通发言不会自动刷新关注，避免电视或旁人连续说话抢占焦点。所有发言仍进入片场，权重不截断声音、不改变 ASR、
不充当声纹分数，也不自行触发打断。多人定向回应可以关注多人；新对象明确提问仍可加入。
目前尚未运行专门的环境音分类/突出事件检测；响度或尖锐程度不会被伪造成人物权重。
未来可把这类事件作为独立的环境关注信息，而不是自动停止播放的条件。

接口依据：[火山说话人分离说明](https://docs.volcengine.com/docs/DoubaoVoice/speaker-separation?lang=zh)。
模拟云端协议用于验证链路；实际服务测试记录见下节，家庭现场效果仍需试用。

### 在线实时性复测（2026-10-03）

已实际连接火山识别服务，使用公开测试音频按实时速度发送 100 ms PCM 包。
双向流式 `bigmodel_async` 保留 `enable_nonstream=true`，多人模式明确设置 `ssd_version="200"`。
`JSHI_VOICE_END_WINDOW_MS` 默认改为 500；可设 300～5000，数值越小越容易把自然停顿拆成多轮。
未启用首字加速，避免仅为上屏更快而降低首字准确度。主流程仍只使用 `definite=true` 的最终分句；
中间转写只作预览，不写入记忆、不绑定介绍、不自动停止播放。

同一段四人音频的前 22 秒对比：

| 配置 | 首次出字 | 首段定稿 | 观察 |
| --- | --- | --- | --- |
| 双向两遍、SSD 200、500 ms 判停 | 1.35 s | 第 12.42 s | 说话人之间短停顿不足以触发句尾，首段结束至定稿约 5.67 s |
| 双向两遍、SSD 200、300 ms 判停 | 1.35 s | 第 4.86 s | 首段结束至定稿约 0.55 s；也出现跨人片段错归上一人的情况 |
| 单向语义分句、SSD 200 | 18.96 s | 第 18.96 s | 本次实验明显更慢，不作为默认实时入口 |

这些单次结果没有隔离网络、参数与模型波动，不能推出通用速度或准确率承诺。
先前约第 21 秒返回的是最终分句时间，不是首次出字时间，也不能全部算为模型计算耗时。
测试前几个人之间约 240～280 ms 的短停顿低于原来的 800 ms 判停阈值，长时间等待定稿是重要因素。
500 ms 暂作平衡设置；需要更快可设 300 ms，但要同时观察过早切句和身份归属，而不是只看延迟。
另用两段不同人的公开样本，中间插入 1.2 秒静音，按实时速度输入 500 ms 配置。
服务返回两位说话人、三段最终转写，发言结束到定稿约 0.70、0.68、0.36 秒。
这是有清楚停顿的轮流说话测试，不能代表重叠说话或家庭真实录音。
ASR 定稿之后仍有本地身份匹配、输入合批等待（现默认 2 秒停顿）、JEV/主模型和合成播放时间；上述数字不是端到端回应时间。

文档依据：[双向流式接口](https://docs.volcengine.com/docs/DoubaoVoice/bidirectional-streaming-automatic-speech-recognition-websocket?lang=zh)。

前端每 100 ms 发送 16 kHz、单声道、16-bit PCM。检测到声音或收到转写本身不会暂停播放。
先由 JEV 判断，接话、明确停止或需要澄清时才停播；判断期间保持播放。浏览器回声消除效果需实机确认。

JEV 不按字/音频包调用，在最终发言合批后判断 ignore / resume / stop / respond / clarify。
明确停止、附和、不完整碎片、已知重叠先走小规则；播放时附和和重叠保持播放，空闲时不因重叠自动追问。
需要判断的插话走独立 `voice_jev` 模型档位，结合当前回答、说话人和新发言判断是否对匠石说话；换人本身不是打断依据。
模型判断等待上限 3 秒，失败或超时保持播放；超时尚未结束的调用不会导致继续堆积模型请求。
网页显示每次 JEV 的动作和原因。当前规则只对完整转写的明确停止生效；停止按钮直接生效。
JEV 的 ignore / resume 不丢掉现场材料，但不启动主流程；背景发言留在历史和现场缓存里。
JEV 接到原回应对象、完整计划、实际已播放/部分播放/待播内容及新说话人证据，不推测声纹。

有效打断取消合成并清空待播队列。回复编号与轮次编号拦截迟到音频、旧模型回调和旧播放确认。
当前同步主模型 HTTP 调用不能强制终止：让旧轮完成必要写场，同时抑制旧输出，新发言排队进入同一主流程。
打断判断不等旧轮写场；主流程本身串行，避免两轮同时修改场。

## 流式输出与记忆

认知的完整 verbal 方案一旦交出就开始分句合成，PCM 音频边生成边播放；不等待写场完成，也不等待全段音频生成。
当前不是未定稿 JSON 字符串逐字朗读：现有认知流式接口的交付边界仍是完整 response_plan/reply 字段。
写场只记录“准备说”；经历里的原回复也标为实际交付待反馈。
播放器逐句确认已播放；句中打断只标记该句部分播放，不伪造精确听到的字。
完成的句子另入经历，生成完成不等于播放完成。下一轮把播放快照带进信封，重连后从历史恢复最近交付事实。
“工具结果已用于回答”在音频路径先暂留，整段播放完成后再用实际播放文本确认；打断后不会仅凭生成文字就关闭事项。

匠石声音先固定一款预置音色，默认语速略慢（-5），不随对象变化。
模型可在 `response_plan.items` 中顺序给出多个 verbal，每项携带 `target_ids`，空数组表示向全场说。
语音端按数组顺序串行播放，逐句记录实际交付对象；仅允许本次现场中的目标 id，避免凭空路由到别的档案。
JEV 决定保持原回应时不生成新回答；确有必要的新回应按实际播放状态编排，明确打断会清空旧待播内容。
本地音色只支持调语速；在线的音色 id、语速、语气说明可通过 `.env` 配置，不做真人声音克隆。

## 验证范围

语音输入默认等待约 2 秒停顿收成一批；明显未完句至少等 4 秒，继续到达的转写会延长等待，单批最长收集 10 秒。
用 `JSHI_VOICE_INPUT_PAUSE_MS` 调整停顿等待（300–3000 毫秒），它独立于云端 ASR 的分段设置。
本批输入按时间排列，每句带名字、对象 id、临时轨迹和时间，不把多人的话拼成同一个对象。
信封的 `current_utterances` 明确标记本批新发言，`utterances` 保留近期现场观察。
主流程思考或写场期间不逐批调用 JEV，新发言累积成一批待处理输入；当前轮次收尾后统一接话判断，
再调用一次主模型。明确的停止播放指令仍立即执行。网页会显示“主流程忙碌，新发言正在合并”。

网页可展开“轮次信息”，点击 `/PROMPT`、`/TIMING`、`/tool` 查看最近已完成语音活动。
页面以对话为主体，宽窗口右侧为声音登记与检查；窄窗口把检查区放到对话之后。
可在输入上点击“选择声音”，多选同一个人的清晰片段并填写姓名，关联已有对象或建立新对象。
每段分别提取并归一化声纹；过短片段合并取样，多段声纹综合为一个归一化中心向量。
登记使用独立的一致性阈值 `JSHI_VOICE_ENROLL_THRESHOLD`（默认 0.8，尚未针对家庭录音校准），匹配阈值仍为 0.65。
网页“声音与姓名”提供匹配门槛滑条，范围 0.30–0.95，连接后即时调整并保存。
保存到相应声纹库旁的 `.settings.json`，重启后优先使用；CAM++ 和 ERes2NetV2 分别设置。
滑条只调整匹配分数门槛，不调整第二候选差距或登记一致性检查；降低会增加命中机会，也可能增加混认。
每段至少 1.5 秒，单段至少 3 秒，多段合计至少 4 秒；不再把短句拼成一个特征而绕过一致性检查。
长片段按 3 秒窗口提取并比较，拒绝不一致的组合。失败会标出对应片段和最低相似度。
相似度低不能直接判断为杂音或不同人；收声变化也会影响。同样，这些检查不能保证检测出所有混入的人声。
登记使用每条输入的独立编号和对应 PCM，不根据临时云端编号批量认领其他语句。
当前会话最多保留 128 条样本、16 MiB PCM，每条最长 30 秒；重叠、过期或缺失音频不登记。
结束会话清掉 PCM，长期保存声纹特征。手工选择在历史里标记为 manual_selection。

轮次下拉保留本次连接最近 12 个完成活动。PROMPT 可选认知、写场调用，以及 system/user/Schema/实际区块。
还可查看输入信封、现场上下文、身份依据、播放交付、接话判断和模型结构化输出，或复制内容。
PROMPT 按活动编号读取实际发送的 system/user（包括认知和写场），不是重新组装的预览；
TIMING 是主流程各步耗时；tool 包含本轮选取的任务、输入材料、热状态与模型处理决定。
提示词按需读取，不在每个音频包上加载。轮次信息只在当前连接内可读。
TIMING 的 voice 中，asr_lag_ms 是接收到定稿时采集进度与语句结束时间之差；queue_wait_ms 含合批、接话判断和等主流程空闲。
model_to_reply_ms、first_audio_ms、playback_start_ms 均从该轮主流程开始计时；
synthesis_first_packet_ms 从合成开始计时，区分模型、待播和合成等待。实际播放开始依赖浏览器反馈。

云端可能重复下发历史结果并修改文字、合并分段或调整临时说话人编号。
已交付分段共享起止边界的历史修订不再触发新轮次；近期记录按时间保留，过期历史有水位拦截。
不同时间的新发言和新到达的不同边界重叠发言保留，不按文字相同直接丢弃。
这项去重不修复云端转写准确率或多人分离准确率。

排队输入在真正调用主流程前刷新实际播放状态，并标记回答生成前收到的补充，要求只回答尚未覆盖的信息。
普通停顿默认等 2 秒，明确未完句尾延长到至少 4 秒；连续输入单批最长等 10 秒，明确停止不等待。
未完句超过等待时间仍可作为现场观察输入，提示主流程记录并等续句，不猜测其后半句。规则只是辅助，不能判断所有语句是否完整。
在线匿名人声采用本地声纹聚类维护“未命名访客 N”，独立于可能漂移的云端说话人编号。
姓名匹配使用界面门槛；匿名延续使用不高于 0.60 的门槛和候选领先检查，避免严格姓名门槛拆散临时对象。这些相似度门槛尚未经家庭录音校准。
清晰匹配的匿名对象保留原始声纹和至多四份近期长句声纹；短句、候选接近或边界分数用“声音归属待定”占位，不新增访客。
首个匿名对象至少需要三秒音频；之后疑似新对象需两段至少三秒且相互相似的音频支持。待确认样本至多八份，会话结束清空。
“声音归属待定”是未归属音频的占位，不表示同一个人；自我介绍只关联本句，不整体搬移这个占位的其他发言。
未知姓名不限制进入主流程。JEV 根据称呼、内容和现场关系判断是否回应，不能以未登记姓名或声纹为由忽略打招呼、明确提问或纠正。
自我介绍或手工登记后，已有匿名对象和当前片场通过关联记录对接到姓名；历史原始对象编号保留。
匿名聚类只在当前会话连续使用，跨重启的识别依赖持久化登记声纹；声纹不够或重叠时不强行合并人物。
连接时显示已加载声纹数量，每段输入的身份比对说明保留失败原因、分数及匹配门槛。
当前发言文字只放在本轮输入里，信封保留对象和时间元数据，片场不再重复放入同一批文字。
下一轮携带上一轮实测耗时，避免模型把未经测量的迟缓归因于查天气或设备故障。
界面区分收到时间、会话相对音频位置、估算录音时间和回答生成时间；估算录音时间以服务收到首包 PCM 为基准。
“说话中”由实际播放队列决定：音频生成结束而播放器未播完时仍显示说话中，播完后切回聆听或处理状态。

默认在线模式由火山转写并提供临时说话人轨迹，本地模型提取声纹并匹配已登记对象。
临时编号不等同于固定身份；短句、重叠或音频缓存已过期时可能无法匹配。
旧版本误登记为 `L U X 你好` 的自我介绍档案，存在唯一对应 lux 档案时，声纹解析归到该档案；
保留原始记录，不删除历史。合成连接空闲后重建，复用连接在发送文本前失效时可安全重试一次。

自动测试覆盖未知对象、身份关联、重名、声纹冲突、流式协议、多人分段、打断并发、旧输出拦截、
播放反馈、合成失败降级和本机 WebSocket 入口。Node 的播放器状态测试可运行 `node tests/test_voice_player.cjs`。
本地官方样例已在 CPU 上完成真实推理，具体样例结果记录于本地 `.tmp/voice-validation/benchmark.json`。
同一录音回放的声纹命中用于验证接线，不代表不同录音的真人识别准确率。
官方多人样例约 56.86 秒音频以 6 秒窗处理，CPU 2 线程总计算约 3.21 秒。
实际输出仍有短片段身份未知和跨窗轨迹碎分，不能把输出轨迹数当真人数量，也不能宣称已可靠分清家庭成员与电视。
测试明细在 `.tmp/voice-validation/diarization-benchmark.json`，需要现场标注录音评估轨迹稳定性与重叠检出。
LARK A2、扬声器回声、家庭多人误识率、在线服务权限/账单和真实首字延迟仍需要现场验证。
当前 ONNX 后端固定走 CPU；现有 PyTorch 为 CPU 版，不会自动用 RTX 5060。
GPU 升级候选为 Qwen3-ASR-0.6B（识别）与 Qwen3-TTS/CosyVoice（合成），尚未集成或在本机验证显存和并发延迟。

声纹对照已增加 CAM++ 与 ERes2NetV2，使用同一份手工标注录音。`voice-setup --speaker-model eres2netv2` 可准备官方 ONNX。
网页“声纹方案对比”先选择姓名和 5–30 秒片段加入登记样本，再用另一段发言加入测试；未登记的其他姓名用于测试误认。
样本 WAV 和标签保存在 `.jshi/voice_trials/current/`，重启仍保留。重复音频和同会话时间重叠的样本不允许同时充当登记与测试。
报告记录登记提取数、熟人漏认/认错数、未登记者误认数、模型加载与声纹提取耗时；不把相似度当识别概率，也不把测试集调参后的结果当独立验证。
对照不会登记进正式库；网页可选择下一次连接使用哪个本地模型，ERes2NetV2 使用独立 `voiceprints-eres2netv2.json`，CAM++ 旧库不变。
云端登记接口需要 5–30 秒录音的 HTTPS 地址。尚无上传服务时仅保留现有 `voice-enroll --audio-url` 入口，报告云端为未运行，不伪造对照结果。

JEV 在空闲、刚说完和播放中都判断发言是否向匠石提出、是否需要接话；主流程忙时先合批，空闲后再判。
`ignore` 和 `resume` 都不启动认知/写场调用，但发言及对象、时间仍进入现场缓存和历史；下一次真正接话时可看到最近现场。
