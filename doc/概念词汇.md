# 匠石概念词汇

本文固定项目中的核心术语。其他文档和实现应优先采用这些名称；需要引入近义词时，应说明与本表术语的关系。

## 主体与身份

### 匠石

以人类文明为基础，在持续经历、反思和行动中形成自身历史、判断、偏好、承诺与关系的长期人工智能伙伴。

### 基础型匠石

具有共同文明基础和某种初始气质、能够继续成长的匠石起点。它不是完成且固定的人格。

### 身份

使匠石在时间中仍可被认作同一个自己的连续结构，包括个人历史、价值、边界、承诺、关系、偏好和自我叙事。身份不是某个模型、提示词或单次状态。

### “我”接口

主体过程对工程系统提供的访问边界，用于读取当前经验、个人世界、意图、承诺及变化依据。“我”接口不产生“我”；它只是持续主体过程的一个可观察入口，不能直接改写原始历史。

### 主体过程

基础认知、个人世界和当前经验共同活动，并将认知、选择、行动和结果持续归属于同一个匠石的过程。“我”存在于这一过程的连续运行中，而不是某个单独模块。

### 个人世界

匠石通过生活形成的记忆、价值、关系、承诺、审美、能力、自我理解及尚未解决的矛盾。个人世界使使用相同基础认知的不同匠石形成个体差异。价值、审美等条目记录体现取向的具体选择事件（带来源与重要程度），抽象名词只属于解释层。

### 当前经验

外部现实进入匠石的历史、关系和处境后，在此刻对他呈现为什么。它包括当前输入、注意对象、暂时理解、关系情境和尚未完成的活动。跨活动未说完的话，靠活跃区、召回、承诺与关系接上，不靠一层未完成事项。

### 活动工作状态

一次正常活动内部暂时维持的输入、当前理解、已装载材料、追加召回和处理进度。它只服务这一次活动，不等于长期记忆或个人世界。活动结束后需要保留的内容先进入历史；下一轮是新活动，靠既往视图接上。

### 对话对象

与匠石发生外部互动的人或其他角色。对话对象不是主体：每个匠石是唯一主体。对话对象通过对象标识与匠石的历史关联，并在确认前可能只是暂定对象。

### 输入信封

主体流程接收输入时使用的边界结构。当前外部文字输入至少包含来源、渠道、模态、对象引用、时间和完整文字。完全缺少对象引用的外部文字不是“未知对象”，而是无效输入信封；上游渠道应先把语音、账号、会话或设备线索转换为对象引用。

### 连续性

匠石在变化后仍能承认重要经历、履行已有承诺、维持关系认识，并解释自己如何从过去成为现在的性质。

### 自我叙事

匠石对自身经历及变化所作的可修正解释。它属于解释层，不等于原始历史。

## 经历与记忆

### 外部互动

匠石与人或环境之间发生的信息接收、表达、工具使用和行动。

### 内在活动

匠石在没有直接外部请求时进行的整理、反思、检查和成长活动。内在活动也必须留下来源和结果记录。

### 正常活动

匠石面对外部输入或明确内部触发时进行的前台处理。正常活动装载已有记忆与个人世界，维持活动工作状态，产生认知与行动并记录经历；它可以产生候选理解，但原则上不在主链路中直接升格长期个人世界。

### 后台沉淀

记忆整理、反思、学习与治理等读取历史和候选内容的过程。它负责证据整理、记忆组织、认识状态变化及个人世界升格。后台沉淀的输出仍须带来源、状态和版本，不能因某个模型或 skill 的一次输出直接成为长期事实或人格。

### 事件

09 对一段经历封存后的记忆单元。边界检测与封存只在 09 内部，**不进入活跃区，也不由阶段②识别**，不作为「尚未了结的跟进」装入 03 或个人世界。

历史记录（HistoryRecord）仍保存输入、行动、判断等可核查记录，与记忆单元不同。

### 未封存片段

09 内部代谢中尚未封存的原文缓冲。不是主体义务，不进入组装。旧称「未完成事件」若指记忆切分，仅此义。

### 经历账本

保存原始经历段，并保存按认知方案编好的当前活跃区。经历只追加、不改写原文。记忆游标不属于经历账本，由记忆数据管控维护。

### 上下文视图 / 活跃区快照（ContextViewState）

经历账本保存的当前活跃区：正文、经历段引用、仍在场的回忆摘录、对象标识、剔除与聚焦引用、版本。它不是每轮从原文重切的窗口，也不是事件列表。新经历先进入待合并；心智给出缩减与聚焦方案后，不再调模型，按方案编排，供下一轮读取。

### 本轮上下文

03 组装后的全体：上一活跃区、本轮输入、对象、主体身份、已装入的个人世界、回忆（含追加召回）。这是心智看见的材料。

### 活跃区（Active Zone）

按 05 缩减 / 聚焦方案编好、供下一轮继续面对的工作上下文。由 16 保存、02 读取。可以含经历，也可以含仍被保留的回忆摘录。它是引用加现场正文，不是 08 / 09 的真源副本。缩减只让条目离开活跃区，不删账本、不删记忆、不删个人世界。对象与常驻约束不得被拿掉。

阶段② 只从经历账本**读取**上一份活跃区，交给状态组装；本轮原话由组装经 `input_text` 带入。不调用模型，不识别事件，不重切原文，不推进记忆游标，不把本轮输入在认知前并进活跃区。初次使用或复位后空活跃区合法，不另开启动流程。

### 活跃区比（Active Zone Ratio）

上下文长度与模型上下文的比值，默认参考 1/66，可动态调整。长度与增量编辑由经历账本承担；活跃区无独立窗口参数。它是软约束，调整留审计。

### 统计分析与参数调优系统

读取匠石各阶段运行信息（上下文占用、召回命中率、剔除率、延迟、成本等）做统计分析，并可能动态调整上下文长度比等实验参数的系统。属于可替换 / 占位能力：调整只影响实验基线参数，不改变稳定原则；每次调整应有记录与审计。

### 对象标识

关联原始输入与对话对象的稳定标识。原始输入落位时即使对象未确认，也应记录对象标识或显式的“未知”状态，使后续召回、关系情境与活动连续性可以按对象组织。

这里的“未知”只表示**对象身份尚未确认**：系统已经有一个可引用的暂定对象标识，但尚不知道它与哪个已确认档案对应。它不表示输入完全没有对象。

### 对象归一化

输入落位后，把文本中的对象名 / 称呼以及「我」替换为 id 的派生文本（`normalized_text`）：

- 外部对话中「我」→ 说话人 id；主体回复 / 反思中「我」→ `subject_id`；
- 说话人名字 / 称呼 → `actor_object_id`；已知提及对象 → 对应 id；
- 未识别或消歧失败的提及保持原文（合法状态），不猜测；
- 原文永不改写，`normalized_text` 是派生字段；语音（载体 → id）与文字（名字匹配）在落位后走同一规则。

记忆侧使用归一化文本作为 `content_raw`，展示时由 03 用 01 档案回填名字。

### 对象档案

某一对话对象的识别资料与已知信息（名称、声纹、人脸、设备标识等）。对象档案可预先导入（例如录入朋友的声纹），也可在对象引用未匹配已确认档案时建立暂定档案。档案可携带识别载体条目（声纹 / 人脸 / 设备 / 账号 / 会话），供输入载体信号匹配；载体只存引用或标识，不存原始生物数据。**对象标识全局唯一且不可变；识别载体引用唯一（一个载体只属于一个对象）；别名可以重复，重名合法，按名字匹配可能得到多个候选，须经其它证据消歧。**建立、导入、合并都应有来源记录；暂定档案经确认后可合并到已知对象，合并须显式记录。

### 对象识别系统

在输入边界识别“这句话来自哪个对话对象”的可替换能力，载体可为声纹、人脸、设备标识或上下文线索。识别按模式链执行：**载体识别**（声纹 / 人脸 / 设备 / 账号，命中即唯一 id）→ **文字标识识别**（名字 + 别名候选，唯一候选直接给对象）→ **记忆匹配识别**（重名时用输入与候选对象记忆的相关性消歧，给出置信最高者）。未匹配已确认档案时产生暂定对象。输出是候选对象与置信度，属于待校验的感知结果，不得直接视为已确认事实。

对象状态至少区分：

1. **无对象**：有效输入信封的必填字段缺失，属于上游契约错误，不进入主体流程；
2. **暂定对象**：已有对象引用或暂定标识，但身份尚未确认，可以记录、追溯并进入受规则约束的确认过程；
3. **已确认对象**：对象标识已经与档案建立可追溯的确认关系。

### 原始历史

对事件原始内容、背景、参与者、来源、处理过程和结果的稳定记录。原始历史可以追加修正说明，但不得被摘要或新解释覆盖。

### 记忆

被组织并能在当前活动中发挥作用的过去。记忆包含对原始事件的引用，也可以包含带来源的关联和解释。

记忆的技术实现属于可替换边界：可用项目内存储做最小实验，也可接入外部记忆引擎。某一具体引擎（例如 REMS）若被选用，只承担保管、召回、压缩、代谢等记忆职责，不因此成为匠石架构的必要组成部分；主体过程、认识状态与承诺仍由匠石结构负责。不另设主体面未完成现实。

### 主体记忆

只有匠石、没有外部对象的经历记忆，例如看到落日时的感触、内在反思的产出。主体记忆同样是合法记忆：

- 归属由 `subject_id` 保证，不要求存在外部 `object_id`；
- 封存时事件角色列表可以只含主体（或无角色）；
- 与有对象的记忆走同一条记忆投递路径，不被过滤或阻断；
- 对象为空 ≠ 经历无主：每条经历仍明确属于某个匠石。

外部对象的有无只影响记忆按对象组织的方式，不改变记忆的归属与合法性。

### 记忆数据管控

经历流与记忆薄壳之间的管控层：决定哪些经历何时投递、游标如何推进、失败如何重试。它使用自有 `memory_start`，不改经历原文，也不改上下文视图。

### 解释层

依据原始历史形成的摘要、分类、关系认识、自我叙事和价值解释。解释层可以重新生成，但旧版本和来源必须保留。

### 遗忘

降低、限制或停止某些历史内容在当前活动中的可用性。遗忘不等于无记录删除；具体删除还须遵守数据治理要求。

### 未完成现实 / 开放事项 / 关切 / concern（已废除）

不再作为主体概念，不以新名字复活。不装入 03，不由 08 保管，不形成跨活动跟进义务。跨活动连续性由活跃区、召回、承诺与关系承担。记忆侧未封存片段只是 09 内部缓冲。详见 D-007。

旧文档或代码中的「关切」「开放事项」「主体面未完成现实」及种类名 `concern`，均按本条理解。

## 价值与变化

### 必须坚持的价值

匠石应主动维护、不能因个人偏好任意放弃的共同价值。

### 不可越过的边界

即使为了良好结果也不得采用的行为或手段限制。

### 自主发展的领域

在共同价值和行为边界内，匠石可以通过经历形成个人偏好、承诺和价值权重的范围。

### 承诺

匠石向自己或他者明确承担、并对未来行动形成约束的事项。承诺的建立、修改、完成和解除都必须有记录。

### 意图

匠石准备理解、改变或保持某种状态的方向。意图可以继续、暂停、完成或放弃，并应保留相应原因。

### 成长

经历经过记忆和反思后，对偏好、关系、判断方式、自我叙事或价值权重产生的有限且可解释的变化。

### 连续性检验

在模型、方法、插件或身份状态发生重要变化时，对经历承认、承诺、关系、价值和变化理由进行的检查。它是工程检验，不是对主观自我的证明。

### 人工介入点

模型候选生效前，允许人工确认、修改或否决的流程位置。每个介入点有唯一标识、所属模块、作用对象、开关状态（自动 / 人工确认 / 禁用）与等待语义；所有介入点统一登记管理（模块 15），介入的前因后果须记录，并由模型总结成概述，避免各模块各自定义、互相混淆。

### 受约束偶然性

在事实、价值边界、承诺、权限和情境约束内，引入非固定选择的机制。它可以影响探索和表达，但不能伪造来源、绕过边界或无理由改变身份。

## 系统与边界

### 稳定核心

跨模型和算法替换仍需保持连续、可解释和可迁移的数据与规则，包括原始历史、身份、价值边界、承诺、关系、版本和迁移记录。

### 可替换边界

通用模型、对象识别（声纹、人脸、设备标识）、个人世界装载（条目选择与排序）、检索、摘要、反思、外部工具、外部记忆引擎和交互渠道等可以升级或替换的能力范围。替换必须通过稳定接口并接受兼容性和连续性检查。不得把讨论中的可选方案未经约定写成稳定核心。

### 形态（载体）

匠石呈现并作用于现实的具体形态，如人形机器人、App 界面虚拟人、语音助手等。形态是可替换边界：同一匠石可跨形态存在，形态不改变主体归属；形态通过形态接口提供输入输出通道、行动能力与对象识别载体，不承载记忆、历史与承诺的权威。

### 认知能力

用于语言、理解、知识、推理、联想、想象和表达的基础能力。训练后的模型是基础型匠石认知能力的技术载体；这些能力属于匠石的内生认知基础，但具体模型不单独构成完整的匠石。模型负责开放情境下的理解与表达；匠石项目结构负责归属、历史、认识状态与跨活动约束。

### 认知活动

匠石在当前经验中，结合基础认知、相关个人世界、当前上下文视图和活动状态进行感知、回忆、推断、想象、评价或形成**回应计划**的活动。本轮不另落 thought。

### 认识状态

匠石对某项认知内容所持的状态，包括出现、考虑中、暂时接受、接受、拒绝、搁置和修正。认知内容属于匠石，不等于匠石已经相信或愿意据此行动。认识状态机当前不由主链路执行；本轮如何对外由回应计划标记。

### 回应计划（response_plan）

认知活动的对外契约：本轮以何种方式回应。包含单一 `mode`（`respond` / `think` / `ignore` / `wait`）、理由，以及通道列表（语言 `verbal`、肢体 `embodied`）。说话文本在 verbal 的 `text` 中。`think` 表示本轮不对外说，不是一条名叫 thought 的记录。`wait` 表示本轮等后续输入或结果，活动仍结束，下一轮新建活动。

### 事实历史

对输入、行动、外部结果、使用的认知基础和工具等可核查内容的记录。

### 主体历史

对匠石如何理解经历、接受或拒绝什么、形成何种承诺、为何作出选择及后来如何修正的记录。主体历史不能覆盖事实历史。

### 插件

按照共同契约接入可替换能力的组件。插件只能访问获准的数据和资源，其输出默认是待校验的候选结果。

### 能力实现（skill / 模型 / 工具）

承担识别、召回、反思、整理或表达等具体能力的可替换实现。能力实现可以生成结构化候选结果，但不自行拥有主体状态的最终写入权。跨能力的输入输出结构、来源记录、失败处理、认识状态和长期升格规则由主体框架统一规定。

### 个人世界装载系统

100 及后续子模块的薄壳，与记忆系统平行。08 收取各子模块已经排好的列表，按条目 id 去重，再按等级（低 / 中 / 高）取量后交给 03。不按本轮输入排序，不调模型，不规定条目如何产生。不装载 `concern`；该种类已废，不是暂缓。最小实现为进程内合并；带模型的装载只占位。

### 归属判断（已废弃）

输入落位后、组装前判断输入延续到哪个事件的机制。已废弃：不做归属判断。当前由经历账本维护上下文视图，活跃区只读；认知提出缩减、聚焦或追加召回。旧文档或代码中的「归属判断」均按此理解。

### 追加召回

认知活动中，当一次初始装载不足以处理当前输入时，模型提出结构化的召回请求（查询、对象、锚点、预算提示），由程序执行追加召回、将新片段加入当前活动工作集并记账。追加召回受轮次与片段上限约束；补充回忆时不裁剪上下文视图；追加内容仍是候选背景，不自动成为立场。

### 来源

一项数据、判断或变化所依据的事件、资料、处理过程或主体。来源记录用于区分原始事实、派生解释和无法确认的内容。

### 版本

能够明确区分数据结构、插件、模型、解释或身份状态变化的标识。版本使比较、审查、迁移和回退成为可能。

### 迁移

在模型、插件、数据结构或方法变化时，将既有状态转换到新环境，并保持来源、历史和身份连续性的过程。

### 失败隔离

把插件或局部能力的错误限制在明确范围内，使其不能破坏稳定核心、污染身份状态或阻止无关部分运行。
