# 人物长期经验：当前接入

本页描述 JShi 目前对邻仓 REMS 人物经验模块的接入。这里的“经验”是可修订的相处认识，与 JShi 的 `MemoryExperience` 活动片段、Event 回忆及 REMS 描述性人物肖像分别处理。

## 启用与数据流

设置 `JSHI_MEMORY_BACKEND=rems3`，并按原有 REMS 启动要求配置模型和数据目录。JShi 用同一个 REMS pipeline 的数据库、`RoleRepository` 和模型组装 `ExperienceModule`；进程内记忆后端没有人物长期经验。

REMS 写入记忆批次后，JShi 根据本次返回的 `role_ids` 在后台逐人调用 `refresh_person`。REMS 导入未处理白描，达到其配置的条数或字数阈值才尝试模型更新。刷新错误记入日志，不阻断当前对话。CLI 单次运行已接收的刷新任务会在进程退出前完成；进程被强制终止时可用下面的显式命令重试。

已有白描不会因为安装新版 JShi 而自动全库扫描。可按人物 ID 显式刷新：

```powershell
jshi person-experience-refresh SUBJECT_ID OBJECT_ID
```

命令输出 `imported_white_paintings`、`updated`、`pending_white_paintings`、`pending_chars` 和 `review_outcome`。`waiting` 表示还未达到 REMS 阈值或缺少可用模型；不表示出错。`--data-dir` 仍是顶层参数，应写在子命令前面。

## 对话读取

03 组装只为本轮**已确认身份**的对话对象，用稳定 `object_id` 读取人物经验；未识别、临时对象或尚无经验时直接跳过。默认向 REMS 申请最多 500 字的内容，结果与 Event 回忆共享工作集预算。REMS 可在预算较小时返回 `brief` 版本。

送给 05 的经验有独立的“人物相处经验·可修订”标记，并保留 `object_id`、`variant`、更新时间及来源 Event ID。来源 ID 是整份人物经验肖像吸收过的白描证据，不保证每个 Event 支持其中每一句。现有 Event `recall()`、描述性 `portrait()` 和记忆写入语义没有改动。

## 当前限制

- 这里只接人物经验。通用经验库、检索与 Dream 生成流程尚未实现；相关方案见[做梦模块讨论草稿](草稿箱/做梦模块.md)。
- 自动维护只覆盖新记忆批次返回的 `role_ids`；已有对象需逐人显式刷新。后台队列在进程内，不是跨进程持久任务。
- 经验质量、反例处理和具体交互效果还需要用真实白描与模型逐例核对。当前自动化测试覆盖适配、装配、提示词与刷新调度，未运行需要真实 REMS 数据和模型的端到端案例。
