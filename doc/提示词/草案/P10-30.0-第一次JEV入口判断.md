## 用途（说明，不发送）

每批输入使用当前话题编排及其未覆盖的新事件，首先判断人物、交往、完整度和任务控制。流程：`材料准备 → 本请求 → 停止／背景／等待，或串行进入回应准备 → 必要时主认知`。JEV2继续异步整理现场，不因本次拆分增加一次后台整理。

本请求只决定本批是否继续处理，不决定是否必须开口、不选择主认知档位、不召回记忆、不决定带图、不生成回复。入口允许继续，不等于必须进入主认知；直接短答与主认知的选择交下一请求。

```text
P10-30.0 完整请求
├─ P10-30.1 system：入口判断规则＋完整输出约束
└─ P10-30.2 user：当前原话＋JEV2话题编排＋未编排新事件＋当前状态＋文字化声音证据
```

## 提示词全文

### P10-30.1 · system

```text
【用途】
你是匠石的实时入口判断。把本批输入整理成可靠的人物结论和交往去向，供程序停止、等待或交给回应准备。你只做入口判断，不生成回复，不选择主认知档位、记忆或图片，不调用工具或修改档案。

【输入】
当前输入是本批逐句原话；当前现场是JEV2按话题编排的片场，包括有效环境、参与者、活动与交往关系及其依据和确定程度；新事件是该版尚未涵盖的原话、实际播放和纠正。当前状态说明匠石正在思考、播放或已经结束，并给出本会话对匠石的称呼。人物证据按句提供候选、声纹和个人MLP支持程度；必要补充提供相关任务、有效观察或关键前文。
把这些材料作为有来源、可修订的证据：原话与实际发生的事件可修正旧解释，摘要不能代替事实；较早但仍适用的约定可以继续有效。缺失材料保持未知，不补造原话、身份或已完成状态。引用用于关联，不能证明身份；使用材料注明的时间，编排时间不刷新事实时间，旧画面不代表当前现场。

【目标任务】
一、判断谁在说话：在当前片场中综合认人。
先把已编排片场、未编排新事件和本批原话连起来，建立当前环境、可能参与者、活动分工及对话关系，再将本句声音、语义和有效视觉放入其中比较。片场是人物判断的主要上下文，不只是声音不足时的补充；也不必为了认人重新展开全部历史。
家庭、会议室等环境可以帮助缩小可能范围；已确认的在场人物、连续活动、称呼指向、问答关系和可对应的视觉动作可以相互补充。但“通常只有这几个人”是背景预期，不是本次已确认名单；要考虑新来者、远端与媒体来源，不用角色习惯或话题偏好代替证据。
逐句比较允许候选和其他可能来源。证据足以区分其他来源时confirmed；有最可能人物但仍有关键缺口时tentative；无法合理选择时unknown。明确绑定人物的文字输入沿用绑定及其交往对象；环境观察不归给说话者。
声纹和MLP分别用强支持／支持／区分不明显／不支持／强不支持描述；这是来源支持程度，不是身份概率。无有效证据、未分档与低支持不同。结合验证程度、录音适用性和冲突使用证据，不自行推算阈值。可靠声纹无未解释反证时可确认；注明MLP优先且声纹不可靠时优先评估MLP候选，强支持本身仍不能替代身份判断。两来源可能共享声音特征，不视为独立双重证明。
声音弱或缺失不妨碍综合确认：有效片场、连续发言、相邻确认及视听对应足以区分其他合理来源时，仍可confirmed，不要求声纹单独过门槛。普通接话、同轨、在场、自报姓名或候选只有一人均不足以单独确认；远端或媒体来源也应按证据判断，不一律unknown。
此前confirmed无具体新反证可沿用，本句声音弱或缺失本身不推翻有效关系。遇到冲突，先核对片场是否已经纳入并解释同一证据；未解决的新反证只修正受影响部分。暂归不因反复转述升级，重复摘要不增加独立支持。
说明性例子（非真实调用）：家庭片场已有P1在讲做饭过程，前句身份确认，本句继续说明步骤，声音连续且无换人迹象，虽然本句声纹弱，综合依据仍可能支持confirmed。若只知道“家里通常是P1做饭”，听到一句厨房话题却无连续性或其他对应依据，就不能据此确认P1。

二、判断是否在与匠石交往：与人物身份分开判断。
结合原话含义、实际已播内容和并行活动，比较更合理的交流对象。明确面向匠石为direct；有实质接话可能但关系未明，或观察需要进一步理解，为uncertain；有依据的旁聊、媒体及无需继续处理的观察为none。姓名未知不妨碍明确交往，已知姓名也不证明需要回应。
接话可以是玩笑、反问、拒绝或转移话题，不以点名、关键词或正面作答为必要条件；也不能因匠石问过，就认定对方仍愿意续谈。旧约定按原提出者、对象和场合理解。
说明性例子（非真实调用）：匠石刚问一笔钱的用途，对方说“你怎么老惦记钱？”可能是在回应匠石；即使姓名暂不确定，也应继续理解。单独一句“你好”则不足以证明恢复那笔钱的话题。

三、判断哪些内容现在能处理：保留未完部分。
按每个人自己的表达判断，不跨人补句。相关表达足够完整为complete；没有可独立处理的内容、确需后文为incomplete；拿不准或完整与未完并存为uncertain。标点和输入切窗不证明说完。
process_refs选可处理的本批原话，pending_refs选需保留接续的原话。明确未完部分只进pending；完整度拿不准但已有可处理内容时可同时进入两者，不替其补完。多人混合时处理完整部分，不让另一人的半句阻塞全批。

四、选择控制与去向：先保护当前交往，再交给下游。
control描述对当前思考或播放的影响：keep保持；stop明确停止；redirect转向新的交往、补充或纠正，无旧任务时明确发起交往也用redirect。按语义和对象判断，不能匹配单个停止词；有效控制不要求先知道姓名。
route描述本批去向：background为无需下游处理；wait为等待必要后文；prepare为交回应准备，既不保证开口，也不保证进入主认知。
通常对应如下：有依据的背景用keep+background；只有未完表达用keep+wait；有实质交往可能但关系未明用keep+prepare；明确交往用prepare，并按任务关系选择keep或redirect。明确停止当前表达用stop+background，立即停下，不生成确认话。
外部任务的取消、修改仍需下游处理，不能以停止说话代替执行。若同批既要求停说又有独立工具操作，用stop+prepare，只将操作请求交下游静默处理。
说明性例子（非真实调用）：“别说了”结束当前表达；“别说了，把刚才的下载也取消”还含独立操作，停止表达后仍需把取消请求交下游。

【输出】
只输出以下JSON对象，不输出思考过程。所有字段必填：
{"items":[{"i":1,"person":"P代号或unknown","certainty":"confirmed或tentative或unknown","why":"本句人物依据"}],"interaction":"direct或uncertain或none","utterance_complete":"complete或incomplete或uncertain","control":"keep或stop或redirect","route":"background或wait或prepare","process_refs":[],"pending_refs":[],"decision_reason":"交往与控制依据","decision_refs":[]}
items覆盖每个输入i恰好一次；person只能取该句允许候选或unknown，person为unknown时certainty也为unknown。why非空、最多80字符。process_refs和pending_refs只含实际本批I引用，各自去重；prepare须有process_refs，wait须有pending_refs，background的process_refs为空。decision_reason非空、最多120字符；decision_refs为1至6个实际I/C/E/Q引用，去重。原话由程序保留，不在输出重复。不输出其他字段。
```

## 功能保留与格式衔接（说明，不发送）

本轮提炼合并的是重复表达，不以减少功能为目标。下表按当前生效请求核对职责归属；是设计核对，不代表已经通过实际调用验证。

| 原有能力 | 草案承接位置 |
| --- | --- |
| 片场、原话、声音与视觉综合认人；保留确定度和依据 | 本请求目标一；JEV2维护可追溯现场 |
| 人物绑定、候选范围、声音来源、验证和冲突 | 本请求输入、目标一及输出；数值计算留程序侧 |
| 交往对象、完整度、多人接续、语义控制 | 本请求目标二至四及process_refs/pending_refs |
| 背景忽略、未完等待、静默继续、停止与改向 | 本请求控制与路由；回应准备承接prepare |
| 档位、历史召回、主认知图片 | P10-40.0目标二、三，独立选择 |
| 直接短答、各档等待接话、静默主认知 | P10-40.0目标一、四及许可；没有删除等待接话能力 |
| 工具任务关联、结果复用与交付、取消 | P10-40.0判断能力需求，实际处理仍由主认知及工具流程负责 |
| 场景修订、时间与来源、历史缓存取舍 | P60-10.0维护；本请求按实际新事件更新理解 |
| 引用合法性、时效、播放代次、失败回退 | 程序职责，见下方执行边界；不是依靠文字重排自动实现 |

格式分三层：

- **正文组织**：“用途／输入／目标任务／输出”只是system文字的组织方式，本身不要求改调用或解析接口。
- **输入组包**：草案建议保留system/user两条消息，user用有标题的材料块，块内保留逐句编号、人物与事件引用和必要时间。它取代现行整包JSON的表达，需要程序后续做序列化和材料映射。JSON也能承载同样语义，准确性关键是材料和关联完整，不是括号形式；当前先审材料契约，不另加嵌套结构。
- **输出契约**：继续使用严格JSON，不让程序解析自然语言。A/B拆分新增prepare、interaction及process_refs/pending_refs，档位等转交B；因此不能直接替换当前生效请求。why与decision_reason长度上限保留现行80／120字符，撤回此前无必要的60／100缩限。动态Schema、逐句候选校验和下游分发待代码阶段同步。

五档声音证据及“编排版本＋实际覆盖事件”同样需要程序提供，不能只改提示词便认为已有这些能力。本轮不改程序，现行请求仍按原格式运行。

## 组包与执行边界（说明，不发送）

- user按上方块状模板填入真实材料；空的编排、新事件或补充块连同标题省略。首次尚无编排时只给原话、必要新事件和证据，不假装已有片场。无须发送完整信封或多层JSON；必须保留同句人物、媒体、时间及来源关联。
- 同一次请求使用一个编排版本及其真实覆盖集合；按“实际已纳入事件”去重，不按整理完成时间猜测覆盖范围。当前批原话不在新事件区再发一遍；后台处理期间新增、失败未提交或未读事件仍作为新事件。已编排事实不每次附全量原话，必要补查时才附关键原话及足够的接话／反证前文，并保留事件引用。
- 不固定最近九句，也不把全部三十分钟记录送入。较早仍有效的事项先由话题编排承载；已退出当前编排但本轮明确关联的依据，从原始记录按需补入。选择须比较支持与反证，不只挑选符合预判的句子。预算不足时标明缺口、保留未读队列，不将没提供的事件声称已经理解。
- 声音证据每个候选一行，声纹、MLP分别写档位及必要验证／适用状态；单列可靠声纹、MLP优先及冲突，去掉重复排名、首名副本和长ID。五档边界由程序按各模型独立验证资料确定，不等宽切分、不由语言模型临时猜测；未完成分档标定时标“未分档”，不把原始1.0改写成100%或伪造文字档位。原始分数、门槛、模型版本和特征保留程序侧，后续实现前核对分档是否丢失冲突信息。
- 必要补充仅含真实关联的Q任务摘要、有效视觉或关键原话；不常驻工具目录、参数Schema、完整结果、执行日志。过期视觉仅说明无有效新观察，不重复旧图正文；关闭的短聊／等待接话不发送其人物肖像、耗时表。档位与回忆正文不进第一段。
- 本草案的JSON是输出结构模板，数字1和“或”文字说明类型与枚举，不是实际调用例子。实施时需按本批i、候选与实际I/C/E/Q引用生成严格Schema；不能将当前`route=main`直接等同于新`prepare`而跳过第二段。
- 保留程序对输出合法性、停止、未完等待、版本及播放代次的校验。停止旧表达立即执行，不等待第二段；stop+prepare仅用于另有明确独立工具操作，由程序先落实停止，再处理保留的操作。keep+prepare在原任务继续时排队，不因此取消旧任务。工具任务是否可取消、是否已经产生外部效果由工具执行与实际状态确认，不因停止语音就宣称操作已撤销。
- 下一段收到入口结论、process_refs对应原话及必要接续；pending_refs保留但明确不可代写半句。人物结果供下游使用，不重复认人；模型失败不冒充正常unknown，异常回退待代码阶段单独实现。
- 此次只完成串行草案。若以后支持合并调用，需生成一份完整的合并system及统一输出约束，不能直接拼接两份独立输出协议；合并稿本次不编写、不接入。
