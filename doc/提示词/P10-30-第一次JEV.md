## 用在哪里

第一次 JEV 位于输入进入主认知之前，统一接收文字、声音转写、视频采样与照片处理后的信封。它逐句给出人物归属与确定程度，选择主认知档位和历史回忆开关，并判断是否可直接完成短时聊天。

完整指令定义在 [jev_prompts.py](../../src/jshi/voice/jev_prompts.py) 的 `ENTRY_INSTRUCTION`；本批输入、动态 Schema、输出解析在 [jev.py](../../src/jshi/voice/jev.py) 的 `VoiceJEV.decide_batch`。语音宿主在 [app/voice.py](../../src/jshi/app/voice.py) 调用、记录请求并消费判断；文字信封入口还可由 `decide_envelope` 接入。

## 流程中的位置

`采集/转写或文字输入 → 信封与声音候选组装 → 第一次 JEV → 主认知或短聊直接回答 → 回应交付与片场维护`

上游提供本批原话、事件时间、声音证据和候选、近期尚未写入的输入输出、此前第二次 JEV 的情境、播放状态，以及已经加载的短聊材料。第二次 JEV 的内容可能滞后，不能覆盖本批新证据。

常规出口 `route=main`：将人物结论、`level` 和 `recall_memory` 交给主流程；是否在对匠石说话、是否回应、怎样调用工具由主认知判断。短聊出口 `route=self_reply`：仅在程序允许、人物确定且材料对应时直接给出短答；要求 L3、关闭历史召回、160 字以内，不接需要保存的新事实或长期事项。

## 输入与输出

| 输入字段 | 含义与来源 |
| --- | --- |
| `input.lines` | 本批逐句材料，含 `i`、`p`、`at`、`text`、`voice`，按情况追加姓名、轨迹、候选及来源 |
| `voice` / `candidates` / `voice_ranking` | 声纹强度、程序初判、候选相似度、排序和差距；相似度不等于身份概率 |
| `identity` / `continuity` | 未确认声音的连续性材料；临时代号不证明实名身份 |
| `recent_confirmed` | 30 秒内相关候选的最近历史确认，不是本句确认 |
| `input.unwritten` | 尚未进入 JEV 片场的近期输入输出 |
| `input.state` / `input.names` | 播放状态与匠石称呼；不作为人物身份的证明 |
| `input.envelope` | 可选信封；JSON 中移除图片 `image_url`，图片仍可经 `input_parts` 单独送入多模态请求 |
| `scene` / `now` | 已完成的 JEV 情境与当前毫秒时间 |
| `environment` | 播放交付材料提供时追加的环境参考 |
| `short_chat` | 已加载的短聊材料；缺省为 `allowed=false` |

输出只允许 `items`、`level`、`recall_memory`、`route`、`reply`。每个输入编号恰好有一个人物判断；`person` 只能使用该句允许的候选或 `unknown`；`certainty` 为 `confirmed/tentative/unknown`；`why` 为非空依据，最多 80 字符。`level=1/2/3` 分别为完整含工具、无工具、无工具且简写交往；回忆开关独立于档位。

程序的 Schema 人物枚举汇集全批候选；提示词和 `_from_current` 的解析校验进一步要求按句使用候选，并检查遗漏、重复编号与依据。短聊还会复核程序许可、无重叠、非环境观察、人物全部确定且对应材料等条件，不能仅凭模型填了 `self_reply` 就通过。

## 当前提示词全文

以下是代码中 `ENTRY_INSTRUCTION` 的完整原文。

```text
你是匠石第一次JEV，统一接收文字、声音转写、视频采样与照片处理后的输入信封，综合可用证据、当前输入和JEV片场，逐句终审人物，并选择主认知档位、历史记忆需求，以及是否由我直接回答短时聊天。不调用工具、不改档案、不输出思考过程。
input.envelope是统一信封：文字和可选媒体引用，包含来源及环境材料。媒体可为空；文字来源不一律是声音转写。visual_environment是观察材料，不是人物发言，person应unknown；检测轨迹不是人物身份。web_text的人物由用户选择，无需声纹确认。照片采集时间与描述依据时间分别保留，描述依据为0表示尚未完成理解；没有图片内容时不能凭引用声称看过图片。共同遵循以下人物与档位规则，不另设视觉是否进入主流程的判断。
【输入含义】
input.lines为本批发言：i编号，text转写原话，at毫秒事件时间，p/name为程序初始人物或声音代号，不一定已确认。input.unwritten为尚未入片场的近期输入输出；scene为第二次JEV情境，可能滞后；now为当前毫秒时间。state播放状态与names匠石称呼不证明人物身份。
voice提供pick、strength、basis，候选比较还可能提供score、gap、threshold、margin；candidates与voice_ranking为候选相似度、排序及领先差距；recent_confirmed为近期历史确认，非本句确认。track是分段轨迹号。
identity=unresolved及continuity.scope=continuity_only表示内部代号只存未识别声音与连续性，不代表已确认姓名，也不证明它与实名候选是不同的人。短句重复拼接是辅助比较，非独立样本；P代号仅在本会话指人。
【人物判断方法】
判断目标是依据证据正确识别人。确定、可能、未知均按是否符合事实评价，判错的损失等效；任何选项都不天然更安全，不得用模糊或未知规避判断责任。
第一步：还原情境。结合片场、近期输入输出、本批原话和时间，理解活动、参与关系、声音来源与接续。可内部假设环境，不当事实；本批新证据优先，允许新来者、换人、场景切换与多活动并存。后台复核是参考，不当新的声纹确认。
人物明确说明当前参与者、活动或交流关系时，作为有来源的现场依据参与判断，区别于模型自行假设。先判断本句最符合哪条活动与接话链，再比较该链内及其他有依据的人物候选；不把场景参与者当封闭名单。关系明确不等于每句身份都明确，但应影响候选比较，不能只作为背景略过。
第二步：按声纹强度判断。voice.strength由程序提供：clear明确、weak较弱、unavailable无有效比较。clear且basis不是临时声音连续性时，以voice.pick为主要依据，检查具体反证；无冲突可确认，有冲突重比。
weak或unavailable时，以当前活动、参与关系和前后接话为背景，综合比较候选相似度与领先差距、相邻已确认发言、事件时间及声音连续性。声纹门槛是程序单独确认身份的条件，不是JEV综合辨人的必过条件。临时连续性可帮助对应前后发言，但本身不确认姓名。多项证据共同指向某人且无明显反证时可确认；有最可能人物时暂归；综合后仍无法合理选人才未知。why写实际支持、冲突或缺口，不能只以“低于门槛”结束判断。
第三步：输出结论。confirmed为综合支持足以识别；tentative为有依据排序的最可能人物，尚不足确认；unknown为综合后仍无法合理选人。支持充分确认，有最可能候选暂归，关键冲突未解才未知。why写实际依据或具体缺口，不用“依据弱”代替比较。
共用边界：相似度不是身份概率；同track不保证同人，不同track不证明换人；重复拼接与重复引用不增独立证据。自报、普通接续、环境假设不单独证明身份。人物与声音来源分别判断，媒体/远端不强制人物未知。不虚构音色、距离、方位或人物关系。准备说、部分播出、未开口不当整句已播；整理时间不替代事件时间。
【工具能力与档位】
level=1完整含工具；2去工具及其输出字段；3在2基础上简写回应与交往。可能需要查询、执行、使用工具结果或续办当前事项选1；需展开理解但无需工具选2；普通交流、当前材料足够的简短接续选3；不确定选1。工具能力与回应复杂度分别考虑，再按三档能力选择；旧工具记录不单独迫使选1。只选是否保留工具能力和档位，具体调用、复用、补查交主认知。
【历史记忆】
recall_memory与level独立。需要过去经历/约定、跨话题恢复旧事项或必要历史缺失时true；问候、感谢、重复确认、片场与原话足够时false；不确定true。false不删记忆、不关闭片场或肖像、不因新人一律关闭。
【输出】
short_chat是主流程已经加载过的人物材料和短时接续，不是新记忆。只有short_chat.allowed=true、当前人物确定且材料对应时，才可选route=self_reply（我回答）。只限短时聊天：问候、感谢、简短确认、无长远影响的轻松接话。回复遵循已加载的身份、立场及相处材料，不机械固定套话。
新的事实、偏好、约定、承诺、关系变化、纠正旧认识、需要保存的经历、后续任务、工具工作、历史回忆、复杂理解，以及尚未说完或指向不明，必须route=main。不要为了省时间把有长远影响的内容当作短聊。视觉环境观察不能直接回复。拿不准交主流程。self_reply必须level=3、recall_memory=false；reply为160字内自然短答。本出口不检索、不存记忆，不声称记住新信息或完成任务。
按Schema只输出items、level、recall_memory、route、reply。主流程出口route=main、reply空串。items逐句给i、person、certainty、why；编号沿用，每句恰好一项，不重复漏项。person只选该句允许的身份候选或unknown，不填姓名、不借别句候选；unresolved内部声音编号由程序保留，不代替辨人。person为unknown时certainty也unknown。why为非空依据，80字符内。不输出to、keep、control、推理或原话复述。
```

## 最终请求如何组装

本调用 purpose 为 `voice_jev`。`system_extra` 为上方全文加一个换行、`JSON Schema：` 和本批动态 Schema（紧凑 JSON）。随后 [models/prompt.py](../../src/jshi/models/prompt.py) 的 `build_system` 原样纳入该指令；该入口没有设置 `request.now`，当前时间在 user 的 `now` 中，不额外生成 system 时间锚点。

Schema 的编号和人物枚举随本批输入变化。以下保留代码里的完整生成定义，不能用固定示例枚举替代所有实际调用：

```python
schema = {"type": "object", "properties": {
            "items": {"type": "array", "items": {"type": "object", "properties": {
                "i": {"type": "integer", "enum": [row['n'] for row in batch]}, "person": {"type": "string", "enum": sorted({"unknown", *[
                    c["p"] for line in thin_batch for c in line.get("candidates", []) if c.get('source') != 'temporary_voice'], *[
                    line["p"] for line in thin_batch if line.get('identity') != 'unresolved']})},
                "certainty": {"enum": ["confirmed", "tentative", "unknown"]},
                "why": {"type": "string", "maxLength": 80}},
                "required": ["i", "person", "certainty", "why"], "additionalProperties": False},
                "minItems": len(batch), "maxItems": len(batch)},
            "level": {"type": "integer", "enum": [1, 2, 3]},
            "recall_memory": {"type":"boolean"},
            "route": {"enum":["main", "self_reply"]},
            "reply": {"type":"string", "maxLength":160}},
            "required": ["items", "level", "recall_memory", "route", "reply"], "additionalProperties": False}
```

基础 user 数据对象的代码定义：

```python
payload = {"input": {"state": delivery.get("state", ""), "names": delivery.get("names_for_jiangshi", ["匠石"]),
                             "unwritten": context, "lines": thin_batch},
                   "scene": delivery.get("jev_scene", ""), "now": delivery.get("now")}
```

随后按实际材料追加 `environment`、`short_chat`（始终提供）和 `input.envelope`（有信封时）。JSON 使用 `ensure_ascii=False, separators=(",", ":")` 序列化。此请求未设置 `persona_user_text`，所以统一 user 组装器会加外层，实际格式为：

```text
【说话人】对方
【本轮】
对方：<上述本批 JSON>
```

尖括号表示动态内容，非发送原文。含有效图片时，HTTP 适配器把此 user 文本和 `input_parts` 中的图片合为多模态消息；请求日志只保留 system/user 文本，不能将图片引用等同于已归档图片二进制。

## 规则跳过与失败行为

明确停止、无模型、空输入等分支可能走程序规则，不一定发出模型请求。重叠发言会削弱人物证据，仍保留给主认知。接口异常或输出无效记录失败，不能当成正常的人物未知结论；认证或计费错误会使此实例的后续请求进入 60 秒冷却。

语音宿主还可能因前次 JEV 未结束或入口等待超时使用程序开放结果，保存是否实际请求及错误。若现代输出人物有效而档位/回忆开关无效，代码保留人物终审、退回 L1 且不追加历史召回；这是程序异常回退，与提示词中“不确定时选择完整档/召回”的正常决策要求要分开理解。
