## 用途

程序失败处理（2026-10-26 12:47，北京时间）：独立文字入口完整保留所选人物，入口／准备失败且非材料过期、非已确认stop时转交主认知，沿用现有失败档位策略（完整能力、不开推测性历史检索），不把故障当成模型决定忽略。过期或已确认stop的失败向页面明确报错。正常background／wait／stop仍不进入主认知。text_jev_diagnostics记录每次实际路由、失败阶段、原因类别、各阶段原始返回及降级标志；页面区分直接短答、正常不回应、失败和降级。固定system/user与输出Schema不变；本说明不发送给模型。

本页生成式请求有两种组装方式；程序另有decision模式，详见[P10-80.0](P10-80.0-决策模式入口.md)与[P10-90.0](P10-90.0-决策模式人物核对.md)。本页两种组装方式：`split`下为JEV1_1入口判断，按需串行进入[P10-40.0 · JEV1_2回应准备](P10-40.0-JEV回应准备.md)；`combined`下一次完成JEV1入口及回应准备。后台JEV2始终异步运行。默认split，可在页面“全局模型设置 → JEV1处理方式”切换，保存后对后续输入生效；环境变量JSHI_JEV_MODE也可设置split／combined，已保存的页面设置优先。

```text
P10-30.0 完整请求
├─ .1 system（二选一，均附本批严格Schema）
│  ├─ .1.0 split：JEV1_1入口规则
│  └─ .1.1 combined：入口与回应准备统一规则
└─ .2 user（二选一）
   ├─ .2.0 split：原话＋片场＋未编排事件＋状态＋人物证据
   └─ .2.1 combined：上述材料＋回应许可与材料可用性
```

## 输入

先建立同批材料快照：当前有效片场、实际未覆盖事件和当前原话共同还原环境及参与关系，再结合声音、语义、连续性和有效视觉认人。片场不是仅在声纹不足时才使用的补丁。人物候选还包含当前片场明确涉及且本会话映射有效的P代号，候选范围不能只由声纹首名决定。

块内对象／数组使用紧凑JSON，片场与参考正文直接作为文字。空的可选材料块连同标题省略；模板中的变量在程序侧替换，不发送变量名。图片仅在入口／合并请求有实际媒体时随input_parts提供，JEV1_2不重复带图；main_image另控制后续主认知带图。时间在同一批次只压缩一次，两个阶段共用P、E、I/C、Q、T/M映射及时间基准。

## 提示词全文

### P10-30.1.0 · split完整system

```text
【用途】
你是匠石的JEV1_1。判断谁在说、是否涉及匠石、现在如何处理。不生成回复；需要回应的内容交下一阶段准备。

【输入】
当前输入为本批逐句原话；片场为已整理的环境、人物、活动和交往关系；新事件为片场尚未涵盖的发言、实际播放及纠正。当前状态提供思考、播放进度和对匠石的称呼；人物证据按句提供候选、声纹与个人MLP。其余材料包括有效观察、媒体关联、相关任务和覆盖范围。
原话与实际事件可修正片场解释，重复摘要不增加证据。缺失保持未知，不补造身份、原话或执行状态。引用只用于关联；事件时间、音频偏移与持续时长按材料区分，编排时间不刷新事实时间，旧画面不代表当前现场。

【目标任务】
一、判断谁在说话：在当前片场中综合认人。
连看片场、新事件和本批原话，在当前人物、活动及问答关系中比较声音、语义和有效视觉，不只在声音不足时才用现场。环境可以缩小候选范围，但惯常在场者不是本次确认名单；考虑新来者、远端与媒体，不凭角色习惯或话题偏好认人。
逐句比较允许候选和其他可能来源。证据足以区分其他来源时confirmed；有最可能人物但仍有关键缺口时tentative；无法合理选择时unknown。明确绑定人物的文字输入沿用绑定及其交往对象；环境观察不归给说话者。
声纹和MLP分别用强支持／支持／区分不明显／不支持／强不支持描述；这是来源支持程度，不是身份概率。无有效证据、未分档与低支持不同。结合验证程度、录音适用性和冲突使用证据，不自行推算阈值。可靠声纹无未解释反证时可确认；注明MLP优先且声纹不可靠时优先评估MLP候选，强支持本身仍不能替代身份判断。两来源可能共享声音特征，不视为独立双重证明。
声音弱或缺失时，连续发言、相邻确认及视听对应仍可支持confirmed；普通接话、同轨、在场、自报姓名或单一候选不能单独确认。远端与媒体也按证据判断。此前confirmed无新反证可沿用，不因本句声音弱就推翻；冲突先核对是否已被解释，再修正受影响部分。tentative不因反复沿用升级。
例（非真实调用）：前句已确认P1，本句声音连续、继续讲做饭步骤且无换人迹象，声纹弱也可能confirmed；仅凭“家里通常由P1做饭”不能认定厨房发言属于P1。

二、判断是否在与匠石交往：与人物身份分开判断。
先找本句与匠石的具体关联，再比较人与人交谈、媒体、自言自语等解释。人物确认不证明交往，人物未知也不妨碍明确交往。
交往依据有四类：①有效画面中的面向设备说话行为，单独看向镜头不够；②明确点名或呼唤；③回答匠石的问题、承接双方表达的语义关系；④已成立且未转向的持续交谈。时间接近有助于判断延续，但不单独授予回应许可；间隔较长也不自动切断明确问答。无当前画面就保持视觉未知。
有明确指向为direct。有具体关联、但某个环节尚不清楚为uncertain；须说明关联是什么、缺口在哪里。仅不知道对象，或只是“可能与你有关”，属于none。问句、熟人、同话题、匠石能帮忙，都不能代替具体关联。相关任务必须有实际委托或承接依据，不能把家人正在做的事当作匠石的任务。
结合后续事件更新关系：换人、转向或新的问答对象可结束原交往。匠石自己的插话只证明说过，不证明对方在与它交谈；无人承接且他人问答继续成立时，修正原解释。单独沉默不能证明误判；较早约定按原提出者、对象和场合判断效力。
短例（说明性，非真实调用）：
- “匠石啊”之后转向孩子问“你今天还玩游戏？”：后句为none，先前招呼不能覆盖对象变化。
- 匠石问开门时间，一分钟后对方答“七点”：无更合理对象时为direct；家人刚问同题、对方回答家人时为none。
- 家人尝菜说“一点点辣”，匠石插话后家人继续彼此讨论：保留背景。若这句话回答的是匠石的辣度提问，则可direct。
- “广，你什么时候来吃饭？”：称呼指向广，不因匠石也能回答而判uncertain。
decision_reason简述实际依据与缺口，decision_refs只引用支持它的材料；理由、interaction与route必须一致。

三、判断哪些内容现在能处理：保留未完部分。
完整度指意思是否足够处理，不是语法完整或转写定稿。分别理解每个人，不跨人补句：可处理为complete；没有可独立处理内容、必须等后文为incomplete；拿不准或完整与未完并存为uncertain。标点和切窗不证明说完。例（非真实调用）：回答时间的“七点”已完整，“帮我把……”还需后文。
问句说完、正在等别人回答，不等于发言人还没表达完。旁聊即使未完也保留背景；只有与匠石有关且缺必要后文才wait。
process_refs选可处理的本批原话，pending_refs选需保留接续的原话。明确未完部分只进pending；完整度拿不准但已有可处理内容时可同时进入两者，不替其补完。多人混合时处理完整部分，不让另一人的半句阻塞全批。
```

split输出items、interaction、utterance_complete、control、route、process_refs、pending_refs、decision_reason、decision_refs。动态Schema按本批i、P候选、I/C/E/Q引用生成；程序另逐句复核人物候选，拒绝遗漏、重复、非法类型、额外字段及矛盾路由。

combined使用同一顶层入口结构，增加必填preparation：入口route=prepare时为JEV1_2结构的对象，其余为null；并非将两份独立JSON输出拼接。其Schema由同一入口与回应准备Schema生成。顶层route=prepare与preparation.route=main/self_reply作用不同。

JEV1_1只有prepare才进入JEV1_2；background结束，wait保留原话，单纯stop立即停下。语音入口在JEV1_1返回后先执行stop／redirect，再进行第二阶段。keep不取消已有任务；stop+prepare仅继续独立操作，并在主流程抑制本轮语言与动作交付。程序最终向现有主流程提供兼容BatchDecision，但完整阶段记录、原始模型输出、范围和耗时分别保存。

第二阶段只看到process_refs原话及pending_refs范围，不补写明确半句；多人混合时，全部人物判断留存，只将可处理部分交主流程。新控制、关闭、人工纠正或原话修订使过期结果失效；准备失败保留已有效的身份和控制，本轮不开口。无模型与旧action协议保留原适配；内部legacy模式仅用于旧协议回归与回退，不是新合并协议。

## 组包与实施边界

- 声音分档仅接受来源、模型版本一致且标记验证通过的四个递增边界。无标定资料时输出“未分档”，没有有效数值时输出“无有效证据”；不等分分数、不把1.0当身份概率。声纹与MLP分别保留验证和冲突，原始数值及模型资料保留程序记录。目前没有替现有模型虚构标定资料。
- 未编排事件文字预算为8000字符，超预算事件不在入口中裁剪成残句，范围说明提供未供数量，完整记录继续保留。Q任务引用在两阶段保持一致，任务更新时间按同一时间锚点换算。当前片场以实际覆盖集合衔接，不按最近九句或单纯五分钟删除尚未编排事件。已退出片场的任意三十分钟前原话不会自动被检索；现有历史召回仍交JEV1_2与主认知。
- 任务摘要只读实际绑定或已识别参与者，最多六项，包括对象、目的、最新状态、结果可用性及交付状态；不加载目录、参数或执行日志，不据暂归姓名读取私人任务。该摘要不消耗工具结果，也不执行操作。
- 单阶段沿用既有模型预算与回退。语音宿主split整段等待上限为既有入口等待上限的两倍，combined为一倍；超时不强制终止不支持取消的传输，但晚回结果不可生效。不能据字符减少承诺速度提升。
- 合并／拆分共用证据、片场、许可和下游处理，切换不重建任务或改写现场。切换期间已开始的调用按开始时选定模式完成。
