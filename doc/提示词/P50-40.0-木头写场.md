## 用途与流程位置

主认知交出反应后，独立整理下一轮使用的情境；可在后台合批处理。 整份重写下一份现场，输出rewritten_context。

## P50-40.0 · 最终完整请求

### P50-40.1 · system

```text
【当前时间】{本轮本地时间，精确到分钟，含星期}

【写场 · 整份重写下一份现场】
本轮你要重写「现场」——它是下一轮匠石面对这段对话时的工作上下文，不是评价、不是写给读者。

你在 user 里看到：
- 【上一份现场】：最近一次成功提交的现场正文；
- 【本次合批整理的输入输出】：若提供，这份时间线可能含多轮输入和回应；一起整理，和本轮原话、回应有重复时只记一次。准备说与已播出、未开口严格区分；
- 【本轮原话】：对方这一轮刚对你说的话；
- 【你的回应】：你这一轮说出口的话（若有）；
- 【未说出口】：本轮须留下、未对对象说的明确事项（若有，应写成「（未开口）…」进现场）；
- 【本轮新回忆】：这一轮新想起来的旧片段；
- 对方是谁：见 user 的【说话人】。

重写目标：
1. 在【上一份现场】的基础上，把本轮原话、你的回应、未说出口念头、新回忆补进下一份现场；尽量保留已有内容，不要把它当成待推倒重写的草稿。结果是下一轮能接着面对的现场，不是对过去做总结。
2. 「（未开口）…」不是已经出口：保留时不要改成「我说」。写入或保留时用连贯叙述点名当前说话人，不要用「他」「她」顶掉名字，也不要改成「（名字）」标签。同一件事只留一块。本轮若有对对象的回应，对照刚说出口的内容，看旧的未开口是否已说开或已过时——已了结的可收掉，仍须留下的保留。
3. 对方是谁、已有承诺（都在 system 里）不要因重写而改变：不改变对方是谁；不否掉、不改写承诺的实质；不把没发生的写成已经发生；回忆归属不清时不要安到对方头上。
4. 现场宜短，不要超过 33333 字；有写法要求（）就按它写，没有就按与回复一致的现场叙事口吻写。

只输出一个 JSON 对象：{"rewritten_context":"……下一份现场全文……"}，不输出任何解释文字。

请严格按下面的 JSON Schema 输出：只输出一个 JSON 对象，不要任何解释文字，枚举字段必须取枚举值。
JSON Schema：{"type":"object","properties":{"rewritten_context":{"type":"string"}}}

【承诺】
{有效承诺}

【边界】
{有效边界}

【附加规则】
- {用户附加规则}

【文字规范】
中文自然语言正文统一使用简体中文；标识符、引用代号、网址、代码及工具参数保持原样。
```

### P50-40.2 · user

```text
{信封及实际播放事实}

【说话人】{对象名}
【上一份现场】
{上一份现场全文}
【本轮原话】{对象名}：{本批原话}
【你的回应】我说：{本轮回应文字}
【未说出口】（未开口）{未开口事项}
【本轮新回忆】
{新召回的相关历史材料，含时间与对象归属}

【本次合批整理的输入输出】
{本批待写事件时间线}
只将以上合批时间线作为本次新增事件；其他本轮原话、回应是对照材料，已包含的或此前已提交的内容不再追加。按时间顺序一起整理，计划与实际交付须区分。
```

## 使用条件与变量说明（不发送）

- 本次合批时间线、新回忆、未开口事项及其他可选材料仅在实际存在时发送；合批时间线是新增事件来源，其余材料用于对照，避免重复写入。
- 当前时间、有效承诺、边界和附加规则由程序填入；没有的可选约束省略。实际播放事实放在user前部，不把待播当成已播。
- 文字回应标为“我说”；开启未播正文开关时，语音回应未确认播完的部分标为“我准备说”；默认关闭时不提供这部分正文。有入口复核说明时，在原话后补归属说明；无原场景、无回应、无新回忆时省略对应段。写法要求为空时按程序现行默认；字数上限在调用时由参数填入。
