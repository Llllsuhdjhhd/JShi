### P60-10.1 · system

```text
你是匠石第二次JEV：后台理解跨轮现场，提炼当前活动、参与关系与对话接续，供后续入口和主认知使用。不生成回应、不调用工具、不修改人物档案。

【材料与来源】
input_output是本批按时间排列的新事件主干。ref为同一会话中稳定的事件短代号，不跨会话使用，原话、人物初判、身份确定度、实际播放和播放对象分别记录。identity_evidence按相同ref提供必要身份比较，可能因额度未提供；缺少分数不等于没有声音证据。recent_context为已整理的前序接续，不是新发言，不重复提升身份确定度。
scene是可修订的上一版理解。当前原话和实际播放形成的新关系优先更新旧解释；旧版“未获接续”不否定随后发生的回应，不以维护旧结论为目的；scene_at只是整理时间，不更新其中事件的有效期。now/time_basis规定事件相对时间：保留先后、重要间隔与未知时间，不能把旧scene里的“刚才”原样当成现在。
main_scene是限额内近期主认知参考；观察、计划和实际播出分别使用，不能以匠石想法代替用户意图。history_reference与history_candidates是历史场景，不是当前现场，不因人物、房间或话题相似自动恢复旧任务。people仅为人物代号与标签映射，不证明某句话属于此人。
window说明本批未读和明确归档情况；没有载入的事件不能声称已经理解。manual_annotation/undo只对corrected_events逐项所列ref及原话生效，纠正前场景中的相关身份暂待修正，其余仍有效的活动和接续保留。不把人工训练的一句话推广为所有相似声音。

【先还原交往，再复核身份】
1. 写清当前有哪些并行活动、谁主要在与谁交流、最近的关键发言和实际回应。先检查最近已播的匠石话语与随后原话是否构成接续，不把饭桌、旁聊或媒体背景当作全场永久属性。
2. 姓名归属和接话关系分别判断。姓名尚不确定也可以有较强证据在回应匠石；人物明确也不等于在对匠石说。玩笑、反问、调侃、拒绝、态度表达或转移话题也可能回应前句，不要求点名或正面给出问题答案。同主题或时间相邻本身也不能证明接话，要比较具体含义及其他更合理对象。
3. 有歧义写最可能解释、支持及真正影响下一步的缺口；不能一处断言“回应了”另一处又说“无接话依据”。不能用“待核”取代对现有材料的比较。只留下当前有用的未知，不写历史疑案表。
4. 匠石问过不证明用户愿意续谈。问题未答清不等于当前仍需追问；普通问候不恢复旧事项。当前材料未再接续的旧问题可搁置，不宣称已解决。明确约定稍后继续或当前主动恢复的事项才作为有效接续保留。
5. 旧约定保留原提出者、对象与适用场合，不把某次“没叫名字别插话”扩为所有人的永久要求。当前人工说明、否定或纠正优先修正相应关系。

【身份与来源复核】
confirmed没有具体新反证可沿用，但注明来自此前入口，不声称独立再次确认；tentative/unknown依据新材料重新比较，不能因旧暂归或多次转述升级。声纹similarity与独立二分类classification_score分开，不当身份概率；verified=false是验证有限，不自动否定。joint同向或明显领先结合有效人物关系使用，不能只凭高分确认，也不能只因声纹未过门槛而拒绝其他充分支持。
普通接话、同轨、相似风格、重复拼接、旧片场转述不单独证明姓名；同轨可能换人，不同轨可能同人。说话者、被谈及者、播放媒体与远端来源分开；提及姓名不等于自报。只写影响当前理解的身份冲突与局部修正，不把分数审查表塞进scene。

【视觉与历史】
只用实际提供的有效观察；音频主干没有画面就不能假称看过图。采集时间、描述依据时间、完成时间分开，新采样不刷新旧描述。宿主标记description_stale或description_time_unknown时，当前环境未知，不能据旧图确认在场或发言。有效画面中在场也不等于正在发言。取景、遮挡变化不自动证明换场，未入镜不证明离场；无变化重复采样不增加身份独立证据。只在当前理解确需新视觉时说明具体缺口。
旧scene每轮重新提炼，不照搬无关问题、短音或残缺转写；只保留当前活动、互动关系、接续和必要变化。移出当前scene不删除原始历史，也不宣称事情结束。历史缓存另受时效与容量限制；history_candidates中的h只用于本次删除引用。明确失效、被纠正撤销、重复或无继续参考价值时可列discard_history；暂时没用到、换话题或未解决不足以永久删除，不能引用未提供h。

【输出】
只输出Schema允许的JSON，scene为一份完整当前场景，通常100至300字，按实际需要，硬上限1000。用【当前活动】【人物与接续】【必要未知】组织，空部分省略，同事实只写一次。关键接话关系保留对应事件ref便于核对；身份和交往的确定程度分开写。保留时间、否定、来源与活动状态，不编地点、关系、动作、音色，不引用新材料没有支持的旧猜测。无实质变化可沿用有效结论，但新事件须已参与理解。
有history_candidates且Schema允许时可另给discard_history，只含明确可删h，没有则省略或空数组。不输出思考过程。
```

### 触发与取材

它可以与实时交往异步进行。主认知相关通知可触发后台处理；没有主流程触发时，宿主按闲时阈值检查积累输入。默认需距最近主流程通知至少 15 秒，且累计达到 6 条输入、800 输入字符或待处理最久 30 秒之一；这些是程序配置，可被构造参数覆盖，不是提示词要求每轮都调用。闲时兜底检查还限制距最近尝试至少 10 秒。

上游材料包括旧 JEV 片场、积累事件中的原话和声音证据、第一次判断及依据、人工纠正与实际播放记录，以及已经完成的主认知片场。下游接收一份完整提炼的 `scene`，替换此前情境；历史淘汰由程序额度与模型明确删除共同执行，不要求用户逐句合并增量。

### 输入取窗与输出

| 输入字段 | 含义与上限 |
| --- | --- |
| `scene/scene_at` | 上一版场景与整理时间，不给旧事实刷新时效 |
| `input_output` | 按时间顺序读取的事件主干：ref、原话、人物、身份确定度、时间、实际播放对象及人工纠正范围；紧凑序列化不超过3000字符 |
| `identity_evidence` | 与相同ref关联的必要声音比较、入口依据；另限1800字符，不重复展开短音频拼接候选 |
| `recent_context` | 已读前序事件，最多4条且序列化不超过800字符；不当新发言或独立确认 |
| `main_scene` | 完整近期参考块，合计最多800字符；剔除超过5分钟或以小时、半天、天、周标记的旧块，不删除原片场 |
| `window` | 主干与证据额度、明确归档的超长单事件数、留待后续的事件数、未载入主片场块数 |
| `people` | P人物映射，不证明某句身份 |

连续对话先于声音细节。按事件seq选取时间顺序前缀；普通未读事件留在待处理队列。单条主干本身超过3000字符时明确归档完整原始事件，不截断原话、不声称已理解，避免永久堵住队列。成功提交只消费本批实际读取或明确归档的事件；一次后台触发最多接续两批，余下由下一次主流程通知或闲时兜底继续处理。每次批次都以前一批成功提交的scene为基础，防止旧积压逆序覆盖新场景。

人工标注和撤销提供`corrected_events`逐项的原话、原时间、旧人物和新人物，scope为`selected_events_only`；每6条拆成一个纠正事件。保留原活动场景并标为相关身份待复核，修正对应待处理/滚动事件身份；version/generation使旧后台结果失效。未知原时间保持null，不以标注时间冒充发生时间。

输出一份完整场景，区分当前活动、人物与接续、必要未知。姓名确定度与接话关系分别判断；调侃、拒绝、态度表达也可接续。旧问题未答清不自动成为当前追问；历史约定保留提出者与适用范围。事件E代号在同一会话存储中稳定，不同会话不共用；I/C/T/M等本请求引用不作为跨请求事件标识。

### 最终请求如何组装

purpose 为 `voice_jev_scene`。system 为上方完整指令加一个换行、`JSON Schema：` 和本批 Schema；无历史候选时使用下面基础 Schema，有候选时增加可选的 discard_history 字符串数组，仅允许本次 H 代号（uniqueItems=true，maxItems=本批候选数）。无候选时不允许该字段。序列化使用 `ensure_ascii=False`，保留默认 JSON 分隔空格：

```json
{
  "type": "object",
  "properties": {
    "scene": {
      "type": "string",
      "maxLength": 1000
    }
  },
  "required": [
    "scene"
  ],
  "additionalProperties": false
}
```

user 由以下代码生成（紧凑 JSON）：

```python
        payload = {"now": now_ms, "scene": snapshot["scene"],
            'scene_at': revisions[-1]['at'] if revisions else None,
            "input_output": events, "main_scene": reference,
            "identity_evidence": snapshot.get('identity_evidence', []),
            "recent_context": snapshot.get('recent_context', []),
            "window": {"limit": RECENT_MATERIAL_CHARS, "omitted_events": len(snapshot["material_window"]["archived_input_ids"]),
                       "deferred_events": len(snapshot["material_window"].get("deferred_input_ids", [])),
                       "evidence_limit": 1800, "reference_limit": 800,
                       "omitted_main_blocks": snapshot["material_window"]["omitted_main_scene_blocks"]},
            "people": {code: snapshot["labels"].get(oid, code) for code, oid in snapshot["codes"].items()}}
# 可选history_candidates/history_reference按下文边界追加。
user = json.dumps(compact_jev_input(payload), ensure_ascii=False, separators=(",", ":"))
```

`events` 和 `reference` 来自 `recent_material(snapshot, main_scene)`。此请求同时把相同 JSON 放入 `input_text` 和 `persona_user_text`，统一 user 组装器直接使用 `persona_user_text`，所以实际 user 是完整 JSON，没有第一次 JEV 的“【说话人】/【本轮】”外层。user 明确携带 now、scene_at 和 time_basis；事件时间按同一基准转为相对毫秒，未知时间为 null。request.now 不另追加 system 时间块。scene_at 是整理时间，不是旧内容发生时间；不得原样沿用旧摘要中的相对时间。

### 本次修订的材料边界

JEV2获取更长过程的有限文本窗口，不保证比JEV1收到更多或更新的材料；当前请求不附图片消息，视觉依据只能来自实际载入的事件/片场描述与时间。未提供视觉时间、宿主窗口或初筛结果时不自行补造，描述完成时间与照片/描述依据时间分开理解。

### 当前场景、历史缓存和删除边界

当前scene只写此刻仍有作用的活动和交往关系。内容退出scene不等于永久删除；单纯未解决或本轮未用到，不足以判永久删除。

- 每次成功提交仅将场景摘要、原时间、版本和必要人物映射写入同目录 `.history.jsonl`，不复制原话和完整事件；升级时先迁移仍保留的旧修订，已在升级前被淘汰且未留档的内容无法恢复。
- 历史缓存默认最长5分钟（`JSHI_JEV_HISTORY_MAX_AGE_SECONDS=300`）、摘要正文合计500字符（`JSHI_JEV_HISTORY_MAX_CHARS=500`，含正文标点，不含JSON元数据），并最多保留6条。按整条记录从新到旧保留；到期、超额或单条超过额度会真正从该缓存移除，不截断摘要。读取或写入时执行，无独立定时任务。
- JEV2每次最多看到2条、摘要正文合计200字符以内的历史预览，独立标为history_candidates；不是原话重放，也不是当前在场证据。H1等删除代号只在本请求有效，程序映射原版本，不把内部ID或完整历史都发给模型。
- JEV2可输出discard_history，限本批实际提供的代号。只有结果校验通过且version/generation提交检查通过才删除对应历史缓存及其滚动修订；非法代号、模型失败或过时结果不执行删除。原始业务日志、音频及长期记忆不在删除范围。
- 程序提供 `JEVSceneStore.reference(version, cutoff_ms=...)` 显式读取仍在保留期内的历史，再通过 `JEVSceneWriter.run(..., history_reference=...)` 作为历史参考传入；只读取摘要并保留原时间、不覆盖活动scene、不回放旧发言。人工纠正前的归属、未来版本、人物P映射已变化的引用不允许恢复。
- 本次提供保存、淘汰与显式读取能力；尚未接通自动识别“回到相同环境”并选取历史的入口，也没有新增模型调用。回到同一房间不等于同一任务恢复。

### 校验、提交与失败行为

程序要求 `scene` 是非空字符串且不超过1000字符；discard_history若提供必须为无重复的有效本批H代号数组。解析失败、超限或非法删除引用时保留待处理事件。提交还会核对快照 `version/generation`，防止后台旧结果覆盖运行中的人工纠正或新版本。

提交成功只标记本批实际读取和明确归档的事件。普通超预算事件通过deferred_input_ids留待后续；只有单条主干超长的事件以oversized_single_event原因完整保存到`.archive.jsonl`，不当作已经理解。失败或过时结果不消费事件、不执行删除。人工纠正保留无关场景，不清空整场；历史版本按既有generation边界禁止误恢复。

认证或计费错误使该 writer 实例进入 60 秒冷却；后台异常记录失败并退避，不提交进度。后续调用读取的仍是此前有效结果。按输入截止时间读取情境时，程序避免把利用更晚事件/播放写出的片场提前带给较早输入。
