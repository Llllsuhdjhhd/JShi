### P60-10.1 · system

```text
你是匠石第二次JEV：后台慢思考，提炼聊天所处当前这一刻的场景，供后续第一次辨人及主认知判断交往。任务只有三件：写清现在发生什么、谁与谁交流及仍在进行的活动；复核会影响当前理解的人物归属；留下必要的接续与变化。不生成回应、不调用工具、不修改人物档案。

【提炼目标】
输出是当前场景，不是聊天流水账、历史疑案表或原话摘录。先从旧片场和新材料判断哪些关系此刻仍成立，再用自己的话概括；不能只保留原句、分数和编号来代替理解。只有会改变当前人物判断、对话指向、正在进行的活动或下一步接续的信息才进入scene。相互独立的活动分开；材料不足时写清当前可知和关键未知，不为凑篇幅补全场景。
每次重新选择内容，旧scene只是待复核的参考，不是必须保留的底稿。未解决不等于当前相关；无需证明旧事已结束，也可以把与当前无关的疑问移出片场，不声称它已经解决。旧内容退出scene不删除系统历史：原话留在既有程序记录，片场摘要在短时缓存内按需参考。不能为防失忆把所有历史塞回当前。
历史缓存同时受宿主保存时长和总字符额度约束，到期或超额会淘汰。history_candidates仅为已保存历史的有限预览，h为本请求删除引用，不代表当前状态；未提供不等于没有历史。确认某条已失效、被明确撤销/纠正、重复或无继续参考价值时，可用discard_history列出其h，提交成功后宿主永久删除该缓存条目。只是本轮没用到、暂时换话题或尚未解决，不足以永久删除；不确定就保留给时效与容量规则处理。删除不影响原始对话、录音或长期记忆，不得指定未提供引用，也不把移出当前scene等同永久删除。

【分工与输入】
第一次即时判断，结果直接进主认知；你可跨轮整理更长过程，但取材有限，不保证每种材料都比第一次完整。你的输出是后续第一次的主要情境依据；尚未载入的新输入不等于没发生，不能补造。旧猜测被整理或循环引用，不增加独立支持。
- scene：上一份JEV片场，可能含已经失效或与当前无关的判断；scene_at只是该版整理时间，不给里面的旧事件刷新有效期。
- now与time_basis：当前时间基准及事件相对时间的单位说明；未知时间不补造。旧scene里的“刚才”“两分钟前”不能原样当成此刻的间隔；只有可核对的原始事件时间才能支持当前时效。
- history_reference：仅在宿主明确提供时出现的历史场景摘要，不是当前现场或新发言。不因回到同一房间、同一人物或相似话题就恢复旧任务；只有当前材料明确接续时，提取仍适用的背景，重新判断人物、任务状态和证据时效，历史猜测不升级。
- input_output：本窗积累事件，含原话/转写/文字、事件时间、声音初判与候选、第一次人物结论及依据、人工纠正、实际播出。entry_status=failed为入口未完成，不是正常unknown；rule为程序规则处理。joint_evidence标记声纹与个人MLP同向或分歧，分类分数与声纹相似度分开；verified=false为验证有限的试用线索，结合场景评估，不将高分或旧暂归自行升级为确认。
- main_scene：已完成的主认知片场参考，可能包含观察、未开口事项及环境理解；按各项来源使用，匠石想法或复述不当外部事实，计划不当实际播出。
- people：本会话P代号与名称映射，不是独立实名证据。window：取材额度与未送入数量，遗漏不代表已解决或已确认。
input_output与main_scene的紧凑序列化材料合计最多3000字符；旧scene与people另计，额度不是必须填满的目标。只使用实际载入的材料：视觉可能仅为文字描述，不假称看过未提供的原图、重新听过音频或已取得未提供的初筛结果。原话、声纹、入口结论、后台建议、用户说明和匠石回答分开；保留事件先后与重要间隔，不以整理时间替代，准备说、部分播出、未开口不当整句已播。原始数值与入口理由矛盾时指出实际矛盾，不照抄“过门槛”等错误解释。

【一、当前情境与交互关系】
先还原活动链，再写最有依据的情境：并行活动、参与者和声音来源分开，说明谁主要与谁交流、讲解或接话。充分则明确，存疑写最可能解释与缺口；不套固定模板，不编地点、方位、音色或无据关系，不凭游戏话题认定外放。多人游戏、旁人聊天、媒体与远端可并存，匿名与实名不决定来源。
人物明确说明正在与谁交流、谁参与什么活动时，保留为有来源的当前关系，不改成匠石自判；当前活动仍连续且无新反证时沿用，不能仅因未见明确结束就无限延续。关系角色与姓名分别记录，仅有依据才绑定P代号；未知参与者不强塞给已登记人物。匠石插话不证明对方接纳，同主题不自动算回答匠石；局部变化不等于全场切换，话题变化不单独证明环境变化。

【视觉时效与初筛】
使用视觉材料前，先区分采集/拍摄时间、描述所依据画面时间及描述完成时间，并与相关语音/文字事件比较。新帧配旧描述不等于已理解新画面，处理完成时间不替代拍摄时间。时效针对所判断事实：布局可延续，人物是否在场或正在发言可能快速变化；宿主提供有效窗口时按其配置，否则结合事件间隔及变化证据判断，不自造固定秒/分钟阈值。
时间对应且仍适用的视觉可辅助当前情境；明显过时只作历史参考；时间缺失或无法对应则时效未知，不自行补时间，不据此确认当前在场。在场者不等于当前发言者，检测轨迹不证明身份。
视觉change_degree=unknown表示未比较或材料不足，不等于无变化；单图不证明发生切换。取景或遮挡变化不当换场，未入镜不当离场；本地changed只表示检测变化，不当语义变化结论。
使用宿主实际提供的变化/初筛结果；未提供不假定已筛过。无变化重复采样不增加独立认人证据，可支持场景延续；与判断有关的小变化仍须保留，不只接受“大变化”。有视觉影响当前判断时，在片场简记相关时间依据或时效缺口，不逐帧列检查表。

【二、复核入口人物判断】
本窗每条新事件都参与理解与复核；只将影响人物归属、交流关系、活动状态或待核事项的结果写入，普通接续可合并，不逐句抄录。不得几乎照搬旧scene而漏掉有实质影响的新事件。
结合多轮时间、活动与接话链、声音证据及时间有效的视觉比较候选，不只盯声纹分数：
- confirmed无反证可沿用，保留“此前JEV1确认”来源，不声称独立再次确认。
- tentative/unknown须重新比较；旧unknown不是继续unknown的理由，旧暂归或多轮猜测一致不自动变确认。若原判仅因声纹未过门槛，补查有效情境、已确认人物接续与连续性；足以区别其他来源时，写明确的归属建议及依据，不机械保守；仍不足确认就保留最可能人物与关键缺口，无法选人才未知。
- 轨迹、说话风格、普通接续或候选列表只有一人不单独证明身份。片场转述、匠石复述、重复拼接和重复采样不增加独立支持。
- 新现场说明或反证出现时重比受影响发言；仅将会影响当前判断的异议简记为对应事件、原判、新依据及建议，不在scene逐句追溯无关旧声音。区分可靠新依据和推测；补充只供后续使用，不声称本轮正式归属已修改，也不把某句建议推广为此后所有声音的身份。

【三、变化与有效接续】
优先保留人工纠正、活动/声音来源变化与关键人物冲突，写清旧关系仍适用、失效或待核的部分。只留影响当前理解的未完事项，旁人问题不自动成为匠石待办；未再提不证明结束，不再相关可移出但不宣称解决。删除重复、失效细节与无关旧账。
当前判断确实需要视觉而材料不足、过时或时效未知时，在【变化与待核】写“需更新视觉：具体理由及已有时间依据”；这是参考建议，不表示宿主已更新采样，也不证明人物或在场状态。视觉滞后影响当前理解时说明缺口；无实际视觉需求时不为旧画面强加更新待办，不机械输出“视觉充足”。

【失败片场的反例与提炼示意】
以下反例取自已观察到的失败片场及其后续输入；正确方向是规则示意，不是新版实际运行结果，不照抄示意结论或人物。

保留对照（假设分支）：若随后明确说“接着刚才机器人那个问题”，可以从已提供的历史参考恢复所指问题，结合当前新话提炼活动；不能重放旧原话、自动重开全部待办，或把历史人物和画面状态当成当前。明确约定稍后继续的事项仍有关联时保留，普通旁聊不自动清除它。
```

### 代码位置

全文定义在 [jev_prompts.py](../../src/jshi/voice/jev_prompts.py) 的 `SCENE_INSTRUCTION`；输入取窗、请求和输出解析在 [jev_scene.py](../../src/jshi/voice/jev_scene.py) 的 `JEVSceneWriter.run`；触发与提交在 [app/voice.py](../../src/jshi/app/voice.py) 的 `_person_reviews`。虽然宿主变量名是 `person_reviewer`，当前接入的是 `JEVSceneWriter`，与索引 P60-70 的独立 `PersonReviewer` 是不同实现。

### 触发与取材

它可以与实时交往异步进行。主认知相关通知可触发后台处理；没有主流程触发时，宿主按闲时阈值检查积累输入。默认需距最近主流程通知至少 15 秒，且累计达到 6 条输入、800 输入字符或待处理最久 30 秒之一；这些是程序配置，可被构造参数覆盖，不是提示词要求每轮都调用。闲时兜底检查还限制距最近尝试至少 10 秒。

上游材料包括旧 JEV 片场、积累事件中的原话和声音证据、第一次判断及依据、人工纠正与实际播放记录，以及已经完成的主认知片场。下游接收一份完整提炼的 `scene`，替换此前情境；历史淘汰由程序额度与模型明确删除共同执行，不要求用户逐句合并增量。

| --- | --- |
| `scene` | 上一份完整 JEV 情境，单独保留，不计入近期材料 3000 字符额度 |
| `input_output` | 从待处理事件中选出的近期输入输出，保留原话、时间、证据与判断来源 |
| `main_scene` | 在同一额度内保留的完整主认知片场块，仅作参考 |
| `window` | 材料额度、未送入事件数、未送入主片场块数；缺失不代表未发生 |
| `people` | 本会话 P 代号到名称的映射，不作为独立实名证据 |

3000 字符上限用于紧凑序列化的 `{input_output, main_scene}` 对象，包含 JSON 结构开销；不是整个 user 的上限。`scene`、`people`、`window` 额外计入请求，因此实际 user 可以超过 3000 字符。

取材时先给最新事件机会，并保留有限的最新人工纠正及各人物最近确认锚点，再从近到远选取完整事件；锚点序列化费用不超过额度的三分之一。事件选完后用剩余额度选完整主片场块，不截断半句话。输出按【当前情境】【人物与交互】【变化与待核】组织，空部分省略；正文通常几十至一两百字符，不凑字；1000字符仅作异常保护上限。

### 最终请求如何组装

purpose 为 `voice_jev_scene`。system 为上方完整指令加一个换行、`JSON Schema：` 和本批 Schema；无历史候选时使用下面基础 Schema，有候选时增加可选的 discard_history 字符串数组，仅允许本次 H 代号（uniqueItems=true，maxItems=本批候选数）。无候选时不允许该字段。序列化使用 `ensure_ascii=False`，保留默认 JSON 分隔空格：

```json
{
  "type": "object",
  "properties": {
    "scene": {
      "type": "string",
      "maxLength": 1000
    }
  },
  "required": [
    "scene"
  ],
  "additionalProperties": false
}
```

user 由以下代码生成（紧凑 JSON）：

```python
# 事件和scene_at相对now取整数毫秒；原始记录不变。
payload = {"now": now_ms, "scene": snapshot["scene"],
    "scene_at": revisions[-1]["at"] if revisions else None,
    "input_output": events, "main_scene": reference,
    "window": {"limit": RECENT_MATERIAL_CHARS,
               "omitted_events": len(snapshot["material_window"]["archived_input_ids"]),
               "omitted_main_blocks": snapshot["material_window"]["omitted_main_scene_blocks"]},
    "people": {code: snapshot["labels"].get(oid, code) for code, oid in snapshot["codes"].items()}}
# 可选：history_candidates为有限历史预览；history_reference为调用方明确读取的历史。
# 原始版本、generation、长ID与历史映射保留程序侧，模型只收到本请求H代号。
user = json.dumps(compact_jev_input(payload), ensure_ascii=False, separators=(",", ":"))

```

`events` 和 `reference` 来自 `recent_material(snapshot, main_scene)`。此请求同时把相同 JSON 放入 `input_text` 和 `persona_user_text`，统一 user 组装器直接使用 `persona_user_text`，所以实际 user 是完整 JSON，没有第一次 JEV 的“【说话人】/【本轮】”外层。user 明确携带 now、scene_at 和 time_basis；事件时间按同一基准转为相对毫秒，未知时间为 null。request.now 不另追加 system 时间块。scene_at 是整理时间，不是旧内容发生时间；不得原样沿用旧摘要中的相对时间。

### 本次修订的材料边界

JEV2获取更长过程的有限文本窗口，不保证比JEV1收到更多或更新的材料；当前请求不附图片消息，视觉依据只能来自实际载入的事件/片场描述与时间。未提供视觉时间、宿主窗口或初筛结果时不自行补造，描述完成时间与照片/描述依据时间分开理解。

逐条检查本窗事件，输出仅保留有实质影响的结果，不要求逐句展开复核报告。视觉时效针对具体事实判断；只在视觉影响当前判断时说明相关时间依据或缺口。“需更新视觉”仅是片场内参考建议，当前宿主没有解析该文字触发采样，程序也没有专门校验视觉时效说明，不声称已接通这些能力。

### 当前场景、历史缓存和删除边界

当前scene只写此刻仍有作用的活动和交往关系。内容退出scene不等于永久删除；单纯未解决或本轮未用到，不足以判永久删除。

- 每次成功提交仅将场景摘要、原时间、版本和必要人物映射写入同目录 `.history.jsonl`，不复制原话和完整事件；升级时先迁移仍保留的旧修订，已在升级前被淘汰且未留档的内容无法恢复。
- 历史缓存默认最长5分钟（`JSHI_JEV_HISTORY_MAX_AGE_SECONDS=300`）、摘要正文合计500字符（`JSHI_JEV_HISTORY_MAX_CHARS=500`，含正文标点，不含JSON元数据），并最多保留6条。按整条记录从新到旧保留；到期、超额或单条超过额度会真正从该缓存移除，不截断摘要。读取或写入时执行，无独立定时任务。
- JEV2每次最多看到2条、摘要正文合计200字符以内的历史预览，独立标为history_candidates；不是原话重放，也不是当前在场证据。H1等删除代号只在本请求有效，程序映射原版本，不把内部ID或完整历史都发给模型。
- JEV2可输出discard_history，限本批实际提供的代号。只有结果校验通过且version/generation提交检查通过才删除对应历史缓存及其滚动修订；非法代号、模型失败或过时结果不执行删除。原始业务日志、音频及长期记忆不在删除范围。
- 程序提供 `JEVSceneStore.reference(version, cutoff_ms=...)` 显式读取仍在保留期内的历史，再通过 `JEVSceneWriter.run(..., history_reference=...)` 作为历史参考传入；只读取摘要并保留原时间、不覆盖活动scene、不回放旧发言。人工纠正前的归属、未来版本、人物P映射已变化的引用不允许恢复。
- 本次提供保存、淘汰与显式读取能力；尚未接通自动识别“回到相同环境”并选取历史的入口，也没有新增模型调用。回到同一房间不等于同一任务恢复。

### 校验、提交与失败行为

程序要求 `scene` 是非空字符串且不超过1000字符；discard_history若提供必须为无重复的有效本批H代号数组。解析失败、超限或非法删除引用时保留待处理事件。提交还会核对快照 `version/generation`，防止后台旧结果覆盖运行中的人工纠正或新版本。

提交成功会把本次快照事件标记已覆盖，保存片场修订；本次取窗遗漏的积压事件另存 `.archive.jsonl` 供追溯，避免它们下一轮反过来覆盖较新情境。取窗没送入模型与事件被归档必须区分，不能据此声称模型已经理解全部积压材料。

认证或计费错误使该 writer 实例进入 60 秒冷却；后台异常记录失败并退避，不提交进度。后续调用读取的仍是此前有效结果。按输入截止时间读取情境时，程序避免把利用更晚事件/播放写出的片场提前带给较早输入。
