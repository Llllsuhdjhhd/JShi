## 1. 用途与流程位置（说明，不发送）

用于单条兼容入口判断插话与播放接续；“单条”是接口名称，实际原话可先聚合。流程：`有效转写 → 聚合/停止快捷规则 → 需要时单条JEV → 宿主处理播放与接话`。正常批量入口仍走P10-30，不额外调用本模型。

## 2. 作用与目的（说明，不发送）

结合本批原话、当时主认知片场、近期接续、已有L3文字肖像与播放事实，判断是否向匠石接话，给出忽略、续播、停止、回应或澄清。只给处理建议，不生成回答。

**语音调用条件：**当前Qwen路径：fixed切段策略默认500ms静音、最长3.5秒；每窗仍只发一次千问batch，Smart Turn CPU整句检测在独立线程与转写并行。默认阈值0.5，complete或unknown即组装交JEV1；明确incomplete保留同一可靠声音组的原片段和音频上下文，下次只转写新音频、联合判断，原话不跨人拼接。没有整句结果时最多从并行任务启动等600ms，超时放行给JEV1；未完且静音无新片段2秒、累计12秒音频、32段或采集结束时也释放，不丢输入。未归属、重叠及长间隔不强接续。JEV1仍可keep并保留原话，普通collection_complete仍为null，不把工程分段当成语义说完；没有恢复统一1秒文字等待。固定system/user模板及输出Schema不变；动态收尾状态和合批边界改变，当前版本真实调用例子待补充，原有真实例子保留其历史版本边界。

**实际传入的背景：**

安排方式：system只放判断规则；user的单条输入JSON中，delivery.main_scene放当时主认知片场，delivery.person_portraits放L3肖像，delivery.scene放近期接续，并附播放、聚合与关注材料。不再发送delivery.jev_scene。顶层now/time_basis提供时间依据，不增加模型调用。

### P10-70.1 · system

```text
你是匠石单条兼容JEV：根据原话、播放状态和上下文做语义判断，选择action。不生成回答、不调用工具、不改身份或档案；程序不以停止词匹配代替判断。

【输入】
utterance是原话，speaker初判不证明身份。
delivery内：state为当前状态；spoken已播、pending待播；main_scene为当时主认知片场，scene为近期接续。待播、想法或准备说不当已发生。
delivery.person_portraits是已加载的历史文字肖像，只助理解交往，不证明声音归属或本轮意图；candidate_only仅属候选，无资料照常判断。
delivery.collection.expression_complete仅示停顿：false未观察到足够停顿，true不保证说完，null未知。delivery.attention只影响关注，不证明身份；按time_basis读时间，T只示连续性。

【判断】
结合原话、主认知片场、实际播放和近期接续判定对谁说；具体新反证只局部修正旧关系，缺材料不推翻。自然接话有充分依据即可respond，不要求点名或任务，有问号也不证明在问匠石。
仅在向匠石交往且转写明确缺损或指代不明、必须澄清才能继续时clarify；无音频不声称听不清。
旁聊、噪声、附和或仅复述回应无新接话：播放中resume，否则ignore。语义未完保留接续；不单凭collection判定说完或未完，不凭分批阈值抢话。stop只用于明确停止，声音突出、换人或高关注权重不构成打断。
姓名未知、匿名访客、声音待定都不是忽略或拒绝进入主流程的理由；问候、自介、纠正或询问能否听见均按内容判断，不先要求登记声纹。身份不明不把附和归给原说话人。

【输出】
只输出JSON：{"action":"ignore|resume|stop|respond|clarify","reason":"简短依据","claimed_name":""}。claimed_name只取本批明确自介，不填提及他人的姓名，没有则空串。不输出思考过程。
```

<summary>代码位置、实际组包、校验及运行边界</summary>

### 代码位置

正文定义：[jev_prompts.py](../../src/jshi/voice/jev_prompts.py) · `SINGLE_INSTRUCTION`；调用与解析：[voice/jev.py](../../src/jshi/voice/jev.py) · `decide`。正常语音宿主走批量JEV1；仅判断器不支持批量接口时才调用此兼容入口。明确停止同样由模型按上下文判断，不用停止词匹配。不能把所有批量调用都当作先额外请求一次单条模型。

### 程序快捷规则

不再按停止词、短碎片或附和词匹配决定停止。无有效模型时保守维持当前播放；兼容入口仍对重叠和空转写做保守处理。普通转写由模型按原话、播放与上下文决定action。

### 动态user与输出

实际输入包含utterance、speaker、delivery和now，经compact_jev_input生成模型侧副本，再以ensure_ascii=False及紧凑JSON序列化。delivery只保留state、spoken、pending、names_for_jiangshi、attention、scene、main_scene、person_portraits、collection；不把完整信封重复送入单条判断。原始程序记录不改写。

请求purpose为voice_jev，system_extra为上方全文，不另追加动态JSON Schema。默认文字适配器将JSON包在user外层：

```text
【说话人】对方
【本轮】
对方：<单条输入JSON>
```

尖括号只是动态材料说明，不是真实发送文本。当前单条入口也调用compact_jev_input：移除内部ID，轨迹/媒体映射为请求内短代号；有效now存在时，时间相对now取整为毫秒并在顶层time_basis注明，音频偏移/间隔仅取整。无now不补造相对时间。

模型按提示输出action、reason、claimed_name。action只允许ignore/resume/stop/respond/clarify；程序验证action，reason转为字符串并截取前200字符。claimed_name不采用模型填写值，而使用 `explicit_name(text)` 从本条明确自我介绍提取的结果，防止模型把提及他人的名字写入身份关联。

### 失败行为与判断边界

明确停止在本地处理，包含“别说了别说了”“先先不要说了不要说了”等重复表达；引用他人的停止话语不按直接命令处理。完整语音转写命中规则后绕过声纹、合批和模型。停止按钮直接清空浏览器正在播放及排队的音频，不保留为暂停；服务端同时清理待处理输入和待播回应，旧轮次不能恢复播放。未识别完成的语音仍受ASR交付速度影响。

解析、调用或action校验失败统一返回resume，reason为JEV不可用并保持播放的说明；这不证明当时确有播放。输出没有严格Schema字段白名单验证。程序规则与模型语义判断需区分，规则处理没有模型实际提示记录。

播放状态不证明人物身份，关注权重只影响关注，不证明姓名；换人本身不要求打断。匿名人物可以正常交往。这个兼容入口仍判断对话指向，而现代批量入口把常规对话指向交给主认知，两者职责不能混用。

研究与聚合参数依据见[语音轮替与JEV聚合](../语音轮替与JEV聚合.md)。当前仅合并已到达材料，64段上限用于限制单批处理规模，不表示语义完整。
