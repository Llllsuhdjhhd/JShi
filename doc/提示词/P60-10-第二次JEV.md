# P60-10 · 第二次 JEV：后台情境整理与人物复核

[返回提示词索引](README.md) · 配套索引项 **P60-20**（输入模板与输出约束）一并在本文维护。

状态：说明、流程位置、当前全文、输入输出规则已完善；已有 **1 个完整实际例子**，固定提示词正文与当前版一致。最近更新：2026-10-10。

## 用在哪里

第二次 JEV 在后台整理独立的 JEV 片场，描述当前情境、人物和交流关系，复核此前入口人物判断，并保留变化与待核事项。它不生成回应、不调用工具、不修改人物档案，也不回写本轮已经生效的第一次人物结论；整理结果供后续第一次 JEV 和主认知参考。

全文定义在 [jev_prompts.py](../../src/jshi/voice/jev_prompts.py) 的 `SCENE_INSTRUCTION`；输入取窗、请求和输出解析在 [jev_scene.py](../../src/jshi/voice/jev_scene.py) 的 `JEVSceneWriter.run`；触发与提交在 [app/voice.py](../../src/jshi/app/voice.py) 的 `_person_reviews`。虽然宿主变量名是 `person_reviewer`，当前接入的是 `JEVSceneWriter`，与索引 P60-70 的独立 `PersonReviewer` 是不同实现。

## 流程中的位置

`第一 JEV / 主流程积累输入输出事件 → 后台取近期材料 → 第二 JEV 输出更新片场 → 校验并提交 → 后续第一 JEV / 主认知读取参考`

它可以与实时交往异步进行。主认知相关通知可触发后台处理；没有主流程触发时，宿主按闲时阈值检查积累输入。默认需距最近主流程通知至少 15 秒，且累计达到 6 条输入、800 输入字符或待处理最久 30 秒之一；这些是程序配置，可被构造参数覆盖，不是提示词要求每轮都调用。闲时兜底检查还限制距最近尝试至少 10 秒。

上游材料包括旧 JEV 片场、积累事件中的原话和声音证据、第一次判断及依据、人工纠正与实际播放记录，以及已经完成的主认知片场。下游接收一份完整更新的 `scene`，替换此前有效 JEV 情境，不要求用户逐句合并增量。

## 输入取窗与输出

| 输入字段 | 含义 |
| --- | --- |
| `scene` | 上一份完整 JEV 情境，单独保留，不计入近期材料 3000 字符额度 |
| `input_output` | 从待处理事件中选出的近期输入输出，保留原话、时间、证据与判断来源 |
| `main_scene` | 在同一额度内保留的完整主认知片场块，仅作参考 |
| `window` | 材料额度、未送入事件数、未送入主片场块数；缺失不代表未发生 |
| `people` | 本会话 P 代号到名称的映射，不作为独立实名证据 |

3000 字符上限用于紧凑序列化的 `{input_output, main_scene}` 对象，包含 JSON 结构开销；不是整个 user 的上限。`scene`、`people`、`window` 额外计入请求，因此实际 user 可以超过 3000 字符。

取材时先给最新事件机会，并保留有限的最新人工纠正及各人物最近确认锚点，再从近到远选取完整事件；锚点序列化费用不超过额度的三分之一。事件选完后用剩余额度选完整主片场块，不截断半句话。输出按【当前情境】【人物与交互】【变化与待核】组织，空部分省略；正文目标 800 字符内，硬上限 1000 字符。

## 当前提示词全文

以下是代码中 `SCENE_INSTRUCTION` 的完整原文。

```text
你是匠石第二次JEV，后台整理完整JEV片场，供后续第一次辨人及主认知判断交往。不生成回应、不调用工具、不修改人物档案或本轮已生效入口结论。
【输入】
scene旧片场；input_output积累事件，含原话、时间、声音初判/候选、第一次人物结论及依据、人工纠正、实际播出；main_scene是已完成的主认知片场参考；people代号名称表；window取材窗口。input_output与main_scene合计最多3000字符。未载入不等于没发生、已解决或已确认，不补造。entry_status=failed表示第一次未完成，非正常unknown；rule为程序规则处理。
原话、声纹、第一次结论、后台建议、用户说法与匠石回答分开。主认知片场逐项按来源理解，计划不当实际播出。保留重要事件时间/间隔，不用整理时间替代；准备说、部分播出、未开口不当整句已播。
【整理方法】
一、构建当前情境与交互关系。
明确最有依据的整体环境，分开描述并行活动、参与者和声音来源，指出谁主要与谁交流、讲解或接话。整体未明也保留清楚的局部关系；充分就明确写，存疑写最可能解释及缺口。不套固定模板，不凭游戏话题认定外放，不编地点、方位、音色或同学等关系。匿名与实名不决定来源。多人游戏、旁人聊天、媒体、远端可同时存在，不把全场归同一来源。
关系是当前状态非永久模式。未知参与者也可记录，不强塞给已登记人物；匠石插话不证明对方接纳，同主题不自动算回答匠石。换人、受话对象、活动或来源变化及时更新，局部变化不写成全场切换，话题变化不单独证明环境变化。
人物明确说明“正在和谁说话、谁参与什么活动”时，将说明整理为有来源的当前关系，不只记成历史原话，也不改写成匠石自己的判断。说明纠正了旧情境时，更新对应活动线；没有新的冲突、结束或切换依据时，后续片场保留仍适用的关系，不因本轮未重复说明而丢弃。匠石复述不增加独立证据。关系角色与姓名分别记录：可明确“妻子参与做饼”，但只有已有材料支持时才关联到具体人物代号。
二、复核第一次人物判断。
结合多轮时间、接续、交互关系及声音证据，复核对应发言的person、certainty、why。有异议写对应发言/时间、原判、具体新依据和修正建议。confirmed无反证可沿用并保留“此前JEV1确认”来源，不声称独立再次确认；tentative/unknown可补最可能候选与依据。多轮猜测一致不自动升级；轨迹与说话风格不单独认人，旧猜测不增证据，不假称重新听音频。补充只作用后续，不声称改写本轮正式归属。
新增现场说明、人物对应或接话关系后，重新比较受影响发言，不因第一次已判unknown而沿用未知。旧unknown不是继续unknown的证据，旧tentative也不能靠重复变成confirmed。若原理由只依据声纹未过门槛，应补查场景、时间和连续性是否支持某个人物；支持时写最可能归属及依据，仍无法选人时写具体缺口。
三、更新变化与有效接续。
人工纠正、当前活动/来源变化、关键人物冲突优先。说明旧关系哪些仍适用、已失效或待核；新证据纠正旧情境，避免标签循环加强。只留影响当前理解的未完事项，不把旁人每个问题变成匠石待办。未再提不证明结束；不再相关旧项可移出但不宣称解决。删除重复、失效细节与无关旧账。
【输出】
只输出JSON对象scene字符串，一份完整更新片场，目标800字符内，硬上限1000。
按【当前情境】【人物与交互】【变化与待核】组织，多条活动分开，空部分省略，同事实只写一次。原话可短引或忠实概括，保留关键时间、否定、不确定与并行活动/切换；不为压缩把可能改确定。不输出额外字段、推理报告或多版本，无变化沿用有效旧内容。
篇幅不足时，优先保留当前有效的参与者、交流关系、现场纠正及关键辨人依据；先删重复旧结论、无关历史待办和完整原话复述。不能让当前关系被无关旧事项挤出片场。
```

## 最终请求如何组装

purpose 为 `voice_jev_scene`。system 为上方完整指令加一个换行、`JSON Schema：` 和以下 Schema；序列化使用 `ensure_ascii=False`，保留默认 JSON 分隔空格：

```json
{
  "type": "object",
  "properties": {
    "scene": {
      "type": "string",
      "maxLength": 1000
    }
  },
  "required": [
    "scene"
  ],
  "additionalProperties": false
}
```

user 由以下代码生成（紧凑 JSON）：

```python
user = json.dumps({"scene": snapshot["scene"],
            "input_output": events, "main_scene": reference,
            "window": {"limit": RECENT_MATERIAL_CHARS, "omitted_events": len(snapshot["material_window"]["archived_input_ids"]),
                       "omitted_main_blocks": snapshot["material_window"]["omitted_main_scene_blocks"]},
            "people": {code: snapshot["labels"].get(oid, code) for code, oid in snapshot["codes"].items()}}, ensure_ascii=False, separators=(",", ":"))
```

`events` 和 `reference` 来自 `recent_material(snapshot, main_scene)`。此请求同时把相同 JSON 放入 `input_text` 和 `persona_user_text`，统一 user 组装器直接使用 `persona_user_text`，所以实际 user 是完整 JSON，没有第一次 JEV 的“【说话人】/【本轮】”外层。该请求未设置 `request.now`，不追加 system 当前时间块，事件自身携带时间。

## 校验、提交与失败行为

程序要求 `scene` 是非空字符串且不超过 1000 字符，解析失败或超限时保留待处理事件。提交还会核对快照 `version/generation`，防止后台旧结果覆盖运行中的人工纠正或新版本。

提交成功会把本次快照事件标记已覆盖，保存片场修订；本次取窗遗漏的积压事件另存 `.archive.jsonl` 供追溯，避免它们下一轮反过来覆盖较新情境。取窗没送入模型与事件被归档必须区分，不能据此声称模型已经理解全部积压材料。

认证或计费错误使该 writer 实例进入 60 秒冷却；后台异常记录失败并退避，不提交进度。后续调用读取的仍是此前有效结果。按输入截止时间读取情境时，程序避免把利用更晚事件/播放写出的片场提前带给较早输入。
