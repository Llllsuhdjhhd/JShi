当前Qwen路径：fixed切段策略默认500ms静音、最长3.5秒；每窗仍只发一次千问batch，Smart Turn CPU整句检测在独立线程与转写并行。默认阈值0.5，complete或unknown即组装交JEV1；明确incomplete保留同一可靠声音组的原片段和音频上下文，下次只转写新音频、联合判断，原话不跨人拼接。没有整句结果时最多从并行任务启动等600ms，超时放行给JEV1；未完且静音无新片段2秒、累计12秒音频、32段或采集结束时也释放，不丢输入。未归属、重叠及长间隔不强接续。JEV1仍可keep并保留原话，普通collection_complete仍为null，不把工程分段当成语义说完；没有恢复统一1秒文字等待。

麦克风音频先进内存再转给识别，录音存档由后台线程批量写盘，收音不再等磁盘；收音比实际时间慢3秒以上时页面会提示。连续说话时先把转写文字送到页面，声纹排名、训练预选和个人声音模型结果随后补到同一行；待处理队列满时等待，不丢已识别的句子。入口判断默认等待5秒，超时则本轮不开口并提示；上一次判断超时仍在进行时，下一批另用一个线程开始判断，不排在它后面。修改后重启Windows匠石服务生效，WSL千问无需重启。

适用于当前这台Windows电脑、主体`stone`。日常推荐启动「语音＋图像」页面，使用WSL千问批量转写、本地播报；原云端识别和播报继续可选。

## 1. 日常启动：语音＋图像＋本地千问

需要两个PowerShell终端：一个运行WSL转写服务，一个运行Windows对话服务。两者保持运行。

### 终端一：启动千问转写

```powershell
cd C:\Users\Lenovo\Desktop\project\JShi
wsl -d Ubuntu -- bash /mnt/c/Users/Lenovo/Desktop/project/JShi/tools/start_qwen_batch_wsl.sh
```

看到`Qwen batch service ready`后再继续。模型加载和编译需要等待，终端暂时没有新日志不代表已就绪。如果批量服务已运行，本步骤跳过，不要重复加载模型。

这个服务在WSL中使用GPU，接口端口为`8000`。当前项目需要原生batch服务，不能用旧的`/home/lenovo/qwen3-asr/start_server.sh`代替；旧脚本启动的是不含项目批量接口的标准服务。

不确定是否已启动，可在另一个PowerShell查看：

```powershell
$qwenModels = Invoke-RestMethod http://127.0.0.1:8000/v1/models
$qwenModels.data | Select-Object id, capabilities
```

应返回模型名称，且`capabilities`包含`audio_batch=True`。只返回普通模型列表、没有此能力时，需要换用上述项目脚本。

### 终端二：启动stone的语音与图像页面

```powershell
cd C:\Users\Lenovo\Desktop\project\JShi
.\jshi.cmd vision stone --asr qwen --tts local --port 8765
```

然后打开：<http://127.0.0.1:8765/>。

- 点击顶部「开始对话」开启语音；麦克风在「设置与调试」中选择。
- 点击「开始视频」开启摄像头观察；开启视频时也会确保语音已连接。
- 点击底部「文字」展开输入框，可选择人物、输入文字，并使用「图片」按钮。
- 浏览器请求麦克风、摄像头权限时，按需要允许。

`stone`是匠石的主体ID，不是当前发言人的姓名或声纹编号。上面这条完整命令同时保留语音和视觉，不会因为改用千问ASR就关闭图像入口。

## 2. 第一次使用：准备Windows依赖和模型

本机已准备好时不用重复执行。首次部署或提示缺少依赖、音色、声纹、VAD模型时，在运行项目的同一Python环境执行：

```powershell
cd C:\Users\Lenovo\Desktop\project\JShi
python -m pip install -e ".[voice-local,voice-turn,vision]"
.\jshi.cmd voice-setup --tts --vad --diarize --turn --semantic-turn
```

`--turn`准备Smart Turn v3.2 CPU模型及其校验，`--tts`准备本地播报音色，`--vad`准备Silero端点模型，`--diarize`准备多人分段及兼容原CPU链路的资源。模型默认保存在项目`.jshi/voice_models/`。千问运行时不加载SenseVoice或Zipformer作为其前置ASR。

如果现有`.env`选择了`JSHI_VISION_DETECTOR=yolo`，还需要对应视觉依赖及权重：

```powershell
python -m pip install -e ".[vision-yolo]"
```

视觉理解沿用项目已有的视觉/全局模型配置，需要可接收图片的模型和相应连接。千问Qwen3-ASR只负责语音转文字，不负责看图。

## 3. 参数与模型切换

| 参数 | 含义 | 可选值或默认值 |
|---|---|---|
| `stone` | 主体ID，放在`vision`或`voice.cmd`后面 | `vision`必须明确提供；`voice`省略时进入既有主体选择逻辑 |
| `--asr` | 语音转文字模型 | `qwen`、`local`、`online`、`deepgram` |
| `--tts` | 回应文字转语音 | `local`、`online` |
| `--port` | Windows网页服务端口 | 默认`8765`；与千问服务的`8000`不同 |
| `--help` | 查看当前命令帮助 | 不启动服务 |

`vision`命令自身的默认值是`--asr local --tts online`。日常启动建议像第1节一样明确写出两个参数，避免与`.env`里想选的组合不同。

下面每条命令都保留图像功能。先结束旧Windows对话服务，再选一条执行，不要同时占用8765端口。

| 组合 | Windows启动命令 |
|---|---|
| 本地千问识别＋本地播报 | `.\jshi.cmd vision stone --asr qwen --tts local` |
| 本地千问识别＋火山播报 | `.\jshi.cmd vision stone --asr qwen --tts online` |
| 原CPU识别＋本地播报 | `.\jshi.cmd vision stone --asr local --tts local` |
| 火山识别＋本地播报 | `.\jshi.cmd vision stone --asr online --tts local` |
| Deepgram识别＋本地播报 | `.\jshi.cmd vision stone --asr deepgram --tts local` |

`qwen`需要第1节的WSL服务；其他ASR不依赖该服务。火山识别或火山播报需要`.env`里的`JSHI_VOICE_API_KEY`；Deepgram识别需要`JSHI_DEEPGRAM_API_KEY`。识别和播报独立选择，不修改主认知模型。

页面的「语音识别」下拉框可以选择当前已加载、凭据已配置的后端；结束当前对话后再切换。CPU本地与Qwen按启动参数加载，两者互换需要重启Windows对话服务。不要只改页面下拉框却不加载对应模型。

查看帮助：

```powershell
.\jshi.cmd vision --help
.\voice.cmd --help
```

## 4. 如果继续使用voice.cmd

下面是语音启动入口：

```powershell
.\voice.cmd stone --asr qwen --tts local --port 8765
```

它只有在`.env`启用视觉时才会加载图像功能：

```dotenv
JSHI_VISION_ENABLED=true
```

修改后重启Windows服务并刷新页面。想直接使用语音＋图像，优先使用第1节的`jshi.cmd vision stone ...`，不必额外设置此开关。

`voice.cmd`没有显式`--asr/--tts`时读取`.env`，例如：

```dotenv
JSHI_VOICE_ASR=qwen
JSHI_VOICE_TTS=local
JSHI_VISION_ENABLED=true
JSHI_QWEN_ASR_URL=http://127.0.0.1:8000/v1
JSHI_QWEN_ASR_BATCH_SIZE=8
```

只修改这些字段，不用覆盖整份`.env`或删除已有模型连接。

## 5. 检查、停止与重启

检查当前网页服务是否加载图像：

```powershell
Invoke-RestMethod http://127.0.0.1:8765/status | Select-Object asr, vision_available
```

预期为`asr=qwen`、`vision_available=True`。

### 停止Windows对话服务

先在页面结束对话，再到运行`jshi.cmd`或`voice.cmd`的Windows终端按`Ctrl+C`。这不会停止WSL中的千问服务。只修改网页、模型选择或视觉启用配置时，通常只需重启Windows服务。

### 只关闭千问服务，保留WSL

如果千问运行在可见终端，在该终端按`Ctrl+C`即可。如果它在后台运行，或原终端已找不到，在Windows PowerShell执行：

```powershell
wsl -d Ubuntu -- pkill -TERM -f '[j]shi.voice.qwen_batch_server'
```

这条命令停止项目的千问批量转写服务，释放其占用的GPU资源，不关闭Ubuntu，也不删除模型。命令没有输出通常是正常现象；如果服务本来没运行，可能返回非零退出码。需要再次识别时，按第1节重新启动千问服务。

### 关闭整个WSL

先保存WSL中其他正在进行的工作，然后在Windows PowerShell执行：

```powershell
wsl --shutdown
```

这会关闭所有正在运行的WSL发行版和其中的进程，千问服务也会停止。Windows对话网页服务不会因此自动退出，但无法再使用WSL千问转写；它仍需在自己的终端用`Ctrl+C`停止。关闭WSL不会卸载Ubuntu或删除模型文件。

如果只想关闭Ubuntu，保留其他WSL发行版：

```powershell
wsl --terminate Ubuntu
```

查看发行版状态：

```powershell
wsl --list --verbose
```

完全退出的建议顺序：页面结束对话 → Windows对话服务按`Ctrl+C` → 保存WSL内的工作 → `wsl --shutdown`。如果直接关闭整个WSL，就不必再单独执行关闭千问的命令。

### 常见问题

| 现象 | 检查与处理 |
|---|---|
| 没有「开始视频」「图片」 | 查看`vision_available`；用第1节的`vision stone`命令重启并刷新页面 |
| 提示Qwen连接失败 | 确认WSL批量服务已就绪，检查`8000/v1/models` |
| 提示不支持批转写 | 启动了旧标准服务，改用`tools/start_qwen_batch_wsl.sh` |
| 提示8765端口被占用 | 先退出旧Windows服务；或增加`--port 8766`并打开8766地址 |
| 提示8000端口被占用或重复加载模型 | 先检查已有千问服务，不要另起第二份模型 |
| 提示模型或本地音色未准备 | 在正确Python环境执行第2节的准备命令 |
| 页面能开，但没有声音或画面 | 检查浏览器设备权限、页面麦克风选择，以及系统摄像头是否可用 |

## 6. 转写耗时实测

2026-10-21使用当前本机WSL批量服务、官方公开音频，每组连续测3次。模型已热启动，重复样例可能受缓存影响。

| 输入 | 转写接口往返中位数 | 三次范围 |
|---|---:|---:|
| 单段中文，约4.2秒音频 | 0.171秒 | 0.156～0.270秒 |
| 2段batch，约4.2＋5秒 | 0.306秒 | 0.285～0.512秒 |
| 4段batch，每段约4.2～5秒 | 0.319秒 | 0.310～0.357秒 |

这是从Windows发出转写请求到WSL返回结果的时间，包含服务端准备、可能的排队、推理和HTTP往返；不含采集、VAD停顿等待、声纹分析、JEV、主认知及播报。当前服务没有单独记录纯GPU执行时间，不能把这张表称为纯模型/GPU耗时，也不能保证真实家庭录音具有相同延迟。

详细测量记录：`work/qwen-asr-latency-20261021.json`。批处理方式是同一处理窗一次提交，默认最多8段，超限小批依次处理；不足8段直接提交，不额外等待凑批。

## 8. 切段与整句策略切换

模型原理、时序及接续边界详见《[整句判断说明](整句判断说明.md)》。

当前`.env`已设置500ms/3.5秒与Smart Turn。可分别选择策略：

```dotenv
JSHI_VOICE_SEGMENT_STRATEGY=fixed
JSHI_VOICE_END_WINDOW_MS=500
JSHI_VOICE_MAX_WINDOW_MS=3500
JSHI_VOICE_TURN_STRATEGY=smart_turn
JSHI_VOICE_TURN_THRESHOLD=0.5
JSHI_VOICE_TURN_TIMEOUT_MS=600
JSHI_VOICE_TURN_MAX_HOLD_MS=2000
JSHI_VOICE_SEMANTIC_TURN=namo
JSHI_VOICE_SEMANTIC_THRESHOLD=0.5
JSHI_VOICE_SEMANTIC_TIMEOUT_MS=200
```

切段`fixed`按配置，`patient`至少1000ms静音，均使用配置的最长窗；整句`smart_turn`使用本机模型，`eager`只关闭声音整句模型；语义开启时仍会做文字判断，不宣称句子完整。模型缺失时明确报准备错误，不偷偷切换。策略接口还可接文本或组合判断，目前文本语义使用Namo；TurnSense不属于文本模型，未接入。

重启Windows服务并刷新网页生效；`/status`的`speech_policies`显示设置，scope为Qwen本地链路。火山/Deepgram仍走自身流式切段，CPU旧链路保留；不声称这些后端已应用本地3.5秒窗口或Smart Turn。页面先显示转写预览，明确未完时提示等待接续，放行后显示原片段与人物详情。`voice_latency.jsonl`记录整句概率、并行计算耗时、转写后额外等待及接续释放原因。

关闭文本语义：在`.env`设`JSHI_VOICE_SEMANTIC_TURN=off`后重启Windows服务。关闭声音整句：设`JSHI_VOICE_TURN_STRATEGY=eager`。两个开关独立；都关闭时已有材料直接交JEV。启用Namo但文件缺失时，先执行`jshi voice-setup --semantic-turn`。
