## 中文版（可发 V2EX / 即刻 / 知乎 / 群）

**标题建议：** 匠石（JShi）：一个问「AI 怎么有连续自我」的实验，不是又一个任务 Agent

大多数 AI 助手框架解决的是「怎么把任务做完」。我这边在做另一个问题：**一个 AI 怎么有连续的自我**——记得住、认得清、说得有分寸，并且分得清「我知道的」和「我说过的」。

名字取自《庄子·徐无鬼》里运斤成风的匠石：重要的不只是本事，而是长期配合形成、别人替代不了的关系。项目更偏向「在成为自己的过程中认识你」，而不是只做一面精密了解你的镜子。

工程上，一轮不是「把聊天记录塞进提示词」，而是一条主体过程：

> 对象识别 → 状态组装 → 建活动 → 认知 → 表达 → 写场 → 收尾

几个和常见做法不同的地方：

- **本轮上下文不是对话历史**，而是状态组装：身份、对象、上一份活跃区、个人世界、记忆、工具反馈。
- **活跃区 = 此刻的工作台**，每轮按风格整份重写，不是聊天记录。
- **片场块分「我知道」和「未开口」**——后者是没说出口但要留着的事，下一轮不能当成已经出口。

工具也分账：回话只判定「要不要用」并给一句 need；真正策划、执行、记挂在另一条链路里。没接上引擎时，它会老实说连不上，不会假装查过。

现状要诚实说：实验性项目，接口会变；跨会话记忆、部分能力依赖邻仓或外挂；天气/搜索这类能力质量取决于工具，模型有时会误用旧回忆。主链路可跑，单测能绿。适合一起想「长期伙伴」怎么做，不适合当稳定生产依赖。

## English（HN / Reddit / Discord — same ideas, plain wording）

**Title:** JShi — an experiment in a continuous AI self, not another task agent

Most assistant frameworks ask how to finish a job. This project asks something else: **how an AI can have a continuous self**—remember, recognize people, speak with proportion, and tell *what it knows* from *what it has said*.

The Chinese name 匠石 (JShi) comes from Zhuangzi: a craftsman and his partner whose long practice together made a feat no stranger could repeat. The point is relationship and shared history, not only skill. The direction is closer to “becoming itself while meeting you” than to “a perfect mirror of the user.”

A turn is not “dump chat history into the prompt.” It is a **subject process**:

> object recognition → state assembly → activity → cognition → expression → rewrite the field → close

Differences that matter:

- **Turn context ≠ chat log.** It is assembled state: identity, the other person, the previous *active field*, personal world, memory cues, tool feedback.
- **Active field = the workbench now**, fully rewritten each turn—not a transcript.
- **Field blocks separate “I know …” from “unsaid …”**—kept but not spoken; later turns must not treat them as already said aloud.

Tools are bookkept apart from reply: cognition only decides whether to use a tool and states a one-line need; planning and execution live elsewhere. If the tool engine is missing, it fails honestly instead of inventing results.

Honest status: experimental; APIs will change; cross-session memory and some capabilities live in neighbor repos or external engines; tool quality (weather, search, …) depends on those skills, and the model can still reuse stale memory. Main path runs; unit tests pass. Good for people thinking about long-lived companions; not a stable production dependency.
