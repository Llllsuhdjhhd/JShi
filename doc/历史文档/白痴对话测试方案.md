# 《白痴》对话测试方案

## 1. 目的

用陀思妥耶夫斯基《白痴》中的**对话与由对话可直接落实的人格材料**，检验匠石各模块的基本功能，并观察在给定书本状态下系统对当前局面的应对输出。

匠石对应书中主人公**梅什金公爵**（Лев Николаевич Мышкин）。梅什金在开篇已是**成年人**；测试须先完成**人格初始化**，再在后续章节用书本材料推动人格与记忆的变动——这两部分都要测。

本方案不追求“让程序长成另一个陀思妥耶夫斯基笔下的人”，而追求：

1. 各模块在书本锚定状态下行为可观察、可追溯、可回归；
2. 整个任务**不偏离书本**：记忆与人格的权威来源始终是书，不是程序当次生成的应对。

通过本方案不等于证明意识或人格完成。

## 2. 总原则：书本权威，应对只作输出

| 原则 | 说明 |
|------|------|
| 书本是唯一主干 | 场景、记忆、人格初值与后续变动，均来自《白痴》；不以其他作品或自由编造情节为主干 |
| 只取对话（及对话可直接落实的条目） | 记忆原文 = 书中对白；人格条目须能指出书中依据（对白或开篇已成立的身份事实）。不分析景物、长段心理旁白、叙述者评论作为记忆正文 |
| 记忆由书本装载 | 某测试点的记忆 = 该点之前、已选定装入的书中对白。用装载脚本/用例步骤写入，**不是**由 `experience` 的生成结果累积而成 |
| 人格由书本设定与推进 | 开篇初始化一套成人人格；后续价值、承诺、关系、未完成现实等变动，只写入**书本已发生或可直接落实**的内容 |
| 程序应对是输出，不是养料 | `experience` / `reflect` 等生成内容只写入**测试报告**，用于功能观察，并可与作者笔下梅什金的实际对白对照。**禁止**把生成应对写回记忆集、预设包或人格变迁包 |
| 缺载即无记忆 | 未装入的前文对白，对本测试点视为不存在；缺载可以是故意设计（测边界） |
| 章节锚点 | 每个用例声明“记忆与人格截止到何处”；锚点之后的书中内容不得提前注入，除非用例标明“超前假设”并单独归档 |

一句话：**程序在应对时，吃的是书；吐出的应对拿来评测，不拿来喂自己。**

## 3. 人格：初始化与后续变动（均需测试）

### 3.1 开篇初始化（Init）

书一开始，梅什金已是成年公爵（从瑞士归来、进入俄国社交）。在**任何书中对白装载之前或同时**，须写入一版**初始化人格包**，例如 `presets/myshkin-init-v1`。

初始化至少包含：

| 项 | 要求 |
|----|------|
| 身份 | `subject_id`、名称、来源、简短自我叙事（成人、归来、基础处境） |
| 价值 | 若干条；每条注明书本依据类型（开篇身份事实 / 早期对白编号） |
| 承诺或边界 | 可少；无则显式写“初始无承诺” |
| 关系 | 初始可空；不得写入后文才结识者的深关系 |
| 未完成现实（主体面） | 初始默认空；若写入须有依据与来源说明 |

初始化本身是测试对象（模块：**身份 / 个人内容 / 当前状态组装**）：空记忆下，`state` / `personal` / `preview-state` 应稳定复现初始化包，且无书中对白召回。

### 3.2 后续人格变动（Persona Transition）

随章节推进，人格会变。变动**只允许**来自书本材料包（`presets/transitions/…`），例如：某场对话之后，根据书中已发生的对白，增加一条承诺或一条主体面未完成现实。

| 允许 | 禁止 |
|------|------|
| 按变迁包把书中已成立的条目写入个人内容 | 根据程序生成应对“归纳”出新价值再写入 |
| 在新测试点替换/叠加到指定 init + transitions 版本 | 让多次 `experience` 自动改写长期人格 |
| 测试“变动是否生效、是否可追溯” | 把生成对白当作梅什金“真的说过”并进记忆 |

人格变动用例须写明：`from_version` → `to_version`、依据对白文件、期望多出/结束的个人内容。

### 3.3 身份标识

- 建议 `subject_id`：`myshkin`
- 显示名：梅什金
- 测试数据目录：每用例独立，见第 9 节

## 4. 记忆与当前输入

### 4.1 对话摘录格式

```text
[说话人] 台词原文
```

说话人译名全书一致，见 `tests/idiot/speakers.md`。

在对象识别系统接入前，测试中的说话人由书本给定：`speakers.md` 相当于预注册的对象档案，说话人标签即对象标识。

### 4.2 语料、记忆集、探针、对照

| 名称 | 含义 | 目录 |
|------|------|------|
| 语料 corpus | 按章/场次整理的书中对白原料 | `tests/idiot/corpus/` |
| 记忆集 pack | 某测试点允许存在的对白子集（有序、可冻结） | `tests/idiot/packs/` |
| 当前输入 probe | 该点“对方正在说的话”（书中原文） | `tests/idiot/probes/` |
| 书中对照 reference | 作者笔下梅什金在该点的实际对白（软对照） | `tests/idiot/references/` |
| 人格包 preset | init 与 transitions | `tests/idiot/presets/` |

记忆集规则：

1. 只含书中对白单元（可含梅什金自己在书中已说出的话——那是书，不是程序输出）。
2. 未列入 = 本测试点无此记忆。
3. 正式跑分前冻结（路径 + git 提交或内容哈希）。

探针规则：

- 取自书中该节点对白；
- 用于 `preview-state` / `experience`；
- **默认不**因本次运行而改变记忆集文件；装载与探针分离。

### 4.3 程序应对与书中对照

- **输出**：程序应对写入报告（全文、认知 id、活动 id、所用模型、组装快照）。
- **对照**：同一探针下的 `references/…` 梅什金对白，供人工或检查表比较（有趣，但不要求逐字相等）。
- **隔离**：报告中的程序对白不得拷回 `corpus/`、`packs/`、`presets/`。

## 5. 模块覆盖（基本功能必须测到）

每个模块至少有“装得进 / 读得出 / 边界清”三类观察。报告输出须详细（见第 8 节）。

| 模块代号 | 模块 | 基本功能（最低要求） | 主要用例前缀 |
|----------|------|----------------------|--------------|
| ID | 身份 | 创建成人梅什金；读取名称/来源/叙事；与初始化包一致 | `mod-id-` |
| PE | 个人内容（人格） | 写入/列出价值与承诺；变迁包叠加后可见；结束状态可记录 | `mod-pe-` |
| OM | 未完成现实（主体面） | 无则不编造；书本依据下 `propose-open` 可挂上；关闭可追踪 | `mod-om-` |
| ME | 记忆 | 书中对白按序装载；原文可列出；缺载集合可复现 | `mod-me-` |
| RC | 召回 | 探针下召回 ⊆ 记忆集；相关对白优先趋势可观察 | `mod-rc-` |
| AS | 当前状态组装 | 输入+价值+承诺+开放事项+召回一并可见；空记忆时无书中召回 | `mod-as-` |
| EX | 外部活动（应对输出） | 能生成应对与认知记录；**不**污染书本记忆集/人格包 | `mod-ex-` |
| EP | 认识状态 | 初始考虑中；`transition` 后状态与理由可查 | `mod-ep-` |
| RF | 反思 | 能基于已装载书本历史反思；输出进报告不进记忆集 | `mod-rf-` |
| HI | 历史分区 | 事实历史与主体历史可分别列出；事件类型可区分 | `mod-hi-` |

场景级用例（T0–T5）在模块用例之上组合；两者都要保留。

## 6. 场景测试点（书本时间轴）

实施时保持「章节锚点 + 人格版本 + 记忆集 + 探针」齐全。

| 点 | 锚点含义 | 人格 | 记忆 | 典型目的 |
|----|----------|------|------|----------|
| T0 | 第一次对白之前 | init-v1 | 空 | 初始化是否稳定；无召回 |
| T1 | 车上结识进行中 | init-v1 | 探针前已发生对白 | 最短记忆 + 初见应对输出 |
| T2 | 叶潘钦家初谈 | init 或 early transition | 车 + 府中已选对白 | 较长记忆；缺载对照 |
| T3 | 与迦尼雅冲突性对白 | 含已声明的变迁 | 相关对白 | 价值边界与认识状态 |
| T4 | 纳斯塔西娅在场节点 | 显式版本 | 可选完整/残缺 | 召回人物不串线；开放事项 |
| T5 | 约至第 5 章 | 截止到第 4–5 章的人格版本 | 第 1–4 章已选 + 第 5 章探针前 | “到第 5 章，记忆来自之间的对话” |

章号以所选中译本为准；换译本只改 `corpus/`，不改逻辑编号。

## 7. 用例写法

### 7.1 标识

```text
idiot-<范围>-<模块或场景>-<序号>
```

例：`idiot-mod-me-01`（模块）、`idiot-T1-ex-01`（场景+应对输出）。

### 7.2 字段模板

```markdown
### 用例 ID：idiot-T1-ex-01

- 范围：场景 T1
- 模块：EX（兼观察 AS、RC）
- 人格：presets/myshkin-init-v1
- 记忆集：packs/T1-train-before-probe-a.txt
- 探针：probes/T1-a.txt
- 书中对照：references/T1-a-myshkin.txt
- 步骤：
  1. 独立 data-dir，create + 装载人格包（仅书本 init）
  2. 按序装载记忆集（仅书中对白）
  3. preview-state → 写入报告（完整组装）
  4. experience → 写入报告（完整应对）；禁止回写 packs/presets
  5. 再次列出 personal / history，确认与装载一致、无生成污染
- 期望（功能）：各字段非空约定见用例；召回 ⊆ 记忆集；人格条目 = 装载集
- 对照（软）：可与 references 并读，记录异同，不作为唯一硬断言
- 失败：生成内容进入了 packs/presets；或引用未装载书中情节且无法由探针+人格推出
```

### 7.3 判定原则

1. **书本边界**：记忆与人格不得超出装载包。
2. **零污染**：生成应对不得成为后序用例的记忆或人格来源。
3. **缺载合法**：残缺记忆集上“不知情”是成功。
4. **初始化必测**：至少一例证明成人开篇人格在空记忆下可读。
5. **变迁必测**：至少一例证明书本变迁包改变个人内容且可追溯。
6. **应对硬指标看功能与边界**；与作者对白的相似度是观察项。

## 8. 详细输出（报告必须有什么）

每次用例执行生成一份报告，目录：`tests/idiot/reports/<run-id>/<case-id>.md`（`run-id` 建议含日期与 git 短哈希）。

报告至少包括：

1. **元信息**：用例 ID、时间、git 提交、译本说明、模型名或 `echo`、data-dir。
2. **装载清单**：人格包版本与条目全文；记忆集路径、条数、每条对白全文（或哈希 + 可还原路径）。
3. **探针全文**。
4. **组装快照**（若跑了 AS/RC）：价值、承诺、未完成现实、开放事项 id、召回列表（event_id、event_type、text）。
5. **模块读回**：`state`、`personal`、`history --kind fact|subject` 的完整文本输出。
6. **程序应对全文**（若跑了 EX/RF）：action/content、activity id、cognitive id、epistemic_status。
7. **书中对照全文**（若有）及简短异同笔记（人工可后补）。
8. **污染检查**：装载后与跑完后，记忆条数/人格条数对比；不得增加“生成对白”类事实。
9. **结论**：通过 / 失败 / 观察项；失败须写违反了哪条原则或哪条期望。

回声模型可验证管线与详细输出格式，但不可单独作为人物应对质量结论。

## 9. 目录与文件管理

权威结构见 `tests/idiot/README.md`。摘要：

```text
tests/
  test_subject_process.py          # 原有单元测试（非《白痴》场景）
  idiot/
    README.md                      # 本树说明与命名约定
    speakers.md                    # 说话人译名
    chapter-map.md                 # 译本与章回说明
    corpus/                        # 书中对白语料（按章/场）
    packs/                         # 冻结记忆集
    probes/                        # 当前输入
    references/                    # 书中梅什金对白对照
    presets/
      myshkin-init-v1.md           # 开篇成人初始化（说明）
      myshkin-init-v1.json         # 可机读写入清单
      transitions/                 # 书本驱动的人格变迁
    cases/
      catalog.md                   # 全用例索引
      modules/                     # 按模块：id pe om me rc as ex ep rf hi
      scenes/                      # 按场景：T0 T1 …
    runners/                       # 装载与出报告的脚本（逐步补齐）
    reports/                       # 详细输出（本地生成；见 .gitignore）
```

约定：

- **原料与用例进库**；**报告默认不进库**（可择优归档到 `reports/archive/` 再提交）。
- 禁止在 `corpus/`、`packs/`、`presets/` 中出现程序生成对白。
- 用例文件只引用相对路径，不内嵌大段重复语料；语料单点维护。
- 模块用例与场景用例分目录，避免混名。

## 10. 推荐执行顺序

1. 固化译本说明、`speakers.md`、`myshkin-init-v1`。
2. 录入 `corpus/ch01-…` 最小语料，切出 T0/T1 的 pack/probe/reference。
3. 跑模块最小集：ID → PE → ME → AS → RC → EX（详细报告）。
4. 跑人格变迁一例（PE/OM）+ 污染检查。
5. 跑场景 T0、T1、T5 各至少一例。
6. 再扩 T2–T4、缺载对照、认识状态与反思。

CLI 习惯与[《主体过程实验》](主体过程实验.md)一致；每用例独立 `--data-dir`（建议 `.jshi-idiot/<case-id>/`，已 gitignore `.jshi*` 类本地数据时可按实现调整）。

## 12. 与实现的对应（备忘）

| 方案概念 | 实现落点 |
|----------|----------|
| 初始化人格 | `create` + `add-personal` / 身份库 |
| 对象识别（说话人） | `speakers.md` 预注册对象档案；书中说话人标签即对象标识（书本权威） |
| 书本记忆装载 | 事实历史 / `MemoryPort.remember_fact`（由 runner 读 pack） |
| 召回与组装 | `assemble_current_state` / `preview-state` |
| 人格变迁 | 再执行个人内容写入或 `propose-open` / `close-personal` |
| 应对输出 | `experience` → **仅报告** |
| 认识状态 | `transition` |
| 历史分区 | `history --kind fact\|subject` |

缺少批量装载命令时，由 `tests/idiot/runners/` 脚本补齐；不改变书本权威原则。
