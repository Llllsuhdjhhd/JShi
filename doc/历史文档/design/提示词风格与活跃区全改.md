# 提示词风格与活跃区全改

> 本分支（`tune/prompt-zone-memory`）的口径文。术语以《概念词汇》为准。模块细节分别落在 05 / 16 / 02 / 03 / 00。决策见 D-009。
>
> 状态：已实现（D-009）。风格包、写场 skill（回复 / 写场两次调用）与人格片场已在跑；模块细节见 05 / 16 / 02 / 03 / 00。
>
> 想法：I-015。

## 1. 定位

本文件回答：匠石仍是同一个主体；05 的提示词和活跃区按**选中的风格包**来写；记忆的落库与召回仍按**原始素材**走。

木头、苏西坡、斯密斯是匠石的**风格包**（配置名），不是另一个主体，也不是匠石的绰号入口。发给模型的提示词里只出现「匠石」，不出现这些配置名。

## 2. 两层分工

| 层 | 谁做 | 做什么 | 不变的东西 |
|----|------|--------|------------|
| 材料层 | 现行管线（落位、16 原文、03、09 召回、30 投递） | 按原始素材记账、召回、把本轮新料交给 05 | `text_raw`、09 已存正文、01 对象档案、08 承诺与价值 |
| 现场层 | 选中的风格包（05） | 按该风格开口；把本轮看见的全体**整份重写**成下一份活跃区 | 主体仍是匠石；真源不因重写而改 |

「木头」在材料层就是现在这一套，始终运行，选了别的风格时也不另开一轮认知。  
「木头」在现场层是**默认风格包**（现行提示词文风）。未主动切换时用它。

选中苏西坡或斯密斯时：材料层仍按木头管线供料；05 的口头和活跃区按该风格写；用户看不见材料层的文风。

不跑第二次心智。不要做成两个主体共享一个记忆库。

## 3. 风格包

配置里可选。程序侧是可注册的包，不写死在主链路。内置先占三份名：木头（默认）、苏西坡、斯密斯。

每包两套槽，由程序选择，不让模型猜：

| 槽 | 何时用 |
|----|--------|
| `instruction_first` | 空现场，或现场 `style_pack_id` ≠ 当前包（含硬切） |
| `instruction_continue` | 现场已有正文，且就是当前包写的 |

写法正文另议，内置三包目前槽位为空。新增人格：`StylePack(...)` 后 `registry.register`，不必改主链路。CLI `/style` 列已注册包。

规则：

1. **选中状态随主体保存**，直到主动切换。重启后仍是同一份风格包。
2. **提示词不出现配置名**，只写匠石，以及该包槽位里的写法要求（空则只用 skill 里的【现场】）。
3. 风格包只改 05 的 system 写法、口头，以及活跃区正文。不改 `subject_id`，不改 01 / 08 / 09 真源。
4. 内部活动（反思）暂不套风格包，仍走现行裸模型。
5. 新增风格包是加一份写法要求，不是新建主体。

## 4. 每一轮怎么走

```text
材料层（始终）
  本轮原话入账（text_raw 不改）
  09 按 input_text 召回原文（query = 本轮原话，object_id = 说话人）
  记下召回触发流水（哪次输入 → 召回了哪些）
  03 组装：上一份活跃区 + 本轮原话 + 对象真源 + 身份 + 08 真源 + 本轮新回忆

现场层（选中风格，一次认知）
  看见组装全体
  必出 response_plan（按该风格开口）
  必出整份新活跃区正文（按该风格整理；含对象、承诺、回忆、上一现场、本轮新料）
  16 保存该正文，覆盖主体这一份活跃区
```

本轮原话仍走 `input_text`，不在认知前并入上一份活跃区。并入（以重写后的形态）发生在 05 交出新现场、16 保存时。

同一风格连续多轮：在上一份已按该风格写过的活跃区上，加上木头本轮新给的输入和回忆，再整份重写。

## 5. 活跃区整份重写

活跃区为选中风格服务，按该风格写进去。

- 05 交出的是**整份新现场正文**，不是 `remove` / `drop_recall` / `focus` 补丁。
- 16 不再按段 id 拼现场。保存 05 交出的正文；超长由程序按硬上限截断。
- 现场里的木头原文**不强保**。不要求活跃区能对上 09 的 `event_id` 或账本 `segment_id`。分析不靠现场对齐，靠召回触发流水。
- 空正文不合法为「清空现场」：解析失败或未交出现场时，16 **保留上一份**，不把现场抹掉。本轮原话仍在账本，下一轮仍经 `input_text` 进来。
- 不得把整份活跃区再 ingest 进 09。记忆仍只收新输入、新口头。

对象与承诺：

- **档案不变。** 01 的对象是谁、08 的承诺与价值写了什么，05 不得改实质、不得否掉、不得新造一条写回 08。
- **现场要按风格重写。** 对象、承诺、身份、回忆、上一现场、本轮新料，都进入这一份新正文，按该风格的需要写详略、顺序和句子。不把对象或承诺留在改写区之外当「不可改写的原文块」。
- 03 每轮仍装 01 / 08 / 身份真源，作为本轮重写的依据，避免连续改写后实质漂移。现场不再带 `personal:{id}` 之后，03 **不再**因「活跃区里已有同一 id」而跳过 08。

## 6. 切换风格

主体一份活跃区，不按风格各存一本。切换少见，**硬切**：立刻换风格包，用当前现场加上材料层仍在的真源，按新风格整份重写并覆盖。不为切走的风格保留快照。

## 7. 记忆：落库与召回仍是材料层

- 召回、投递、09 原文：与现在相同。query 仍是本轮 `input_text`。
- **本轮不做回忆现场打分**（`memory_ratings` 可空，有效性分析不靠本轮打分推进）。
- **要留下召回触发流水**（匠石侧，不进 09 后端，不叫记忆）：
  - 哪一次输入触发（活动 id、经历段 id、`input_text` 或其哈希）；
  - 说话人 `object_id`、档位、limit；
  - 09 返回了哪些 `event_id`；
  - 03 因预算跳过了哪些 id。
- 09 契约仍是：后端 `recall` 不登记 `recall_log`。流水在匠石库，供以后统一分析。

缺材料仍可记在口头或下一拍；不在本轮二次召回、二次认知（D-008 仍有效）。

## 8. 提示词

发给模型时：

- system：匠石的稳定规则 + **当前风格包本轮对应槽位**（首次或续写）+ 本轮 01/08/身份真源（实质依据）；
- user：本轮原话 + 上一份活跃区 + 本轮新回忆原文；
- 说话人仍单列；对人只用名字，默认不出现 `object_id`；
- 要求交出口头，以及整份新活跃区正文；
- 明确：重写现场不得改变对象是谁、承诺内容与是否仍有效；不得把未发生的事写成经历。

风格包的配置名只存在于主体配置与审计，不进上述文本。

各人格的写法正文（首次按块编写 / 非首次只扩充新材料）**另议**，不在本文件写死。程序只负责选槽、注入 `{style_instruction}`。

## 9. 模块落点

| 模块 | 本文件要求它做什么 |
|------|-------------------|
| 05 | 风格包入请求；口头按风格；交整份新活跃区；不打分；不写 08；不 ingest |
| 16 | `text_raw` 仍只追加；活跃区改为保存整份正文；失败则保留上一份；硬上限截断正文 |
| 02 | 仍只读 16 当前活跃区；正文即上一轮重写结果 |
| 03 | 仍装真源与新回忆；记召回触发流水；08 不去重跳过 |
| 01 / 08 / 100 | 真源不变；05 重写不等于写入 |
| 09 / 30 | 召回与投递不变；不收整份活跃区；后端仍无 recall_log |
| 06 / 10 / 07 | 仍只消费 `response_plan`；不编活跃区 |
| 有效性分析 | 本轮不依赖打分；以后吃召回触发流水 |

## 10. 本轮不纳入

- 提示词里自称木头 / 苏西坡 / 斯密斯；

- 现场打分与有效性分析本轮推进；
- 内部活动套风格包；
- 改 09 后端契约去登记 recall_log。

## 11. 验收（文档层）

- 材料层：原文可追溯；召回 query 为本轮输入；流水能回答「这次输入召回了哪些」；
- 现场层：05 交整份正文；16 保存后 02 下一轮读到的是该正文；
- 01 / 08 条目不因 05 重写而增删改实质；
- 提示词样例中不出现风格包配置名；
- 整份活跃区不进入 30 批次。
