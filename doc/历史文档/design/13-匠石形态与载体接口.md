# 13 匠石形态（载体与呈现）

> 模块文档。术语以《概念词汇》为准，流程位置见《00 流程总览与输入边界》。
>
> 状态：初稿，待讨论定稿。

## 1. 职责与边界

- 回答：同一个匠石以什么形态呈现并作用于现实——人形机器人、App 界面中的虚拟人、语音助手等；形态如何接入系统。
- 位置：可替换边界，横跨输入通道、输出呈现与行动能力；不参与主体过程本身。
- 不做：
  - 不决定匠石是谁——身份与个人世界属于主体，与形态无关；
  - 不承载记忆/历史——记忆、事件、承诺的权威在主体侧，形态只提供通道；
  - 不替代基础认知模型——形态只提供输入输出，不改变认知归属。

## 2. 接口契约

### 2.1 EmbodimentPort（形态/载体接口，可替换）

| 能力 | 说明 | 当前实现 |
|------|------|----------|
| 输入通道 | 麦克风、摄像头、触摸、键盘等 | 文字（语音先转文字） |
| 输出呈现 | 文本、语音、表情、动作、界面 | 文本 |
| 行动能力 | 移动、工具使用、界面操作 | 无（占位） |
| 识别载体 | 声纹、人脸、设备标识（供 01 身份识别按载体匹配，命中直接给出对象名；只存引用，不存原始生物数据） | 无（占位） |

### 2.2 形态清单（未来）

- App 界面虚拟人：文本/语音输入，虚拟形象表情与动作输出；
- 人形机器人：多模态感知，语音 + 动作 + 表情输出，具身行动能力；
- 语音助手 / 音箱：语音输入输出；
- 其它未来载体。

当前实现仅覆盖"文字界面"这一种最小形态。

## 3. 行为规则

1. 形态是可替换边界：同一匠石可跨形态存在，形态不改变主体归属；
2. 输入信封的 channel / modality 由形态提供；对象识别载体（声纹 / 人脸 / 设备）也由形态提供；
3. 语言行动是主体过程的输出，形态负责把它渲染成文本 / 语音 / 表情 / 动作；
4. 形态切换 = 换载体，不换主体：个人世界、主体历史与承诺必须原样保留（主体面未完成现实已废除，D-007）；
5. 形态切换须经过治理 / 连续性检验（11），确认承诺与重要关系未因切换无故消失。

## 4. 占位与未来

- 当前：文字界面占位（CLI / 文本输入输出）；
- 未来：App 虚拟人、人形机器人、语音助手；形态接口保持不变，新增形态只扩展通道与能力。

## 5. 验收标准

- 同一匠石在不同形态下读回相同的身份、历史与承诺；
- 形态切换后身份、历史与承诺仍在（连续性检验通过）；
- 形态只负责通道，不产生独立的"另一个匠石"。

## 6. 与其他模块的关系

- 依赖：无（被动提供通道）；
- 被依赖：输入信封（00）、身份识别载体（01）、行动与反馈（10）、治理 / 连续性检验（11）；
- 概念边界：形态 ≠ 主体；模型 ≠ 匠石；同一匠石 = 同一身份档案 + 个人世界 + 主体历史，与形态无关。

## 7. 扩展性预留

- EmbodimentPort 能力清单可扩展（新通道、新输出、新行动能力）；
- 新增形态不改七阶段骨架与主体过程；
- 代码挂靠点：未来实现 `jshi/embodiment/` 占位系统包（端口 + 占位实现）。

## 8. 记录、评价与参数

- 记录：形态通道的输入输出耗时、错误率、载体命中情况（未来）；
- 评价：形态识别与表达的客观指标（延迟、失败率）供 14 分析；
- 参数：形态侧无主体参数；主体侧参数（如对象置信度门禁）由主体模块声明。
