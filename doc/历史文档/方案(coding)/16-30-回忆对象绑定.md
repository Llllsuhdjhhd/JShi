## 1. 目标与范围

对话壳只声明「现在是谁」时，主链路在落位后补上「名字/称呼 → 档案 id」，外部输入段与主体回复段都带这份表；30 把对话对象 id 写入 `interlocutor`，并把投递 `text` 编成带名字的对话（言语 + 动作）。召回过滤仍用档案 id；提示词仍只用名字。

不做：

- 不改 `talk` / 不强迫信封自带映射表；
- 不解析正文里的第三人（不扩映射表）；
- 不给对象编短编号，提示词不出现 `OBJ-…`；
- 不改 09 端口、不改邻仓、不重放 `.jshi/rems` 已封存事件；
- 不改召回 query 文本、不按显示名过滤。

## 2. 接口落点

账本 `append_*` 签名不变。改接线与 30 取值。

## 3. 数据结构

不新增字段。映射表形状仍是 `{名字或称呼: object_id}`。

补表规则（落位后、写入前）：

```text
mapping = 调用方 objects 的副本（去掉空键空值）
对本轮说话人的 label、aliases，以及档案里已有的 aliases：
    mapping[名字] = 本轮 object_id
```

本轮说话人的名字以 01 为准（可覆盖映射表里同一名字的旧值）。他人条目原样保留。不从正文抽新名字。label 为空则不写该键（01 契约上 label 非空）。

## 4. 行为变更

### 4.1 16 写入

1. `append_external`：`objects` 用补齐后的表；事实历史 `content["objects"]` 同步。
2. 有口头则 `append_subject_reply`，否则 `append_subject_state`：同一份表。无口头的一轮仍是对同一人说话，空表会导致 30 把该段当成主体自述。
3. `mentioned_object_ids`：在已有提及上并入本轮 `speaker.object_id`（去重）。多人映射时 30 用它认定对话对象，不任取。

### 4.2 30 `interlocutor`

```text
若 actor_object_id 非空 → 用之（外部输入）
否则取 objects 的值、去掉空串与 subject_id、去重：
    恰一个 → 用之
    多个 → mentioned_object_ids 里第一个落在该集合中的 id；都对不上则空
    零个 → 空（主体自述）
```

只透传，不编造对象。

### 4.3 提示词

本轮不改组装与人格 user 文案。回忆行继续用 `_object_display`（名字；重名用档案称呼）。验收时确认 user 文不含档案 id。

### 4.4 投递正文（对话实录）

30 `_experience_text` 不再原样抄 `text_raw`，也不把 `state_delta` 的 JSON 当作正文。编成对话行后再交给 09：

```text
有 text_raw：
    已以「该说话人：」或「该说话人:」开头 → 不重复加前缀（多轮信封可能已自带名字）
    否则 → `{说话人}：{text_raw}`
仅有肢体、无口头：
    `{说话人}：（动作：{embodied}）`
无言语、无动作（think / wait 的 JSON 等）→ 正文空串，不冒充对话行
```

说话人名字：外部段用映射表里指向该 `actor_object_id` 的名字（优先 `label`）；主体段用身份 `name`（缺档则「匠石」）。不把 `OBJ-…` 写进正文。

现有回复段已把口头与 `（动作：…）` 拼进 `text_raw`，投递时整段带上，不丢掉动作。一批多段由 09 按序拼接，例如：

```text
lux：你会游泳吗
匠石：我是一段程序……你信不信？（动作：抬起手比划了两下像是在划水，目光带着笑意看lux）
```

未开口的提及对象留在原句里，不编造「贾母：」行。空正文的段仍进批次（游标要走），拼接时跳过空行。

主体显示名：`build_batch` 读身份档案 `name`；30 不新增端口字段。

## 5. 测试计划

现有 `test_experience_carries_objects_mapping`：信封已带表时应仍原样（说话人名字与档案一致）。

新增：

- 只给 `object_ref`、不传 `objects`：输入段与回复段都有 `label`（及 aliases）→ 该 `object_id`。
- 信封另带第三人：说话人名字被补上且指向本轮 id；第三人条目保留。
- `build_batch`：外部段 `interlocutor == actor_object_id`；回复段无 `actor_object_id` 时等于映射表中的对方 id。
- 映射表多个对方 id 时：回复段 `interlocutor` 为本轮 `mentioned` 中的说话人，不任取。
- 投递 `text`：输入为 `lux：你会游泳吗`；回复保留 `（动作：…）` 且冠 `匠石：`；仅动作无口头为 `匠石：（动作：…）`；think 的 JSON 不进正文。
- 原文已带 `lux：` 前缀时不叠成 `lux：lux：`。
- 回归：`talk` 仍不传 `objects`；user 提示词不出现 `OBJ-`。

进程内后端即可。不把「邻仓语义路仍可能滤空」写成本仓库失败。

## 6. 风险与未决

- 已封存的旧事件没有这张表、正文也无说话人名字，对那些记忆召回仍可能空。本分支不回填。新投递的段才能对上。
- 邻仓若仍按 payload 硬过滤，JShi 补表之后**新**事件才有资格进语义路；硬过滤是否过严另开邻仓。
- 00 写「映射覆盖文本涉及的所有人」；本轮只保证本轮说话人，第三人仍靠信封。与 01「不解析正文」一致，不在本方案扩大。

回退：去掉补表、`interlocutor` 回退与对话行冠名，账本字段可空，投递正文回到抄 `text_raw`。
