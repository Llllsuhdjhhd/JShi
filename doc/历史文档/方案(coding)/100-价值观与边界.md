# 100 价值观与边界——实现方案

> 对应文档：[doc/design/100-价值观与边界.md](../doc/design/100-价值观与边界.md)
> 状态：初稿，待确认后编码

## 0. 目标与范围

本轮实现完整 100：装载侧、窄写入、JSON 导入/导出、自省整理。

### 做

1. 扩展 `PersonalStatus`：新增 `CANDIDATE`、`ACCEPTED`、`LOCKED`、`REJECTED`。
2. 完整实现 `src/jshi/personalworld/values.py`：
   - `ValuesPort`：装载 + 写入 + 导入/导出 + 自省；
   - `InProcessValues`：以 `personal_items` 本地存储承载 100 逻辑；
   - `ValueSource`、导入/整理报告数据结构。
3. 08 薄壳正确识别 `accepted` / `locked` 价值为可装载。
4. 补齐测试：价值生命周期、边界常驻、导入导出、自省幂等。

### 不做

- 不新增独立数据库表，本轮仍用 `personal_items` + `metadata`。
- 不做 CLI 子命令与外部工具，只把 JSON 作为交换格式。
- 不自动调用 `mark_used`；使用记录作为显式审计钩子，避免正常活动静默写库。
- 不在主活动链路中自动写入或升格价值。

## 1. 接口落点

### 1.1 `src/jshi/subject/domain.py`

- `PersonalStatus` 增加价值生命周期状态。

### 1.2 `src/jshi/personalworld/values.py`

- `ValueSource`：`classic_work` / `classic_novel` / `model_proposal` / `human_intervention` / `derived_experience` / `governance_review`。
- `ValuesPort`：
  - 装载：`select_values`、`select_boundaries`、`standing_constraints`；
  - 写入：`propose_value`、`review_value`、`lock_value`、`supersede_value`；
  - 交换：`import_entries`、`export_document`；
  - 自省：`consolidate`；
  - 使用审计：`mark_used`。
- `InProcessValues` 实现上述接口，写入历史记录与状态迁移审计。

### 1.3 `src/jshi/personalworld/port.py`

- `InProcessPersonalWorld.select` 改为读取全部状态，再按以下规则过滤：
  - `COMMITMENT` / `CONCERN`：仅 `ACTIVE`；
  - `VALUE`：仅 `ACTIVE` / `ACCEPTED` / `LOCKED`；
  - 其他普通条目：仅 `ACTIVE`。

### 1.4 `src/jshi/personalworld/__init__.py`

- 导出 `ValueSource`、导入/整理报告、`is_loadable_value`。

## 2. 数据结构

逻辑字段到当前存储的映射：

| 逻辑字段 | 当前落点 |
|----------|----------|
| `id` / `subject_id` / `content` / `source_ids` / `revision` | `PersonalItem` 同名字段 |
| `role` | `metadata.role` |
| `summary` / `stance` / `source_type` / `source_id` | `metadata` |
| `domains` / `context_tags` / `importance` | `metadata` |
| `binding` | `metadata.binding`（边界缺省 true） |
| `status` | `PersonalItem.status` |
| `last_used_at` / `use_count` | `metadata` |

## 3. 行为变更

1. `candidate` / `rejected` / `superseded` 不进入装载；`accepted` / `locked` 与旧 `active` 可装载。
2. `review_value` 仅接受 `candidate`；`lock_value` 仅接受 `accepted` / `active`；`supersede_value` 仅接受 `accepted` / `locked` / `active`。
3. `import_entries` 允许 JSON 中直接写入 `accepted` / `locked`，用于人工讨论定稿的种子；`model_proposal` 仍候选。
4. `consolidate` 只输出建议，写 `value_consolidation_run`，可 cursor 续跑。

## 4. 测试计划

新增/扩展 `tests/test_values.py`：

- 价值生命周期：propose → review accept → lock → supersede；
- 状态过滤：candidate/rejected/superseded 不装载；
- 边界 binding 常驻；
- `import_entries` / `export_document` 往返；
- `consolidate` 重复检测、抽象检测、cursor 幂等；
- 历史记录：`value_proposed` / `value_reviewed` / `value_locked` / `value_superseded` / `value_consolidation_run`。

回归：全套 pytest 通过。

## 5. 风险与未决

- 仍用 `personal_items` 存储，未来可拆独立 `ValueStore` / 表。
- 排序中的模型评价本次不接模型，只保留规则兜底；模型排序接口后续由 100 自省或 14 接入。
- `mark_used` 不在装载链路自动调用，待 14 确认记账方式后接线。
