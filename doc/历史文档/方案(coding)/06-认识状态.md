# 06 活动状态标示——实现方案

> 对应文档：doc/design/06-认识状态.md（初稿）
> 状态：初稿，与当前 `response_plan` 接线对齐

## 1. 目标与范围

本次做到**最小**：把 06 接到 05 的 `response_plan`。

- 05 输出 `ResponsePlan`（mode / reason / items）；
- 06 校验合法 mode 与 channel；
- 标记到 `Activity.response_statuses`（展平：mode + channels）；
- 记录 `activity_response_state`（含 reason、items）；
- 未知值忽略并记录。

旧 `EpistemicStatus` 状态机保留为历史兼容，不作为本模块契约。
I-001 流式分段不纳入。人工介入（15）保持占位。

## 2. 接口落点

- `src/jshi/models/base.py`：`ResponsePlan` / `ResponseItem`；
- `src/jshi/subject/process.py`：`mark_activity_response_status(response_plan)`；
- `src/jshi/subject/domain.py`：`Activity.response_statuses`（已有，不改结构）。

## 3. 行为变更

主流程在认知之后、行动之前调用 06。06 不改生命周期。`wait` 只表示本轮不说话、等后续输入；07 仍关闭本活动，下一轮新建活动。

## 4. 测试计划

- 模型多通道计划被正确标记；
- 未知状态忽略并记录；
- `think` / `ignore` / `wait` 无 language_action，活动仍 completed；
- `wait` 后下一次输入是新活动。

## 5. 风险与未决

- mode 与 channel 共用一张展平列表，语义不够干净；若验证困扰，再改为活动直接存 `response_plan`。
- 同一活动挂起式 `wait` 本期不做。

## 6. 记录、评价与参数影响

- 记录点：`activity_response_state`；
- 评价点：旁路收集，不进入主流程（I-005）；
- 参数：枚举固定，15 开关未实现。
