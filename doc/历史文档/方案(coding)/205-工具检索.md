# 205 引擎命令检索——实现方案

> 对应文档：`doc/design/工具使用.md`（I-017 / I-018）。
> 只解决一件事：**205 如何从引擎目录里找到具体命令**，再点名写进 `command`。
> 状态：按讨论编码。不换引擎、不改 10/08/16、不把 OpenClaw/Hermes 整套代理嵌进匠石。

## 0. 问题

现行 `ToolPlanSkill` 把 `list_commands()` **整表**（name + description，将来还可能带 schema）塞进任务 JSON，让模型读一遍再抄 `command`。目录小时（Stub 一条 `echo`）能用；Pi 一类斜杠清单变长之后，会占满策划上下文，也没有「按意图找」的口。

05 仍然只给 `use_tool` + 一句 `need`。206 仍然执行。本刀不改这两头。

## 1. 选用哪一种找法

对齐 **Hermes Tool Search** 的分层披露，而不是 OpenClaw 那份标成 experimental 的同名能力：

| 档 | 条件 | 205 第一次看到什么 |
|----|------|-------------------|
| eager | 可延迟工具不超过 8 条 | 全量 name + description（有 params 则带上）。与现行小目录行为一致。 |
| listing | 带短描述的名单不超过预算 | 桥 + 每条 name + 短描述。完整 schema 用 describe。 |
| names | 短描述超预算、仅名字仍放得下 | 桥 + 仅 names。必须 search 或按名 describe。 |
| index | 连 names 都超预算 | 桥 + 按 source 的条数摘要。必须 search。 |

检索：**BM25**（k1=1.2, b=0.75），文档 = 命令名 + 描述 + 参数名。查询里 **语料中最稀有的词必须出现在命中文档里**，避免 `send` / `create` 这类高频词把半个目录打上来。

与 Hermes 的一处可用化修正：查询里 **从未在任何工具文档出现的词（地点、人名、OOV）不参与稀有词门闩**。否则「杭州天气」会因「杭州」df=0 而整次检索为空。门闩只用语料里有的查询词；若查询词全部是 OOV，才空组并提示换功能词。

205 **不做 `tool_call`、不执行**。循环只允许 `search` / `describe`，最后仍输出 `ok` + `command` + `params`，由 200 launch → 206。

小目录（Stub 只有 `echo`）保持现有测试：单条可程序补 command；未知 command 仍失败。

## 2. 范围

### 做

1. `src/jshi/tool/discovery.py`：索引、分档、BM25、describe、披露结构。
2. `ToolPlanSkill` 短循环：任务 JSON **不再在大目录时整表塞 schema**；schema 增加可选 `lookup`。
3. 指令写明：能不能做只看这一次 need 与当前目录/检索命中；现场只补地点/产物进参数；不拿片场旧失败判定本次。
4. `/tool plan` 的引擎目录区按同一分档展示，避免调试视图自己把整表打满。
5. 无模型的 discovery 单测 + 用假端口模拟 search → describe → plan。

### 不做

- 换 Pi / 嵌 OpenClaw / Hermes 运行时。
- 向量检索、万级目录、MCP 服务器塌缩的完整实现（source 摘要只按 `source` 字段分组，缺省为 `engine`）。
- 模板动态切换；205 只出定义不点名。
- 改 10 / 08 / 16 / 05 提示词工具目录。
- 要求 describe 之后才能点名：listing 里已见的名字可以直接 `ok`（Pi 常常只有 name+description，没有独立 schema）。

## 4. 数据结构

任务 JSON（eager）：

```text
need / verbal / object_id / field_ref / scene / catalog / engine_tools
```

任务 JSON（非 eager）：

```text
need / … / catalog / discovery / lookups
```

`discovery`：`{tier, total, listing, sources, note}`。`lookups` 为历次 `dispatch` 的答复列表。

模型输出检索：

```json
{"ok": false, "lookup": {"op": "search", "query": "weather", "limit": 5}}
{"ok": false, "lookup": {"op": "describe", "names": ["get_weather"]}}
```

`lookup` 优先于 `ok`。最终仍是 `ok: true` + `template` + `command` + `params`。

## 5. 行为

1. 第一次策划才 `list_commands`（现有懒加载不变），立刻建成 `ToolIndex`。
2. eager：行为与现在相同，含「唯一命令可自动填」「模板名误当 command 且正好在引擎名单里则对齐」。
3. 非 eager：不把全表 params 放进第一次 user。模型用 `lookup`；程序在 205 进程内检索，不另调模型。
4. `command` 仍必须落在引擎名单里（有名单时）；不在则 `PlanFailure`，失败句规则不变。
5. 超轮次失败句用认知口吻，不写 `lookup` / 字段名：「我这边还没能从目录里定下该用哪个工具。」
6. 现场污染：指令禁止用旧工具失败块判定本次能不能做。

## 6. 测试

`tests/test_tool_discovery.py`（不依赖 `tmp_path` 做唯一证据）：

- 小目录 eager；80+ 条假目录不是 eager，第一次 payload 不含全表 params。
- BM25：`send weather` 只中天气工具（稀有词 `weather`），不中几十条 `send_note_*`。
- OOV：`杭州天气` 仍能中带「天气」的工具。
- 纯 OOV 查询 → 空组 + hint。
- describe 未知名 → `not_found`；已知名返回未裁到 80 字的说明。
- listing 超预算降为 names；再超则 index。
- `_JsonPort` 脚本：search → describe → `ok` 点名 `get_weather`。
- 连续 lookup 超过上限 → `PlanFailure`。
- 现有 `tests/test_tool_hang.py` 小目录用例仍过（未知 command、单条补全、scene 现读）。

## 7. 风险与未决

- Pi 的 `get_commands` 仍只有 name+description，describe 不能变出 SKILL.md。点名之后的真实发挥仍在 206/Pi 会话里。这是引擎能力边界，不是检索能补的。
- 模型可能把整句 need 当 query；OOV 软化减轻这一点，但仍要指令写「用功能词检索」。
- listing 预算用字符不是 tokenizer；中文偏保守，宁可降档也不灌满。

## 8.5 下一步：判断「用 / 造」（2026-09-12 拍板，**未编码**）

> 本刀只做了「怎么找到命令」。下面这四条是用户拍的口径，是下一刀的范围；写在这里免得丢。

**口径（用户原话要点）**

1. **205 是查询，不是「点名或失败」。** 查询结果（可能命中现成工具、也可能为空）**连同这次的工具需求一起交给模型判断**：现成的合不合适用；不合适/没有，就让 **Pi 去造一个**。**不能「没有就不管了」。**
2. **造工具用 Pi。** 造工具是引擎能力，不在匠石侧另开造工具模块——否则 Pi 就没有意义。
3. **造完要判断是否保存、能否重复使用。**（这一条是本步的关键：不保存＝下次还得重造；保存＝进目录、可被检索到、可复用。）
4. **造/用的初始阶段就要给出评估并反馈给对象。** 反馈慢一点可以接受，但一开始要有一句「我在查 / 我在造，大概什么代价」。

**范围（预估）**

- **205 输出**要能表达「用现成」与「造新的」两种结论，并把查询命中情况一并交给模型（现在只有它自己搜出来的那几条 + 小目录整表）。
- **200 内部**要新增「造」这条路：发一个造的需求给 Pi → 跟随后续 → 回报；造出的东西落回目录，下一轮策划能检索到。
- **反馈**：发起的初始阶段要有可见状态句（不是等终态包装）。走片场工具块还是另开「进行中」语义，待定。
- 不做的：改 Pi 内核；在匠石侧自建能力注册表。

**已知前置（会在这一步被撞到）**

- **目录是「第一次策划时读一次并缓存」的**：不处理这件事，同一会话里造出来的工具**检索不到**，于是会重复造。
- **重复造**：判断「有没有现成的」依赖目录新鲜；目录不刷新 + 不判重，同一天能把同一件事造三遍（B16/B33/B43 三个「我没有」块就是现在的痕迹）。
- **预算/资源未实现**：见下。
