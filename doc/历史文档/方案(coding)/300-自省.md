# 300 自省——实现方案

> 对应文档：[doc/design/300-自省.md](../doc/design/300-自省.md)（设计初稿，核心已定）
> 状态：初稿，待确认后编码。
>
> **本次级别：最小**（结构可运行、可回归）。切片只接两个触发源：**事件结果** 与 **闲时回顾**；
> 其余 7 类触发源、判定机制（个人世界 + 心智）、⑥ 候选形态都留占位，见 §5。

## 0. 目标与范围

### 做

1. **300 有真正的自省入口**：`ReflectionPort` 从"一句 `reflect(prompt)`"扩成
   "触发 → 入队 → 排程 → 拼现场 → 六问 → 落记录"。
2. **入口层按「信封 + 探测器 + 三种时刻」搭**（设计 §2.1）：每个源只负责把自己的特殊性翻译成
   统一信封（条目 / evidence / 去重键 / 默认投入与及时性）；信封之后通用过程不认识源。
   本刀只实现**两个探测器**（事件结果、闲时回顾），其余源留注册位。
3. **只接两个触发源**：
   - **事件结果**：`experience()` 收尾后按 §3.2 的占位规则判定，命中就入队——**不等、不挡主流程**；
   - **闲时回顾**：宿主显式调 `process.introspect_idle(subject_id)`（CLI 子命令 `introspect-idle`）。
     本次**不做**后台定时器、不做空闲探测。
   - CLI `jshi reflect|inner` 保留，作为"人工"触发走同一条路（同步返回，命令行为兼容）。
4. **现场**（设计 §4.1）：账本按**时间窗** `[t0−Δ, t1+Δ]` 取段 + 09 召回一次，拼成现场正文。
5. **六问**（设计 §4.2，**不缩**）：一次结构化模型调用（新 skill `introspection`）；
   解析失败降级为整段文本落库，**不阻断、不重试**。
6. **并行**（设计 §3.4）：进程内自省队列，按 **及时性 → 触发时间** 排序；
   主题锁 + 冷却；队列上限 + 单次超时。跑在哪个线程见 §5.10。
7. **落记录**：04 `kind=internal` 活动、历史事件、`CognitiveContent`；
   ⑥ 候选写 **占位记录**（500 学习未立，不写 08 / 100）。

### 不做（本切片明确不做）

- 不做后台定时器 / 空闲探测 / 多 worker 真并发 / 抢占式"让路"；
- **不调 `append_internal`**——接上就会被 30 投进 09，而设计 §11-C12 未定，见 §5.1；
- 不写 100 / 08（候选只写占位记录）；
- 不接 200 工具入口（`intake` 的 `object_id` 语义未定，见 §5.2）；
- 不接做梦与情绪（触发源本身还不存在）；
- 及时性 / 投入等级不接个人世界与心智，先用**触发源默认值**（见 §5.3）。

## 2. 数据结构

### 2.1 枚举（`reflection/port.py`）

```text
IntrospectionTrigger   event_result | idle | manual        # 预留 7 类见设计 §2
IntrospectionUrgency   urgent | soon | slow
IntrospectionLevel     low | medium | high
IntrospectionStatus    queued | running | done | dropped | failed
```

### 2.2 数据类（`reflection/port.py`）

```text
IntrospectionRequest
  subject_id / trigger / urgency / level
  entry_ref        # 被考察条目：activity:<id> | segment:<id> | manual:<主题>
  entry_at         # 条目发生时间（"当时"的中心）
  entry_text       # 条目文本（现场取窗与召回 query 的种子）
  object_id / note / request_id / created_at

IntrospectionScene                       # 设计 §4.1 的现场
  request_id / subject_id / entry_ref
  window           # (开始 − Δ, 结束 + Δ)
  segments         # ①②：时间窗内的经历段（含 internal 段）
  recalled         # ③：09 召回的片段
  text             # 拼好的现场正文（六问的输入）
  source_ids       # 段 id + 召回 event_id，供溯源

IntrospectionAnswer                      # 六问（⑤ 拆三个出口）
  what / choice_and_result / why / better
  next_time        # ⑤a 条件—动作
  tool_need        # ⑤b 要不要用工具 + tool_capability / tool_when / tool_worth
  interaction_need # ⑤c {object_id, kind: apologize|reply|explain|confirm|ask, gist, when}
  worth_learning   # ⑥
  candidates       # ⑥ 占位：形态未定，先原样存
  raw_text         # 模型原文
  degraded         # 解析失败降级标记

IntrospectionRun                         # 一次自省的落库结果
  request / scene_source_ids / answer
  activity_id / cognitive_content_id
  status / duration_ms / model_tag
```

### 2.3 历史事件（`HistoryKind.SUBJECT`）

| event_type | 何时写 | 关键内容 |
|------------|--------|----------|
| `introspection_queued` | 入队成功 | trigger / entry_ref / level / urgency |
| `introspection_dropped` | 未入队或被丢 | reason：`cooldown` / `queue_full` / `disabled` / `timeout` |
| `introspection_done` | 六问落库后 | activity_id / cognitive_content_id / 段数 / 召回数 / 耗时 / model_tag |
| `introspection_candidate` | ⑥ 判定值得学时（占位） | suggested_kind / content / worth_learning |

### 2.4 魔法数（`core/params.py`，**全部占位，交 400 调**）

```text
INTROSPECTION_ENABLED = True
INTROSPECTION_SCENE_WINDOW_SECONDS = 600      # Δ：条目前后各取多久
INTROSPECTION_SCENE_MAX_SEGMENTS = 40         # 现场段数上限
INTROSPECTION_RECALL_LIMIT = 6                # 09 回溯条数
INTROSPECTION_COOLDOWN_SECONDS = 3600         # 同主题冷却
INTROSPECTION_MAX_QUEUE = 8                   # 队列上限（超了丢最"缓"的一条）
INTROSPECTION_TIMEOUT_SECONDS = 90            # 一次自省超时
INTROSPECTION_MODEL_CALLS_LOW = 0             # 低：不调模型
INTROSPECTION_MODEL_CALLS_MEDIUM = 1          # 中：1 次
INTROSPECTION_MODEL_CALLS_HIGH = 3            # 高：最多 3 次
INTROSPECTION_IDLE_WINDOW = 40                # 闲时回顾只在"最近 K 段"里挑，避免翻旧账
```

### 2.5 入口层类型（`reflection/port.py` 与 `reflection/sources/`）

```text
SourceContext                      # 一次 pump 的上下文（探测器只读它）
  subject_id / moment / now
  activity / plan / action_id      # 仅 after_activity 时刻有
  repository / ledger / memory / hang_store

IntrospectionSource（协议）
  name: str
  moments: frozenset[str]          # after_activity | idle | explicit
  detect(context) -> tuple[IntrospectionRequest, ...]

SOURCES = (EventResultSource(), IdleSource())        # 本刀两个；其余源留注册位
detect(moment, context) -> tuple[IntrospectionRequest, ...]
  ① 逐个探测器问一遍
  ② 合并：同一 entry_ref 的多条 → 合成一条（条目取该条记录，evidence 合并，level/urgency 取高）
  ③ 交判定层（本刀直接落默认值）→ 入队
```

信封字段与三种时刻的定义见设计 §2.1；探测器集中住 `reflection/sources/`，
**两个例外**（事件结果的钩子在 `experience()` 末尾、人工入口在 CLI）由主流程那两行负责。

## 3. 行为变更

### 3.0 入口层（每个源怎么接）

```text
after_activity（收尾后 pump 一次）
    EventResultSource.detect(ctx)
       最后一条 ToolResult 的 status != "ok"   → 信封（条目 = 该活动，证据 = {tool_status}）
       （think 不作信号；ideal 只作辅助，见 §3.2 与 §5.14）
idle（宿主调 introspect_idle 时）
    IdleSource.detect(ctx)
       最近 K 段里"最早未自省过的一段"      → 信封（条目 = 该段）
explicit（CLI reflect）
    直接造信封（条目 = manual:<主题>），不走探测器
```

- 探测器**只读**：不写历史、不入队、不改状态；入队由 300 统一做；
- 本刀不接的源（边界被触碰、承诺、同类重复、对象关系变化、情绪）**留注册位**，
  在 §5.11 / 设计 §11-C16-C17 里写明缺什么信号。

### 3.1 主流程钩子（事件结果触发）

位置：`process.experience()` 末尾，`governance.check(...)` 之后、`return` 之前
（`process.py:828` 一带）。

```text
timing = clock.finish(completed.id)
self._maybe_trigger_introspection(subject_id, completed, plan, action_id)   # 新增
return SubjectActivityResult(...)
```

- 只入队，不等待；整段包 `try/except`，异常只 `logger.warning`——**自省坏了不能影响本轮**；
- 入队失败（冷却 / 队满 / 禁用）写 `introspection_dropped`，不影响返回值。

### 3.2 占位触发规则（事件结果）

| 信号 | 本次判据 | level / urgency |
|------|----------|-----------------|
| 工具没做成 | 本次活动的记挂里最后一条 `ToolResult` 的 **`status` 不是 `ok`**（主判），或 `ideal is False` **且** `ideal_note` 非空（辅助）；按 `field_ref.activity_id` 匹配（`HangStore.list_for`） | 中 / 尽快 |
| 其他 | 不触发 | — |

**为什么去掉 `mode == "think"`**：cognition 提示词里 `think` 是"没有人期待你开口"的**正常**模式，
拿它当"结果出乎意料"会大量误触发；而且 `ToolResult.ideal` 的**默认值就是 `False`**
（`tool/contract.py:134`），单看 `ideal` 会把没设过这个字段的结果当成失败——所以主判改用 `status`。

**承认的失败面**：本轮收尾时只看得见"自己这一边的结果"；结果到底好不好，往往要**下一轮**
（对方的反应）才知道。结果类自省要么**滞后一拍**，要么先用弱信号——本刀选前者（跨拍回看留到下一刀）。

边界被触碰、认识被修正、同类重复、承诺、人工 / 治理、关系变化这 6 类**本次不接**（设计 §2 已列，
按 §5.3 的"判定机制待完善"留到下一刀）。人工触发（CLI `reflect`）按 高 / 尽快 处理。

### 3.3 闲时入口

`process.introspect_idle(subject_id, *, object_id=None) -> IntrospectionRequest | None`

- 选条目（**占位、确定性**，不用纯随机，见设计 §11-B6）：只在**最近 K 段**
  （`INTROSPECTION_IDLE_WINDOW`）里取"最早一段尚未自省过的段"
  （自省过的判定：历史里有指向它的 `introspection_done` / `introspection_queued`）；
  **限定 K** 是为了不让闲时从最老开始"翻旧账"；
- `entry_at = segment.occurred_at`，`entry_text = segment.text_raw or 该段 state_delta 摘要`；
- level = 低 / urgency = 缓；命中冷却则返回 `None` 并记 `introspection_dropped`。

### 3.4 队列与执行

```text
enqueue(request)     主题锁命中冷却 → dropped(cooldown)
                     队列已满      → dropped(queue_full)（丢最缓的一条，同级丢最旧）
drain(subject_id)    取队首（urgency 序：urgent > soon > slow；同级按 created_at）
  拉主题锁 → build_scene → run_introspection → 写冷却 → 释放锁
  超时（INTROSPECTION_TIMEOUT_SECONDS）→ 记 dropped(timeout)，丢弃半成品
```

- 本刀的 `drain` 是**同步执行口**：由宿主在**两拍之间**调用（CLI 每轮之后、`introspect-idle`
  命令里、以及测试里）；常驻 daemon worker 见 §5.10；
- 主题键 = `entry_ref`；锁与冷却都在内存（重启丢失，本次接受，见 §5.7）；
- "让路"本次只用 **队列上限 + 超时** 表达；抢占式让路与全局配额等设计 §11-B4 定了再说。

### 3.5 现场构建（`scene.build_scene`）

```text
① 当时的上下文 + ② 前后现场
   segments = [s for s in ledger.list_experiences(subject_id)
               if window_start <= s.occurred_at <= window_end]
   按 sequence 升序，超过 INTROSPECTION_SCENE_MAX_SEGMENTS 从两端等量截断
   段状态取 accepted / consumed（不取 archived）；段正文用 text_raw，
   无正文的段用 state_delta / response_plan 摘要
③ 回溯记忆
   recalled = memory.recall(subject_id, entry_text, limit=INTROSPECTION_RECALL_LIMIT,
                            object_id=request.object_id, level=1)
拼正文
   现场 = 时间地点 + ①②按段列（说话人/输出类型 + 文本）+ ③召回片段（content or text）
```

- 现场**只读**：不写账本、不写活跃区、不改个人世界；
- 找不到任何段与召回时，**不硬编**：记 `dropped(no_material)`（设计 §4.1「材料不足就不硬编」）。

### 3.6 六问执行与降级

```text
purpose="introspection"
input_text = 现场正文
subject_state = 该主体的当前组装身份（只取 subject_state，不装活跃区：对齐 00 §4.2）
skill.run(...) → 六字段 JSON
  JSON 合法 → IntrospectionAnswer（六问齐全；缺字段按空串，不补编）
  解析失败 → 降级：answer.raw_text = 模型原文，六字段空，status 仍 done（标 degraded）
模型调用次数受 INTROSPECTION_MODEL_CALLS_* 限制（低档 0 次 → 不调模型：只落规则摘要 + 一条记录，
字段仍一个不少、④⑤⑥ 标"未评"；见设计 §3.1「步骤不减、深度可变」与 §11-B5「低档简单跑」）
```

- ⑤b 的判据用《概念词汇》「工具」那三条（在主体边界之外 / 主体自己办不到 / 有代价有不确定）
  + **经 200 才算工具**（叫模型、召回记忆、装载个人世界都不算）；
- ⑤c 只产出**候选**：本刀**不写承诺、不写关系、不发 `intake`**（设计 §11-C19）；交往需求的红线见设计 §5。

### 3.7 落记录

```text
04：Activity(kind=INTERNAL, trigger=entry_ref) + activity_created
认知：CognitiveContent(kind=EVALUATION, epistemic_status=CONSIDERING,
                      evidence_kind=COGNITIVE_REASONING,
                      source_ids=现场 source_ids, model=model_tag)
      （是否新加 CognitiveKind.INTROSPECTION 见 §5.4）
历史：introspection_queued / introspection_done / introspection_candidate
07：activity_close.close(reason="introspection_finished")
```

`worth_learning` 为真、或 ⑤b / ⑤c 有内容时，写一条 `introspection_candidate`（占位载荷：
`suggested_kind` + `content` + `tool_need` + `interaction_need` + 现场 source_ids）。
**不写 08 / 100、不发 `intake`、不建承诺条目、不调 `append_internal`**（§5.1 / §5.12 / §5.13）。

### 3.8 与主流程的隔离

- worker 只读：账本、记忆、身份；不写：活跃区、经历段、个人世界、参数；
- 不调 05 / 06 / 10 / 200；
- 自省活动不参与主流程的"当前活动"（不置 `last_*`、不进 `StepClock`）；耗时单独记在
  `introspection_done.duration_ms`。

## 4. 测试计划

新增 `tests/test_introspection.py`（风格对齐 `tests/test_subject_process.py`：`tmp_path` + `ContextModel` 替身）：

| 用例 | 断言 |
|------|------|
| 探测器：事件结果 | 直接调 `detect("after_activity", ctx)`：`mode=think` → 1 条信封；`mode=respond` 且工具达理想 → 空 |
| 探测器：闲时 | `detect("idle", ctx)` → 信封条目 = 最早未自省过的那段；全部自省过 → 空 |
| 入口合并 | 同一活动同时命中"没开口"+"工具未达理想" → **只出 1 条**，`evidence` 里两个信号都在 |
| 探测器只读 | 调完 `detect` 后：历史条数、账本段数都不变 |
| 事件结果触发：工具没做成 | 记挂里放一条 `status=failed` 的 `ToolResult` → `experience()` 正常返回；历史多出 `introspection_queued`；不被自省拖住 |
| `think` 不触发（回归） | `mode=think` 且无失败工具 → **无** `introspection_queued`（正常沉默不当异常） |
| 事件结果不触发：工具 `status=ok` | 无 `introspection_queued` |
| 闲时回顾选条目 | 取到"最早未自省过的一段"；已有自省记录时跳到下一段 |
| 现场时间窗 | 造 5 段（±Δ 内外各 2 段）→ 只取窗内；段数与顺序正确；`recall` 被调一次且 query 是条目文本 |
| 无材料 | 空账本 → `dropped(no_material)`，不调模型 |
| 六问落库 | 模型返回合法 JSON → `CognitiveContent` + `introspection_done`，六字段与 JSON 一致 |
| 六问降级 | 模型返回非法 JSON → 不抛异常，`raw_text` 落库、status 标 degraded |
| 候选占位 | `worth_learning=true` → 有 `introspection_candidate`；无则没有 |
| ⑤b / ⑤c 只落记录 | 模型回 `tool_need=true` / `interaction_need={object_id,...}` → 候选记录载荷里含这两项；**08 个人世界条目数不变、无 `intake` 记录、无 `ToolRequest`** |
