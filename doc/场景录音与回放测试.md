## 首个单人场景发现后的修复

2026-10-29：回放时钟已移到模型初始化完成后启动，避免加载耗时使后续音频追赶投递。旧本地 `LocalASR` 新增每段所处窗口、收尾原因、流式解码及分析转写耗时，帮助区分窗口等待与计算时间；未修改其6秒上限或声学端点策略。

`SessionAudio` 取音增加末尾20毫秒内的有界容差：请求尾部略超已有音频时只使用实际已有范围，不补静音；原转写时间保留，直接匹配的诊断另记实际取音范围和修剪量。更大的差距、起点缺失及已淘汰区间依旧失败，不跨会话取音。20毫秒是本轮保守工程容差，未宣称已完成供应商边界校准。

原18.2秒素材的末段原请求结束为18.202秒，修复后实际取到18.200秒，并在隔离副本中恢复qf声纹匹配。这是本地取音／匹配复验，没有重发外部服务。不能据此推断全部信封合批与JEV问题已解决。

随后已将火山本地声音完整度接入正式在线入口，并原速复测同一素材。三段均匹配qf；声音判断第一段完成，后两段未完，EOF时原文完整释放。详细配置与降级见[整句判断说明](整句判断说明.md)。这不等于独立场景平台的完整合批／撞车报告功能也已实现。

## 收录录音

重启语音服务加载新代码后，从“近期录音 → 长期场景测试库”进入 `/entry-tests`。

1. 点击近期连续录音卡片的“选取这段现场”，查看波形并试听。
2. 拖动开始、结束位置，或播放到需要的位置后标记起点、终点；试听选中区间。
3. 填写场景名称，点击“保存场景与录音”。说明和预期可稍后补充。

也可上传16kHz、单声道、16位PCM WAV。其他格式当前需先转换，不能直接导入。每次从近期缓存选取最长五分钟，原声独立复制，不随近期缓存过期；缺失区间拒绝保存，不补静音。

素材默认位于程序数据目录的 `entry_test_assets/`，与当前人格的近期缓存独立。页面保存场景新版本，旧版本保留。素材及运行记录被 Git 忽略。库没有自动备份或容量清理，重要素材应另行备份。

现有近期录音没有逐音频块接收记录，保存后标记为“重建输入节奏”；不能精确还原网络抖动。新存储接口支持完整接收时间表，但实时采集侧尚未接入自动记录。

## 命令行

```powershell
python tools/entry_replay.py --root .jshi/entry_test_assets list
python tools/entry_replay.py --root .jshi/entry_test_assets import-wav C:/recording.wav
python tools/entry_replay.py --root .jshi/entry_test_assets save C:/scenario.json
python tools/entry_replay.py --root .jshi/entry_test_assets run SCENARIO_ID --decoder-factory jshi.testing.entry_cases.adapters:local_decoder
```

用实际数据目录替换 `.jshi`。本地模型位置通过既有 `JSHI_VOICE_LOCAL_DIR` 配置，只读加载模型；每次运行新建人物和声纹状态，不读取正式人物参考。`qwen_decoder` 可替换本地适配器，需要已有千问与本地分析模型配置，可能调用真实服务。

`--fast` 只用于内容检查，不用于断句等待、耗时或撞车结论。默认原速回放，结束后等待一秒再明确标记 EOF 强制刷新。音频生产不等待识别完成，积压走正式管线的限制。

冻结 JEV 场景文件示例属于人工构造的格式示意：

```json
{
  "schema_version": 1,
  "name": "人工入口样例",
  "timeline": [{
    "type": "jev", "at_ms": 0,
    "batch": [{"n": 1, "who": "unknown", "text": "你好", "source": "audio"}],
    "context": [], "delivery": {"state": "completed"}
  }],
  "annotations": {"note": "预期待人工填写，不进入模型请求"}
}
```

```powershell
python tools/entry_replay.py run SCENARIO_ID --gate-factory jshi.testing.entry_cases.adapters:live_gate
```

真实 JEV 采用环境模型配置，需要事先配置凭据；此命令会调用真实模型。三种模式均运行并保存完整实际请求、结果及阶段记录。decision 服务在新运行状态中默认 off，实际会回退；当前尚无页面配置 active 的入口，不能据此判断原生 decision 的质量。自定义工厂可显式设置服务配置和回调，但不得写正式数据。

输出在 `test_runs/entry/<运行编号>/`，包含场景快照、事件、请求和结果 JSON。人工预期留在场景快照，不发送给模型。暂无自动评分、HTML 并排报告。

## 覆盖边界

已实现：长期录音收录、人工音频场景编辑与版本、连续流式回放、真实识别管线时间事件、冻结 JEV 三模式入口、结果归档和未评分标记。

未完成：统一信封 E5/E6 与正式会话合批接入、联测、受控撞车屏障、页面运行／取消、原生 decision 的设置页面、时钟平移、人工标注评分和对比报告，以及文字／图片／视频的页面输入。冻结 JEV 多事件回放只是按时间发起调用，不代表已经验证正式撞车调度；结果明确标记该覆盖边界。

本批没有变更业务提示词或模型请求组装规则，没有自动保存既有录音或调用真实模型。实际使用前先重启应用加载路由。
