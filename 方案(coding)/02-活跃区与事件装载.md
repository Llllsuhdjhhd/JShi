# 02 活跃区与事件装载——实现方案

> 对应文档：doc/design/02-活跃区与事件装载.md（初稿，含"初始化无特例"）
> 状态：初稿，待确认后进入编码

## 1. 目标与范围

占位 → **最小实现**（活跃区装载与剔除/落位可运行，模型筛选与动态参数占位）：

- 阶段② 只**装载**活跃区事件视图并**标记本次输入**（`subject/event_loaded`），不调用模型、不调整；
- **初始化无特例**：第一次输入时活跃区为空，装载结果是空事件视图，流程与后续输入完全一致；
- 阶段⑦ 超预算时程序按 `updated_at` 剔除（占位策略）、落位记忆、记账 `event_evicted`；显式事件 id 可召回（`recall_by_ids`，记账 `event_recalled`）；
- 活动挂载：认知后模型返回 `focused_event_ids` 时回填活动事件挂载（占位模型不返回 → 挂载空）；
- 从主流程**摘除归属判断**：不再调用 `AttributionPort`、不写 `input_attributed`、不再双路组装；端口保留并标注已废弃，待 07 统一清理；
- 概念迁移的接口侧先行：新接口用 `event` 命名；数据字段 `active_concern_ids`、`PersonalKind.CONCERN` 保持兼容，迁移由 07 事件生命周期负责。

不做：

- 事件独立表 / 07 事件生命周期（事件本体仍存 `personal_items`，kind=concern）；
- 模型筛选协议真实解析（`focused_event_ids` 字段占位、默认空；提示词协议归 05 认知文档）；
- 完成事件的超时归档（依赖定时触发，07 / 12）；
- 动态活跃区比与弹性策略参数化（14 调参系统占位，本期常量）；
- 新事件创建/完成由模型提议的接线（仍走 `propose_open_matter` / `close_personal_item` 现有接口）；
- CLI 显式事件 id 参数（本期不做，接口预留）。

## 2. 接口落点

### 新增 `src/jshi/activezone/`（端口 + 进程内实现）

- `ActiveZoneEvent`：`event_id`、`content`、`status`（unfinished / completed）、`updated_at`、`metadata`；
- `ActiveZoneView`：`events` 元组（预算内、排除已剔除事件）、`budget`、`loaded_at`；
- `ActiveZonePort`（Protocol）：
  - `load(subject_id, input_text, *, budget=None) -> ActiveZoneView`——只读装载，不调整；空集合法；
  - `evict_overflow(subject_id, view, *, elasticity=1) -> tuple[ActiveZoneEvent, ...]`——超预算剔除（占位按 `updated_at` 从旧到新），返回被剔除事件；
  - `recall_by_ids(subject_id, event_ids) -> tuple[RecalledFragment, ...]`——显式事件 id 直接装载/召回，程序侧唯一文字匹配之外的窄接口；
- `InProcessActiveZone`：基于 `SubjectRepository` + `MemoryPort` 的实现：
  - 事件来源：`personal_items` 中 `kind=concern` 的条目（未完成 = `status=ACTIVE`；完成 = COMPLETED / RELEASED / SUPERSEDED）；
  - 剔除 = 写 `metadata["zone_state"]="evicted"`（保留 `evicted_at`），不删事件本体、不改 `status`；
  - `recall_by_ids`：对 evicted 事件恢复可装载（移除 evicted 标记），返回 `RecalledFragment(event_id=item.id, event_type="event", text=item.content, kind="event")`；对未剔除事件直接返回片段，不改变状态。

### 常量

- `ACTIVE_ZONE_RATIO = 1 / 66`——设计语义常量，保留供 14 调参系统换算；
- `ACTIVE_ZONE_DEFAULT_BUDGET = 8`——占位条数预算；未来按"模型上下文 × ratio"换算，本期不按 token 核算；
- `ACTIVE_ZONE_EVICTION_ELASTICITY = 1`——允许超出 1 条不剔除（软约束的一次弹性）。

### 修改 `src/jshi/models/base.py`

- `ModelResponse` 增加 `focused_event_ids: tuple[str, ...] = ()`：认知阶段模型聚焦的事件 id（与 `recall_requests` 同模式，占位默认空）。

### 修改 `src/jshi/subject/process.py`

- `SubjectProcess.__init__` 增加 `active_zone: ActiveZonePort | None = None`，默认 `InProcessActiveZone(repository, memory)`；摘除 `attribution` 依赖（参数保留可选，默认废弃占位，主流程不再调用）；
- `AssembledCurrentState`：`open_matter_ids` 语义调整为 `active_event_ids`（本次装载的事件 id），新增 `active_zone` 视图引用；
- `SubjectPreview`：删除 `attribution` / `mode` 字段，改为 `active_zone` 视图；
- `experience()` / `preview_state()`：删除 `_judge_attribution`、`_assemble_concern_centric` 与双路分支，改为单一路径；
- 阶段④ 活动建立：挂载空（或显式引用），认知后由 `focused_event_ids` 回填（`update_activity(activity.id, active_concern_ids=...)`，字段名待 07 迁移）；
- 阶段⑦ 收尾：活动完成前执行 `active_zone.evict_overflow(...)`，逐条记账 `event_evicted`。

### 修改 `src/jshi/app/cli.py`

- `preview-state` 输出：去掉"归属 / 组装模式"，显示活跃区事件列表；
- 其它命令不变。

### 修改 `src/jshi/attribution/port.py`

- 文件头标注"已废弃（02 起不再接线）"，代码保留供测试与回退。

## 3. 数据结构

### 活跃区持久化（本期不建新表）

| 存储 | 内容 |
|------|------|
| `personal_items`（kind=concern） | 事件本体（内容、状态、来源、时间） |
| `personal_items.metadata` | 剔除标记：`zone_state="evicted"`、`evicted_at` |
| 历史记录 | 记账：`event_loaded` / `event_evicted` / `event_recalled` / `activity_events_attached` |

被剔除事件"落位记忆" = 事件本体保留 + `event_evicted` 历史记录作为记忆锚点；接入 09 记忆引擎后改为调用引擎落位。

### 历史事件（`HistoryKind.SUBJECT`）

| event_type | content | source_ids |
|------------|---------|------------|
| `event_loaded` | `event_ids`、`unfinished_ids`、`completed_ids`、`budget`、`input` | `(fact.id, *event_ids)` |
| `event_evicted` | `event_id`、`content`、`status`、`reason`（默认 `budget_overflow`） | `(event_id,)` |
| `event_recalled` | `event_ids` | `(*event_ids,)` |
| `activity_events_attached` | `activity_id`、`event_ids`、`basis`（`model_focus`） | `(*event_ids,)` |
| `current_state_assembled`（字段变化） | 删除 `mode` / `attributed_concern_ids`，改为 `event_ids`、`budget` | `(fact.id, *event_ids)` |

不再产生 `input_attributed`。

## 4. 行为变更

1. 阶段②：`active_zone.load()` → 记 `event_loaded`；不调用模型（零额外 LLM 延迟）；
2. 空活跃区（首次输入）：同一条路径，`view.events == ()`；不设初始化分支；
3. 无归属判断：不写 `input_attributed`，模型调用次数仅来自认知阶段（含追加召回轮次）；
4. 阶段③：单一路径组装——身份 + 活跃区事件 + 承诺 + 当前输入；文本召回只保留为追加召回（05），阶段③不再全量文本召回；
5. 阶段④：活动建立时空挂载；认知后 `focused_event_ids` 回填并记 `activity_events_attached`（占位模型不返回 → 空）；
6. 阶段⑦：超出预算 + 弹性后仍超出的，按 `updated_at` 从旧到新剔除到"预算 + 弹性"以内；剔除只改 `metadata` 标记，不删事件、不改事件状态；
7. 显式事件 id 引用：`recall_by_ids` 恢复 evicted 标记并返回片段，记 `event_recalled`；程序侧不做文本关键字解析，事件 id 由输入信封/活动上下文显式携带（未来）；
8. 完成事件在预算允许时保留在活跃区；
9. `preview_state` 保持只读、不调用模型，输出活跃区视图。

## 5. 测试计划

新增 `tests/test_active_zone.py`：

- 首次输入（空活跃区）：`event_loaded` 的 `event_ids == []`，活动正常完成；计数模型断言阶段②无额外调用（全程仅认知调用）；
- 存在未完成事件：装载包含该事件，`event_loaded` 有记录；
- 完成事件：预算允许时保留在活跃区；
- 超预算：剔除 `updated_at` 最旧事件，记 `event_evicted`，事件本体仍在（status 未变、metadata 有 `zone_state=evicted`）；
- 弹性：仅超出 1 条时不剔除；
- 剔除后可召回：`recall_by_ids` 恢复可装载并记 `event_recalled`，后续 `load` 重新包含；
- 模型返回 `focused_event_ids`：活动回填并记 `activity_events_attached`；
- 显式 id 装载不经过模型；
- `preview_state` 只读：不落库、不调用模型，返回活跃区视图。

修改既有测试：

- `tests/test_new_flow.py`：删除归属断言（`attribution_single_concern_continuation` → 活跃区装载断言；`full_assembly_when_no_concern` → 空活跃区断言）；`preview` 断言去掉 `attribution` / `mode`；
- `tests/test_subject_process.py`、`tests/test_external_activity_flow.py`：`input_attributed` 断言改为 `event_loaded`；`active_concern_ids` 断言改为"认知后回填或空"。

回归：全部 pytest 通过（`py3125` 环境，`--basetemp` 指向工作区 `.pytest-tmp`）。

## 6. 风险与未决

- **预算单位**：本期用条数（默认 8），与"上下文 × 1/66"的 token 语义有偏差；未来由 14 调参系统按模型上下文换算并留审计；
- **剔除策略**：`updated_at` 占位，模型选择未来接入；
- **事件本体归属**：仍存 `personal_items`（kind=concern）；07 文档需定义事件独立表/字段迁移，届时 `active_concern_ids` 迁移为 `active_event_ids`；
- **超时归档**：未实现，依赖定时触发（07 / 12）；
- **模型协议**：`focused_event_ids` 字段占位，真实提示词与解析归 05 认知文档；
- **记忆落位**：目前是历史记录 + metadata 标记，接入 09 后改为调用记忆引擎。
