# 05 模型提示词分层——实现方案

> 对应：`doc/design/05-认知.md` §4 / §8；组装材料来自 03，本方案只改**发给模型的 HTTP 形态**
> 状态：**已确认并编码**
> 本轮不做流式（I-001 仍开放、不纳入）

## 0. 独立判断

现行 `OpenAICompatibleModel` 把 skill 说明、Schema、说话人 UUID、身份、价值列表、整份工作集 JSON 拼进**一条 system**。同一段对话在 `context_view` 全文和 `segments` 里各出现一次；身份 / 对象 / 价值在适配器前半和 JSON 里再各写一次。正反例里的 `{speaker_label}` 全局替换后，第三人例子会和当前说话人撞名。

这些是发送形态问题，不是 03 工作集错了。身份分片、对象分片仍要留给缩减保护；价值实例仍在 08。改的是：稳定内容进 system，本轮会变的进 user；能用正文说清的不用 JSON 分片。

不做流式：口头仍等整份 JSON。提示词里「先填 `response_plan`」只约束字段，不提前开口。

## 1. 目标与范围

### 做

1. **System**：认知规则（无正反例、无说话人占位）+ 紧凑 Schema + 匠石身份/立场 + 08 正文（价值 `content` 换行连接；承诺、边界同样）。
2. **User**：`{名字}：{本轮原话}`；上一活跃区只给一份「段 id + 原文」；在场回忆摘录同行。默认不出现 `object_id`。
3. **仅重名未消歧**时，user 用别名等可区分信息标明「不是世界上只有这一个人」，**不写 UUID**。
4. 模型 JSON 里 `object_assessment.object_id` 为空时，程序填本轮说话人 id（已有召回绑定逻辑不改）。
5. `/prompt` 展示分层后的 system 与 user，不再只打 skill 骨架。
6. skill 升 **v6**。确认后回写 05 §4 三句（HTTP 形态；对象在 `ModelRequest` 单列不等于写进 system；段 id 仍为缩减依据）。

### 不做

- 不改 03 五源、不删身份/对象分片、不改 08/100 存储、不改 16 活跃区结构。
- 不删价值库条目（含 `val-20`）。
- 不做流式、function calling、越狱条款、按对象切活跃区。
- 不把 `lux：` 前缀写入经历账本；落库仍是对方原话。
- 不把个人世界挪到 user。

### 本次层级

最小：真实 HTTP 两条消息按上表拼；单测锁形态与「无 id / 重名才有 id」；既有流程测试不因组词变化而改契约。

## 3. 数据结构

不新增表，不迁数据。

```text
ModelSpeaker
  object_id, label, aliases, status
  reason            # 新增，来自 01。重名未消歧：ambiguous_names / ambiguous_names_no_memory

AssemblySpeaker
  同上增加 reason
```

`ModelRequest.context` 仍可含 03 全部分片（程序与缩减仍认这些 id）。**写入 HTTP user 的只有：**

- `kind=active_zone_refs` 的 `segments`（有则用；**不用**同条上的空 content，也不用 `kind=context_view` 全文）
- `source=memory` 的分片
- 活跃区 `recall_excerpts`（若未与 memory 去重则只保留一份，优先段/摘录列表）

**写入 HTTP system 的 08 正文（非 JSON）：**

- 身份、立场：`subject_state.identity_summary` / `current_stance`
- 价值：`salient_values` 各条 `content`，换行连接
- 承诺：`commitments` 同样
- 边界：`context` 里 `kind=boundary` 的 `content`，换行连接（工作集里有才写；无则整节省略）

空节省略，不写「已有承诺：」空行。

## 4. 行为变更

### 4.1 System 骨架

```text
{CognitionSkill.instruction}          # 无正反例、无说话人姓名/id
请严格按下面的 JSON Schema…
JSON Schema：{紧凑 JSON}

你是{identity_summary 逗号来源}。你以{名}的身份回应对方，不是在讨论、也不是评审。
当前立场：{current_stance}

【价值】
{content₁}
{content₂}
…

【承诺】
…

【边界】
…
```

对象确认规则改为指「user 里的说话人名字」：渠道已指定则按这个人；不要问「你是这个名字吗」；只在 user 标明重名时才问清是哪一位。问第三人仍走召回，`object_ids` 用那人已有档案或留空（I-011 规则保留，例子删除）。

### 4.2 User 骨架（外部认知）

默认：

```text
【说话人】lux
【活跃区】
{segment_id}：{原文}
…
【回忆】          # 无则整节省略
{memory:id}：{正文}
【本轮】
lux：你好吗
```

`reason` 以 `ambiguous_names` 开头时，在【说话人】下增加：

```text
此名字有多份档案，未消歧。当前这一位别名：…（无别名则写「当前先按这一位。」）不要当成世界上只有这一个人。
```

provisional 且非重名：一句「档案暂定，无冲突按此人说话，不要问你是{名}吗。」仍放 user，不放 system（避免升格后打断规则前缀缓存）。

### 4.3 程序补 id

```text
模型 object_assessment.object_id 为空
  → 填 request.speaker.object_id 与 label
模型填了别的 id
  → 不覆盖（重名时允许模型点名）
召回 object_ids
  → 仍走现有 _bind_recall_object_ids / lookup_by_name
```

### 4.4 与 03 的边界

工作集里的 `identity:stone`、`stance:stone`、`object:OBJ-…`、`context-v*` **继续装载**。HTTP 不再把它们当背景 JSON 倒出。`/context` 预览仍可列出这些分片（组装事实），与 `/prompt`（发出稿）分开。

## 5. 测试计划

| 用例 | 断言 |
|------|------|
| `build_system` 稳定前缀 | 不含说话人 label、不含 `OBJ-`、不含 `【正例】` / `【反例】`、不含 `context-v` |
| `build_system` 价值 | `salient_values` 各 content 出现一次，无 `personal:val-` id |
| `build_user` 默认 | 含 `lux：{原话}`；含段 id 与原文各一次；不含 `object_id=`；不含 `context_view` 全文块 |
| `build_user` 重名 | `reason=ambiguous_names` 时出现当前 `object_id` |
| Schema | `system_extra` 中 Schema 为紧凑一行对象，无缩进空格块 |
| skill v6 | `model_tag` 为 `…@v6`；instruction 无 `{speaker_label}` |
| 解析补位 | 模型 JSON 无 `object_id` 时结果等于说话人 id |
| I-011 规则仍在 | instruction 仍含「问另一个人用那人已有档案」「不要编没有印象」；**不再**要求「lux 是不是你朋友」整句正例 |
| `/prompt` | 文本含 `【本轮】` 与 system 的 `【价值】` |
| 既有流程 | `experience` 落库的 input 仍是裸原话；缩减仍拒绝 `context-v*` 当段 id |

不新增 live 调 DeepSeek 的测试。

## 6. 风险与未决

| 项 | 判断 | 处理 |
|----|------|------|
| 去掉 few-shot 后 I-009 / I-011 回潮 | 可能 | 规则仍在；本方案不靠例子。回归靠你本地 `talk`，不在本方案加活模型集 |
| 模型 remove 填错 id | 段 id 仍在 user | 继续丢弃 `context-v*`；非法 id 现有清洗保留 |
| 价值只送 content，`val-20` 像施暴描写 | 已知 | 本轮按你选的 content 连接；若要 stance 另说，不改库 |
| 缓存 | 规则+价值在 system，价值整体替换才换前缀 | 不测命中率；可选下一刀记 `usage.prompt_cache_*`（本方案不纳入） |
| 活跃区与 memory 原文相近 | 03 记忆源仍可能装到与段重复的话 | HTTP 侧按 id 去重：同一原文优先留段 id；本方案做这一层，不改 03 装载 |

拍板已含在范围里：个人世界留 system；对话与活跃区留 user；无流式。

## 9. 确认后回写 05 的三句（草案）

插在 §4「说话人必须单列」之后：

> 发给模型时：稳定规则、Schema、身份与 08 正文在 `system`；本轮原话与上一活跃区（段 id + 原文）在 `user`，写法为「名字：原话」。`object_id` 默认不出现，仅重名未消歧时写入 user。`ModelRequest.speaker` 仍单列，供程序补 `object_assessment` 与召回绑定。工作集里的身份/对象分片不因 HTTP 省略而删除。
>
> 本轮原话进账本时不加说话人名前缀。
>
> 不纳入流式分段（I-001）。
