## 3. 数据结构

`HangRecord`（对齐设计 §9.3，本轮可落地的子集）：

```text
task_id
request_id
subject_id
object_id              # 发起时说话人；装载键
origin                 # external_05
status                 # open | notified | cancelled
need / template
field_ref              # {activity_id, zone_kind: wood|persona, zone_rev}
note                   # 短由头 = need 截断
feedback               # ToolFeedback 列表（只增）
notify_caller          # 规则占位：有 RESULT 且非 propose_only 拒绝以外 → true
updated_at
```

`ModelResponse.tool_request` 最小形状（不必整份 `ToolRequest` 进 JSON）：

```text
need: str
template: str          # 可空，引擎自选
params: object         # 可空
expected_result: str   # 可空
```

编排层补：`subject_id`、`activity_id`、`origin=external_05`、`ask=execute`。

存储：`{data-dir}/.jshi/hang.jsonl` 或小 sqlite。与 `subject.sqlite3` 分开，避免记挂混进 08/16。程序崩溃可丢进行中的子进程，账本仍在（status=open，无终态）——可接受，下一刀再补巡检。

## 4. 行为变更

```text
回复调用 → 06 → 10 → 写场
         → 若 tool_request：建记挂 + 后台 execute（不等）
         → 07 completed（与有无工具无关）
```

- 本轮活动不因工具挂起。
- 工具结果不进本轮 `verbal`，不改写场正文。
- 后台完成只改 HangStore，不调 05、不调 16。
- `notify_caller=true` 本轮只落库，对话壳不自动再开口。
- Stub 单测仍同步 `submit`；后台路径用 Stub + 可 join 的测试钩子（`ToolRunner.drain_for_tests`）避免 flaky。

现场引用：木头读 `current_context_view` 的 `updated_at` 或保存后的版本字段（有则用，无则 `activity_id`）。人格用 ZoneStore 现有版本若无则同样只记 `activity_id`。禁止把 `rewritten_context` 全文写入记挂。

## 6. 风险与未决

- **后台线程 vs 进程**：Pi 子进程 + 线程同用要注意关闭。本轮测试只强制 Stub；Pi 可仍走 CLI 同步。
- **叫醒而无新活动**：用户会感觉「查完了但没回话」。这是刻意切刀，方案写明；下一刀才内部触发。
- **05 乱填 tool_request**：无判定细则时可能过触发。只靠可空 + 提示词一句；可加「need 过短则忽略」。
- **现场引用粒度**：本轮 `activity_id` 即可；16 若无稳定 revision 字段不新造。
- **D-007**：账本按对象列出，03 本轮不装，故不会每轮全量进工作集。

未决（设计已列、本方案不拍板）：内部信封字段、210 模型输入裁剪、fact 种类、Pi 预算语义。
