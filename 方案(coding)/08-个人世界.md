# 08 个人世界——实现方案

> 对应文档：[doc/design/08-个人世界.md](../doc/design/08-个人世界.md)、[doc/design/100-价值观与边界.md](../doc/design/100-价值观与边界.md)
> 状态：初稿，待确认后进入编码

## 0. 定位与顺序

- 08 只做**薄壳**，本轮不搭通用子系统框架；不把 08 和 100 一股脑做成一坨。
- 本轮重点是 **100 价值观与边界的装载侧**；08 壳只做最小接线，让 100 能进入 `03 状态组装`。
- 101–104 预留；09 记忆不在本方案范围；`concern` 仍按过渡态处理，长期归 07。

## 1. 目标与范围

### 1.1 本轮做

1. 新增 100 模块 `src/jshi/personalworld/values.py`：`ValuesPort` + `InProcessValues`，只实现装载侧。
2. 最小改造 08 薄壳 `InProcessPersonalWorld`：把价值与边界的选择委托给 100，自身只做协调。
3. `PersonalWorldPort` 增加 `select_boundaries`；`standing_constraints` 纳入 `binding` 边界。
4. `PersonalWorldSource` 正确标记承诺与 `binding` 边界为常驻，边界不因普通价值预算丢失。
5. 补齐 100 装载侧与 08 协调侧的自动化测试。

### 1.2 本轮不做

- 不实现 100 的 `propose_value` / `review_value` / `lock_value` / `supersede_value` / `consolidate`。
- 不实现 101–104，也不预设它们的内部架构。
- 不搭通用容器注册框架或独立装载报告系统。
- 不迁移 `concern`（归 07）。
- 不重构 03 的整体预算模型。

## 2. 接口落点

### 2.1 `src/jshi/personalworld/values.py`（新增，100 装载侧）

`ValuesPort` 协议：

- `select_values(subject_id, context, *, budget)`：选择普通价值观。
- `select_boundaries(subject_id)`：返回不可越过边界。
- `standing_constraints(subject_id)`：返回 `binding` 边界，供 08 汇总为常驻约束。

`InProcessValues` 最小实现：

- 读取 `PersonalKind.VALUE` 的活动条目；
- `metadata.role == "boundary"` 的条目视为边界；`metadata.binding` 缺省按 `True`；
- `binding` 边界进入 `standing_constraints` 与 `select_boundaries`；
- 非边界价值按重要程度排序，查询相关性只用于打破同一重要程度内的并列。

### 2.2 `src/jshi/personalworld/port.py`（08 薄壳，最小改造）

- `PersonalWorldPort` 协议新增 `select_boundaries(subject_id)`；
- `InProcessPersonalWorld` 增加 `values: ValuesPort` 依赖，默认构造 `InProcessValues(repository)`；
- 常驻约束 = 遗留的 `COMMITMENT` / `CONCERN` + 100 的 `binding` 边界；
- `select` = 常驻约束 + 边界（始终在场）+ 普通条目（含价值与其他预留类型，按预算截断）；
- `select_boundaries` 委托 100；
- 遗留 `COMMITMENT` / `CONCERN` 仍由薄壳直接识别，待 101 / 07 后续接管。

### 2.3 `src/jshi/assembly/sources.py`（03 侧最小接线）

`PersonalWorldSource` 在构建 `AssemblyFragment` 时：

- `concern` 继续过滤，由事件源承载；
- `commitment` 与 `binding` 边界标记 `always=True`；
- 边界片段 `kind="boundary"`，普通价值片段 `kind="value"`，避免边界混入 `salient_values`。

### 2.4 `src/jshi/subject/process.py`（最小改动）

- 默认构造 `InProcessValues(repository)` 并传入 `InProcessPersonalWorld`；
- 主流程顺序与 03 调用方式保持不变。

### 2.5 导出

- `src/jshi/personalworld/__init__.py` 导出 `ValuesPort`、`InProcessValues`，并保留 `InProcessPersonalWorld`、`PersonalWorldPort`。

## 3. 数据结构

| 结构 | 关键字段 | 说明 |
|------|----------|------|
| 边界表达 | `PersonalItem.metadata.role = "boundary"` | 暂不新增 `PersonalKind.BOUNDARY` |
| 边界约束 | `PersonalItem.metadata.binding = True`（缺省 True） | `binding` 边界进入常驻约束 |
| 价值排序 | 重要程度优先，相关性破并列 | 与现有 `item_importance` 语义一致 |

## 4. 行为变更

1. 100 的边界与常驻约束由 `ValuesPort` 提供并接入 08；普通条目暂由薄壳统一排序，待 101–104 独立后按子系统聚合。
2. 常驻约束从“承诺 + 主体面未完成现实”扩展为“承诺 + 主体面未完成现实 + `binding` 边界”。
3. 边界条目始终在场，不因普通价值预算耗尽而消失。
4. 普通价值仍按重要程度优先排序；“情境匹配档优先”留作 100 启用 `context_tags` / `domains` 后的目标语义，本轮不实现。
5. 正常活动仍只读已有个人世界，不写入、不升格长期价值。

## 5. 测试计划

### 5.1 新增 `tests/test_values.py`

- `select_values` 按重要程度排序，相关性只破并列；
- `select_boundaries` 只返回 `role="boundary"` 的条目；
- `standing_constraints` 返回 `binding` 边界；
- 边界不因普通价值预算为 0 而丢失。

### 5.2 修改 `tests/test_personal_world_port.py`

- `standing_constraints` 同时返回承诺、`concern` 与 `binding` 边界；
- `select` 始终包含边界，即使 `budget` 很小；
- `select_boundaries` 走 100 端口。

### 5.3 修改 `tests/test_assembly.py`

- `PersonalWorldSource` 中承诺与 `binding` 边界为 `always`；
- `current_state_assembled` 中 personal 源明细包含边界与价值；
- 既有去重、预算截断、跳过项报告断言保持通过。

### 5.4 回归

- 全套 `pytest` 通过；沙箱内运行需将 `tmp_path` 指到工作区。

## 6. 风险与未决

- **排序语义**：本轮维持“重要程度优先”；`08/100` 文档中的“匹配档优先”待 100 启用结构化标签后统一措辞。
- **遗留约束路径**：`COMMITMENT` / `CONCERN` 暂由 08 薄壳直接识别，未来移交 101 / 07。
- **非 `binding` 边界**：本轮把边界缺省视为 `binding=True`；非强制边界的语义留到 100 详细实现时再定义。
