# 00 流程总览——整体实现顺序与依赖

> 对应文档：doc/design/00-流程总览与输入边界.md（初稿）
> 定位：00 不映射到单个代码系统，本文件只定**整体实现顺序与依赖**。

## 1. 现状

主流程七阶段已以占位系统接线（一次提交完成）：识别、归属、意图、偶然性、反馈、治理、反思均为端口 + 占位实现；组装、活动、认识状态、关切生命周期、个人世界、记忆为最小实现。

## 2. 依赖关系

```text
01 身份识别（独立，可先行）
09 记忆系统（真实召回）──┬─→ 03 状态组装（关切中心细化）
                        ├─→ 05 认知与追加召回（预算配置化）
                        └─→ 07 关切生命周期（记忆面/主体面分离）
02 归属判断（语义确认）──依赖 03 / 09
10 行动与反馈（结果反馈）──依赖 07
11 治理与连续性（检验实现）──依赖 07 / 08
12 反思（真实化）──依赖 05
13 匠石形态（EmbodimentPort）──通道层，最后
```

06 认识状态、04 活动、08 个人世界已最小实现，按需增强，不阻塞主链。

## 3. 建议顺序

1. **01 身份识别**（当前讨论中）：对象解析（必填 / 寻找 / 新建 / 门禁 / 确认），独立模块，先行；
2. **09 记忆系统**：真实召回（或接 REMS），被 03 / 05 / 07 依赖；
3. **03 状态组装 + 02 归属判断**：关切中心细化 + 语义确认；
4. **05 认知与追加召回**：预算配置化、多轮确认；
5. **07 关切生命周期 → 10 行动与反馈 → 11 治理与连续性**；
6. **12 反思**；
7. **13 匠石形态**（通道层收尾）。

每个模块遵循：文档定稿 → 本目录方案 → 代码 → 测试。
