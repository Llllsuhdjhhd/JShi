# 00 流程总览——整体实现顺序与依赖

> 对应文档：doc/design/00-流程总览与输入边界.md（校准初稿）
> 定位：00 不映射到单个代码系统，本文件只定**整体实现顺序与依赖**。

## 1. 现状

主流程七阶段已以占位系统接线，可作为当前实验基线：识别、意图、偶然性、反馈、治理、反思均为端口 + 占位实现；组装、活动、认识状态、关切生命周期、个人世界、记忆已有不同程度的原型。

已有接线不等于七阶段顺序、阈值或占位行为已经定稿。归属判断已于概念层废弃（由活跃区装载取代），主流程摘除属于 02 的实现范围；本轮先写 02 方案，不改主流程实现细节。

## 2. 依赖关系

```text
01 身份识别（独立，可先行）
09 记忆系统（按 id 召回 / 追加召回）──┬─→ 03 状态组装（单一路径：活跃区 + 承诺）
                                    ├─→ 05 认知与追加召回（预算配置化）
                                    └─→ 07 事件生命周期（事件本体 / 超时归档）
02 活跃区与事件装载──依赖 03 状态组装 / 09 记忆（显式 id 召回）
10 行动与反馈（结果反馈）──依赖 07
11 治理与连续性（检验实现）──依赖 07 / 08
12 反思（真实化）──依赖 05
13 匠石形态（EmbodimentPort）──通道层，最后
```

06 认识状态、04 活动、08 个人世界已最小实现，按需增强，不阻塞主链。

## 3. 校准后的推进顺序

1. **全局校准**：统一输入对象语义、正常活动与后台沉淀、验证章程和决策记录；
2. **01 身份识别复核**：保留已有代码，只检查是否违反“无对象 / 暂定对象 / 已确认对象”契约；
3. **02 活跃区与事件装载**：按本文档实现装载、剔除/落位、显式 id 召回，并摘除归属判断主流程接线；
4. **03 状态组装**：改为单一路径（活跃区事件 + 身份 + 承诺 + 输入），与 02 同步；
5. **05 认知与追加召回**：明确 skill / 模型结构化请求与主体框架的边界（含 `focused_event_ids` 协议）；
6. **06 认识状态 + 07 事件生命周期 + 08 个人世界**：事件本体独立、超时归档、候选内容经后台过程沉淀；
7. **10 行动与反馈 → 11 治理与连续性 → 12 反思**：闭合结果、审查和后台沉淀；
8. **13 匠石形态**：在主体与输入契约稳定后接入通道。

每个模块遵循：全局与依赖检查 → 文档定稿 → 必要时验证性实验 → 本目录方案 → 代码 → 测试与验证。

模块编号仍用于文档定位，不强制代表实现先后。
