# 05 问第三人走追加召回——实现方案

> 对应：`doc/design/05-认知与追加召回.md` §6、想法 I-011
> 状态：**已确认并编码**
> 本轮目标：对方问起另一个人时去取记忆，口头依据召回说。不改 30，不为查询新建对象。

## 0. 独立判断

「你有哪些朋友 / lux 是不是你朋友」走 `think`、又没有 `recall_requests`，是提示词把召回收窄成「只对说话人」的后果。现行 skill 写死 `object_ids 用说话人 id`，第三人永远取不到。

这不是身份盘问：渠道上的说话人已经定了。问的是材料里有没有第三人。走 §6 信息不足即可。

正文里出现新名字时，01 的 `resolve` 会为**说话人**建暂定档；提到的第三人若走同一套 `ensure_provisional`，会污染对象库。查询必须只读已有档案。

## 1. 目标与范围

### 做

1. 认知 skill：【信息不足——追加召回】写明问第三人 = 召回；`object_ids` 用那人已有档案 id，不是只能填说话人。对不上档案则只写 `query`。
2. 正例：对方问另一个人、材料不够 → `respond` + `recall_requests`；召回回来后口头可「我想起…」，不念 `event_id`。
3. 反例：没召回就说「没有印象」；为第三人新建对象；把问第三人写成「你是……吗」。
4. 01 只读按名查找（已有 `label` / aliases，不 `ensure_provisional`）。编排层在组 `recall_requests` 前：正文里像人名的词先查找，命中则填 `object_ids`。找不到不新建。
5. 追加召回之后的第二次认知：材料里已有 `memory:` 则必须依据它们说；召回结果为空才允许说对不上。

### 不做

- 不改 30、不提前 ingest、不新增 mode。
- 不做代词解析（「他」是谁本轮不猜）。
- 不把提及名字自动写成说话人候选。
- 不在没有召回循环时让模型编关系网（I-007 仍开放、不纳入）。

05 文档 §6 方案确认后补三句：问第三人；只读档案；口头依据召回。

## 3. 行为变更

```text
对方问 lux
  → 第一次认知：材料不够 → recall_requests（query=lux 或 object_ids=已有档案）
  → 编排层 09.recall（可带 object_id）
  → 第二次认知：有片段则依据说；空则说对不上
```

初始 03 的 MemorySource 仍按**当前说话人**召回，不在组装阶段替第三人预取。第三人只走追加召回，避免每轮都把别人的记忆装进来。

## 4. 测试计划

- skill 文本：第三人、只读档案、禁止没取就说没有印象。
- 只读 lookup：已有 lux 档案则返回 id；没有则 None，库行数不变。
- 流程（假模型）：第一拍交出对第三人的 `recall_requests`，第二拍 verbal 含召回原文中的可辨片段，不含 event id。

## 5. 风险与未决

| 项 | 判断 | 处理 |
|----|------|------|
| 模型仍不申请召回 | 提示词不能 100% 约束 | 正例 + 测试锁提示词；不在编排层猜「这句话在问谁」而自动召回 |
| 重名第三人 | 与 01 相同：不够领先则只 query，不任取 | 不在本方案放宽 |
| lookup 从正文切词 | 中文无空格，乱切会误伤 | 本轮只对模型已经写进 `query` / 明显专名（如 lux）做 lookup，不做全句分词器 |

拍板：编排层**不**根据用户原话自动召回，只补全模型已提出的请求。你若要「问到已有对象名就强制召回」，须另说，那会绕过 05。
