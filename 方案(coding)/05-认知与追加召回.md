## 1. 目标与范围

把 05 从“认知 + 记忆子循环”收敛为：

- 模型单次多用途响应；
- 不另落 thought；对外产物是 `response_plan`；
- 输出 `response_plan`、对象确认、缩减意见、上下文补充需求等候选；
- 上下文补充需求只作为候选交给主流程/09，05 不执行 `MemoryPort.recall`；
- 回忆评价不由 05 同一轮输出，而是召回后另起评价过程；05 提供该过程需要的材料；
- 05 不写 `recall_extended` / `recall_metrics` / `recall_evaluated` / `recall_reference` 等记忆侧指标。

不做：

- 重要性排序 / 上下文缩减三线执行（02/14）；
- 用途段人工介入开关（15）；
- 流式响应与多用途段流式消费（I-001，未来）；
- 模型路由与版本管理（I-004，未来）。

## 2. 接口落点

### 保留 `src/jshi/models/base.py`

- `ModelResponse` 承载 `response_plan` / `recall_requests` / `object_assessment`；`text` 由 verbal item 派生，兼容旧构造。
- `RecallRequest` 是上下文补充需求，归 05 产出；`RecallEvaluation` 是独立评价过程的输出，不再由 05 同一次模型响应产生。

### 修改 `src/jshi/subject/process.py`

把当前 `_cognize` 拆成三层：

1. **05 认知层（单次模型调用）**
   - 只根据当前工作集生成 `ModelResponse`；
   - 不调用 `self.memory.recall`；
   - 不写记忆指标。

2. **主流程上下文协调层**
   - 消费 `response.recall_requests`；
   - 需要时调用 `self.memory.recall(...)` 获取补充片段；
   - 把补充片段送回下一轮认知；
   - 记忆相关日志与指标由 09 或统一记录评价系统负责，主流程只负责编排。

3. **独立评价层**
   - 召回发生后，收集请求、补充片段、最终 `response_plan` 与来源链、返回条数与耗时；
   - 使用独立模型 / 过程生成 `RecallEvaluation`；
   - 评价不可用时不阻塞主流程。

若后续为 09 建立独立召回协调器，则把第 2 层迁入 `jshi.memory`，`SubjectProcess` 只注入并调用协调器。

### 建议保留的模型输出

- `response_plan`：回应计划（mode / reason / items）；
- `recall_requests`：上下文补充需求；
- `object_assessment`：对象确认候选；

## 3. 数据结构

05 自身只写：

| 记录点 | 内容 |
|--------|------|
| `cognitive_content_appeared` | activity_id、认知内容 id、content、初始 epistemic_status |
| `object_identity_assessed` | 对象确认候选被主流程校验后的结果 |

记忆侧记录（不再由 05 写）：

| 记录点 | 归属 |
|--------|------|
| `recall_extended` / `recall_metrics` / `recall_reference` | 09 或统一记录评价系统 |
| `recall_evaluated` | 独立评价过程写 |
| `memory_sealed` / `object_memory_updated` | 09 落位 |

## 4. 行为变更

1. 05 单次模型响应仍可携带多个用途段，但只负责候选解析与传递；
2. 模型请求上下文补充时，主流程决定是否执行、执行几轮；
3. 05 不再直接调用记忆端口，也不再生成记忆侧指标；
4. 主链路不另落 thought；说话文本在 `response_plan` 的 verbal item；
5. 对象确认由主流程消费 05 候选后回填；
6. 若主流程当前未接 09 召回协调器，可以暂时不执行 `recall_requests`，但应显式记录“已识别未执行”，避免误认为已有记忆能力；
7. 回忆评价由独立过程完成，不放进认知模型的同一轮 `ModelResponse`。

## 6. 风险与未决

- 当前主流程仍是编排者，`_cognize` 拆分后的职责边界需要与 09 协调器落地同步验证；
- `RecallRequest.level` 已由 09 实现，后续应由主流程透传，不能留在 05 内作为“已实现记忆”；
- 记忆侧指标统一归属尚未落地，先不要继续散写在 05；
- 事件结束、缩减、人工介入仍为占位，不越界接线。

## 7. 记录、评价与参数影响

- 05 新增记录点保持最小：认知内容落位、对象确认；
- 05 不再新增记忆侧记录点；相关评价与参数由 09 / 14 / I-002 统一管理；
- 参数：上下文补充轮次、片段预算、回忆档位均归主流程/09；05 只表达候选需求。
