## 0. 何处用模型，是否都做成 skill

**200 自己要思考的，做成 skill。不思考的，不要做成 skill。引擎内部的模型，不是匠石 skill。**

| 位置 | 调模型？ | 形式 | 理由 |
|------|----------|------|------|
| 05 回复 / 写场 | 是 | 已有 `CognitionSkill` / `WriteZoneSkill` | 不属 200。05 只出 `use_tool` + `need`。 |
| **205 策划** | 是 | **新 `ToolPlanSkill`** | 选模板、填参数、写估价槽。规则 echo 只是占位。 |
| **包装可见人话** | 是 | **新 `ToolWrapSkill`** | 把 210 里的阶段性事实写成给 03 的一句。 |
| 「要不要可见」单独一次 | 否 | 包进 `ToolWrapSkill` 的 `visible` | 再开一个 skill 会和包装抢活，也多一次延迟。 |
| 210 记挂 | 否 | 账本 | 多本并行；不思考。 |
| 206 适配 | 否 | 翻译 | 读 Pi 事件、写入对应 210。不改 Pi 内核。 |
| Pi 进程里的 LLM | 是，但是引擎 | **不是**匠石 skill | 改 Pi 要单独评估风险收益，本方案不做。 |
| CLI `jshi tool` | 否（旁路） | 直打引擎 | 调试用，不经 200 skill。 |

两条 200 skill 都走现有 `Skill` 基类（instruction + JSON Schema + 解析 + 降级 + `model_tag`），在 `skills.json` 注册。不要复用认知 skill，也不要为 200 另写一套调模型框架。

思考档位：这两条是填槽/写一句人话，`thinking` 默认 `disabled`，避免 V4 Flash 后台写长思维链。

## 1. 目标与范围

**本次方案：200 内部按「多交接、多记挂、两 skill」落地的完整切法。** 编码分三刀（§9），确认方案后先改设计再按刀编码。

### 已落地（I-017 通道，不重做）

- 05 只出 `use_tool` / `need`；写场后 `intake`，07 照关。
- `ToolService`：`intake` / `list_visible` / `cancel`。
- 交接 `tool.jsonl` ≠ 记挂 `hang.jsonl`。
- 03 原样装 `summary` → `tool_input`；不叫醒；写场不带这一路。
- `RulePlanner`、Stub 整包 `submit`、Pi 攒到 `agent_settled`：视为占位。

### 本方案要做

1. **210 = 记挂账本**（号留下）。只收 Pi 的阶段性事实，丢掉思维链；一本一请求；有新事实就通知 200。
2. **`ToolWrapSkill`**：只读这一本 210 的新事实，产出 `{visible, summary}`。可见 = 这句话可进 `list_visible`。
3. **`ToolPlanSkill`**：读交接 + 模板说明（含时间、异常），产出定义 / 失败句。失败不建 210。
4. **206**：边读边写入对应 210。不改 Pi 协议、不加 Pi 字段。修适配器侧明显坑（如 `stderr=PIPE`）。
5. **多本并行**：可重入；一本一包装队列；按对象 `list_visible` 上限 8；后一句覆盖给 03 看的那条。

### 不做

- 改 Pi 内核或 Pi RPC 加 `time` / `exception` 字段。
- 叫醒 / 插内部活动。
- 05 填模板名或参数。
- 200 经 10 对人开口。
- 自省 300 的完整入口（`origin=introspection` 字段预留即可）。
- `fact/tool_*`、08、权限 100/15 实装。

## 2. 内部结构与数据流

```text
05 need → 200.intake（交接，立刻返回）
              ↓
         ToolPlanSkill（205）
              ├ 失败 → list_visible 交失败句（无 210）
              └ 成功 → ToolRequest + estimate 槽
                         ↓
                    建 210（一本）
                         ↓
                    206 ↔ 该次 Pi 会话
                         ↓
                    事件写入这一本 210（不要思维链）
                         ↓
                    通知 200：这本有新阶段性事实
                         ↓
                    ToolWrapSkill（只看这一本）
                         ↓
                    写回 210：visible + summary
                         ↓
下一轮 03：list_visible(对象) → tool_input
```

复杂情形（正路，不是边角）：

| 情形 | 处理 |
|------|------|
| 一条 need 拆多条请求 | 一本交接，多本 210，各跟各的 Pi。 |
| 上一轮还在跑，又 intake | 旧账继续，新账另建；不得一把锁堵住第二次 `intake`。 |
| 同一对象多条可见 | 只交该对象、`visible` 且有 `summary` 的，上限 8。 |
| 不同对象 | 按 `object_id` 隔离。 |
| 一本上多次阶段性成果 | 新 `summary` 覆盖给 03 看的那条；同一 `task_id` 03 只装一次；旧句留账备查。 |
| 包装失败 | 跟随不停；本轮可不交可见，或降级极短事实句；禁止 Pi 原文进 03。 |
| 取消 | 只注销那本 210 及其会话；其它照跑。 |
| 进程崩溃 | 210 行还在，Pi 子进程可丢；不假装跑完。 |

**一本一队列**：包装调模型排在该 210 自己的队列，不挡 206 读流，也不跟其它本抢一把全局模型锁到无法 `intake`。允许有总并发上限（占位，14 后调），排队而不是丢掉事实。

## 3. Skill 简版

共用约定：输入先做成窄结构，再塞进 `ModelRequest.input_text`（JSON 文本），走 `Skill` 基类。结果是候选。失败走降级，不把模型原文当人话。`model_tag` 记在该次交接或该本 210 的 meta。

### 3.1 `ToolPlanSkill`（205）

- **name**：`tool_plan`；**version**：`v1`
- **何时**：`intake` 之后、建 210 之前。每份交接一次（拆多条请求则一次输出数组，或连续几次调用；本刀允许一次输出 1 条，多条为后续）。
- **读**：交接（`need`、口头、对象、活动、`field_ref`）+ 匠石侧模板目录（槽位说明：意图、预估时间、费用、可能结果、风险/异常、参数、期望形态）+ 引擎可提供的工具内容短说明（`get_commands` 的 description；读不到就空，用通用槽默认「时长未知、有执行风险」）。
- **不读**：活跃区全文、Pi 思维链、09 记忆。
- **instruction（简）**：

```text
你是匠石的工具策划，不是对说话的那一轮认知。
根据意图选一个定义模板，填参数和估价槽。
不要点名编造目录里没有的模板。
外部路径已经对人说过需求的，定义须与那句一致，不要另起一套。
填不出就失败，写出一句给匠石自己看的原因，不要装成已经在跑。
```

- **schema（简）**：

```text
ok: bool
template: string          # ok 时；匠石侧模板名
params: object
estimate: { time_est_ms, cost_est, benefit, downside, need_confirm }
expected_result: string
ask: execute | propose_only   # 主路径默认 execute
error: string             # !ok 时，给 03 的失败句
```

- **降级**：解析失败或 `ok` 假 → `PlanFailure`（现有失败可见路径），不建 210。不要默默 `echo`。
- **落点**：`src/jshi/skill/tool_plan.py`；`plan.py` 的 `ToolPlanner` 换成这个；测里仍可注入 `RulePlanner`。

### 3.2 `ToolWrapSkill`（包装；200 内部，不占对外号）

- **name**：`tool_wrap`；**version**：`v1`
- **何时**：某本 210 新增了**阶段性事实**（有内容的 progress.partial、或 result）。不要每个 JSONL 行都调。Pi 思维链 / 无内容的 start 心跳：不调。
- **读**：该本 `need`、已发出的模板名、**本批新事实**（已剥思维链）、上一句 `summary`（若有）。
- **不读**：其它 210 的账、对方原话、活跃区全文。
- **instruction（简）**：

```text
你把工具进行中的事实写成一句给匠石看的话，像他自己刚弄清的进展。
不是对那个人开口，不要称呼对方、不要写成 response_plan。
不要把引擎思维链、调试日志写进去。
没有可说的阶段性成果就 visible=false。
有可说的就一句，短，不要堆过程。
同一件事不要换个说法再报一遍。
```

- **schema（简）**：

```text
visible: bool
summary: string    # visible 时必填；给 03 原样装的那句
```

- **降级**：解析失败 → `visible=false`（跟随继续）。连续终态仍失败 → 可用结果里已有的极短 `error`/`status` 作一句，仍禁止 Pi 长文。
- **可见**：`visible=true` 且 `summary` 非空，才进 `list_visible`。策划失败条目仍走交接上的 `plan_error`，不经本 skill。
- **落点**：`src/jshi/skill/tool_wrap.py`；由 `ToolService` 在该 210 的包装队列里调用。

`skills.json` 增：

```text
tool_plan: thinking disabled, streaming false
tool_wrap: thinking disabled, streaming false
```

## 4. 非 skill 块

### 4.1 210 记挂

号留下。存储仍默认 `{data-dir}/hang.jsonl`，与 `subject.sqlite3` 分开。

做：按 `task_id` 追加反馈；保存当前 `visible` / `summary`；有新阶段性事实则投递包装队列；按对象列出；注销。

不做：选模板、填参数、写人话、对人开口。

`notify_caller` 改名为 `visible`（读旧键兼容一版）。注释里的「叫醒」删掉。

### 4.2 206 与 Pi

`PiEngine` 继续只翻译：发 prompt、按 LF JSONL 读、`tool_execution_*` → 信封。

本方案改适配器行为，不改 Pi：

- 读到一条可入账事件，**立刻** `HangStore.append_feedback`，不要等 `agent_settled` 整包。
- 入账前丢掉思维链类事件（未映射为 start/update/end 的，直接丢）。
- `update.partialResult` 有文本才算阶段性事实，才通知包装。
- `stderr` 不要 `PIPE` 堵死（改继承或文件，属 206）。
- 时间、异常：**不**往 Pi 协议加字段。写在匠石模板说明和（若有）Pi `description`/`SKILL.md` 文本里，给 `ToolPlanSkill` 读。

Stub 仍可整包，但 Runner 应改为「引擎若回调/迭代就逐条入账」；Stub 没有流时，跑完一次写入仍可，包装仍只在有 result/有内容 progress 时触发。

### 4.3 定义模板说明

新增匠石侧模板目录（建议 `src/jshi/tool/templates/*.json` 或一份 `catalog.json`）。每条至少：

```text
name
intent_slot
time_note          # 预估时间怎么填、未知时怎么说
cost_note
result_note
exception_note     # 常见失败 / 异常
params             # 槽名与含义
expected_shape
```

通用底模板一条；`echo` 保留给测试。真 Pi 命令名与匠石模板名的对应由策划 skill 选，不在 05。

## 8. 测试计划

在现有 `tests/test_tool_hang.py` 上加，不把 live Pi 当单测。

1. `intake` 后 RulePlanner/假 skill 失败 → 无 hang，`list_visible` 有失败句。
2. Stub 跑完 → 包装（假 skill 固定 `visible=true`）→ `tool_input` 等于 `summary`，不是 Pi/Stub 长 `result` 原文。
3. `visible=false` → `list_visible` 不含该 task。
4. 同一 `task_id` 两次包装 → 03 仍一条，内容为后一次 `summary`。
5. 两个 hang、两个对象 → 各自 `list_visible` 不串。
6. 第二次 `intake` 在第一次还在跑时能返回（可重入）。
7. `cancel` 一本不影响另一本。
8. 包装抛错 → 跟随仍写入 result；不进可见或走降级短句。
9. Pi 适配单测用录制事件：先 `update` 再 `end`，断言 hang 在 `end` 之前已有 progress 行（边读边入账）。不启动真 Pi。
10. `ToolPlanSkill` 解析失败 → 无 hang。选目录外模板名 → 当失败。

回归：`test_assembly.py`、`test_model_prompt.py`、`test_skill.py`（认知）不得被 200 skill 带坏。

## 9. 建议编码顺序（确认方案并回写设计之后）

1. **210 账本 + 206 边写入账 + 一本一通知**（包装仍规则占位：有 result 则 `visible`，`summary` 仍可先用短摘要）。
2. **`ToolWrapSkill`** 换掉规则摘要。
3. **模板说明 + `ToolPlanSkill`** 换掉 `RulePlanner`。

理由：没有边写入账，包装永远只能看整包结束；没有包装，03 仍吃引擎残片；策划可以后上，echo 仍能跑通通道。

## 10. 风险与未决

- 包装过密：必须「有阶段性成果才调」，否则费用与 `tool_input` 都会吵。阈值本刀用「有文本的 update / 任意终态」；过密再收。
- 一条 need 拆多条请求：本刀 skill 先出 1 条；多条是后续。
- 总并发上限数值：占位，用户拍板前用小整数（如同时包装 2）。
- 主流程是否默认 Pi：不在本方案改；仍 Stub 默认。
- 设计文档仍写 210「判断可见」：以本方案为准回写后才能编码。
