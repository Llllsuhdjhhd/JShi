## 0. 依赖系统实现状态（防遗忘清单）

| 依赖系统 | 文档 | 实现状态 | 09 本期使用方式 | 后续替换点 |
|----------|------|----------|------------------|------------|
| 事实历史 | 00/07 | 已实现（`histories` kind=fact） | 作为最小原文存储与召回来源 | 外部引擎 / 独立记忆表 |
| 对象标识 | 01 | 已实现（`object_id` 在事实历史 content） | 召回按对象过滤 | 01 正式字段化 |

## 1. 目标与范围

占位 → **最小实现**：

- 为 `MemoryPort.recall` 增加 `level`（1–9）与 `anchor_event_ids` 参数；
- `InProcessHistoryMemory` 实现档位 → 片段上限映射、对象过滤、近因优先、中文/拉丁词重叠加权、显式 `limit` 覆盖；
- `MemorySource` 不再内含档位映射/对象过滤/排序，改为透传 `memory.recall(level=...)`；
- 05 追加召回把 `RecallRequest.level` / `object_ids` / `anchor_event_ids` 传给 09；
- CLI `recall` 增加 `--level`，并让 `--limit` 未指定时按档位推导默认条数。

不做：

- 事件本体独立、按事件锚点真实召回（07 未实现，`anchor_event_ids` 本期仅记录）；
- 事件完成/分割后的记忆落位与「已存标记」回填（07/05 未实现）；
- 外部记忆引擎接入、摘要压缩、代谢遗忘与删除；
- token 预算换算（14）；
- 向量检索或语义排序。

## 2. 接口落点

### 修改 `src/jshi/memory/port.py`

- 新增 `recall_level_limit(level: int) -> int`：1–9 映射为 3 / 5 / 8，越界收敛；
- `MemoryPort.recall` 增加 `level: int = 1` 与 `anchor_event_ids: tuple[str, ...] = ()`；
- `InProcessHistoryMemory.recall`：
  - `limit` 改为 `int | None = None`；
  - `cap = limit if limit is not None else recall_level_limit(level)`；
  - 对象过滤、近因优先、词重叠加权与回退逻辑不变，改用 `cap`；
  - `anchor_event_ids` 本期只接收不参与过滤（07 未来接线）。

### 修改 `src/jshi/assembly/sources.py`

- `MemorySource.__init__`：`memory or InProcessHistoryMemory(repository)`，保证始终走 09 端口；
- `MemorySource.load`：删除本地档位映射与事实历史直读 fallback，改为调用
  `self._memory.recall(ctx.subject_id, ctx.input_text, object_id=ctx.object_id, level=ctx.recall_level)`；
- `status` 保持 `implemented`，docstring 说明已由 03 适配器升级为透传。

### 修改 `src/jshi/subject/process.py`

- `_cognize` 不再直接执行召回；主流程上下文协调层透传给 09：
  - `limit=request.budget or 默认条数`；
  - `object_id=request.object_ids[0] if request.object_ids else None`；
  - `level=request.level`；
  - `anchor_event_ids=request.anchor_event_ids`。

### 修改 `src/jshi/app/cli.py`

- `recall` 命令增加 `--level`（默认 1）；
- `--limit` 默认改为 `None`，未指定时由 09 按档位推导默认条数。

### 导出

- `src/jshi/memory/__init__.py` 增加导出 `recall_level_limit`。

## 3. 数据结构

无新持久化表：

| 存储 | 内容 |
|------|------|
| `histories`（kind=fact） | 原文落位；`content` 继续携带 `text` / `object_id` 等 |

| 档位 | 上限 |
|------|------|
| 1–3 | 3 |
| 4–6 | 5 |

## 4. 行为变更

1. 03 初始装载：`MemorySource` 透传 `level=1`（线索级）与说话人 `object_id`，返回对象过滤后的最近事实线索；
2. 05 追加召回：`level` 由模型请求指定，`limit` 由请求预算控制；未指定对象时保持跨对象召回；
3. 显式 `limit` 覆盖档位默认条数；
4. 无词命中时按近因回退，低信号输入仍有结果；
5. 阶段③ 仍不调用模型、不写长期记录；记忆召回只读。

## 6. 风险与未决

- **档位映射是占位**：以「返回条数」代理「上下文深度」，无理论依据，待 14 验证后调整；
- **对象过滤语义**：阶段③ 强过滤，阶段⑤ 默认跨对象；若后续要求 05 默认按当前对象过滤，需调整 `_cognize` 的默认值并补充验证；
- **anchor_event_ids 本期无行为**：事件本体独立（07）前无法真正锚定，仅保持接口兼容，避免误以为已实现；
- **近因与词重叠评分**：当前为确定性的轻量占位，未来可替换为更强检索，不影响端口稳定性；
- 显式 `limit` 覆盖档位后，档位在 05 追加召回中只作意图记录，客观效果由 14 指标闭环评价。
