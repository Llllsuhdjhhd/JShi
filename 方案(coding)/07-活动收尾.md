# 07 活动收尾——实现方案

> 对应文档：doc/design/07-活动收尾.md（初稿）
> 状态：初稿，按已接线代码整理，不是新功能

## 1. 目标与范围

本次做到**最小**：07 只关闭活动并审计，记忆投递交给 30。

- `ActivityClosePort.close` 将活动标为 completed，写 `activity_completed`；
- 主流程在 close 之后调用 `MemoryControlPort.run_once`，07 不构造 MemoryBatch、不调用 09。

I-001 不纳入。超时归档、放弃/等待等最终状态判断本期不做：当前一律 completed。

## 2. 接口落点

- `src/jshi/activityclose/port.py`
- `src/jshi/activityclose/inprocess.py`
- `src/jshi/subject/process.py`：行动后 `advance` 活跃区窗口，再 `activity_close.close`，再 `memory_control.run_once`

## 3. 行为变更

收尾顺序：语言行动 → 经历流追加回复 → 反馈占位 → 推进活跃区起点 → 07 close → 30 run_once → 11 治理占位。

07 不包含记忆逻辑。向 30 的“投递信号”目前是主流程顺序调用，不是 07 返回的消息总线。

## 4. 测试计划

- `tests/test_support_modules.py`：close 后活动为 completed，有 `activity_completed`；
- 回归：外部活动流程仍能完成并触发记忆管控尝试。

## 5. 风险与未决

- 设计中的 `handoff_to_memory_control` 尚未做成显式字段，主流程直调 30；
- `wait` / 放弃尚未进入 close 判断。

## 6. 记录、评价与参数影响

- 记录点：`activity_completed`；
- 评价点：活动完成情况，由评价旁路收集；
- 参数：超时归档阈值未来由 14 管，本期无。
