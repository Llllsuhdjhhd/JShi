## 1. 目标与范围

占位 → **最小实现**：

- 新增 `src/jshi/assembly/`：统一装载能力（组装请求 / 装载片段 / 装载报告）、组装器、六个装载源适配器；
- 六个源中四个实装（身份、个人世界、事件、记忆），两个占位空（认识状态、对象档案摘要），占位源在报告中明确标记，不静默缺失；
- `SubjectProcess.assemble_current_state` 委托组装器；`AssembledCurrentState` 保留现有字段并新增统一片段与装载报告；
- 预算：组装额外预算 = 活跃区预算 × 1/2（占位），合并后按优先级截断，跳过项进入报告；
- 记忆源：按说话人对象过滤 + 近因优先 + 最低可用档（占位映射）；
- 记账 `current_state_assembled` 增加各源装载明细。

不做：

- 09 原生档位与对象过滤接口（09 模块实现）；
- 06 认识状态装载、01 对象档案摘要（占位空）；
- 07 事件本体独立（仍用活跃区视图）；
- 05 追加召回档位字段；
- 并行执行（接口可并行，占位顺序）；
- token 预算换算（14 调参系统）。

## 2. 接口落点

### 新增 `src/jshi/assembly/`

`port.py`：

- 组装请求：主体标识、输入文字、说话人对象标识、活跃区视图、组装额外预算、回忆档位、可选的显式引用（事件 / 对象标识）；
- 装载片段：来源类型、标识、内容、子类型、状态、重要程度、来源链、是否常驻；
- 装载报告：源名、装载数、预算、片段标识、跳过标识、实现状态（implemented / placeholder）、失败原因（可选）；
- 装载能力（协议）：装载源接收组装请求，返回装载片段与装载报告。

`assembler.py`：

- 组装器：接收装载源列表与偶然性钩子；执行 收集 → 去重 → 预算截断 → 快照 → 偶然性 → 汇总报告；
- 去重：同一标识只保留一次，优先级 事件 > 个人世界 > 记忆 > 其他；
- 预算截断：常驻 > 事件 > 个人世界 > 记忆 > 其他；跳过项进入报告；
- 失败隔离：单个源异常时记录失败原因，继续使用其余源结果。

`sources.py`：

- 身份源：读身份档案，生成常驻片段（身份摘要、立场）；
- 个人世界源：包装 `personal_world.select`，过滤 concern 条目，承诺常驻；
- 事件源：转换 `ActiveZoneView`（未完成常驻、完成按活跃区预算）；
- 记忆源：占位实现（见 §3 回忆占位）；
- 认识状态源：占位空，报告标记 placeholder；
- 对象源：占位空，报告标记 placeholder。

### 修改 `src/jshi/subject/process.py`

- `__init__` 增加 `assembler: CurrentStateAssembler | None = None`；默认构造注入现有 repository / identities / personal_world / active_zone / memory / chance；
- `assemble_current_state` 委托组装器，`AssembledCurrentState` 新增 `fragments` 与 `source_report` 字段（现有字段保留）；
- `_subject_state` 逻辑移入组装器（快照生成不再散在 process）；
- `current_state_assembled` 记账增加 `sources` 明细；
- `recall_events`（显式 id 召回）行为不变，仍走 02 端口。

### 修改 `src/jshi/app/cli.py`

- `preview-state` 增加各源装载报告摘要（源名、装载数、实现状态），便于直接查看哪些源还是占位。

## 3. 数据结构

### 组装工作集

| 内容 | 说明 |
|------|------|
| 统一片段列表 | 合并去重后的全部装载片段（进模型上下文） |
| 主体状态快照 | 身份摘要、立场、价值、承诺、未完成事件文本、来源标注 |
| 活跃区视图 | 阶段② 结果原样保留 |
| 装载报告 | 每源：装载数、预算、标识、跳过项、实现状态、失败原因 |
| 输入文字 | 本次输入原文 |

`AssembledCurrentState` 在现有字段（input_text / subject_state / personal_items / active_zone / active_event_ids / recalled）基础上新增 `fragments`、`source_report`，既有调用方与测试不破坏。

### 预算

- 组装额外预算 = `max(1, active_zone.budget // 2)`（占位：活跃区 8 → 额外 4）；
- 各源自行决定份额内装什么；合并后由组装器按优先级截断到额外预算；
- 跳过项进入装载报告（供 14 分析）。

### 回忆语义（由 09 定义）

- 档位 1–9 → 片段数映射由 09 定义：1–3 → 3 条（线索级）；4–6 → 5 条；7–9 → 8 条（当前占位常量，见 09 方案）；
- 对象过滤、近因优先、查询词重叠加权与「不查询活跃区」均由 09 的 `recall` 执行；
- 03 的 `MemorySource` 只透传 `object_id` 与 `recall_level`，不再内含记忆检索规则。

## 4. 行为变更

1. `assemble_current_state`：组装器调用六个源（顺序占位）→ 合并去重 → 预算截断 → 生成快照 → 偶然性 → 汇总报告；
2. 事件源直接使用阶段② 视图，不重复读取；个人世界源跳过 concern，避免与事件源重复；
3. 记忆源按说话人对象过滤 + 近因优先 + 最低可用档；认识状态源、对象源返回空但报告标记 placeholder；
4. 单源失败：记录失败原因，其余源正常装载；
5. `current_state_assembled` 的 content 增加 `sources`（每源：source / count / budget / ids / skipped / status / error）；
6. `preview-state` 展示装载报告摘要；
7. 阶段③ 仍不调用模型、不写长期记录（记账除外）。
