## 1. 目标与范围

把阶段⑤ 的「回复」与「写场/现场提炼」从**一次调用、同一个 JSON、一刀切解析**拆成**两次独立调用**：

- **调用① 回复**（`CognitionSkill`）：交出 `response_plan`（木头）/ `reply/action`（人格）；可流式（I-001）；不做写场。
- **调用② 写场**（新 `WriteZoneSkill`）：木头产整份 `rewritten_context`；人格产 `edit` + 程序追加；以①的回复为输入；独立降级、重试一次。

**明确不做 / 保留**：

- **人格隐藏木头**：选中人格只跑该人格写场（`edit`+程序追加）；木头的写场路径（整份 `rewritten_context`）不执行。
- **30→09 不变**：仍收 `input_text` + 新口头，不把活跃区当记忆；材料层（09 按 `input_text` 召回、01/08 真源、账本 `text_raw` 只追加、对象确认）与活跃区形态无关。
- **boot（无片场写场景）不变**：仍走 `_maybe_boot` 一次性写场景；只在有片场后的常规轮走「两次调用」。

## 3. 数据结构 / 契约变化

### 3.1 回复调用（①）Schema

`CognitionSkill.schema`（木头）去掉 `rewritten_context`；保留 `response_plan`、（可空）`object_assessment`。
人格 `persona_schema` 去掉 `edit`，仅 `{mode,reply,action,reason}`。

`CognitionSkill.run` / `parse` 相应去掉对 `rewritten_context` / `zone_edit` 的填充。

### 3.2 写场调用（②）Schema（新）

```
木头  {"rewritten_context": string}
人格  {"edit": [ {op: add|del|mod, id?: string, text?: string}, ... ]}
```

`WriteZoneSkill.parse`：persona → `ModelResponse(zone_edit=...)`；木头 → `ModelResponse(rewritten_context=...)`。

### 3.3 写场输入的来源

写场调用需看到：当前活跃区/片场正文、本轮 `input_text`、本轮已召回回忆（`fragments`）、主体身份/价值、以及**① 的回复**（木头重写要写「我说：…」；人格 edit 可选）。

- 木头写场：`input_text` = 本轮回复（用作「我说：…」），`context` 带活跃区正文与来源。
- 人格写场：`persona_user_text` = 片场 + 输入 + 回忆（复用 `_persona_user_text`，另附「本轮回应」），模型只交 `edit`。

> **待定的小决策**：写场请求里“回复”用什么字段承载（`input_text` 或新增 `reply_text`）。倾向：`input_text` 直接放回复；活跃区/回忆放 `context`。

## 4. 行为变更（主流程拆分）

### 4.1 `_cognize` 拆成两段

```python
# ① 回复（现 _cognize_once，去掉写场字段）
response = self._cognize_once(current, working_recalled, on_reply=on_reply)
#   → response_plan (+ object_assessment)；不产出 rewritten_context / zone_edit
#   → 06 → 10（mark_activity_response_status / action 不变）

# ② 写场（新）
write_plan = self._write_zone(current, response)   # 见 4.2
```

`_write_zone`：

- 构建 `ModelRequest(purpose="write_zone", input_text=<回复>, ...)`，按 `style_packs` 选中包决定走木头 Schema 还是人格 Schema。
- 调 `self.write_zone.generate(request)`；**失败重试一次**；仍失败 → 返回空写场结果（木头 `rewritten_context=""`，人格 `edit=()`）。
- 返回写场结果。

### 4.2 写场分发（替换现 711–725）

```python
pack_id = self.style_packs.get(subject_id)
registry = getattr(self.style_packs, "registry", None)
if is_persona(pack_id, registry=registry) and self._persona_ready(subject_id, current):
    self._apply_zone_edit(subject_id, write_result, current)     # write_result.zone_edit
else:
    self.activity_ledger.save_rewritten_context(
        subject_id,
        getattr(write_result, "rewritten_context", "") or "",
        speaker_object_id=(speaker.object_id if speaker is not None else None),
        style_pack_id=pack_id,
    )
```

- 木头：`rewritten_context` 空/失败 → 16 保留上一份（D-009）。
- 人格：`edit` 为空 → 片场不动；apply 失败 → 片场不动。
- 写场失败不改变 06→10 的结果（回复已先行）。

### 4.3 重试一次 + 保留输入与回忆

- 写场调用失败 → 重写一次（同请求）；仍失败 → 空写场结果。
- **不丢输入与回忆**：本轮 `input_text` 与 `fragments` 仍在材料层（账本 `text_raw` 只追加 / 03 组装），写场重试复用，失败也不删除。

## 5. 测试

- **契约**：回复调用范文中**无** `rewritten_context` / `edit`；写场调用产出 `rewritten_context`（木头）/ `edit`（人格）。
- **两次调用**：`_cognize` 先回复后写场；回复调用后 06→10 可走，不等写场。
- **写场 N → N+1 顺序**：N 轮写场完成后 N+1 轮提示词才生成；N+1 轮读到 N 轮写场结果。
- **人格隐藏木头**：选人格时木头 `save_rewritten_context` 不调用，只走 `_apply_zone_edit`；选木头时反之。
- **写场失败重试一次**：注入失败写场，断言调用一次重试、仍失败后用空写场结果、06→10 结果不受影响、输入与回忆仍在账本/组装。
- **30→09**：`extract_batch`/`ingest` 仍只收 `input_text` + 新口头，不把活跃区当记忆。
- **boot 不变**：无片场人格走 `_maybe_boot` 写场景流程照旧。

## 6. 风险与回退

- **木头每轮 2 次调用**：成本/耗时上升；回退——`write_zone` 若超预算或模型不支持，木头可退回「一次调用产出 response_plan+rewritten_context」（在 `CognitionSkill` 保留旧 Schema 路径，按开关切换）。
- **写场调用依赖回复**（写「我说：…」）：回复若流式提前开口，需在回复完整后再调写场（同轮同步），不可并发。
- **Schema 改动牵连测试**：`test_cognition_recall.py` / `test_new_flow.py` / `test_style_zone_rewrite.py` 等凡断言 `rewritten_context` 来自主调用的都要改为断言来自写场调用。
- **回退开关**：保留 `CognitionSkill` 旧 Schema 与主链路 `save_rewritten_context` 分支，便于一键回退。

## 7. 记录、评价与参数

- 记录：`model_tag`（I-004）分别记**回复调用**与**写场调用**的模型/版本；写场重试/失败记入 `metadata`。
- 评价：写场失败不产出现场打分；仍不进有效性分析（旁路）。
- 参数：活跃区容量（`zone_chars`）、是否拆分调用，归 14/魔法书；05 不展开。

## 8. 验收（方案层）

- 阶段⑤ 两次调用：①回复无写场字段，②写场独立产出；写场 N → N+1 顺序正确。
- 人格隐藏木头写场；木头默认整份重写（保留 D-009）。
- 写场失败重试一次，仍失败→沿用上一份/片场不动，不吞回复、不丢输入与回忆。
- 30→09 与材料层不受活跃区形态影响。
- boot 不变。
