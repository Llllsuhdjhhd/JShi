# 01 身份识别——实现方案

> 对应文档：doc/design/01-身份识别.md（初稿）
> 状态：初稿，待确认后进入编码

## 1. 目标与范围

占位 → **最小实现**（文字对象解析路径可用，渠道层映射未来接入）：

- 外部文字输入**对象必填**：对象来自渠道（账号/会话，未来）或显式提供（`--speaker`，当前）；两者皆无 → 拒绝（明确错误，不落位、不创建活动）；
- **置信度门禁**：候选置信度低于阈值 → 不进入后续活动，记录原因；
- `ObjectProfileRepository`：SQLite 实现（`subject.sqlite3` 新增 `object_profiles` 表），接口可替换；
- 基于文字寻找 / 新建对象：按输入提供的名字/别名匹配档案；未匹配 → 产生新对象候选，通过门禁进入落位时落库为暂定对象（来源 = 输入事实 id）；
- **置信度不落库**：每次活动按"识别来源 × 档案状态"动态计算；
- 认知确认钩子：阶段⑤ 模型可判定对象，记录 `object_identity_assessed`（占位模型不判定）；
- 内部输入（source=internal）跳过识别，标记 system。

不做：渠道层对象映射（声纹 / 账号会话 / 设备 / 人脸）、身份确认回合、档案合并、正文实体解析自动新建、多模态、流式累积。

## 2. 接口落点

- 新增 `src/jshi/recognition/profile.py`：`ObjectProfile` 数据类 + `ObjectProfileRepository`（SQLite，含 create / find_by_name / find_by_id / list）；
- 新增 `object_profiles` 表结构（并入 `src/jshi/subject/repository.py` 或独立 db 模块）；
- 修改 `src/jshi/recognition/port.py`：`ObjectRecognitionPort.resolve(subject_id, text, object_ref, channel=None) -> SpeakerCandidate`；占位实现升级为基于档案的 resolve（查找 / 新建暂定）；
- 修改 `src/jshi/subject/process.py`：experience() 入口做对象必填校验与置信度门禁（不达标 → 拒绝，不建活动）；识别输出进入落位；阶段⑤ 后接确认钩子；
- 修改 `src/jshi/models/base.py`：`ModelResponse.object_assessment`（可选，与 `recall_requests` 同模式）；
- CLI：`experience` / `chat` 增加 `--speaker <名字或对象标识>`（渠道未提供对象时必填）；新增 `add-object`（可选，便于预注册档案）。

## 3. 数据结构

### object_profiles 表（subject.sqlite3）

| 字段 | 类型 | 说明 |
|------|------|------|
| object_id | TEXT PK | 稳定对象标识 |
| label | TEXT | 显示名 |
| aliases | TEXT(JSON) | 称呼 / 别名 |
| channel | TEXT NULL | 渠道标识 |
| source | TEXT | 导入来源 / 输入事实 id |
| status | TEXT | unknown / provisional / confirmed / rejected |
| created_at / updated_at | TEXT | 时间 |

### 常量与事件

- 常量：`MIN_OBJECT_CONFIDENCE = 0.5`（模块级，后续升格为配置）；
- 动态置信度规则（占位）：渠道匹配（已确认 0.95 / 暂定或无档案 0.70）、显式名字匹配（已确认 0.85 / 暂定 0.65 / 无档案新建候选 0.60）、unknown 0.00；
- `fact/external_input`：携带 object 字段（同现状字段）；
- 新增 `subject/object_resolved`（新建暂定对象时）：object_id、label、source、status；
- 新增 `subject/object_rejected`（门禁阻断时）：object_ref、confidence、reason；
- 新增 `subject/object_identity_assessed`：candidate_label、object_id、conclusion（confirm / deny / uncertain）、reason、cognitive_content_id、epistemic_status。

## 4. 行为变更

1. experience() 入口：`object_ref` 缺失（且渠道未提供对象，当前渠道绑定未接入）→ 拒绝（错误返回，不落位、不建活动）；
2. `resolve(subject_id, text, object_ref)`：
   - 按 object_ref 匹配 aliases / label / object_id → 命中复用档案，置信度按档案状态动态计算（已确认 0.85 / 暂定 0.65）；
   - 未命中 → 产生新对象候选（暂定，**不立即落库**），置信度 0.60；
   - 渠道 unknown → 置信度 0.00；
3. **门禁**：置信度 < `MIN_OBJECT_CONFIDENCE` → 记录 `subject/object_rejected`，不创建活动、不进入认知（CLI 返回明确错误）；
4. 通过门禁后落位写 fact（携带 object 字段）；**新对象此时落库为 provisional**（记录 `subject/object_resolved`）；已存在对象不重复创建；
5. 阶段⑤ 认知后：若模型返回 `object_assessment`，记录 `object_identity_assessed`；confirm → 升级 confirmed，uncertain → 保持 provisional，deny → 标记 rejected（追加记录，不改写事实）；
6. source=internal 不经过 resolve，标记 system。

约束：原文永不改写；确认可追溯到认知内容与认识状态。

## 5. 测试计划

对应 doc/design/01 验收标准：

- 缺失对象 → 拒绝（不落位、不建活动）；
- 已知对象 → 匹配档案，落位携带 object_id（置信度 0.85）；
- 新名字 → 产生候选、通过门禁后落库为暂定对象，来源可追溯（object_resolved，置信度 0.60）；
- 低置信（unknown / 0.0）→ 门禁阻断，记录 object_rejected，不建活动；
- 认知确认 → `object_identity_assessed`：confirm 升 confirmed、uncertain 保持 provisional、deny 标 rejected；
- 动态置信度：同一对象在 provisional 与 confirmed 状态下，下一次活动的置信度不同；
- 内部输入 → system，跳过 resolve；
- 兼容：档案表为空时，任意 object_ref 都新建暂定对象（旧 `human` 占位行为由 CLI 必填替代）。

新增用例：`tests/test_recognition_profile.py`。

## 6. 风险与未决

- object_ref 的 CLI 形态（`--speaker 名字`）需要避免误用：object_ref 是"说话人"必填参数，不是正文实体；
- 默认阈值 0.5 是否合适待定（可配置）；身份确认回合（低置信时的轻量交互）本期不做；
- 正文实体解析（"我认识了一个朋友叫小张"）本期不做，避免与 REMS 角色抽取职责重叠；
- 合并机制、渠道层对象映射（声纹 / 账号会话 / 设备 / 人脸）未来接入；存储经接口可替换。
