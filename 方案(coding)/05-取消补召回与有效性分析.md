## 0. 独立判断

现码 [`src/jshi/subject/process.py`](../src/jshi/subject/process.py) `_cognize`：先 `_cognize_once`，若有 `recall_requests` 再调 `RecallCoordinator`、再认知一次。这与 D-008 直接冲突，必须拆掉。

已有 `src/jshi/evaluation/` 只是事件收集，没有报告、没有策略、没有现场打分。不要把该包改名顶替「有效性分析」——新建 `jshi.effectiveness`。旧收集器继续当 `emit` 总线。

03 已按说话人召回（`MemorySource`，`recall_level` 现写死为 1）。策略快照只改这个入参，不改 `MemoryBackendPort`，不改 Jshi_memory。

**开口后下一拍要看见第三人**：只存 `gap_query` 不够——下一轮 03 仍按当前说话人过滤，第三人记忆进不来。本期让组装额外用未消费的 `gap_query` 再召一次（只读、与说话人线索去重后并入工作集，**不**再调 05）。这是 I-011 修订能落地的最小条件。

独立再评估（活跃区 / 打分 / 对象确认各开一次模型）设计允许，但加回主路径延迟。本期字段可空即满足「独立」；自动再调模型下一期。

## 1. 目标与范围

本次做到**最小**。

### 做

1. 取消同轮补召回：`_cognize` 只调一次模型；`recall_requests` 若仍出现则不执行、不二次认知，可记 debug。
2. `ModelResponse` 增加 `memory_ratings`；skill 可解析；无在场 `memory:` 则空。
3. 打分写入主体侧存储，供分析器读。
4. `jshi.effectiveness`：端口 + 进程内实现；记忆分析器（规则汇总，**先不调大模型**）；`run_due` 在收尾后调用，失败吞掉、不挡说话。
5. `RecallStrategyStore`（09 薄壳，json）：`default_level` / `limit` / `source_report_id`。03 组装读快照填 `AssemblyContext.recall_level`。
6. 下一拍：若有未消费 `gap_query`，按该 query 再 `recall` 一次，去重并入，然后标记已消费。
7. skill / 提示词：去掉「提出 recall_requests / 追加召回」；补丁与对象确认标明可空；打分只针对在场回忆。skill 版本号 +1。

### 不做

- 开口后为活跃区 / 打分 / 对象确认再开三次模型。
- 分析器调大模型出长文报告（规则汇总 + 档位建议即可；`model_tag` 留空）。
- 改 Jshi_memory / `MemoryBackendPort`。
- 改 06 / 10 契约。
- 本期不改验证章程 V8、主体过程实验、CLI「其余工作」全文（编码后抽查）。

### 本次层级

最小：主路径一次认知；打分可入库；规则分析器可改档；gap 可供下一拍 03 取第三人线索；既有口头 / 06 / 16 空补丁路径不回归。

```text
03 初始装载（说话人 + 可选 gap_query）
  → 05 一次认知（必出 response_plan；打分/补丁/对象确认可空）
  → 06 → 10 → 16（空补丁仍并入本轮输入/回应）
  → 07 → run_due（旁路）
下一拍 03 读策略档位 + 未消费 gap_query
```

## 3. 数据结构

### 3.1 现场打分（`MemoryRatings`）

逐条（已在场 `memory:` 才有）：

```text
MemoryRating
  ref                     # memory:{event_id} 或短编号还原后的引用
  relevance               # related | partial | unrelated
  helps_understanding     # 0 | 1 | 2
  used_in_reply           # unused | alluded | Relied
  misleading              # bool
  redundant               # bool
  object_fit              # match | other | none
```

整轮：

```text
MemoryRatings
  items: tuple[MemoryRating, ...]
  coverage                # sufficient | thin | missing
  gap_query               # 缺什么、关于谁；空串表示无缺口
```

入库行另加：`subject_id`、`activity_id`、`created_at`、`gap_consumed: bool`。

存储：`{data_dir}/memory_ratings.jsonl`（一行一轮；无打分可不写）。不进 `MemoryBackendPort`。

### 3.2 策略快照

文件 `{data_dir}/recall_strategy.json`：

```text
{
  "<subject_id>": {
    "default_level": 1,          # 1–9
    "limit": null,
    "source_report_id": "",
    "updated_at": "<iso>"
  }
}
```

无快照时 03 仍传 `level=1`。`apply` 只影响后续 `recall` 入参。

### 3.3 有效性报告

```text
EffectivenessReport
  report_id
  subject_id
  analyzer                # memory_quality
  created_at
  materials_ref
  findings                # 短结构化结论（规则生成）
  strategy                # {default_level, limit} 或空
  model_tag               # 本期空
  analyzer_version
```

进程内列表 + 同目录 `effectiveness_reports.jsonl` 归档。不进经历、不进活跃区、不进 05 上下文。

### 3.4 分析器触发（先写死，可进魔法书）

- 未分析打分满 **8** 条，或
- 距上次该主体 `memory_quality` 报告超过 **24h**

规则（夹在 1–9）：

- `unrelated` 占已打分条数 ≥ 1/2 → 建议 `default_level` 降 1
- 最近若干轮 `coverage=missing` 次数 ≥ 3 → 建议升 1
- 其余保持

## 4. 行为变更

1. **主路径**：认知一次 → 06 → 10 → 16（空补丁仍合并待并入段，硬上限兜底）→ 07。不为召回再调 05。
2. **打分**：有 `memory_ratings` 则入库；解析失败或空则本轮无行。不因打分失败改 `response_plan`。
3. **对象确认 / 补丁**：主调用有则照旧回填 01 / 交 16；无则跳过。
4. **`run_due`**：07（及现有 30 `run_once`）之后调用；异常 `logger.exception`，不抛到 `handle`。
5. **下一拍 03**：`recall_level` 来自快照；`extra_queries` 来自该主体未消费且非空的 `gap_query`（可用最近一条）；召回后将该行 `gap_consumed=true`。
6. **timing**：不再有「⑤召回」「⑤认知(补)」步。

约束：策略与打分失败不得改变已经说出的话、已写入的经历原文、已投递记忆。
