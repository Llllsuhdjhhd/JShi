测试条件与指标解释

  1. 同一份 2.160 秒录音“你好，可以怎么称呼你？”，PCM 16 kHz 单声道，每 20 毫秒按实时节奏送入项目语音 WebSocket，文件结束后继续送静音。时点零为播放开始加 2.160 秒，负数表示录音还在播放。ready 和火山连接单列，均发生在播放前。
  2. 每组四轮，共十六轮。每一轮四组的先后顺序轮换。主机为 Apple M5 Max、64 GiB，macOS 27.2，基于 codex/voice-endpoint-latency 工作区（HEAD 1a145f0 含已有未提交改动）。每次重新连接、创建隔离测试身份及空的进程内记忆库。采用迁入的本机声学模型，没有注册声纹。这里测不到正式历史库大小、多说话人场景对材料和耗时的影响。
  3. 本地 ASR 使用 mlx-community/Qwen3-ASR-1.7B-8bit，云端使用项目火山流式 ASR。本地 JEV 使用 mlx-community/Qwen3.6-35B-A3B-4bit，云端 JEV 使用 deepseek-v4-flash。两者均走项目 split 接话判断、关闭思考，沿用已有提示词、校验和完整输出。实际模型按请求路由核验。主认知固定 DeepSeek，TTS 固定本地 Vivian。
  4. 本机服务已启动，JEV 预装提示词前缀，ASR 和 TTS 做过预热。新会话 ready 单独计时。火山的声学轮次、说话人切分、连续说话人分析处于启用状态，本地 ASR 报告这些能力关闭或不可用。四组比较的是现有可切换配置，提供给模型的现场证据、分词与实际输出长度可以不同。
  5. 16 轮均形成两条输入，每条各调用一次 voice_jev_entry。32 次均返回 background / none，无模型错误或超时；均未进入 split 的后续判断。之后自主调度轮询现场事件，组装包含问句的主认知请求。终点在该请求组包完成，早于主认知模型返回。首句发声、整轮写入均在本表边界之外。
  6. 表中每格为组内四次的中位数，悬停可看取值范围和样本数。毫秒保留一位；小于 0.1 毫秒的非零值显示为 <0.1。分别计算的中位数不能直接相加；内含步骤、异步步骤及服务端指标可与其他行重叠。空格以横线表示服务未提供指标或分支未执行。HTTP 响应头的到达时机取决于服务的响应策略，无法用它推算模型首 token 或纯网络耗时。三个 token 指标采用各模型自身的统计口径。
  7. 本地八轮两段共十六次定稿都复用了流式预览。每段检测到 300 毫秒尾静音后即可复用；这个 300 毫秒已经在定稿时点里。语音端点和判断结束后的主流程轮询是两处独立等待。火山服务内部的解码、端点和缓存耗时没有独立观测值。
