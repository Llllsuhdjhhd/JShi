# 匠石（JShi）

**一个长期陪伴型 AI 的「主体过程」实验。**

大多数 AI 助手框架解决的是「怎么把任务做完」。匠石问的是另一个问题：**一个 AI 怎么有连续的自我**——记得住、认得清、说得有分寸，并且分得清「我知道的」和「我说过的」。

> 实验性项目，接口会变。当前状态见文末。

## 一轮对话长什么样

```
对象识别 → 状态组装 → 建活动 → 认知（出回应计划）→ 表达（口头 / 肢体）→ 写场 → 收尾
```

几个和常见做法不同的地方：

- **本轮上下文不是对话历史**，而是「状态组装」的结果：主体身份、对象、上一份活跃区、个人世界、记忆线索、工具反馈。
- **活跃区 = 工作现场**，由认知按当前风格**整份重写**；它是匠石此刻的工作台，不是聊天记录。
- **片场块分两种**：`（我知道）…` 是它当前知道的事实，`（未开口）…` 是没说出口但要留着的念头。两者都不是「我说过的话」。

## 核心设计

- **主体边界**：能力实现只出候选与过程反馈，不写主体的长期状态。
- **工具使用分账**：05 只判定「要不要用」并给一句 `need`；200 内部再分交接账本 / 205 策划 / 206 引擎适配 / 210 记挂 / 包装。对外只开三口（`intake` / `list_visible` / `cancel`）。
- **记忆是端口**：默认进程内后端；生产用 REMS3（邻仓，单独分发）。
- **人格是可插拔风格包**：木头 / 苏西坡 / 斯密斯。
- **自己看自己**：有效性分析系统 + 300 自省。

## 快速开始

需要 **Python ≥ 3.11**。核心只用标准库。

```bash
pip install -e .

python -m jshi.app.cli --data-dir .tmp/demo create stone
python -m jshi.app.cli --data-dir .tmp/demo experience stone "你好" \
    --speaker 火星人 --object 火星人:OBJ-M
```

对话（常驻，多轮）：

```bash
python -m jshi.app.cli talk stone --speaker 火星人
```

### 需要配置什么

不配任何东西也能跑——但只有「没有智能的骨架」。要真的像样，配这些（见 `.env.example`）：

| 想要 | 需要什么 | 缺了会怎样 |
|---|---|---|
| 真实对话 | 模型三件套：`JSHI_MODEL_ENDPOINT` / `JSHI_MODEL_API_KEY` / `JSHI_MODEL_NAME` | 回复退化成兜底句，不报错 |
| 真的用工具 | 装 Pi（`@earendil-works/pi-coding-agent`）。它是**默认**工具引擎 | 205 给诚实的失败句「我这边现在连不上工具引擎」 |
| 跨会话记忆 | 邻仓 REMS3（未随本仓分发）；设 `JSHI_MEMORY_BACKEND` | 用进程内后端，功能正常 |

**测试不需要任何环境变量。** `pytest` 用假模型端口和临时目录，离线可跑：

```bash
pytest -q
```

## 目录

```
src/jshi/          主链路与各模块
  subject/         过程编排（七阶段）
  core/ models/    状态、提示词、模型端口
  skill/ style/    认知 skill、风格包与片场
  tool/            200 工具使用（交接 / 策划 / 引擎适配 / 记挂）
doc/               设计文档：总体架构与各模块
  design/          00 流程总览、03 状态组装、05 认知、09 记忆、200 工具使用…
方案(coding)/      实现方案与修订记录
tests/             单测；tests/live/ 是需要真模型或真后端的 live 脚本
```
